# 0190 — Files thumbnails and default-handler opening

## Status

accepted

## Context

The T-10 Files MVP design deferred thumbnails, Open With, and file opening.
The browser and the Files-owned desktop later needed both: an icon/list view
without previews looks unfinished, and the desktop is an offscreen QML process
where `QDesktopServices::openUrl()` has no platform services. A stale
`mimeapps.list` can also name an application that is no longer installed, so a
plain `xdg-open` can fail silently.

The design system already requires no file-manager daemon and no
reimplementation of host plumbing. Thumbnails must be shared with other
file managers, and opening must use the freedesktop default-application
contract rather than inventing a private association store.

## Decision

- **Thumbnails are generated by the Files process, not a daemon.** A
  `QQuickImageProvider` (`FilesThumbnailProvider`) serves
  `image://files-thumbnail/<base64url(file URI)>`. Requests run on Qt Quick's
  image-reader thread with `ForceAsynchronousImageLoading`, so a large image or
  a PDF/video helper never blocks the listing or the UI thread.
- **The freedesktop thumbnail cache is the shared store.** Thumbnails are
  written under `$XDG_CACHE_HOME/thumbnails/normal` with the standard
  md5-of-URI name and `Thumb::URI`/`Thumb::MTime` metadata, so the cache is
  shared with every spec-conforming file manager. Only local files are
  thumbnailed.
- **Decoding is Qt-first and helper-optional.** Images use Qt's image readers;
  PDFs use `pdftoppm` and videos use `ffmpegthumbnailer`/`ffmpeg` when present.
  A missing helper is a normal state: the view falls back to the type glyph.
  No thumbnail daemon, indexer, or credential store is introduced.
- **Opening resolves the freedesktop default first.** `filesOpen()` resolves
  the MIME's default desktop entry, falls back to the first installed
  registered handler, and only then uses `xdg-open`/`gio open`. It launches the
  child out of process and removes the desktop's forced
  `QT_QPA_PLATFORM=offscreen` from the child environment so the handler can
  map a normal Wayland window.
- **The desktop and browser share the same opener.** Both call `filesOpen()`;
  the desktop never calls `QDesktopServices` in its offscreen process. A file
  argument to `dragonfruit-files` still resolves to its parent folder plus the
  item to reveal.
- **Files remains an ordinary application.** The provider lives in the app
  process; the browser and desktop each own their instance. There is no new
  session service.

## Consequences

- Images preview out of the box; PDF/video previews are opportunistic and
  depend on host helpers. Archive and remote thumbnails remain out of scope
  (G-14).
- The thumbnail cache is interoperable with other file managers, and stale
  cache entries are invalidated by the source mtime check.
- Opening no longer silently fails when `mimeapps.list` is stale; the fallback
  chain is testable headlessly (`tst_files_open`, `tst_files_thumbnails`).
- This ADR records an implementation decision; it does not make the rest of
  the Finder design shipped. Tabs, copy/move, undo, progress/conflicts, Open
  With, and Files menu publication remain open (G-04).
