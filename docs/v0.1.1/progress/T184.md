# T184 — T-21.1b Chrome HiDPI and fractional scale

## Landed

- Vendored `fractional-scale-v1.xml` and `viewporter.xml` (MIT) under
  `protocols/wayland-protocols/`; the shell generates their client bindings.
- `shell/src/chromescale.{h,cpp}`: pure logical -> physical mapping,
  `ceil(logical * scale)` with exact-integer epsilon, integer buffer scale vs
  fractional viewport choice, buffer rects, and pointer round-trip. Added
  `tst_chromescale` (1x/1.5x/2x rounding, 1279.5 -> 1280, 187.5 -> 188,
  pointer round-trip, invalid scale).
- `ShellProtocol` binds `wp_fractional_scale_manager_v1`/`wp_viewporter`,
  creates one fractional-scale object and one viewport per chrome surface,
  tracks `preferred_scale` per surface, and applies:
  - 1x/2x: `wl_surface.set_buffer_scale(1|2)`, viewport unset;
  - 1.5x/other fractions: `buffer_scale=1`, viewport source = physical buffer,
    destination = logical surface.
  Hide paths reset scale 1 and unset the viewport.
- `ShellController` renders every chrome scene at the physical size by scaling
  the QML root item (top-left origin) while keeping item/layout coordinates
  logical. The offscreen window is resized to the physical buffer; pointer and
  wheel injection converts logical -> physical at the injection seam.
- `chrome stats` now prints `logical_size`, `buffer_size`, `buffer_scale`,
  `scale`, and `viewport` per surface.
- Runtime changes: `preferred_scale`, `df_output.scale`, configure, and hotplug
  rerender mapped chrome. `df_output.scale` seeds the first render before the
  first preferred-scale event.
- Control Center: height is `min(1164, logical output height - bar - gap)` and
  its content is in a `Flickable`, so 1.5x/2x do not clip the panel past the
  screen bottom.
- Screenshot selection rects are converted logical -> physical before the
  compositor capture request, so fullscreen captures are 1920x1200 at 1.5x
  instead of a top-left 1280x800 crop.
- ADR 0192 records the contract. Docs updated: `docs/rendering.md` R2.2/P3,
  `docs/design/04-shell.md`, `docs/design/architecture-audit-native-rendering.md`
  §9.5, `docs/captures/README.md`.

## Reusable commands / gotchas

- Unit test: `cd build && ctest -R tst_chromescale --output-on-failure`.
- Full gates: `make qml-test`, `make e2e` (both pass; logs in
  `/tmp/opencode/t184-qmltest-final.log`, `/tmp/opencode/t184-e2e-final.log`).
- Nested scale needs **both** the compositor hook and the shell's display
  policy: seed `display.scale` into the dev-full scratch settings file
  `$XDG_RUNTIME_DIR/<socket>.session/config/dragonfruit/settings.json`
  (`{"schema":17,"keys":{"display.scale":1.5}}`) and run with
  `DRAGONFRUIT_NESTED_SCALE=1.5 make dev-full DEV_FULL_ARGS="--socket-name <name>"`.
  `make demo` is thin (no settingsd), so its `SettingsClient` defaults
  `display.scale` back to 1.0 and the nested scale is overridden.
- `DRAGONFRUIT_CHROME_STATS=1` + `kill -USR1 <shell-pid>` dumps the per-surface
  logical/buffer/scale/viewport lines. Split the shell log with `DF_SHELL_LOG`.
- Runtime scale change on a private bus:
  `DBUS_SESSION_BUS_ADDRESS=<address> gdbus call --session --dest
  org.dragonfruit.Settings1 --object-path /org/dragonfruit/Settings1 --method
  org.dragonfruit.Settings1.Set display.scale "<1.5>"`.
- Full-output captures: set `DF_SCREENSHOT_DIR`, send Cmd+Shift+3 over the
  synthetic socket, click to accept. The shell now sends physical crop rects;
  before T184 a 1.5x capture was the top-left 1280x800 of the 1920x1200 output.
- The Control Center `Flickable` is the first scrollable chrome panel; the
  pointer-axis path now offsets Dock-popup coordinates before injecting them.

## Follow-ups

- Multi-output shell chrome with different scales still shares one scale
  (`m_chromeScale` / `m_outputScale`). A per-output shell scene or one chrome
  surface set per output is the real fix; not required by T184's single-output
  nested rail.
- T185: pooled shm, damage regions, frame callbacks; physical buffers make the
  Dock commit 1920x188 at 1.5x instead of 1280x125, so the copy cost grows.
- T186: GPU/dmabuf transport.
- T191/T192: native DRM proof and benchmark at 1.5x/2x; T184 evidence is nested.
- The Control Center scrollbar is implicit (Flickable has no visible
  scrollbar); a token-styled indicator is a design follow-up, not a scale bug.
