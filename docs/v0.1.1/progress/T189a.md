# T189a — T-21.2c role classification and per-role state

## Landed

- `MaterialRole` now owns the persistent/transient classification:
  `is_persistent()` is true for `Chrome`/`Dock`, false for `Popup`/`Drawer`;
  `wire()`/`from_wire()` fix the protocol values 0=chrome, 1=dock, 2=popup,
  3=drawer. `MaterialRole::ALL`/`COUNT` are the stable role table.
- `EffectiveMaterial` carries a `role` field and
  `EffectiveMaterial::resolve_for_role(role, path, blur_supported, selected)`
  applies the floor:
  - persistent: never below `Reduced` while the sampled path is available;
    a selected `Minimal` resolves to `tier=reduced`, `blur_active=false`,
    `fallback=FloorMissed` (wire 4, name `floor-missed`);
  - transient: follows the ladder to `Minimal`;
  - software/headless: always `Minimal` + `fallback=Software` for every role.
  `EffectiveMaterial::resolve` keeps the old global (unfloored) meaning for the
  legacy v3 event.
- `DfState::effective_material_for_role()` / `effective_materials()` expose the
  per-role table. The render path (`render::chrome_backdrop_render_elements`,
  `render::chrome_blur_panels`, DRM's sampled-path gate) now resolves each
  chrome panel through its role state, so the floor is applied to the actual
  backdrop/blur pass, not just the protocol.
- `df_output` is **v4**. The additive `material_role_state` event carries
  `role, tier, blur_active, fallback`; the legacy v3 `material_state` keeps its
  global meaning. Both are change-only; the role event is tracked per output
  and only changed roles are emitted.
- Shell protocol plumbing: `ShellProtocol` parses and stores the role table,
  exposes `materialRoleTier/BlurActive/Fallback(role)`, and emits
  `materialRoleStateChanged`; QML application is deliberately not wired here.
- Synthetic test plumbing: `set material-path gpu|software` and
  `set material-blur-supported on|off` (headless starts `software`). These let
  the headless conformance test exercise the sampled-path floor.
- New conformance test:
  `shell_protocol_conformance::material_role_state_is_per_role_floor_aware_and_change_only`
  covers software initial state, GPU full/blur, forced Minimal
  (`chrome/dock = reduced/0/4`, `popup/drawer = minimal/0/0`), duplicate-tier
  change-only, Reduced, no-sampled-blur, and return to software.
- Pure floor tests in `window/degrade.rs`: role classification, persistent
  Reduced floor + floor-missed, transient Minimal, absent sampled path reasons,
  and software path determinism.
- Docs: ADR `0203-role-keyed-material-floor.md`, `rendering.md` R4.1/R4.3,
  `02-compositor.md` degrade section, `04-shell.md` chrome materials,
  `STATUS.md` G-12.

## Reusable facts / gotchas

- Protocol role values: 0=chrome, 1=dock, 2=popup, 3=drawer. Fallback values:
  0=none, 1=no-sampled-blur, 2=software, 3=multi-gpu, 4=floor-missed.
- `material_state` is still v3/global; do not change its argument shape. The
  new event is `material_role_state` (since=4), so older clients that bind
  v3 keep a valid message signature.
- `DfState::effective_material()` is the global legacy snapshot; use
  `effective_material_for_role()` for anything that applies policy.
- `MaterialRole::ALL` order is the wire order; `COUNT` sizes per-role tables.
- The role cache in `ShellProtocolState` is keyed by output name, so a late
  output gets its initial table without a duplicate broadcast to the others.
  Remove the entry in the `df_output` destroyed handler when adding outputs.
- Headless always starts `MaterialPath::Software`; use the synthetic commands
  above to exercise GPU floors without a display. They only affect state and
  protocol on headless (no render target).
- Forced `Minimal` now means persistent chrome reports the milky fallback
  (`floor-missed`), not a global blur-off. Tests that assert a global
  `blur=0` at `Minimal` must switch to per-role expectations.
