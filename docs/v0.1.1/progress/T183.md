# T183 — T-21.1a chrome transport baseline and decision

## Landed

- Opt-in shell transport counters (`DRAGONFRUIT_CHROME_STATS=1`) in
  `shell/src/chromestats.{h,cpp}`: `scene_frames`, `commits`, `grab_renders`,
  `shm_allocs`, `shm_bytes`, `frame_callbacks`, windowed `commit_us_*` /
  `frame_callback_us_*`, and per-surface `logical_size`, `buffer_size`,
  `buffer_scale`, commit/byte counts. Emitted on SIGUSR1 (self-pipe +
  `QSocketNotifier`) and on clean exit. Off by default; the timing rings clear
  on emit so each dump describes the interval since the previous one.
- `FrameCommitGate` records scene frames, `grabWindow()` readbacks, and the
  render-completion timestamp; `ShellProtocol::commitTo` records the fresh shm
  allocation/copy and `render completion -> wl_surface.commit` latency.
- Compositor chrome counters in `RenderStats` + `dump_stats`:
  `chrome_shm_imports`, `chrome_shm_bytes`, `chrome_dmabuf_imports`,
  `chrome_frame_callbacks`. Counted at chrome-surface commit before Smithay
  consumes the attachment, using `is_above_window_chrome_surface` (the Files
  desktop `background` layer is excluded). `chrome stats` is a new dump block.
- SIGUSR1 dumps are numbered `SIGUSR1-<n>` in both processes so the baseline
  can map snapshots to scenarios without timestamps.
- `scripts/t21-chrome-baseline.sh`, `scripts/t21-chrome-baseline-driver.py`,
  `scripts/t21-chrome-baseline-report.py`, and `make t21-chrome-baseline`.
  The report is `docs/captures/t21-chrome-baseline.txt`; the visual stills are
  `docs/captures/t21-chrome-baseline-{dock,menu,mission-control}.png`.
- ADR 0191 records the transport decision.

## Measured baseline (nested, private bus, 1920×1200)

- Backend: `QSG_INFO=1` → `Loading backend software`; the shell maps
  `libEGL`/`libGLdispatch`/`libGLX` loaders but **no DRI driver**. Software
  scene graph, no GPU chrome path.
- Idle (5.3 s): zero shell scene frames/commits, zero compositor frames and
  zero client wakeups. This is the zero-wakeup evidence.
- Slow Dock sweep (2.7 s): 291 chrome commits, 268,929,360 shm bytes;
  cadence 193.9 scene frames/s (107.5 commits/s);
  `commit_us` p50/p95/p99 = 1069/1653/1943 µs; compositor `frame timing`
  p50/p95/p99 = 10569/18445/23422 µs.
- Menu dropdown open: 68 commits / 26,307,008 bytes; commit p50/p95/p99 =
  957/1190/1393 µs.
- Mission Control (13 windows): 116 commits / 130,760,400 bytes; commit
  p50/p95/p99 = 908/6766/7526 µs.
- The Dock bar alone is 1920×125×4 = **960,000 bytes per commit**; the
  compositor reports exactly the same `chrome_shm_imports`/`chrome_shm_bytes`
  as the shell. `grab_renders` ≈ commits (the readback re-renders the scene).
  `frame_callbacks=0` and `frame_callback_us_samples=0` in both processes.
- Nested has no hardware vblank, so `presentation stats` is explicitly
  unavailable there. The native half is OPEN for the scenario comparison: the
  host is already a native Dragonfruit session, but the running compositor is
  the installed release build without T-21.1a counters and without
  `DRAGONFRUIT_SYNTHETIC_INPUT`; restarting it would end this session. The
  native snapshot's own `presentation stats`/`frame timing` lines are included
  in the report as context.

## Reusable commands / gotchas

- `make t21-chrome-baseline` (needs a host Wayland session; not in e2e).
  `KEEP_SCRATCH=1` keeps the demo/shell logs under
  `/tmp/dragonfruit-t21-baseline.*`.
- The shell's long stats lines interleave with the compositor's stdout if both
  go to one log. The baseline sets `DF_SHELL_LOG` (read by
  `tools/dragonfruit-dev/src/main.rs`) to split the shell log; the report
  parses shell stats from that file and compositor stats from the demo log.
- Wait for `Dock scene-graph commit path active` in the shell log before
  sending the first SIGUSR1. The synthetic socket appears before the shell has
  loaded QML; early signals only queue in the self-pipe.
- The driver waits for each `SIGUSR1-<n>` pair in the logs before the next
  scenario, otherwise two signals can coalesce into one notifier wakeup.
- The live stills use the trusted compositor capture path: `Cmd+Shift+3`
  (`KEY_LEFTMETA=125`, `KEY_LEFTSHIFT=42`, `KEY_3=4`) then a click to accept.
  Spectacle/screencopy does not work on this compositor. Set
  `DF_SCREENSHOT_DIR`; wait for the PNG size to settle before moving it.
- The Dock window chooser is opened deterministically with
  `DF_DOCK_CHOOSER_FIXTURE=1` after two X11 windows exist; close it by clicking
  empty Dock plate space (`~x=705, y=1155` at 1920×1200).
- `make e2e` inside a live native Dragonfruit session needs the dev-tool leak
  check to ignore the native session's systemd processes; `soak::dragonfruit_processes`
  now filters to the dev run's own process group.
- A stale `milestone_e2e` test binary can warn `interface 'df_output' has no
  event 11` after the XML changes. `touch compositor/tests/milestone_e2e.rs`
  forces the generated client code to refresh (the scanner macro has no
  `rerun-if-changed` for the XML).
