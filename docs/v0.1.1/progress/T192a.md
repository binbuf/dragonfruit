# T192a — T-21.4b GPU/chrome timing counters

## Landed

- `compositor/src/gpu_timer.rs` (new): opt-in `DRAGONFRUIT_GPU_TIMING=1`
  asynchronous `GL_TIME_ELAPSED` queries. `GpuPass` has `scene`, `blur`, and
  `composite`; the glass shader runs inside the final composite, so it is not
  a separately dispatchable pass. A bounded 24-query pool never waits on the
  GPU: results are read only after `GL_QUERY_RESULT_AVAILABLE`, and
  `GL_GPU_DISJOINT` discards a reset window.
- Support detection covers `GL_EXT_disjoint_timer_query` (GLES `EXT` entry
  points loaded through `eglGetProcAddress`) and `GL_ARB_timer_query` (core
  names). Unsupported/disabled/headless reports
  `gpu_time=unavailable` with a reason; no CPU-derived fake value.
- `RenderStats.gpu` (`GpuStats`) keeps a 4096-sample window per pass and
  `dump_stats` emits:
  `gpu stats (<label>): enabled=… available=… gpu_time=available|unavailable
  reason=… scene_*/blur_*/composite_*_samples/_total/_p50_us/_p95_us/_p99_us/_max_us`.
- Nested brackets the offscreen scene, each panel's blur chain, and the final
  damage-tracker output. DRM brackets the scene, each panel blur, and
  `DrmCompositor::render_frame`.
- Nested timer calls make the GL context current, so `with_gl` captures the
  live `eglGetCurrentSurface(EGL_DRAW)` before `with_context` and restores it
  afterwards. Without the restore the next `submit()` fails with a lost
  context (observed while developing this task). Reading the live surface each
  time also survives a resize that recreates the winit surface during `bind()`.
- Shell `chrome stats` already carried `path`, `commit_us`,
  `frame_callback_us`, `shm_bytes`, `dmabuf_buffers`, `dmabuf_fallbacks`, and
  `dmabuf_sync_timeouts`. This task added an explicit `copies` counter
  (commits with `copy_bytes > 0`) to the global and per-surface lines, and
  exposed `ChromeStats::summaryLines()` so the line contract is unit-tested.
- Tests: `compositor/src/gpu_timer.rs` unit tests (unavailable/available,
  percentiles, window bound, disabled flag) and `shell/tests/tst_chromestats.cpp`
  (path, copies, commit/frame-callback timing, dmabuf buffers/fallbacks/sync
  timeouts, per-surface fields).

## Observed numbers

Nested host run with `DRAGONFRUIT_GPU_TIMING=1`, 144 Hz override, one
`animate-dummy 1200`:

```text
gpu stats (SIGUSR1-1): enabled=1 available=1 gpu_time=available reason=none
  scene_samples=0 scene_total=0 ...
  blur_samples=0 blur_total=0 ...
  composite_samples=163 composite_total=163
  composite_p50_us=0 composite_p95_us=201 composite_p99_us=277 composite_max_us=427
```

No `render pass failed` lines and a clean exit. Scene/blur stayed at 0 because
the short nested run had no mapped chrome panel (the material pass did not
run); composite always runs. The p50 of 0 us is the llvmpipe/host timer
granularity, not a fabricated value.

## Gotchas

- `GlesRenderer::with_context` calls `eglMakeCurrent(NO_SURFACE)`; the winit
  backend does not rebind its surface before `swap_buffers`. Always restore the
  nested EGL surface after timer calls (`gpu_timer::restore_surface`). DRM uses
  the surfaceless path and passes `None`.
- The shell `copies` field is appended after the existing fields, so existing
  `grep`/`sed` parsers keep working.
- `make e2e` runs the headless backend, so its `gpu stats` line is
  `enabled=0 available=0 gpu_time=unavailable reason=disabled`; that is the
  expected software-path result.
