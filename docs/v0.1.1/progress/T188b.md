# T188b — T-21.2b per-output frame requests and earliest-deadline arming

## Landed

- New pure library module `compositor/src/frame_scheduler.rs` (exported as
  `dragonfruit_compositor::frame_scheduler`):
  - `FrameScheduler` keyed by output name with independent `urgent` and
    `animation` request bits and an `in_flight` marker.
  - `request_urgent`, `request_all_urgent`, `request_animation`,
    `clear_urgent`, `clear_animation`, `retain_animation`, `mark_in_flight`,
    `clear_in_flight`, and the read-only queries.
  - `should_present(output, now, clocks)` is the per-output render gate:
    urgent wins immediately; animation needs a request, no in-flight frame,
    and a due `PresentationClock`.
  - `next_interval(now, clocks)` is the earliest-deadline timer input. A
    never-presented clock arms zero for its first frame; a presented clock
    that is still due returns its period instead of zero (no busy loop).
- `DfState` owns `frame_scheduler`. `needs_redraw` remains the global urgent
  form (input/commit/resize/scene change), while animation requests are
  reconciled per output:
  - window motions request the output that holds the window,
  - overview/workspace transitions request every output,
  - a scene-free animation (the calibration dummy) falls back to every output.
  `sync_animation_requests()` runs after each animation step and drops an
  output whose motion settled.
- `input::schedule_animation_timer()` arms from
  `DfState::next_animation_interval()`; before the first tick it uses the
  animation clock's interval. It also cancels a timer left over from before the
  final frame when no work remains. `poll_animations()` no longer sets
  `needs_redraw`; it steps, marks the outputs the animation actually moves,
  requests one final frame for a transition that completes on this tick, and
  re-arms from the earliest due deadline.
- `DfState::note_presentation()` now re-arms the timer after updating the
  clock and clears an output's animation request once the transition has
  settled and the final frame presented. `note_output_frame()` consumes urgent
  and drains the settled animation request.
- Nested gates `render_frame()` on the per-output request; no-damage animation
  ticks re-arm one period out instead of spinning. DRM `render_pending()` no
  longer renders all outputs for an animation tick; `render_surface()` gates
  per output, marks a successfully queued frame in flight, and `frame_finish()`
  clears it, updates the clock, records the existing 1.5× missed rule, and
  re-arms. Initial/resume/retry frames pass `force=true`.
- Headless treats each render pass as the output's presentation timestamp, so
  the same scheduler and animation tests work without a display.
- `dump_stats` adds `frame scheduler stats` (urgent/animation/in-flight/timer
  armed) and one `frame request` line per output with `refresh_hz`, period,
  last presentation, next deadline, idle/due, request bits, and in-flight.
- New trace `docs/captures/t21-frame-scheduler.txt` from
  `scripts/t21-frame-scheduler.sh` / `make t21-frame-scheduler`: nested 144 Hz
  request lifecycle plus headless 144/60 Hz cadence controls.
- Docs: ADR `0201-per-output-frame-requests-and-earliest-deadline.md`,
  `docs/design/02-compositor.md`, `docs/rendering.md` P4/R3.2/R3.3,
  `docs/design/STATUS.md` G-02, `docs/captures/README.md`.

## Reusable facts / gotchas

- `needs_redraw` is still the global urgent flag. Do **not** set it from an
  animation tick or from `step_window_motions()` on every live frame; that
  reintroduces the global render gate. It is set on a completed motion (the
  commit frame) and on global scene changes.
- Animation requests are reconciled *after* the step. `start_animation()` must
  not mark requests before the first tick, or an idle presentation clock
  ("first frame due") renders one frame before `frames_stepped` advances. The
  first tick is armed from `animation_clock.frame_interval()`.
- `FrameScheduler::next_interval` returning zero is only safe for a
  never-presented clock. A presented clock that is still due returns its
  period; otherwise a no-damage frame would spin the event loop.
- A transition that completes on its first tick (zero-duration/reduced motion)
  still needs one final frame: capture `animation_output_names()` before the
  step and request those outputs after the step if the clock settled.
- A timer armed before the final frame must be cancelled by
  `schedule_animation_timer()` when `!has_animation() && !animations_active()`;
  otherwise a settled clock steps once more (this was caught in the nested
  trace as `settled != exit`).
- DRM in-flight is a boolean per output, cleared at every `frame_finish()`
  boundary. The scheduler excludes in-flight outputs from both the render gate
  and timer arming; `frame_finish()` re-arms.
- `frame_finish()` keeps the existing `PresentationStats::record` rule:
  interval > 1.5 × the effective deadline is `missed`; `presentation stats`
  already carries `refresh_hz`/`source`. The new scheduler lines are additive.
- The nested host can throttle `submit()` to ~1 Hz, so the nested trace polls
  for `animation=1` and then `animation=0` rather than assuming wall-clock
  duration. Headless 144/60 controls are the cadence evidence (600 ms:
  +81 / +36 steps).
