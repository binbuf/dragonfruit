# T190d — T-21.3 direct-scanout preservation and material counters

## Landed

- `compositor/src/window/scanout.rs` (new): pure `covers_output` and
  `direct_scanout_candidate(output, fullscreen, &[BlurPanel])`. A candidate is
  a fullscreen rect that covers the output with no visible material panel
  intersecting it. Tests cover no/partial fullscreen, no panels, one/many
  visible panels, zero-area/offscreen panels, and a larger-than-output client.
- Fullscreen chrome suppression:
  - `DfState::fullscreen_client_rect[_for_name]` finds a settled, non-closing
    fullscreen window that covers the output (output-local rect).
  - `DfState::visible_chrome_surfaces` filters persistent `top` chrome
    (menu bar/Dock) while a fullscreen client owns the output; transient
    `overlay` chrome (OSD/menus/notifications/popovers) and the desktop band
    stay.
  - `shell::layer::visible_in_fullscreen` is the one pure visibility rule.
  - Render, input hit-testing, and `query scale` use the visible list;
    `send_chrome_frame_callbacks` and `update_chrome_preferred_scale` keep the
    unfiltered list so hidden chrome is not left waiting on a callback.
- Counters (`compositor/src/state.rs`, `instrument.rs`):
  - global `material_frames`, `direct_scanout_candidates`;
  - per-output `output_material` map with `material_frames`,
    `direct_scanouts`, `direct_scanout_candidates`, `material_allocations`,
    last `material_region_px`/`material_region`;
  - `scanout stats` now reports `direct_scanouts`, `material_frames`,
    `direct_scanout_candidates`, rendered/skipped/considered;
  - `output material stats` prints the sorted per-output line;
  - both backends record candidates; DRM records the real `direct_scanouts`
    only from `PrimaryPlaneElement::Element`; nested never fakes it.
- `scripts/t21-live-capture.sh` gained the `fullscreen` state (query
  decorations, pick a window, `fullscreen <id>`), `STATS_OUT`, and
  `ASSERT_MATERIAL_FLAT` (two-snapshot allocation/region assertion).
- `scripts/t21-scanout-counters.sh` / `make t21-scanout-counters`: 4K region
  arithmetic, settled-Dock flat check, fullscreen skip-pass still + stats.
- `scripts/t21-direct-scanout-native.sh` / `make t21-direct-scanout-native`:
  free-seat DRM runner that asserts the real `direct_scanouts>0`; this host
  writes `docs/captures/t21-direct-scanout.open.txt` instead.
- Artifacts: `docs/captures/t21-scanout-counters.txt`,
  `t21-scanout-settled-1x.png`, `t21-scanout-fullscreen-1x.png`, the two

  documented single-union shape); 2x Dock-only 5216x298 = 1 554 368 px.

- Fullscreen 1x: `direct_scanout_candidates=14 -> 15`, `material_frames=4`
  flat, `material_allocations=10` and region `1280x800` flat across the two
  snapshots; nested `direct_scanouts=0` (no primary plane).

## Reusable facts / gotchas

- The nested window size follows the host (here 1280x800 for the fullscreen
  run, 1920x1200 for the settled run); use the stats line, not a fixed size.
- `fullscreen_client_rect` requires the fullscreen window to be settled and to
  cover the output. Mid-transition chrome stays visible.
- Hiding `top` chrome must not hide frame-callback bookkeeping: keep
  `chrome_surfaces` for `send_chrome_frame_callbacks` and
  `update_chrome_preferred_scale`; use `visible_chrome_surfaces` for render,
  input, `query scale`, and material panels.
- `direct_scanout_candidates` is a policy counter and is expected on nested;
  `direct_scanouts` is DRM-primary-plane only. Never derive one from the other.
- `DRAGONFRUIT_MATERIAL_FULL_OUTPUT=1` still forces the full-output scene
  texture; it does not force material when the fullscreen policy skips the
  pass.
- `scripts/t21-live-capture.sh` now writes both `scanout stats` and
  `output material stats` into `STATS_OUT`; the flat assertion groups
  snapshots by the `snapshot` marker.

## Follow-ups

- T191a: run `make t21-direct-scanout-native` on a free DRM seat and commit
  `docs/captures/t21-direct-scanout.txt` with `direct_scanouts>0`; replace the
  OPEN artifact only with real hardware output.
- Shell transport: while fullscreen, the shell still renders and commits its
  hidden top chrome. Skip those commits once the shell can see the
  fullscreen/hidden state; today the compositor filters them and answers their
  frame callbacks.
- Fullscreen chrome auto-reveal (pointer at the top edge) is not implemented;
  the current policy hides the bars until fullscreen exits. A reveal gesture
  would need a transient overlay surface so it keeps the material/frost.
- Multi-rect/tiled material regions remain open from T190b: the menu-bar +
  Dock union is the full output at 4K, so the region only shrinks for a
  Dock-only or menu-only frame.
- The native runner uses `ffplay -fs`/`vkcube`; if the free-seat host has
  neither, set `CLIENT` or attach a fullscreen client manually. The counter is
  still read from the compositor's `scanout stats`.
