## Reusable facts / gotchas

- The installed and running binaries are release:
  `/usr/bin/dragonfruit-compositor -> target/release/dragonfruit-compositor`,
  `/usr/bin/dragonfruit-shell -> build-release/shell/src/dragonfruit-shell`,
  and the running exe is the release path. `native-status` reports selected
  and installed profile `release`.
- `native.env` and the compositor drop-in have no `DRAGONFRUIT_DRM_MATERIAL` /
  `DRAGONFRUIT_DRM_GLASS` value by default; only explicit values are
  persisted.
- The agent UI is a continuously rendering Wayland client. The 10 s startup
  snapshot is the idle `degrade stats` reading; a later snapshot is a load
  observation and may be `reduced` (but not minimal).
- `direct_scanouts=0` is expected with no fullscreen client. A live
  `ffplay -fs` did not enter the compositor's fullscreen Space (SDL Wayland),
  so `direct_scanout_candidates` stayed 0; that is not a policy failure.
- The free-seat probe still reports `/dev/dri/card1: busy (Permission
  denied)` because the live session owns DRM master. The real
  `direct_scanouts>0` trace remains OPEN.
- Do not end the native session to run the rollback: the compositor is the
  session anchor, and the agent cannot complete the password re-login.
