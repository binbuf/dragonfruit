## Reusable facts / gotchas

- **Pass the real EGL context to `eglCreateImageKHR`.** Passing
  `EGL_NO_CONTEXT` for `EGL_GL_TEXTURE_2D_KHR` segfaults Mesa's
  `dri2_create_image_khr`. Get the display *and* context from
  `m_renderContext->nativeInterface<QNativeInterface::QEGLContext>()`.
- **Set `ZWP_LINUX_BUFFER_PARAMS_V1_FLAGS_Y_INVERT`.** A GL texture export is
  bottom-up; without the flag the Dock renders upside-down. The source rect
  is then in the upright (FBO) coordinate system.
- **The GPU producer's QQuickWindow is logical, not physical.** Its
  `QQuickRenderTarget` carries the scale as DPR, so `prepareChromeScene` must
  set the root item scale to 1.0 for GPU producers (the software producer
  still scales the item by `m_chromeScale`). Item positions must be logical
  for GPU producers; `ChromeScale::logicalToBuffer` is only for the software
  path. Pointer/wheel injection must follow the same split.
- **One GPU producer per scene.** The scene-graph API is process-global; if
  the GPU rail is requested, every chrome scene must be a
  `GpuChromeFrameProducer`, otherwise the default producer sees OpenGL and
  takes the `grabWindow()` fallback. Only the Dock's commit is dmabuf in
  T186b.
- **The exported modifier is often `invalid` (implicit), not the probe's
  `linear`.** The compositor feedback table advertises `AB4H:invalid`, so
  validate against the actual export, not the probe's selected pair.
- **Serial matters.** `GpuChromeFrameProducer` recreates its FBO on a DPR or
  size change. The shell must recreate the `wl_buffer` even when the new
  export has the same size/format/modifier; `ChromeDmabufFrame::serial`
  provides that identity.
- **T186b commits one buffer every frame.** It does not wait for
  `wl_buffer.release`; the ring/release/explicit-sync work is T186c. Do not
  read the single-buffer `busy` flag as a correctness gate yet.
- **Nested rail.** KWin virtual output + nested Dragonfruit compositor, same
  as T186a:
  `XDG_RUNTIME_DIR=/tmp/opencode/t186b-capture WAYLAND_DISPLAY=kwin-t186b
  make t21-dmabuf-dock`.
- **Stats to grep:** `path=render-control+dmabuf`, `gpu=dmabuf`,
  `dmabuf_commits=`, `gpu_reason=`, and the compositor's
  `chrome_dmabuf_imports=`.

## Follow-ups

- T186c: 2–3 buffer ring, `wl_buffer.release`-driven reuse, resize
  recreation, and explicit fence/sync. `ChromeDmabufSlot` and
  `DmabufCommitResult::Deferred` are already in place.
- T186d: move the menu bar/popovers/overlays to the same dmabuf commit and
  finish the per-surface `path=dmabuf|shm` stats rollout.
- Native DRM acceptance and default-on remain T191/T192. Multi-GPU/rotated
  output remains out of scope.
- The Wayland QPA opens a second connection for the GL context; if a future
  task needs the parent spec's single-display wording, the GL rail would need
  a manually created EGL display/context on the shell's `wl_display` (the
  offscreen QPA `QNativeInterface::QEGLContext::fromNative` attempt returned
  null on this host).
