## Reusable facts / gotchas

- `MaterialRegion.rect` is output-local logical; `physical` is output-local
  physical and is the region origin. Translate a panel's physical `src` by
  subtracting `physical.loc`; never reuse a full-output `src`.
- `MaterialRegion::for_material` falls back to the full output when the panel
  set has no visible area. The single padded-union rectangle is the full output
  whenever the top menu bar and bottom Dock both blur; a Dock-only frame is
  smaller. A transient Dock-only smoke frame reported `material_region=672x120`
  (`80640` px).
- The Kawase chain must keep the **full-output physical size** as its first
  destination. Sizing it from the region changes the panel's effective blur.
- `DRAGONFRUIT_MATERIAL_FULL_OUTPUT=1` is read once per process. It forces the
  full-output region and the old scene-texture base shape; the region path is
  the default.
- `SceneTextureCache` is grow-only. It reallocates only when the wanted region
  exceeds the allocated texture, or on output mode/scale change. A mode/scale
  change reallocates even if the rounded region size is unchanged.
- `PanelTextureSlots::trim` is the lifetime boundary: a panel that disappears
  drops its slot, and the `Rc`/`Weak` test proves the texture handles are
  released. T190c replaces index keying with stable panel IDs.
- The DRM material path is single-GPU (multi-GPU sampled material is disabled),
  so the scene texture and Kawase chain share one GL context. Each offscreen
  frame is finished before the next bind; the nested `GlesFrame` waits on its
  fence when dropped. No cross-GPU fence hand-off is needed on this path.
- `material stats` now includes `material_allocations`,
  `material_scene_allocations`, `material_panel_allocations`,
  `material_region_px`, and `material_region=WxH`. Extra fields are ignored by
  the existing trace parsers.
- Capture preflight: `make t21-doctor` (PASS, 0 warnings). The capture reuses
  `scripts/t21-live-capture.sh` (it owns the `make demo`/`make dev-full`
  lifecycle); `scripts/t21-capture-lib.sh` is for scripts that start the
  compositor/shell directly and was not needed. The capture script
  seeds settingsd's `display.scale` at
  `$XDG_RUNTIME_DIR/<socket>.session/config/dragonfruit/settings.json`
  (`schema:17`) for scales above 1, because the shell forwards settingsd's
  scale and would otherwise reset `DRAGONFRUIT_NESTED_SCALE` to 1.0. It also
  forces `degrade-tier full` so the nested host's ~1 Hz submit throttle does
  not downgrade the material to Minimal before the capture.
- The nested window size follows the host (1920x1200 or 1280x800/1281x801
  observed), so use the `material_region` field in the stats line, not a fixed
  assumption. `make dev-full` sessions write ~150 MB of scratch data under
  `/run/user/1000/<socket>.session`; clean those directories between capture
  batches or the tmpfs fills.
- The 1.5x/2x captures use `make dev-full` (settingsd + private bus); the 1x
  captures use `make demo`. Both use the compositor capture fixture.

## Follow-ups

- Multi-rect/tiled material regions: a single padded-union rectangle is the
  full output when the menu bar and Dock are both blurred. T190c/T192 should
  decide whether to split the top/bottom strips; not a correctness issue.
- T190c: stable scene/panel IDs, `current_commit`, and damage so a stationary
  Dock does not force full-output damage; replace index-keyed panel slots.
- T190d: direct-scanout policy, per-output `direct_scanouts`, and the
  region/allocation counter contract. The counters and the full-output
  diagnostic env flag are already in place.
- T192: 4K/full-output vs region benchmark; the single-union full-output case
  should be part of the measurement.
- Capture scripts hard-code the settingsd schema revision (`17`); update the
  seed if the schema bumps.
- The nested host throttles `submit()` to roughly 1 Hz, which drives the
  degrade controller to Minimal unless the capture forces a tier. The forced
  tier is test plumbing, not the live policy.
