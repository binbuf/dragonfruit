## Reusable facts / gotchas

- Role wire values: 0=chrome, 1=dock, 2=popup, 3=drawer. Fallback values:
  0=none, 1=no-sampled-blur, 2=software, 3=multi-gpu, 4=floor-missed.
- `Material.fallbackReason(fallback, blurActive, tier)` is the recorded reason;
  a transient `Minimal` with no fallback reason returns `minimal`.
- The popup family uses `chromeFallbackFill` + `popupFallbackOpacity`; do not
  add a second neutral. `Material.drawerFill(true)` keeps the drawer's
  `surface`/`panelOpacity`; its fallback is the same milky plate.
- `setMaterialProperties(item, state, "popupMaterial")` is the prefixed push
  for the two scenes that host more than one role. It returns false when the
  property group is absent, so a non-material surface is ignored.
- The Control Center can lose keyboard focus to the demo's Settings window and
  dismiss itself; `DF_CONTROL_CENTER_FIXTURE=hold` reopens it every 500 ms for
  capture. The OSD auto-dismisses after 1.4 s; `DF_OSD_FIXTURE=hold`
  re-presents it every 1 s.
- Capture crop regions are relative fractions of the primary output in
  `scripts/t21-material-tiers-driver.py`; the nested demo is 1280x800 here but
  the fractions scale.
- The shell logs one `shell: material role=... tier=... blur=... fallback=...`
  line per change-only role event; the capture script appends only new lines
  (`LOG_LINES`) so a scheme's trace is not duplicated.
