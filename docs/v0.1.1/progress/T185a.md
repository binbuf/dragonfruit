## Reusable commands / gotchas

- Gates: `make build`, `make qml-test`, `make e2e`,
  `ctest --test-dir build -R '^(tst_chromebufferpool|tst_dockcore)$' --output-on-failure`.
  Logs from this run: `/tmp/opencode/t185a-{build,qmltest,e2e,unit-final}.log`.
- Baseline: `bash scripts/t21-chrome-baseline.sh` with `OUT`,
  `T21_REPORT_TITLE`, `T21_TRANSPORT_LABEL`; `KEEP_SCRATCH=1` keeps the shell
  and compositor logs under `/tmp/dragonfruit-t21-baseline.*`.
- The host session after the reboot is 1280x800 and its nested window is not
  presented at 60 Hz. For a 1920x1200 measurement, run the nested demo on a
  KWin virtual output:
  `XDG_RUNTIME_DIR=/tmp/opencode/kwin2 WAYLAND_DISPLAY=kwin-t21 kwin_wayland --virtual --width 1920 --height 1246 --socket kwin-t21`.
  The Smithay winit window starts at 1280x800; a KWin script (loaded through
  `org.kde.kwin.Scripting` on KWin's private bus) calls `setMaximize(true,true)`
  on the `Dragonfruit` window, giving a 1920x1200 client area.
- `scripts/t21-closeout-driver.py` reads `query scale` for the output size and
  the `chrome dock` rect, so it works at 1280x800 and 1920x1200. The accept
  click for the shell screenshot overlay must be inside the output; the old
  hardcoded `(960,1170)` missed on 1280x800 and left the overlay stuck open,
  which then swallowed the lock chord.
- The synthetic input harness on the current host does **not** set the Meta
  modifier: `Ctrl+Up` works, but `Cmd+Tab`, `Cmd+Ctrl+Q`, and `Cmd+Shift+3` do
  not resolve. Use the system menu for lock and `spectacle` for stills. At
  1920x1200 the system menu's Lock Screen row is at about `(60, 220)`.
- Host stills: `spectacle -b -n -f -o out.png` on the KWin virtual output
  (1920x1246); crop `(0,46,1920,1246)` to the nested 1920x1200 client area.
- `make demo` nested on KWin under load can take ~60-70 s to reach
  `Dock configured`; wait for that line, not just
  `Dock scene-graph commit path active`.
