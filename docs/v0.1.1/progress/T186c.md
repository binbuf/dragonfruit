# T186c — T-21.1d dmabuf ring, sync, and fallback

## Landed

- `shell/src/chromedmabuf.{h,cpp}`: `ChromeDmabufRing` (capacity 3): acquire/
  busy/release(serial)/abandon, size and format generations, retired-slot
  draining, allocation/reuse counters. `ChromeDmabufFrame` now carries the
  producer `slot`; the serial identifies each committed frame.
- `GpuChromeFrameProducer` owns one FBO/export per ring slot. `exportFrame()`
  acquires a free slot, renders once, waits on a GL fence, exports/caches the
  slot's dmabuf, and returns the slot+serial. `releaseDmabufFrame()` frees it
  on `wl_buffer.release`; `abandonDmabufFrame()` handles deferred/failed
  commits. A size/format change retires the old generation; busy retired
  slots stay alive until release. No render ever targets a busy slot.
- `ShellProtocol` keeps one reusable `wl_buffer` per `(surface, slot)` and
  emits `dmabufReleased(surface, slot, serial)` from `wl_buffer.release`.
  Import params/owners now carry the slot. `commitDmabufTo()` reuses the
  buffer on serial change (the FBO/export is stable per slot) and recreates
  only on size/format change or import failure.
- Sync: `glFenceSync` + bounded `glClientWaitSync` (100 ms) after each render;
  `glFinish` if fences are unavailable. A timed-out fence records
  `sync-timeout` and is not committed. The compositor offers only implicit
  dma-buf sync (no `linux-drm-syncobj-v1`), recorded as the limitation.
- Fallback: ring exhaustion reads back the last complete frame and commits it
  through T185 shm for that frame, keeps the dmabuf rail enabled, and retries
  on release. Export/import/format failures abandon the rail for the session.
  Both are counted with a `gpu_reason`; no path goes black.
- `chrome stats` gained `dmabuf_buffers`, `dmabuf_allocs`, `dmabuf_reuses`,
  `dmabuf_sync`, `dmabuf_sync_waits`, `dmabuf_sync_timeouts` (global and
  per-surface where meaningful).
- Tests: `tst_dmabufcommit` gained six ring cases (reuse, busy/defer,
  resize-retire, format-retire, first-format adoption, reset).
- Capture: `scripts/t21-dmabuf-dock.sh` now runs `make t21-dmabuf-ring`, drives
  two synthetic Dock sweeps, takes two SIGUSR1 dumps, and asserts flat
  `dmabuf_buffers`/`dmabuf_allocs` plus advancing commits/reuses. New artifacts
  `docs/captures/t21-dmabuf-ring.txt`, `t21-dmabuf-ring.png`,
  `t21-dmabuf-ring-fallback.png`.
- Docs: ADR 0196, ADR 0195 supersession note, `docs/rendering.md` R2.3,
  `docs/design/04-shell.md`, `docs/captures/README.md`.

## Reusable facts / gotchas

- KWin virtual host used for the capture:
  `mkdir -p /tmp/opencode/t186c-kwin && chmod 700 ...`;
  `XDG_RUNTIME_DIR=/tmp/opencode/t186c-kwin kwin_wayland --virtual --width 1280 --height 800 --socket kwin-t186c`.
  The nested compositor/shell then use that runtime dir and `WAYLAND_DISPLAY`.
- The synthetic-input socket is `$XDG_RUNTIME_DIR/<nested-socket>.synth`; the
  capture script starts the compositor with `DRAGONFRUIT_SYNTHETIC_INPUT` and
  sweeps normalized `motion-abs x y` at `y=0.955` for a bottom Dock.
- The ring slot id, not the serial, is the shell wl_buffer identity. The serial
  changes every commit even when the FBO/export is reused; only a slot change
  or size/format change recreates the wl_buffer.
- Ring exhaustion is normal under a fast animation and is a counted transient
  fallback, not a hard failure. Do not disable `m_dockDmabufEnabled` for
  `ring-exhausted`/`sync-timeout`; hard failures are export/import/format.
- `dmabuf_allocs` can exceed the live ring size during startup because the Dock
  is configured at several sizes; it must be flat between the two post-warm
  dumps, not equal to 3.
- Do not name a local variable `slots` in a Qt class: `slots` is a Qt macro.

## Follow-ups

- T186d: move the menu bar/popovers/overlays/lock to `commitDmabufTo()` and
  report per-surface `path=dmabuf|shm` plus ring counts. Reuse the
  `dmabufReleased` signal; each producer already owns its own ring.
- Consider treating a full ring as `Deferred` rather than an immediate shm
  fallback for fast animation; the current contract deliberately falls back
  and records `ring-exhausted`. Revisit after the T186d rollout if the counted
  shm frames are too expensive.
- Explicit Wayland sync (`linux-drm-syncobj-v1`) remains unavailable in the
  compositor; the GL fence + implicit dma-fence contract is the current limit.
- Native DRM acceptance and default-on remain T191/T192. Multi-GPU/rotated
  output remains out of scope.
