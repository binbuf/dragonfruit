# T186a — T-21.1d GPU probe and render-control spike

## Landed

- `shell/src/gpuchromecapabilities.{h,cpp}`: pure linux-dmabuf feedback-table
  parsing, EGL extension parsing, and deterministic format/modifier selection
  (`ABGR8888` then `ARGB8888`; linear, explicit, then invalid). Covered by
  `shell/tests/tst_gpucapabilities.cpp` (9 cases, 10 QtTest rows).
- `shell/src/gpuchromeprobe.{h,cpp}`: read-only runtime probe. It binds
  `zwp_linux_dmabuf_v1` (v4/v5 feedback) on an existing `wl_display`, copies
  the format table, queries EGL export/import extensions on the same display,
  and returns a typed result with a fallback reason. `ShellProtocol` runs it
  once at startup and logs `chrome gpu probe (startup): ...` plus a bounded
  format list; `ShellProtocol::gpuCapabilities()` exposes it for T186b.
- `shell/src/gpuchromeframeproducer.{h,cpp}`: `GpuChromeFrameProducer`
  subclasses the T185 `ChromeFrameProducer`. It owns one `QOpenGLContext`,
  `QOffscreenSurface`, `QQuickRenderControl`, hidden `QQuickWindow`, reusable
  FBO and `QQuickRenderTarget` with DPR handling. `ChromeFrameProducer` gained
  a protected `Construction::External` constructor and virtual producer hooks
  (`window()`, `resize()`, `renderFrame()`, `gpuActive()`, `fallbackReason()`).
- `shell/tests/t21-gpu-smoke.cpp`: nested GL smoke rail. Renders one inline
  QML scene at 160x90 logical / 320x180 physical (DPR 2), verifies the four
  quadrant pixels, writes a PNG, and logs the probe verdict. It also has
  `--expect-fallback` for the no-GL rail.
- `scripts/t21-gpu-probe.sh` + `make t21-gpu-probe`: starts one nested
  Dragonfruit compositor, runs the GL smoke, runs the offscreen fallback, and
  writes `docs/captures/t21-gpu-probe.txt` + `docs/captures/t21-gpu-smoke.png`.
- `protocols/wayland-protocols/linux-dmabuf-unstable-v1.xml` vendored (MIT,
  v5) and generated into `build/protocols/` by the shell CMake.
- Docs: `docs/design/adr/0194-gpu-chrome-probe-and-render-control-spike.md`,
  `docs/rendering.md` R2.3, `docs/design/04-shell.md`,
  `docs/captures/README.md`.

## Reusable facts / gotchas

- The shell's `QT_QPA_PLATFORM=offscreen` has no GL context; `QOpenGLContext::
  create()` returns false. The nested GL smoke must run with
  `QT_QPA_PLATFORM=wayland` and a live compositor socket. This is the Qt-side
  GL connection only; the private chrome surfaces remain on the shell's own
  libwayland connection.
- `QQuickRenderControl`'s OpenGL RHI backend creates a **share context** and
  leaves it current after `initialize()`. FBOs/render targets must be created
  and read on that context (`QOpenGLContext::currentContext()` right after
  initialize), not on the context you created and made current. Forcing the
  original context current yields a valid but fully transparent frame. This
  was the main spike bug.
- The first `QQuickWindow` in a process fixes the scene-graph API. The smoke
  calls `QQuickWindow::setGraphicsApi(OpenGL)` before any window; the shell's
  normal path creates QQuickWindows first, so T186b must choose the GL rail at
  process startup rather than after chrome windows exist.
- A hidden `QQuickWindow` does not resize its `contentItem` on
  `QWindow::resize`; set `contentItem()->setSize(logical)` explicitly.
- On this host the native DRM Dragonfruit compositor accepts a nested winit
  window but never sends the configure that lets it bind its socket. Use a KWin
  virtual output instead:
  `XDG_RUNTIME_DIR=/tmp/opencode/kwin2 WAYLAND_DISPLAY=kwin-t21 kwin_wayland
  --virtual --width 1280 --height 800 --socket kwin-t21`, then run the probe
  script with those env vars. This matches the T185a capture workaround.
- Probe log line shape:
  `chrome gpu probe (startup): dmabuf_global=... version=... feedback=...
  formats=... main_device=... egl_export=... selected=... compositor_import=...
  verdict=... reason=...` and a second `... formats: ...` line capped at 16.
- `formatName()` intentionally falls back to the printable FourCC (e.g.
  `AB4H`) for formats not in the small named set; the table can advertise
  64-bit float formats before the 8-bit ones. Selection still finds `AB24`
  (`ABGR8888`) when present.
