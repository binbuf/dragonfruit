## Capture method

The readback is an isolated development-only tool outside the tree:

1. `pidfd_open(compositor-pid)` + `pidfd_getfd(drm-fd)` duplicates the
   compositor's own DRM fd.
2. `drmModeGetResources` finds the active CRTC; `drmModeGetFB2` + three-plane
   dma-buf import (the scanout buffer uses an AMD three-plane modifier) through
   EGL.
3. `glReadPixels` writes a PPM, then Pillow crops/scales to the committed PNG.

It is **not** a screencopy client, not a portal grant, and not a nested
window. It reads the active CRTC's primary plane only, so the hardware cursor
and overlay planes are not in the stills.

The shell states were driven by restarting the installed release shell with
the existing capture seams: `DF_MENUBAR_MENU_FIXTURE=0`,
`DF_APPS_DRAWER_FIXTURE=1`, `DF_CONTROL_CENTER_FIXTURE=hold`,
`DF_OSD_FIXTURE=hold`, `DF_NOTIFY_FIXTURE=1`,
`DF_DOCK_CHOOSER_FIXTURE=1`, `DF_DOCK_HOVER_FIXTURE=1`,
`DF_MISSION_CONTROL_FIXTURE=1`, and
`DF_LOCK_FIXTURE=2500 DF_LOCK_UNLOCK_MS=18000`. Scheme changes went through
`org.dragonfruit.Settings1.Set appearance.colorScheme`. The temporary
systemd drop-in was removed and the shell restarted without fixtures at the
end.
