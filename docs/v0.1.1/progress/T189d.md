# T189d — T-21.2c Refresh-aware hysteresis and load tests

## Landed

- `DegradeController` hysteresis is now wall-clock, not frame-count:
  - `DOWNGRADE_WINDOW = 200 ms` (the old 12 frames at 60 Hz),
  - `UPGRADE_WINDOW = 3 s` (the old 180 frames at 60 Hz).
  The EMA (`0.3`) and recovery ratio (`0.75`) are unchanged. The windows
  accumulate the rendered-frame durations the session loop already feeds the
  controller, so 120/144 Hz panels no longer downgrade/recover ~2.4x faster.
- Flap latch (anti-oscillation):
  - a downgrade within `PROBATION_WINDOW = 10 s` of an upgrade across the same
    ladder boundary latches that boundary;
  - recovery across a latched boundary needs `EMA < 0.4 × budget` for `10 s`
    (instead of `0.75 × budget` for `3 s`);
  - a successful upgrade clears the latch; a forced tier/release resets the
    selection memory (streaks, probation, latch).
  The fallback ladder and per-role floor are untouched.
- `query degrade` / `degrade stats` keep every existing field and add
  `down_window_us=200000`, `up_window_us=3000000`, `latched=0|1`.
- Synthetic test plumbing: `set degrade-frames <count> <microseconds>` feeds
  the real `observe_rendered_frame` path, so a headless compositor can run a
  load sequence without a GPU or a parallel controller.
- Tests:
  - `window/degrade.rs`: `the_hysteresis_windows_are_refresh_aware_at_60_120_and_144_hz`
    (downgrade ~200 ms, recovery ~3 s at all three rates; frame counts
    10/20/25 down and 377/752/867 up),
    `a_steady_pointer_sweep_does_not_repeat_full_reduced_flapping`
    (60 s tier-dependent sweep; bounded to 2 downgrades/1 upgrade/latched at
    60/120/144 Hz, then idle recovery), plus the updated ladder/force tests.
  - `shell_protocol_conformance::material_role_state_follows_a_refresh_aware_load_sequence`:
    headless real-compositor load sequence (steady over-budget, recovery,
    settle, second sweep, flap latch, 20 s latched hold with no role events,
    idle recovery, forced Reduced/Minimal/Full). Asserts the per-role state
    at every phase.
  - `tst_materialpolicy`: `loadSequenceKeepsTheAppliedProperties`.
  - `tst_dock` / `tst_menubar`: `test_load_sequence_keeps_the_applied_material`
    drives one already-created scene through Full → Reduced → floor-missed →
    Reduced → Full in light and dark.
- Load trace: `scripts/t21-degrade-load.sh` (`make t21-degrade-load`) writes
  `docs/captures/t21-degrade-load.txt`; the artifact records the doctor

## Reusable facts / gotchas

- The windows are **time accumulated from frame durations**, not
  `Instant::now()`. The controller stays pure and inert while idle; a slow
  frame counts as more wall-clock time than a fast one. This is deliberate:
  it measures sustained pressure, not a frame count.
- At 144 Hz the observed downgrade lands at 208.325 ms (25 × 8.333 ms), not
  exactly 200 ms, because the test feeds whole frames. 60/120 Hz land on
  200.000 ms. Recovery is ~3.008–3.016 s at every rate (the extra is the EMA
  warm-up from the over-budget value).
- The latch is per boundary (`0` = Full↔Reduced, `1` = Reduced↔Minimal) and
  only gates the boundary immediately above the current tier. A successful
  upgrade clears it; `force`/`release` reset it.
- `degrade stats` now ends with `down_window_us=... up_window_us=... latched=...`;
  `window_conformance`'s `parse_degrade` ignores extra fields.
- The synthetic `set degrade-frames` command is test/capture plumbing only.
  It calls `observe_rendered_frame`, so it also updates the frame stats and
  gesture trace; it does not request a redraw.
- The load-trace script runs cargo tests and therefore normalizes the first
  trace line (libtest prefixes it with the test name). If you add trace lines,
  keep the `degrade-trace:` marker.
- The shell has no hysteresis. It applies the compositor's change-only role
  events through `MaterialPolicy`; the load sequence tests only prove the
  already-created Dock/menu-bar scenes follow those events.
