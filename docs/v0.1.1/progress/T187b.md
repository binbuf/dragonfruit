# T187b — T-21.2a refresh clock wiring

## Landed

- `AnimationClock` now owns `frame_interval` (default `FRAME_INTERVAL`), with
  `set_frame_interval()`. `schedule_animation_timer()` and `poll_animations()`
  arm/re-arm from that interval.
- `DfState` owns `RefreshSchedule` and an optional `DRAGONFRUIT_REFRESH_HZ`
  override. `sync_refresh_policy()` applies the effective refresh
  (override → fastest active output → 60 Hz fallback) to the clock and the
  degrade budget. Output add/remove, mode changes, scale/transform changes,
  hotplug, and resume recompute it; a live animation's timer is cancelled and
  re-armed only when the period actually changes.
- `DegradeController::set_budget_from_deadline()` follows the fastest output's
  deadline. `DRAGONFRUIT_FRAME_BUDGET_US` records `budget_source=env`; the
  synthetic `set degrade-budget` records `budget_source=manual`; normal policy
  is `budget_source=refresh`.
- `presentation stats` appends `refresh_hz=<Hz> source=mode|fallback|override`
  (and keeps every existing field). `animation stats` appends `interval_us`;
  a new `refresh stats` line reports the effective refresh, interval,
  deadline, output count, and override flag.
- New `docs/captures/t21-refresh-144.txt` (`scripts/t21-refresh-144.sh`,
  `make t21-refresh-144`) records a nested simulated-144 Hz run plus headless
  144/60 Hz cadence controls.
- Docs: ADR 0199, `02-compositor.md`, `rendering.md`, `STATUS.md`,
  `docs/captures/README.md`.

## Reusable facts / gotchas

- The 60 Hz period is **16666 µs** (16,666,666 ns), not 16000. Tests that
  asserted the old default degrade budget were updated to 16666.
- The 144 Hz period is **6944 µs** (6,944,444 ns). 143.999 Hz keeps
  6,944,492 ns; `presentation stats` reports `refresh_hz=143.999`.
- `step_animations()` swaps the clock out with `std::mem::take`; the
  placeholder starts at the default interval. It now copies the live interval
  onto the placeholder before stepping, otherwise the first tick silently
  reverts a 144 Hz clock to 16 ms.
- Nested `animate-dummy` cadence is not a reliable timing measurement on a
  headless/dev host: the host vblank can throttle `submit()` to ~1 Hz. The
  nested trace records the derived interval/budget; the headless 144/60 Hz
  controls and `compositor/tests/animation_clock.rs` record the actual step
  cadence.
- `DegradeController::with_budget_us()` is a test constructor and leaves
  `budget_source=refresh`; `set_budget_us()` marks the budget manual. Do not
  use `set_budget_us()` in normal policy code or it will pin the budget.
- `presentation stats` only exists for DRM outputs with a recorded vblank;
  nested/headless use the new `refresh stats` line for the same values.
