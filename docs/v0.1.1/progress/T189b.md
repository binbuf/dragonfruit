# T189b — T-21.2c Shell per-role application: Dock and menu bar

## Landed

- `shell/src/materialpolicy.{h,cpp}` is the shell's one application policy for
  the v4 role table. `MaterialPolicy::applied(role)`:
  - a known role state wins; an unknown role uses the legacy v3 global state;
  - any explicit fallback reason forces `blurActive=false` (milky complement);
  - a persistent role at `Minimal` with no fallback is guarded to
    `tier=reduced`, `blur=false`, `fallback=4` (`floor-missed`).
- `ShellProtocol::materialRoleKnown(role)` tells startup whether the role
  table already has a v4 state.
- `ShellController` seeds the policy after authentication and before the
  first scene, applies `Chrome` to the menu bar and `Dock` to the Dock before
  their first commits, and updates both from `materialRoleStateChanged`.
  `materialStateChanged` remains connected as the legacy compatibility path.
- Tests:
  - `shell/tests/tst_materialpolicy.cpp` — precedence, floor guard, fallback,
    software, transient Minimal, unknown roles.
  - `tst_dock.qml` / `tst_menubar.qml` — forced Full/Reduced/Minimal role
    states in light and dark, including `floor-missed` and software.
- Capture:
  - `scripts/capture-t21-material-tiers.sh` +
    `scripts/t21-material-tiers-driver.py`, target
    `make t21-material-tiers-capture`.
  - 12 crops and 4 review sheets under `docs/captures/t21-material-*`, plus
    `t21-material-tiers.txt`.
- The `DF_SCREENSHOT_CAPTURE_FIXTURE` seam now converts the logical output
  rect through `ChromeScale::bufferRect` before calling `captureScreenshot`.
  Without it a 1.5x/2x nested output captured only the top-left logical-sized
  corner.
- Docs: ADR 0204, `04-shell.md`, `02-compositor.md`, `rendering.md`
  R4.3/R4.4, `STATUS.md` G-12, `captures/README.md`.

## Reusable facts / gotchas

- Role wire values: 0=chrome, 1=dock, 2=popup, 3=drawer. Fallback values:
  0=none, 1=no-sampled-blur, 2=software, 3=multi-gpu, 4=floor-missed.
- The Dock uses role 1; the menu bar uses role 0. T189c must use the same
  `MaterialPolicy` object for roles 2/3 instead of adding another mapping.
- `materialRoleKnown()` is the v3/v4 compatibility switch. Do not seed all
  four roles from `materialRoleTier()` unconditionally: that would mark a v3
  compositor as v4 and freeze the default glass state.
- The shell policy only applies the compositor's decision; it does not run
  the degrade ladder. The floor guard is a malformed/legacy-state safety net.
- Capture host: `spectacle` fails in this Dragonfruit host session. Use the
  compositor capture fixture (`DF_SCREENSHOT_CAPTURE_FIXTURE` +
  `DF_SCREENSHOT_CAPTURE_INTERVAL_MS`) and the shell's `DF_SCREENSHOT_DIR`.
- The capture script reuses the running settingsd and restores
  `appearance.colorScheme` in `cleanup`; it starts a scratch settingsd only
  when no service owns `org.dragonfruit.Settings1`.
- Capture images from the compositor path are the primary output at its
  logical size (currently 1280x800 in the nested demo), not the host window
  size. The driver scales its crop bands from the captured image dimensions.
