## Landed

- `scripts/t21-presentation-bench.sh` + `scripts/t21-presentation-bench-driver.py`
  + `scripts/t21-presentation-bench-report.py`, and `make
  t21-presentation-bench` (not in `make e2e`).
- The main run starts a private session bus and a private XDG tree, starts the

  `DRAGONFRUIT_GPU_TIMING=1`, `DRAGONFRUIT_FRAME_TRACE=1`, and the synthetic

  scenario set and brackets every scenario with shell + compositor `SIGUSR1`

  menu-bar open/close, Dock popover open/close, app launch + window appear,
  Mission Control with 10 windows, fullscreen, fullscreen exit, plus the
  trusted compositor Dock/Mission Control stills.
- Refresh matrix: 60/120/240 Hz overrides plus the main 144 Hz run; each run
  reports the derived `interval_us`/`deadline_us`, shell scene/commit/callback
  deltas, callback cadence, compositor frame percentiles, host presentation
  interval, and transport mix.
- Material matrix: one 144 Hz session with Full/Reduced/Minimal sweeps and a
  baseline snapshot before each tier.
- Report: `docs/captures/t21-presentation-bench.md`; raw compositor/shell/
  driver logs under `docs/captures/t21-presentation-bench-raw/`; native rows
  OPEN in `docs/captures/t21-presentation-bench.open.txt`.
- `docs/captures/README.md`, `docs/rendering.md` R8.2, and
  `docs/design/STATUS.md` G-02 record the harness and the evidence boundary.

## Finding / follow-up

The default **full GPU rail** (`CHROME_GPU_SURFACES=all`) segfaults the shell
during Mission Control. The core backtrace is
`QQuickRenderTarget::operator=` → `QQuickWindow::setRenderTarget` →
`GpuChromeFrameProducer::destroySlotResources` → `releaseGpu` →
`~GpuChromeFrameProducer` → `~ShellController` → `main`. The shell log before
the crash is full of
`qrc:/Dragonfruit/components/Shadow.qml:27/28: TypeError: Cannot read property
'offsetY'/'layers' of null`, so the overview surface's material state is null
before the GPU producer tears down. This is a shell/GPU-overview regression,
not a benchmark-script bug, and T192b does not fix regressions. The benchmark
excludes the overview surface from the GPU rail
(`DRAGONFRUIT_CHROME_GPU_SURFACES=dock,dock-popup,menubar,menubar-popup`) so
the rest of the set completes; the overview row is the visible shm fallback.
Reproduce the crash with `CHROME_GPU_SURFACES=all make
t21-presentation-bench`. File it for T193.

## Gotchas

- The nested shell needs a private session bus and private XDG dirs, or the
  host settingsd applies `display.scale=1.5` and the benchmark runs at a
  different logical size. The script starts `dbus-daemon` and a scratch XDG
  tree per session.
- The shell takes ~60 s to configure its menu bar on this host because
  app-index is scanning the app corpus; the script waits up to 180 s.
- `DRAGONFRUIT_FRAME_TRACE=1` makes the compositor log large (the main raw
  compositor log is ~1.4 MB). The report computes per-scenario frame
  percentiles from the `samples_total` delta and the tail of the trace.
- The shell's `commit_us`/`frame_callback_us` rings clear on every dump, so the
  per-scenario values are interval-windowed; the compositor `frame timing`
  summary is a window, so the report uses the frame-trace delta for scenarios.
- The overview surface's GPU producer crash is the only blocking issue found;
  the rest of the measured set is clean.
