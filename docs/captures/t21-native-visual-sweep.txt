Capture method
--------------
Development-only KMS readback, run by hand outside the tree:

  1. pidfd_open(compositor-pid) + pidfd_getfd(drm-fd) duplicates the
     compositor's own DRM fd.
  2. drmModeGetResources finds the active CRTC; drmModeGetFB2 + a three-plane
     dma-buf import (AMD modifier) through EGL.
  3. glReadPixels writes a PPM; Pillow crops/scales to the committed PNG.

Not a screencopy client, not a portal grant, not a nested window. It reads the
active CRTC's primary plane only: the hardware cursor and overlay planes are
not in the stills.

Live-content test
-----------------
An override-redirect white X11 panel was placed behind the chrome; the
wallpaper and scheme stayed fixed and only the panel moved. A managed window
is clamped below the reserved menu-bar zone by the XWM, so the probe must be
override-redirect. Mean luminance of the chrome region (0..255):

  scheme  surface   baseline  under panel  delta
  light   menu bar     226.3        245.5   +19.2  (light glass is already bright)
  light   Dock          68.7        183.5  +114.8
  dark    menu bar      55.0        113.2   +58.2
  dark    Dock          45.4        161.6  +116.2

The menu bar and Dock visibly sample the live panel, not a static image.
