# T-15 absent-daemon masking matrix (reviewed)

The contract is [The absent-daemon masking matrix (T-15.16)](../design/08-settings.md#the-absent-daemon-masking-matrix-t-1516)
in `docs/design/08-settings.md`; the headless reproduction is
[`t15-absence-matrix.txt`](t15-absence-matrix.txt), regenerated by
`make t15-absence-matrix` (`scripts/t15-absence-matrix.sh`). This file is the
reviewed matrix with the live/VM half recorded — the half no CI host can run.

## Reproduce

```sh
make build
make t15-absence-matrix     # writes the headless transcript
```

The suite runs under a private `dbus-run-session` with **no** settingsd, **no**
`xdg-desktop-portal`, and **no** `system-status` bridge host, so absence is the
state under test. No VM, daemons, host session, or network are required.

## State matrix (22 shipped panes)

"Live on defaults" = the settingsd-backed controls still write in memory on the
schema defaults ([ADR 0030](../design/adr/0030-settingsd-schema-and-dbus-surface.md));
"note" = the adapter-read half is replaced by a one-line absence note and no
write is attempted (three-state projection, [ADR 0029](../design/adr/0029-system-status-bridge-host.md)).

|---|---|---|---|
| Appearance | settingsd | live on defaults | — |
| Desktop & Dock | settingsd → shell/compositor | live on defaults | — |
| Mission Control | settingsd + compositor | settingsd keys live; compositor note | hides |
| Displays | compositor + settingsd | live on defaults; applies on output announce | — |
| Wallpaper | settingsd + wallpaperd + portal | built-in/toggle/fit live; Featured empty; portal row disabled | — |
| Bluetooth | BlueZ | note; toggle disabled | hides |
| Network (VPN) | NetworkManager | note; empty list; writes no-op | hides |

Negative space (distinct from absence, asserted by the same suites):

- A daemon that is **present but unreadable** projects `Error` — the item is
  visible and inert, never leaked into a neighbour.
- An **all-off bus** (e.g. AT-SPI with no tools) is `available` +
  `present: false`, the second hide rule (ADR 0144/0145).
- A **polkit refusal** (`readOnly: true` on VPN writes) is a degradation, not
  absence: the list stays visible and only the writes disable (ADR 0146/0147).

## Headless evidence

- `apps/settings/tests/tst_settings_absence.qml` — the private-bus gate: both
  providers absent, all 22 shipped bodies, the per-pane routing sweep
  (`test_every_shipped_pane_routes_and_stays_live_with_providers_absent`), and
  one case per pane including the shared Mouse section. 28 cases pass.
- The per-pane QML suites (`ctest -R '^tst_settings_'`, 23/23) assert each
  adapter's `absent` value through its fixture seam.
- `services/system-status` (`cargo test -p dragonfruit-system-status absent`)
  asserts every bridge-host adapter projects a hidden slot and answers absence
  on a write; `services/system-adapters` asserts the shared subscription.
- The 15 per-adapter crates each assert an absent mock read and an absent write
  (section 5 of the transcript).

## Live/VM half

Actually stopping BlueZ/UDisks/PipeWire/CUPS/NetworkManager/etc. in a VM and
watching each pane and its Control Center tile is the design's real-VM check
([14-risks.md](../design/14-risks.md)); no VM is in CI. Two live facts stand in
for it and are committed:

- On a live session, **"no bridge host" is the same hidden-everything state**,
  because the host is a separate process. T-07.6a captured that bar
  (`t07-live-menubar-absent.png`).
- **`t15-breadth.png`** is the nested demo with every provider absent
  (no `DF_STATUS_FIXTURE`, no `DF_SETTINGS_FIXTURE`, no host): the menu bar,
  Dock, wallpaper, and client windows all composite with no blank areas,
  clipping, or stray chrome. Regenerate with `make t15-breadth-capture`.

The remaining human step — masking each real daemon on a VM and comparing the
rendered pane/tile to this table — is batched at the T-15 track sign-off
(see [SLICING-REVIEW.md](../SLICING-REVIEW.md)).
