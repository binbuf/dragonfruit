# T-21.1c chrome transport after

Generated by `scripts/t21-chrome-baseline.sh` (`make t21-chrome-baseline`).
The run is **nested**: the shell is a Wayland client of the nested
compositor, and the nested output has no hardware vblank. The native
half is recorded separately below; a nested run is not a native
presentation measurement.

- command: `make t21-chrome-baseline`
- transport under test: `QQuickRenderControl -> ping-pong QImage -> pooled wl_shm (3 buffers/surface) -> wl_surface.commit + wl_surface.frame`
- opt-in switches: `DRAGONFRUIT_CHROME_STATS=1`, `QSG_INFO=1`

## Final-tree environment caveat

The final-tree rerun was made while the nested window was not being presented by the host at 60 Hz: the compositor's `frame timing` p50 is about 1.0 s, so QML animation advanced only on synthetic pointer events and the shell's 100 ms safety tick is visible as `fallback_renders`. The transport invariants still hold per commit (`grab_renders=0`, bounded `shm_allocs`, exactly one full-surface copy per commit), and the idle interval produced zero shell scene frames, commits, and grab renders. The accepted 18:57 nested run, where the host presented at ~55 Hz, recorded the target dock-sweep numbers: commits=136, `grab_renders=0`, `shm_allocs=4`, `shm_bytes=1,198,560`, `copy_bytes=121,280,880`, `frame_callbacks=105`, `fallback_renders=0`; its idle interval was fully zero (shell and compositor). The final-tree deltas in this file are therefore a same-transport, host-throttled sample, not a replacement for the accepted comparison.
