## Hand-off

**State: done.** The session policy keys are registered in settingsd, the
kill matrix is a headless suite, and the T-12 track capture is committed.
Contract frozen in
[ADR 0073](../design/adr/0073-session-policy-keys-and-kill-matrix.md).

What landed:

- **`services/settingsd/src/schema.rs`** — schema v5, new `Session` key group
  with `idle.dim` (150), `idle.blank` (300), `idle.lock` (600), `idle.suspend`
  (0), all `x` whole seconds, range 0–86400, `0` disables. Exactly the four
  names/spellings ADR [0070](../design/adr/0070-idle-timer-engine-and-policy.md)
  freezes. A `the_session_policy_keys_follow_adr_0070` unit test pins
  type/default/range.
- **`docs/settings-keys.md`** — the four rows plus a `session/idle engine`
  consumer-map entry (kept in lockstep by `tests/schema_doc.rs`).
- **`libs/settings-client/settingsclient.cpp`** — `settingsSchemaDefaults()`
  now mirrors v5 (the four idle keys) for the settingsd-absent path.
- **`services/session/tests/session_policy.rs`** (new, 5 tests) — proves the
  keys drive lock/idle/suspend: the settings defaults reproduce
  `IdlePolicy::new()`; a snapshot walks dim→blank→lock→suspend on a fake
  clock and requests/cancels suspend through `SuspendController`; a `0` key
  disables only its stage; a live key change moves the chain; a held
  inhibitor freezes it.
- **`services/session/tests/kill_matrix.rs`** (new, 5 tests) — the
  supervision half of the kill matrix: shell/lock UI restarts (`always`),
  settingsd and notifications restart (`on-failure`), a compositor death ends
  the session and stops everything else, and the plan matches the shipped
  restart policies. The fail-secure "never unlocked" invariant stays with the
  compositor (`session_lock_conformance.rs`, already in `make e2e`).
- **Capture** — `scripts/capture-session.sh` + `capture-session-driver.py` +
  `make session-capture` write `docs/captures/t12-session.png`,
  `t12-session-lock.png`, `t12-session.mp4`, `t12-session.txt`, and
  `t12-session-kill-matrix.txt`.
- **Docs** — ADR 0073; `11-session-and-dev-workflow.md` "Session policy keys
  and the kill matrix (T-12.5b)"; `docs/captures/README.md`.

Gotchas for later tasks:

- **No production idle service yet.** The keys are registered and `from_keys`
  is proven, but nothing binds `ext-idle-notify` or calls `set_policy` at
  runtime; the real consumer is T-12.6/the portals work. T-15.8b writes the
  keys ("Never" is `0`, not the `never` spelling).
- **Idle keys are `x` int64 whole seconds, 0–86400**, owner `apps/settings`,
  consumer `session/idle engine`; convert with `to_string()` into
  `IdlePolicy::from_keys`.
- **`SCHEMA_VERSION` is now 5**; older settings files migrate by filling the
  four defaults. The shell's `MockSettingsClient` defaults were synced too.
- The lockscreen/lock-ui kill invariant is the compositor's
  (`session_lock_conformance.rs`); the session suite asserts supervision, not
  the lock state. T-16.8a/T-17.5a add the VM/DRM no-live-under-lock drills.
