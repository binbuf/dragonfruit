## Goal

Prove the DRM session tears down cleanly and document a reproducible runbook.

## Scope

- 100-cycle nested soak plus one DRM session cycle: no leaked VT master, socket, token, or orphaned client.
- Multi-GPU import/fallback validation.
- Runbook for the dedicated-user second-VT workflow and the VM path, linked from testing-ladder.md.

## Explicitly deferred

- 100-cycle suspend soak (T-16.4).

## Acceptance (agent-completable)

- [ ] Soaks pass with clean teardown.
- [ ] A second person can reproduce the run from the runbook.

## Test plan

### What landed

- **`tools/dragonfruit-dev/src/soak.rs`** — the teardown gate now covers all
  four leak classes. New `teardown_artifacts(socket)` lists the socket,
  `<socket>.lock`, `<socket>.launch-token`, and
  `<socket>.desktop-launch-token`; `run` takes a `backend` and fails on any
  leaked artifact (and still on any orphaned `dragonfruit*` process). Unit test
  `teardown_covers_the_socket_lock_and_both_tokens`.
- **`tools/dragonfruit-dev/src/main.rs`** — `--drm` flag; `dev --soak [N]` runs
  the gate on the explicit `--nested`/`--headless`/`--drm` backend (default
  headless). `dev --soak 1 --drm` is the one DRM session cycle.
- **`compositor/src/multi_gpu.rs`** (new) — the pure import/fallback decision:
  `GpuNode`, `MultiGpuOutcome::{NoGpu, Single, Imported, Fallback}` with
  `classify`/`is_multi`/`marker`, and `format_allowed(renders_locally, linear)`.
  Re-exported from `compositor/src/lib.rs`.
- **`compositor/src/backend/drm.rs`** — prints the `Multi-GPU:` marker after
  the initial device scan (primary first) and filters dmabuf render formats
  through `format_allowed`: a device with no render node falls back to the
  primary renderer and may only import `Linear`.
- **`compositor/tests/multi_gpu.rs`** (new; in the `make e2e` list; 4 tests) —
  pins the classification, the one-line markers, and the format rule.
- **`scripts/multi-gpu-probe.py`** (new) — a sysfs mirror of `multi_gpu.rs`
  (`/sys/class/drm/cardN/device/drm/renderD*`), plus the driver name.
- **`scripts/multi-gpu-validation.sh`** + **`make multi-gpu-validation`** —
  writes `docs/captures/t03-multigpu.txt` (>1 card) or
  `t03-multigpu.open.txt`. Always exits 0.
- **`scripts/drm-soak.sh`** + **`make drm-soak`** — runs the automated soak
  (`dev --soak $SOAK_CYCLES`, default 100) and then one DRM cycle
  (`dev --soak 1 --drm`); on a free seat it re-probes the card to prove DRM
  master (VT) released and writes `docs/captures/t03-drm-soak.txt`; with no free
  seat it writes `t03-drm-soak.open.txt`. Always exits 0.
- **`docs/runbook-drm-session.md`** (new) — the dedicated-user second-VT
  workflow, the libvirt/virtio-GPU VM path, the four acceptance commands, the
  demo walkthrough, teardown expectations, and troubleshooting. Linked from
  `docs/testing-ladder.md` rungs 2 & 3.
- **Artifacts** — `docs/captures/t03-drm-soak.open.txt` (automated 100-cycle
  soak PASS + the no-seat evidence), `docs/captures/t03-multigpu.open.txt`
  (`Multi-GPU: SINGLE device=card0`), `docs/captures/t03-soak-nested-check.png`
  (required live visual check).
- **Docs** — ADR `docs/design/adr/0172-drm-soak-teardown-and-runbook.md` (new);
  `docs/design/02-compositor.md` §"DRM soak, teardown, and multi-GPU (T-03.4)";
  `docs/design/tracks/03-real-session-bringup-perf.md` Status notes;
  `docs/captures/README.md`; `docs/testing-ladder.md` runbook links.

### Deviations

- The DRM cycle and the multi-GPU hardware exercise are **not** performed; the
  unit is marked open with committed artifacts, not silently skipped (the
  task's hardware-unavailable branch). The automated soak is fully exercised.
- I did **not** run the logind/libseat DRM path (it would steal the live host
  session's seat); seat ownership comes from the T-03.2 `libdrm` master probe
  and the no-op seat, the same non-disruptive proxy.
- The "nested soak" is run through the headless backend, the same gate
  `make soak` / `make check` use and the form CI can run; `--nested`/`--drm` are
  wired for the hardware rail.
