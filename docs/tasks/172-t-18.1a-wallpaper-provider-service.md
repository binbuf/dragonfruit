## Goal

A restartable session service that resolves the shipped original default
wallpaper (`assets/graphics/wallpapers/Default.jpg`) to a stable local path,
then fetches Wikimedia Commons Featured Pictures into a lazy local cache with
attribution metadata, selects the deterministic Nature entry for the Featured
row, refreshes weekly, and degrades cleanly offline.

## Scope

**Shipped original default**

- [ ] Install `assets/graphics/wallpapers/Default.jpg` to a stable read-only
      share path at build/package time (e.g.
      `$prefix/share/dragonfruit/wallpapers/Default.jpg`), and expose the
      resolved absolute path; the in-tree copy is resolved for `make dev`.
- [ ] Resolution order (testable): `DF_DEFAULT_WALLPAPER` (dev/test override) →
      installed share path → in-tree `assets/graphics/wallpapers/Default.jpg`.
- [ ] Never copy the bundled asset into the provider cache: the cache holds only
      fetched content. The shipped default is read in place.

**Provider service**

- [ ] New crate `services/wallpaperd` (Rust, MIT, workspace member + service
      registration like the other `services/`).
- [ ] Add one permissively-licensed HTTP client (prefer `ureq`; MIT/Apache-2.0).
      No GPL/AGPL dependency (`docs/licensing.md`).
- [ ] Category map constant for the six categories in ADR 0055.
- [ ] Query builder matching the validated shape: `generator=categorymembers`,
      `gcmnamespace=6`, `gcmlimit=10`, `gcmsort=timestamp`, `gcmdir=desc`,
      `prop=imageinfo`, `iiprop=url|size|mime|extmetadata`, `iiurlwidth=3840`,
      `format=json`, `formatversion=2`; follow `continue`.
- [ ] Post-filter `ns==6` and `mime` starting `image/`; dedupe by `pageid`;
      cap at 10 per category.
- [ ] Normalize URLs: strip the `utm_*` query Wikimedia appends.
- [ ] Download thumbnails to
      `$XDG_CACHE_HOME/dragonfruit/wallpapers/<category>/<pageid>.<ext>` and
      write an `index.json` with `title`, `artist` (HTML stripped), `licenseShortName`,
      `licenseUrl`, `pageUrl`, `description`, `category`, `pageid`, `width`,
      `height`, `fetchedAt`.
- [ ] Deterministic Featured default: first Nature entry under timestamp-desc
      (this is the Featured row's default and the desktop fallback when the
      shipped asset is unavailable — not the out-of-box default; ADR 0094).
- [ ] Offline/error path: keep the cache, set `offline`, no retry storm, no
      crash; never fetch on the compositor/shell frame path.

**Cache warm policy**

- [ ] **Lazy background warm on session launch**: when the session starts,
      build/refresh the catalogue and downloads at low priority and off the
      frame path. Session bring-up never waits on the network; the desktop
      already renders the shipped default.
- [ ] **Eager preload on demand**: expose a `Preload` method so System Settings
      can request an immediate catalogue load when the Wallpapers pane is
      opened; without a `Preload` the service stays lazy.
- [ ] Exactly one in-flight refresh at a time; first-run fetch only when the
      cache is empty; weekly re-check from a persisted `lastFetch`.

**D-Bus API (`org.dragonfruit.Wallpaper1`)**

- [ ] Properties `Status` (`idle|fetching|ready|offline`), `LastFetch`,
      `DefaultSource` (Featured default/fallback), **`BuiltinDefaultSource`**
      (resolved shipped `Default.jpg` path), `Items`.
- [ ] Method `Refresh` (explicit, user-driven); method **`Preload`** (eager
      foreground load for an open pane); signals `ItemsChanged`,
      `StatusChanged`.
- [ ] The interface is the wallpaper API other components consume; T-18.1b
      wires System Settings and the shell to it.

## Design notes

- Send a descriptive `User-Agent`; cap concurrent downloads and per-request
  timeouts.
- Model the provider as an interface so a second content source can be added
  later without changing the D-Bus surface.
- The service is restartable; a cold start rebuilds the catalogue from the
  cache without a network round-trip.
- `DefaultSource` and `BuiltinDefaultSource` are distinct: the former is the
  fetched Featured default, the latter is the shipped original default that
  precedence puts first (ADR 0094).
- Lazy warm is a *service* concern, not a compositor or shell one; nothing on
  the frame path may block on it.

## Acceptance (agent-completable)

- [ ] Headless tests cover parser, filtering, dedup, URL normalization, cache
      layout, Featured-default selection, the offline path, bundled-default
      resolution/precedence, and lazy-vs-`Preload` behavior.
- [ ] The service runs, serves `Items`/`DefaultSource`/`BuiltinDefaultSource`,
      and survives the network being absent.
- [ ] With an empty cache and no network, the shipped default resolves and no
      fetch happens on the frame path.

## Test plan

- Fixture the Commons JSON (the validated `Category:Featured pictures of
  landscapes` response is a good base) and unit-test the query builder and the
  parser.
- A local mock server (or a `file://`-style source seam) drives the download
  and cache tests without the network.
- Test default resolution with `DF_DEFAULT_WALLPAPER`, a fake share prefix, and
  the in-tree fallback; test that `Preload` starts a fetch while an idle launch
  does not block.
- `make e2e` stays green.
