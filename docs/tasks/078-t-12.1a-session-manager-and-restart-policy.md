## Hand-off

**State: done.** `services/session` is no longer a stub: `SessionPlan`/
`ServiceSpec` encode the session composition (launch stages, restart policy,
compositor anchor, readiness gate) and `Supervisor` spawns, reaps, and
restarts the children. Contract frozen in
[adr/0064](../design/adr/0064-session-manager-plan-and-restart-policy.md).

What landed:

- **`services/session/src/plan.rs`** (new) — `RestartPolicy` (`always` /
  `on-failure` / `never`), `ServiceSpec` (name, program, args, env, policy,
  stage, `ends_session`, `gate`, builder methods), `SessionPlan`
  (`default_session`, `stages`, `services_in_stage`, `anchor`, `validate`) and
  `PlanError`. The default plan matches
  `11-session-and-dev-workflow.md`: stage 0 `compositor` (Never, anchor,
  gate); stage 1 `shell` (Always) + `settingsd`/`menu-broker`/`app-index`/
  `notifications` (OnFailure); stage 2 `portal` (OnFailure).
- **`services/session/src/supervisor.rs`** (new) — synchronous, runtime-free
  `Supervisor`: `start()` launches stage 0; `tick()` reaps exited children,
  applies policy, and advances stages; `set_ready(name)` opens the compositor
  gate; `kill(name)` is the kill seam; `shutdown()` tears the session down.
  `ExitOutcome` (Success/Failure/Signaled), `ServiceState`, `SessionState`,
  `SupervisorEvent` are the vocabulary. The anchor is never restarted; its
  exit stops every survivor and ends the session.
- **`services/session/src/main.rs`** — `--print-plan` (default) prints the
  composition in launch order; `--exec PROG [ARGS...] [--policy P]` supervises
  one process until it exits or the session is signalled.
- **`services/session/src/lib.rs`** — re-exports plus the unchanged
  `DBUS_NAME` policy test.
- **`services/session/Cargo.toml`** — `[lib] dragonfruit_session`, `libc`
  dependency (SIGINT/SIGTERM for `--exec`).
- **Tests** — `tests/restart.rs` 8 cases: staged start + readiness gate, a
  `SIGKILL`ed `sleep` restarted with a new pid, `on-failure` leaves a clean
  exit alone, `always` restarts a clean exit, `never` leaves a failure exited,
  the compositor anchor ends the session and stops the shell, a missing anchor
  fails the session, and the binary's `--print-plan`. Plus 5 unit tests in
  `plan.rs`/`supervisor.rs`/`lib.rs`.
- **Docs** — ADR 0064; `11-session-and-dev-workflow.md` composition section
  points at the data; `Makefile` `e2e` now runs `cargo test -p
  dragonfruit-session`.

Commands that work (repo root):

- `cargo test -p dragonfruit-session` — 13/13 (5 unit + 8 integration).
- `cargo clippy -p dragonfruit-session --all-targets -- -D warnings` and
  `cargo fmt -p dragonfruit-session -- --check` — exit 0.
- `cargo run -p dragonfruit-session --bin dragonfruit-session -- --print-plan`
  prints stage 0 `compositor never … anchor` first.
- `cargo run -p dragonfruit-session -- --exec sh -c 'exit 0' --policy always`
  prints `restarted exec (… #1, after exit 0)`, `#2`, …

What the next task must know:

- T-12.1b attaches the environment via `ServiceSpec::env` (T-12.1a leaves it
  empty) and calls `Supervisor::set_ready("compositor")` when the private
  socket exists; it does not need to change the stages or policies.
- The binary's default action is `--print-plan`; the real production
  supervisor is the systemd user units T-12.1b ships. T-12.1a's in-process
  manager is the headless/testable contract those units must agree with.
- `Supervisor::shutdown` currently `SIGKILL`s direct children only; T-12.2's
  logout teardown should extend it to process groups.
