## Goal

Give our first-party apps Phosphor-based artwork: the Dock's **Files** (our
Finder equivalent) tile and the **System Settings** app icon — the latter in the
same gradient-container style as T-19.1b. The System Settings app icon is the
one app icon that carries the gradient container; other app icons look how they
should for where they sit. Keep the Dragonfruit system-menu logo unchanged, and
leave the Dock's folder-stack, Trash, and overflow artwork as they are.

## Context (read first)

- `shell/dock/DockGlyph.qml` — app tiles resolve a themed `iconPath` from
  app-index (T-14.1a) and fall back to an initial tile; the `stack`, `trash`,
  and `overflow` kinds are separate, designed artwork (do not touch them here).
- `apps/files/org.dragonfruit.Files.desktop` — `Icon=system-file-manager`.
- `apps/settings/org.dragonfruit.Settings.desktop` — `Icon=preferences-system`.
- `services/app-index/src/icons.rs` — the themed-name → file resolver; a name
  under a shipped theme is what makes the Dock/menus/portal agree.
- `docs/design/12-packaging.md` and `services/session` install seam — where a
  `share/icons/…` payload would be installed.
- `design-system/components/PhosphorIcon.qml` (T-19.1a) and
  `SettingsCategoryIcon.qml` (T-19.1b).

## Out of scope

- The Applications drawer's grid (→ T-19.2) — it consumes the same icons but is
  its own unit.
- Menu-bar marks (→ T-19.1c); in-Settings category tiles (→ T-19.1b).
- Third-party app icons (stay sourced from the host theme via app-index).
- Reworking the Dock's folder-stack/Trash artwork.

## Design notes

- Prefer shipping icons over special-casing the Dock: one artwork source should
  serve the Dock, the drawer, menus, and the portal file chooser. The bundled
  mapping exists only so nested dev shows the right tile before install.
- The Settings app icon uses the gradient container; the Files icon does **not**
  — it is a normal app tile. Do not put the container on every Dock tile.
- The `.desktop` icon name must resolve in a *clean* session; verify with the
  installed theme, not just the bundled map.
- Keep the icons original assets built from Phosphor, licensed under Phosphor's
  MIT terms (already recorded in T-19.1a's ADR/NOTICE entry).

## Hand-off

**Status: done.**

**Icon names / theme layout.** One SVG per app under `assets/icons/apps/`,
generated from Phosphor by `scripts/gen-app-icons.py`:

- `org.dragonfruit.Files.svg` — flat blue (`#3b82f6`) rounded square
  (`rx 61.44` = 0.24·256) + white Phosphor `folders`.
- `org.dragonfruit.Settings.svg` — the gradient container (`#8e8e93`→`#58585c`,
  top inner white highlight ratio 0.45 / opacity 0.28) + white Phosphor `gear`
  (ratio 0.55). This bakes the `SettingsCategoryIcon` look into the theme file;
  it cannot reference the QML component.

The files are exposed at `qrc:/icons/apps/<name>.svg` (design-system qrc) and
each app installs its file to `${datadir}/icons/hicolor/scalable/apps/`. The
`.desktop` `Icon=` names are now `org.dragonfruit.Files` /
`org.dragonfruit.Settings` (were `system-file-manager` / `preferences-system`),
so a clean session resolves the same artwork by name.

**Bundled mapping.** `DockGlyph` gains `desktopId`; `bundledIcon` normalizes the
desktop id (lower-case, strip `.desktop`) and returns the `qrc` path for
`org.dragonfruit.files` / `org.dragonfruit.settings`; `iconUrl` prefers the
bundled tile and falls back to `file://` + app-index `iconPath`. `DockEntry`,
`DockAppPicker`, and `DockOverflowPopover` forward the desktop id. Keyed on
desktop id deliberately (not `appId`) — two existing tests build first-party
glyphs by `appId` alone and expect the placeholder.

**Deviations.** (1) The Settings app icon's gradient is baked into its SVG
rather than rendering `SettingsCategoryIcon` at the Dock, because the installed
theme file must be self-contained; the QML component remains the in-app
category treatment. (2) The Dock mapping is a small inline table in `DockGlyph`
rather than a shared singleton; T-19.2 should lift it (Follow-ups). (3) T-19.1d
ships `folders` (not `folder-open`) for Files.

**Checks.** `make e2e` green; `ctest --test-dir build` 72/72; `cargo test -p
dragonfruit-app-index` green (incl. the new hicolor-resolution test);
`gen-phosphor-glyphs.py --check`, `gen-app-icons.py --check`,
`check-phosphor-icons.py`, `check-design-tokens.sh`, `gen-tokens.py --check`,
`check-no-capture-grab.sh`, `check-gallery-snapshots.py --strict`,
`i18n-extract.py --check`, `cargo fmt --check`, `clippy -p dragonfruit-app-index`
all green. `check-desktop-names` remains pre-existing red on `HEAD` (unrelated
files; noted in `PROGRESS.md` Follow-ups), which is the only reason `make check`
aborts.

**Live capture.** `scripts/capture-t19-app-icons.sh` →
`docs/captures/t19-app-icons-light.png` and `...-dark.png` (1920×1200).
Inspected: Files is the blue folder tile, Settings the grey gradient gear, the
Downloads stack and Trash unchanged.

**What T-19.2 (drawer) must know.** The mapping key is the normalized desktop
id; reuse the same two `qrc` paths and lift the table out of `DockGlyph` before
the drawer consumes it. After an install the drawer's app-index `iconPath`
resolves the identical file, so the bundled map is a nested-dev fallback only.
