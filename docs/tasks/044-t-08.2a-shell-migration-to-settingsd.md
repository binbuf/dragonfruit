## Goal

The shell drops its own Dock settings/pins and reads from settingsd, removing the file watcher.

## Scope

- Shell drops `DockSettings`/`DockPins`; adopts the existing file shape without migration.
- Remove the shell's `QFileSystemWatcher` in the same change (no two writers).

## Explicitly deferred

- Design-system and compositor consumers (T-08.2b, T-08.2c).

## Acceptance (agent-completable)

- [x] Shell settings come only from settingsd; the watcher is gone.

## Test plan

- Headless: Dock keys change via settingsd and the Dock re-lays-out.

## Hand-off

**Landed.** `DockSettings`/`DockPins` and the shell's `QFileSystemWatcher` are
deleted. The Dock reads/writes every `dock.*` key through the new
`SettingsClient` seam (`shell/src/settingsclient.h`): `DbusSettingsClient`
over `org.dragonfruit.Settings1` (subscribes `Changed`, resyncs `GetAll`,
mirrors `Set`, seeded with schema defaults so the daemon-less demo still
works) and `MockSettingsClient` for tests. The typed view is `DockConfig` +
`dockConfigFromValues()` in `dockmodel`; `dockIconSize()` and
`resolveDefaultDockPins()` moved there. `dock.pinned` is seeded once per
session when empty. ADR 0032 records the seam; the track doc 08 has a
"shell consumes settingsd" section.

**Deviations / gotchas.**
- The daemon exposes no "settings file existed" bit, so an intentionally
  emptied `dock.pinned` is re-seeded on the next launch. Recorded in the
  track doc + ADR; T-08.3 can add a seed marker.
- When settingsd is absent the shell runs from the mirrored schema defaults
  and in-memory writes (the demo/dev tool does not start settingsd). This is
  the intended graceful degradation, not a second owner.
- A `dock.size` change that arrives from the daemon goes through the full
  reconfigure/rebuild path (as the old external file-change did), not the
  size-only divider path; a live Settings-app drag of size would rebuild
  entries until that is made smarter.

**Commands that work** (repo root; `make` sets the toolchain env):
`cargo test -p dragonfruit-settingsd`; `ctest --test-dir build` (19/19, incl.
the new `tst_settingsclient` under `dbus-run-session`); `make lint` exit 0.

**Live visual check.** `/tmp/opencode/t44-capture.sh` started the built
`dragonfruit-settingsd` on the session bus (scratch `XDG_CONFIG_HOME`),
launched the nested demo so the shell consumed it, captured the desktop at
`dock.size=0.5` (`/tmp/opencode/t44-before.png`) and after a D-Bus
`Set("dock.size","<0.9>")` (`/tmp/opencode/t44-nested.png`). The shell log
shows `Dock settings changed (live: dock.size)`, settingsd persisted `0.9`
and the seeded `dock.pinned`, and the measured Dock panel grew from 335x65 to
413x78 px (crop `/tmp/opencode/t44-after-dock.png`; vision read six icons —
pinned/running plus Downloads and Trash — on a centered rounded panel). No
`docs/captures/` file: the T-08 track owns `t08-settingsd.*` for the scripted
flip.
