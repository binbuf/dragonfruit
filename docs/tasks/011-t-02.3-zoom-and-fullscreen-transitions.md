## Goal

Animate between floating/zoomed/fullscreen geometries using the shared clock.

## Scope

- Zoom/unzoom and fullscreen/unfullscreen interpolate between geometries.
- Interruptible mid-flight with existing progress semantics.

## Explicitly deferred

- Multi-monitor geometry (T-16).

## Acceptance (agent-completable)

- [ ] Zoom and fullscreen animate; an interrupt retargets without waiting.

## Test plan

- Headless: assert intermediate transform frames and final geometry.

## Hand-off

Landed:

- `WindowMotionKind::{Zoom, Fullscreen}` in
  `compositor/src/window/motion.rs`: geometry interpolation `origin → target`
  with alpha pinned at `1.0` (visible at both ends). `MotionFrame::scale_for
  (surface_size)` maps a live-sized surface onto the interpolated rect (so a
  zoom/fullscreen survives the client's mid-flight buffer resize); appear/
  minimize keep the target-relative `frame.scale`.
- `DfState::{zoom,unzoom,fullscreen,unfullscreen}_window` now apply the state
  change immediately and start a render-only motion from the geometry being
  left. `begin_window_motion_from` is the explicit-origin variant of the
  launch-motion starter; a re-entrant request starts from the current
  interpolated rect (interrupt without waiting).
- `compositor/src/render.rs` `push_motion_elements` uses
  `frame.scale_for(window.geometry().size)` for surfaces; chrome keeps
  `frame.scale`.
- Synthetic hooks: `zoom|unzoom|fullscreen|unfullscreen <window-id>` and a
  determinism helper `SyntheticInput::query_batch` in the test.
- Tests: 4 new unit tests in `motion.rs`; `window_conformance.rs`
  `zoom_and_unzoom_interpolate_between_geometries_and_commit`,
  `fullscreen_and_unfullscreen_interpolate_between_geometries_and_commit`,
  `zoom_retargets_mid_flight_without_waiting`,
  `reduced_motion_zoom_and_fullscreen_take_a_single_frame` (20/20 suite).
- Docs: ADR `0006-zoom-fullscreen-geometry-motion.md`; the
  `02-compositor.md` "Window lifecycle motion" section.

Commands that work (repo root; `make` supplies the toolchain env):
`cargo test -p dragonfruit-compositor` (174 bin unit + all suites green);
`cargo clippy --workspace --all-targets -- -D warnings`;
`cargo fmt --all -- --check`; `make e2e`; `make soak SOAK_CYCLES=3`.

Deviations / gotchas:

- No shell change: the private-protocol `zoom`/`unzoom`/`fullscreen`/
  `unfullscreen` requests already reach these paths; the shell only sends them.
- The state change is immediate (the window stays mapped and input-correct at
  the destination geometry); only the drawing interpolates. Do not move this
  into a state animation.
- A fullscreen entry hides the SSD titlebar immediately (state is Fullscreen);
  only the content geometry tweens. Unfullscreen re-shows it immediately and
  it shrinks with the content.
- Client buffer lag: until the client commits the configured size the old
  buffer is scaled to the interpolated rect; a slow client can pop at
  completion (documented in ADR 0006, a T-04/post-gate refinement).
- `reapply_insets` (runtime decoration-tier change) still jumps without a
  motion; only explicit zoom/fullscreen transitions animate. Left for a later
  task if desired.

T-02.4 closes the loop with the close ghost; reuse `WindowMotion`/`MotionFrame`
(add a `Close` kind) and do not add a parallel effect path.
