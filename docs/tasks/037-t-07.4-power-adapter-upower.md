## Hand-off

**State: done.** The read-only UPower adapter landed in a new concrete-adapter
crate. No shell wiring (T-07.5 renders the item); no write path
(power profiles are T-15).

What landed:

- **`services/power/`** (new crate `dragonfruit-power`, workspace member; deps:
  `dragonfruit-system-adapters` + `zbus` blocking-api + `serde`):
  `src/source.rs` (raw `PowerData`/`PowerDeviceData`, `PowerSource`, `MockPower`,
  `DEVICE_TYPE_BATTERY`), `src/model.rs` (`ChargeState`, `BatteryLevel`,
  `Battery`, `PowerSnapshot`), `src/upower.rs` (`DbusUPower`, `UPOWER_SERVICE`),
  `src/adapter.rs` (`PowerAdapter<S>`).
- **Live path**: UPower over the system bus (`org.freedesktop.UPower`:
  `OnBattery` + `EnumerateDevices`; device `Type`/`IsPresent`/`PowerSupply`/
  `Percentage`/`State`/`BatteryLevel`/`TimeToEmpty`/`TimeToFull`). Verified
  against the real daemon on this host (line power only); property names match
  `gdbus introspect`.
- **Presence**: `PowerSnapshot` carries `battery: Option<Battery>`; `present()`
  is false on a machine with UPower but no battery (desktop/VM). UPower absent
  is the adapter's `Unavailable` (hidden). Neither errors.
- **Model**: percentage clamped 0–100; `level()` is the 0..=1 glyph fill,
  `percentage_percent()` the 0–100 label; `glyph()` is `"battery"`; charging is
  `charging()` + the label (no distinct glyph case yet).
- **Tests**: 22 lib + `tests/read_path.rs` (7), fixture
  `tests/fixtures/upower-laptop.json`. Acceptance
  `the_fixture_renders_the_battery_level_and_charge_state`,
  `an_absent_upower_hides_the_item_and_never_errors`,
  `a_present_daemon_with_no_battery_has_no_item_to_show`,
  `a_daemon_restart_resubscribes_and_resyncs`. Live smoke test skips on CI.
- **Makefile**: `make e2e` runs `cargo test -p dragonfruit-power`.
- **Docs**: `07-system-integration.md` "The power path (T-07.4)". Per ADR 0026,
  no new ADR (the crate-per-adapter layout and the system-bus UPower choice were
  already recorded).
- **Capture**: `docs/captures/t07-power.png` (nested demo via
  `spectacle -b -n -f`). This unit has no surface of its own, so the demo was
  launched and the desktop confirmed rendering; vision check reported menu bar,
  Dock, windows and desktop all present, no stray artifacts.

Deviation from plan: none material. The raw read keeps `time_to_empty`/
`time_to_full` beyond the minimum "presence/level/charging" scope because
UPower supplies them and the T-07.5b battery menu will want them.

For T-07.5b: hide the battery item when `!snapshot.present()` as well as when
the slot is invisible; add a charging bolt to `StatusGlyph.qml` or render
`charging()`/`label()` otherwise. For T-07.5: drive `PowerAdapter::refresh()`
from UPower signals, never a poll.
