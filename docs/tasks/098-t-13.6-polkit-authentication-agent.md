## Hand-off

Landed (T-13.6):

- **`shell/src/polkitagent.{h,cpp}`** (dockcore) — `PolkitAgent`: exports
  `org.freedesktop.PolicyKit1.AuthenticationAgent` as a `QDBusVirtualObject` on
  the system bus and registers with `org.freedesktop.PolicyKit1` as the shell's
  session agent (subject `unix-session` from `XDG_SESSION_ID`; process-subject
  overrides `DF_POLKIT_SUBJECT_SESSION` / `DF_POLKIT_SUBJECT_PID` and
  `setSubjectSessionId`/`setSubjectProcess`). Registration is **asynchronous**
  (`QDBusPendingCallWatcher`); an absent authority or an existing agent for the
  subject is a degraded state. Parses `BeginAuthentication`'s `(sa{sv})`
  identities by hand (identity attr is `uid`, not `name`) and resolves the
  username via `getpwuid`. Queues concurrent requests.
- **`shell/src/polkitsession.{h,cpp}`** (dockcore) — `PolkitHelperSession`: the
  host helper conversation. Spawns `polkit-agent-helper-1 <user>` (path
  `/usr/lib/polkit-1/polkit-agent-helper-1` or `/usr/libexec/...`, override
  `DF_POLKIT_HELPER`), writes the cookie on stdin, relays the escaped
  `PAM_PROMPT_ECHO_OFF/ON`, `PAM_TEXT_INFO`, `PAM_ERROR_MSG` lines and
  `SUCCESS`/`FAILURE`. Also supports `/run/polkit/agent-helper.socket`
  (`QLocalSocket`, `DF_POLKIT_HELPER_SOCKET`). The **helper**, not the agent,
  reports to the authority.
- **`shell/screenshot/PolkitDialog.qml`** — pure design-system dialog.
- **`shell/src/shellprotocol.{h,cpp}`** — centered `polkit` overlay surface
  (namespace `polkit`, on-demand keyboard, pointer/key routing with shift).
- **`shell/src/shellcontroller.{h,cpp}`** — maps the dialog, owns the response
  buffer (reuses `dragonfruit::lockKeyFromEvdev`, as the lock screen does),
  submits on Return, cancels on Escape/lost keyboard, and presents the
  `DF_POLKIT_FIXTURE` request.
- **Tests** — `tst_polkitagent` (11 cases: fake-helper conversation success /
  wrong password / cancel / missing helper; fake authority registration,
  request, cancel, refused registration; fixture; **real `pkcheck` request**),
  `tst_polkitui` (8 cases). `ctest` 53/53, `make lint` and `make e2e` green.

Live visual check: `DF_POLKIT_FIXTURE=1 make demo DEMO_ARGS="--socket-name
dragonfruit-t98"`, captured with `spectacle -b -n -f` →
`/tmp/opencode/t98/polkit.png`. Verdict: the centered dialog shows
"Authentication Required", the identity "user", the action message, the
"Enter your password" field, "Show details", and Cancel/Authenticate; the menu
bar and Dock render normally around it; 0 binding loops.

Gotchas for later tasks:

- **The KDE session agent occupies the session subject on this dev host**
  (`/usr/libexec/kf6/polkit-kde-authentication-agent-1`); the shell's session
  registration is refused there. That is the intended degradation. The real
  request check therefore registers for a process subject via
  `pkcheck --process <pid>`; in a Dragonfruit session the session agent registers
  cleanly.
- The response buffer is plain text only up to the fixed US/ASCII
  `lockKeyFromEvdev` mapping (the same limitation as the lock screen, T-12.3c).
- `DF_POLKIT_FIXTURE` resolves locally (`presentLocal`) with no helper; the real
  helper is only exercised by `tst_polkitagent` and a live privileged request.
- T-13.7 validates the whole portal set; the auth agent is independent of the
  portal frontend.
