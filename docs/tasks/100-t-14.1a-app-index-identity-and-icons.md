## Hand-off

**State: done.**

What landed:

- **`services/app-index`** is no longer a scaffold. The pure engine in
  `src/index.rs` scans XDG/Flatpak application dirs and resolves in order:
  exact desktop id, `StartupWMClass`, desktop id/stem/reverse-DNS tail, `Exec`
  executable basename, then a tolerant normalized heuristic. Misses are
  recorded and served as the heuristic input. `src/icons.rs` implements the
  freedesktop icon-theme lookup (active theme + `Inherits` + `hicolor` +
  `pixmaps`) with memoized results and cached directory listings.
- **Bus surface** `org.dragonfruit.AppIndex1` at `/org/dragonfruit/AppIndex1`:
  `Resolve`, `ResolveWindow`, `Lookup`, `Enumerate`, `Misses`, `IconPath`,
  `Stats` (flat JSON, additive-only). `src/main.rs` serves it and has debug
  flags (`--resolve`, `--resolve-window`, `--enumerate`, `--icons`, `--icon`).
- **The compositor stub resolver is gone.** `compositor/src/identity.rs` is
  deleted; `resolve_x11_identity` publishes the raw `WM_CLASS` class, Wayland
  `app_id` is already raw, and the identity stats block is removed. ADR
  [0086](../design/adr/0086-app-index-identity-ownership.md).
- **The Dock consumes app-index.** `shell/src/appindexclient.{h,cpp}` loads the
  Dock corpus via `Enumerate`; `DesktopEntry` grew `iconPath`; `dockmodel`
  carries it; `DockGlyph.qml` renders it (`QtQuick.VectorImage` for SVG,
  `Image` for raster) and falls back to the initial tile. SVG support matters:
  the toolchain ships no svg imageformat plugin.
- **`docs/design/02-compositor.md`** "Application identity" now says the
  compositor publishes raw identity and app-index owns resolution.

Tests (repo root):

- `cargo test -p dragonfruit-app-index` — 18 unit + 5 private-bus integration
  cases pass (Wayland app_id and X11 `WM_CLASS` fixtures resolve to the
  expected desktop entry and icon path).
- `cargo test --workspace` — green; `cargo clippy --workspace --all-targets --
  -D warnings` and `cargo fmt --all -- --check` — exit 0.
- `ctest --test-dir build --output-on-failure` — 53/53; `tst_dockcore` adds
  an `iconPath` propagation case, `tst_dock.qml` a themed-icon case.

Live visual check: nested demo with `dragonfruit-app-index` running on the
host session bus and `DF_DEMO_QT_APP=/usr/bin/dolphin`; captured the nested
window (`/tmp/opencode/t100/nested5.png`, dock crop
`/tmp/opencode/t100/dock.png`). Vision: the Dock shows the real themed
Konsole terminal icon and the Firefox fox (default pins resolved through
app-index), Dolphin's folder icon, the Downloads stack, and the drawn Trash;
the unresolvable xmessage keeps the initial-tile fallback. No stray artifacts.

Gotchas for T-14.1b:

- **`Enumerate` icon resolution is hot.** The first cold enumeration of ~265
  entries took ~8s before the icon lookup cached directory listings; it is now
  ~0.2s. A later change that disables the cache or resolves per call will time
  out the shell's 2s blocking call (`AppIndexClient::kCallTimeoutMs`).
- **The shell fallback local scan still exists** (`DesktopEntryIndex::scan`)
  and is used only when the service is absent; T-14.7 deletes it. The launch
  command/`parse` code is still the launch path.
- **SVG needs `QtQuick.VectorImage`**; do not assume `Image` loads `.svg` in
  this toolchain.
- The compositor no longer records the miss set; `app-index` does. T-14.1b's
  events/launch registry/recency extend `AppIndex` and the bus surface
  additively; the subscription API is T-14.1c.
