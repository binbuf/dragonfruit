## Hand-off

**State: done.** The absent-daemon masking matrix is asserted at all three
seams; capture and the idle trace are deferred to T-07.6b as planned.

What landed:

- **`services/system-status/tests/host.rs`** —
  `the_absent_daemon_masking_matrix_hides_only_the_masked_item` masks each
  daemon in turn (kill + refresh) and then all three, asserting the neighbour
  items stay `available`, no slot ever reports `error`, and
  `join`/`set_volume`/`set_mute` answer `absent`.
  `masking_one_daemon_never_turns_a_neighbour_into_an_error` covers the
  present-but-unreadable (`Error`) negative case.
- **`shell/tests/tst_statusmodel.cpp`** —
  `theAbsentDaemonMaskingMatrixHidesOnlyTheMaskedItem` (JSON views → only the
  masked item's `visible`/`enabled` flip) and
  `anUnreachedBridgeHostLeavesEveryItemHidden` (no host → every item hidden; a
  malformed/empty payload never becomes a visible error).
- **`shell/tests/tst_menubar.qml`** —
  `test_absent_daemon_matrix_hides_and_refuses_each_item` builds the
  controller's shape for each single-mask case: the masked slot is hidden and
  refuses to open, every other slot still opens its popover.
- **`docs/design/07-system-integration.md`** — new section "The
  absent-daemon masking matrix (T-07.6a)" with the matrix table and the
  test locations. No ADR: this only proves the contract already recorded in
  ADR 0024/0025/0029.
