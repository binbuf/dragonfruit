## Reference UI/UX (macOS screenshots)

Near-verbatim style target: the standard macOS Appearance pane, in the same
style and wording as the capture set. Local images in `docs/reference/macos/`
(never shipped; see [14-risks.md](../design/14-risks.md)); distilled in
[System_Preferences.md](../reference/System_Preferences.md). The capture set
contains **no Appearance pane screenshot**, so the row list below is the
standard pane and should be confirmed against a capture when one is added.

Sections and rows (expected):

- **Appearance**: Light / Dark / Auto.
- **Accent color**: swatch row plus custom color picker.
- **Highlight color**: swatch row plus custom color picker.
- **Sidebar icon size**: Small / Medium / Large.
- **Allow wallpaper tinting in windows**: toggle.
- **Show scroll bars**: Automatically based on mouse or trackpad / When
  scrolling / Always.

Appearance maps to `appearance.colorScheme`; accent maps to
`appearance.accent` (see
[08-settingsd-live-settings.md](../design/tracks/08-settingsd-live-settings.md)).
Highlight color and the remaining rows are provider TBD (T-15.x). Reduced
motion stays the already-decided Accessibility item.

Adapt or omit (Apple-only): nothing in this list is Apple-only; the accent
swatch set is ours to choose.

## Hand-off

**Landed (T-09.2, done).**

- `apps/settings/AppearancePane.qml` — the pane body: a `SegmentedControl`
  (Light/Dark/Auto) bound to `appearance.colorScheme` and an accent swatch row
  + `Custom…` hex popup bound to `appearance.accent`, both via the `Settings`
  singleton (the two-way T-09.1b pattern).
- `apps/settings/SettingsShell.qml` — a `paneComponent(id)` registry and a
  `Loader` (`paneBody`) render the registered pane body; the placeholder shows
  only while no body is registered. Three `Binding`s mirror
  `appearance.colorScheme` / `appearance.accent` /
  `accessibility.reduceMotion` onto the app-local `Theme` (the shell's
  `ThemeBinding` is in another process).
- `design-system/Theme.qml` (generated) — the accent family is now overridable
  via `Theme.accentOverride`; `scripts/gen-tokens.py` emits the bindings.
  `compositor/src/design_tokens.rs` unchanged.
- `shell/src/themebinding.{h,cpp}` — writes `Theme.accentOverride` from
  `appearance.accent` (and reacts to the key). `shell/tests/tst_themebinding.cpp`
  gained `accentOverrideFlipsTheme`.
- Tests: `apps/settings/tests/tst_settings_appearance.{cpp,qml}` (5 cases,
  `DF_SETTINGS_FIXTURE`) assert every control applies live to the key and the
  local `Theme`.
- Docs: ADR [0037](../design/adr/0037-accent-override-and-app-local-theme-sync.md);
  track 09 "Appearance pane (T-09.2)" section; `docs/settings-keys.md` consumer
  map updated.

**Decisions / deviations.**

- **Reduced motion stays the Accessibility item** (T-15.14), as the reference
  and track say. The Appearance pane does not carry it; the key is already
  wired (shell + compositor) and the app-local `Theme` mirrors it.
- **Highlight color, Sidebar icon size, wallpaper tinting, show-scroll-bars
  are omitted** — no settings provider until T-15.x. The pane ships only its
  two working sections (no-half-panes). Add them when their keys exist; the
  catalog entry is already `shipped: true`.
- The accent override is **QML-only**; the compositor does not consume accent.
  The swatch palette lives in `AppearancePane.qml` (our choice, per the
  reference's "Adapt or omit").

**Commands (repo root; `make` sets the toolchain env).**

- `ctest --test-dir build -R tst_settings_appearance --output-on-failure` —
  5/5.
- `make qml-test` — 24/24; `make lint` green; `make visual-test` (66 gallery
