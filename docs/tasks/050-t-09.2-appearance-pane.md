## Reference UI/UX (macOS screenshots)

Near-verbatim style target: the standard macOS Appearance pane, in the same
style and wording as the capture set. Local images in `docs/reference/macos/`
(never shipped; see [14-risks.md](../design/14-risks.md)); distilled in
[System_Preferences.md](../reference/System_Preferences.md). The capture set
contains **no Appearance pane screenshot**, so the row list below is the
standard pane and should be confirmed against a capture when one is added.

Sections and rows (expected):

- **Appearance**: Light / Dark / Auto.
- **Accent color**: swatch row plus custom color picker.
- **Highlight color**: swatch row plus custom color picker.
- **Sidebar icon size**: Small / Medium / Large.
- **Allow wallpaper tinting in windows**: toggle.
- **Show scroll bars**: Automatically based on mouse or trackpad / When
  scrolling / Always.

Appearance maps to `appearance.colorScheme`; accent maps to
`appearance.accent` (see
[08-settingsd-live-settings.md](../design/tracks/08-settingsd-live-settings.md)).
Highlight color and the remaining rows are provider TBD (T-15.x). Reduced
motion stays the already-decided Accessibility item.

Adapt or omit (Apple-only): nothing in this list is Apple-only; the accent
swatch set is ours to choose.

## Live visual check (required)

Before reporting done, run the app and **look at it**:

- Launch the nested session (`make demo`), open the surface this task changed,
  and capture it (e.g. `spectacle -b -n -f -o /tmp/<task>.png`).
- Inspect the image: all UI/UX must be present and read as intended in the
  compositor window — layout, materials, text, and no stray artifacts.
- A green `make e2e` is necessary but **not sufficient**: the headless suites
  render no pixels, so they miss exactly this class of bug. If the task has no
  surface of its own, still launch the demo and confirm the desktop renders.
- Note the capture path and your verdict in the Hand-off.
