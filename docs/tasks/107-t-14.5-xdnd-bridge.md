## Goal

File drag-and-drop across the X11/Wayland boundary (the known Smithay 0.7 gap).

## Scope

- XDnD translation across Xwayland for `text/uri-list`.
- Budget for a custom bridge; document the gap if not fully closed.

## Explicitly deferred

- Non-file XDnD flavors.

## Acceptance (agent-completable)

- [ ] XDnD round-trips files in both directions, or the gap is explicitly documented at T-17.

## Test plan

- XDnD conformance with `x11rb`.

## Hand-off

**Landed.** The XDnD protocol half plus a documented gap (the task's second
acceptance branch, "or the gap is explicitly documented at T-17"):

- `compositor/src/xdnd.rs` (new): 17 atom names + `XdndAtoms`, the
  `Enter`/`Position`/`Status`/`Leave`/`Drop`/`Finished` client-message codec
  (`XdndMessage`), the `XdndTarget`/`XdndSource` translation state machines,
  and `text/uri-list` parse/format. 11 unit tests.
- `compositor/src/lib.rs` (new): library surface exposing `xdnd`; existing
  binary tests unaffected.
- `compositor/tests/xdnd_conformance.rs` (new): x11rb conformance against a
  live Xwayland server (atoms, `XdndAware`, round-trip of the four messages,
  accept/refuse). Added to `make e2e`.
- Docs: ADR 0099, an implementation note in `docs/design/02-compositor.md`,
  and a "Known compatibility gaps" note in
  `docs/design/tracks/17-premium-gate.md`.

**Deviated / not done.** The bridge's X11 connection/runtime half is not
wired: Smithay 0.7's `X11Wm` keeps its `RustConnection`/atoms private and
exposes no client-message hook, so a bridge must own a second X11 connection
plus a bridge window and call Smithay's `start_dnd` on a drop. Doing that
without testing it would have been a fake pass; the task permits documenting
the gap instead. This is recorded as a known, waived gap at T-17 and listed in
`docs/PROGRESS.md` under "## Follow-ups".

**For T-14.6.** Treat cross-boundary file DnD as a known gap, not a
regression; the zoo can still drag within one side. Note the wire-layout
gotchas (`XdndStatus` action in l[4], `XdndFinished` action in l[2]) if the
connection half lands before the zoo runs.

**Attempt 2 (gate repair, no product change).** Attempt 1 was marked failed
only because the harness `make e2e` verify timed out: a pre-existing flake in
`portal/tests/screencast.rs` wedges forever (not fails) when its four tests
run in parallel — a test thread blocks in a zbus `blocking` `call_method`
while the in-process `dbus::serve` backend starves the shared executor.
`--test-threads=1` reproduces 0/80 hangs (vs 1/30 parallel). The `e2e` recipe
now runs `cargo test -p xdg-desktop-portal-dragonfruit -- --test-threads=1`;
`make e2e` exits 0 in ~63 s. The XDnD code and docs above are unchanged.
