## Goal

Drag a window's live representation onto another Space and move it there.

## Scope

- Reuse `move_to_workspace`; the shell grid remains the accessible path.

## Explicitly deferred

- Multi-monitor drag edge cases (T-16).

## Acceptance (agent-completable)

- [ ] Pointer drag-between-Spaces works and the window is assigned correctly.

## Test plan

- Headless: drag drives the assignment; nested capture.

## Hand-off

**State: done.** Pressing on a live Mission Control representation and dragging
it onto another Space's workspace-strip card moves the window there through the
one `move_to_workspace` primitive; a press that never moves is still the T-05.2
selection.

- `compositor/src/overview/grid.rs` — `GridDrag` (window, press point, current
  point, `moved()`, `offset()`), `DRAG_THRESHOLD` (8), and the pure strip
  geometry `strip_card_rect`/`strip_space_at` (the same centered token layout
  the shell draws). 3 new unit tests. No new transform: the drag reuses
  `GridPlacement`.
- `compositor/src/state.rs` — `DfState::grid_drag`,
  `overview_begin_drag`/`overview_update_drag`/`overview_end_drag`/
  `overview_drag`/`overview_drop_space_at`. `overview_grid_frame` applies the
  drag offset so the live surface, SSD titlebar, and shadow follow the pointer
  (they share `window_render_frame`). `overview_end_drag` reuses
  `select_overview_window` for a click and `move_window_to_space` for a drop,
  leaving the overview open.
- `compositor/src/input.rs` — a left press in `InputOwner::Overview` now begins
  the drag; `PointerMotion` updates it; a left release ends it. Committed
  geometry is still never consulted in the overview.
- `compositor/src/input/synthetic.rs` — `query grid` gained the
  `grid drag <window> <x> <y> moved=<0|1> target=<index|-1>` line; new
  `query spaces` (`space <output> <index> <id> active=<0|1> windows=<n>`) so a
  headless test can prove the destination Space, not just that an assignment
  changed. Wire format and parser documented/tested.
- `compositor/tests/window_conformance.rs` — new
  `overview_drag_moves_the_live_representation_between_spaces`: settles the
  grid, presses a live target, drags to the Space-1 strip card
  (`query grid` drag reports `moved=1 target=1`), releases, then asserts the
  window left the active grid, Space 1 holds it (`query spaces`), the window's
  `decoration … space` equals Space 1's id, the overview stayed open, and all
  three live surfaces stayed mapped. **28/28** conformance tests green.
- Docs — `02-compositor.md` "Dragging a live representation between Spaces
  (T-05.3)" (T-05.2 section updated for press-begins-drag). New ADR
  `0018-overview-drag-drop-target.md` (the drop target is the strip card under
  the pointer, reproduced from the shared tokens).

Commands (repo root; direct cargo needs
`PKG_CONFIG_PATH=~/.local/df-devroot/lib64/pkgconfig` and
`RUSTFLAGS=-L ~/.local/df-devroot/lib64`):

- `cargo test -p dragonfruit-compositor --bin dragonfruit-compositor` — **238**
  unit tests green (`overview::grid` now 17).
- `cargo test -p dragonfruit-compositor --test window_conformance` — **28/28**
  green.
- `cargo clippy -p dragonfruit-compositor --all-targets -- -D warnings` clean;
  `cargo fmt -p dragonfruit-compositor -- --check` clean.

Gotchas for later tasks:

- **One drag seam**: begin/update/end live in `DfState`; the pure geometry is
  `overview::grid` (`GridDrag`, `strip_*`). Do not grow a second transform or
  hit test. Neighbour-Space reveal only widens `overview_drop_space_at`.
- The drop resolver reproduces the shell's centered strip layout from
  `component::overview`/`component::menu_bar` tokens (top = 28 + 16 = 44 at a
  settled overview); it is token-derived, not hand-copied. The test drops at
  the Space-1 card center `(640, 86)` on the 1280x720 headless output.
- In a **nested** session the shell's transparent overview surface still
  captures pointer input, so the shell title-card drag remains the user path;
  the compositor drag is the same headless/test seam as T-05.2. The nested
  capture is T-05.6.
- The drag keeps the overview open (each drop is one assignment); selecting a
  window still leaves the overview.
- `query spaces` is new read-only introspection; it reports `SpaceId.0` (the
  stable id), which is what `query decorations`' `space` field also carries.
