Gotchas for later tasks:

- **The shell interface is at the freedesktop path, not its own.** Both
  interfaces share `/org/freedesktop/Notifications`; the shell reads
  `org.dragonfruit.Notifications1` there. The service must own
  `org.freedesktop.Notifications`; if a host desktop daemon already owns it
  the service exits and the shell renders no banner.
- **Actions are recorded, not advertised or round-tripped.** `ActionInvoked`
  is declared but never emitted; `GetCapabilities` omits `actions`. T-11.1b
  wires the round-trip.
- **One banner at a time.** `NotificationModel::banner()` returns the newest;
  older active banners stay in `banners()`/history. Stacking and click
  activation are T-11.1b.
- **The banner surface is display-only**: empty input region and no keyboard,
  so clicks pass through. T-11.1b must add an input region for activation.
- **The banner is light-scheme white in the dev capture** because the shell's
  Theme follows the host `styleHints.colorScheme` when settingsd is absent.
- **`DF_NOTIFY_FIXTURE=1`** seeds one representative banner (60 s deadline)
  for the demo/capture; the real path is the default.
- **The recurrence/no service:** the dev harness does not start
  `dragonfruit-notifications`; a real session starts it in parallel
  (01-architecture.md). `make e2e` exercises the absent-service path.
- **Expiry is service-owned and event-driven**: a background thread sleeps to
  the earliest deadline and emits `NotificationClosed(1)`. The shell never
  times out a banner itself.

Next: **T-11.1b** adds actions (`ActionInvoked` round-trip), banner activation,
