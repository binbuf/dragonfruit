## Goal

One dev command closes the host session, logs into Dragonfruit as a primary
session, and — from a menu item or after a crash — restores the host desktop
exactly as it was.

## Scope

- `dragonfruit dev --real --round-trip`: write the state file (previous default
  session, autologin armed flag, timestamp), select the Dragonfruit session via
  T-12.6a, optionally arm autologin, then ask the host session manager to log
  out (never `SIGKILL` apps; unsaved-work prompts fire normally).
- Export `DRAGONFRUIT_DEV_RETURN=<previous session>` from the session
  environment (T-12.1b) and show **"Quit to <previous desktop>"** in the
  system/Control Center menu only when it is set.
- The item disarms autologin, restores the previous default session, and logs
  out.
- Crash recovery: a one-shot check on the next login (clean or post-crash)
  reads the state file, restores, and clears the armed state; a "session-ready"
  beat gates autologin commit so a crash cannot loop back in.

## Explicitly deferred

- The second-VT mode (T-12.6c).
- App continuity: only an explicit `.desktop` allowlist may be relaunched;
  unsaved document state is never restored (ADR 0053).

## Acceptance (agent-completable)

- [ ] Arm/return round-trips the saved selection; the state file is the only
      writer and is cleared on return.
- [ ] Simulated crash leaves the state file armed; the recovery path restores
      the previous session and disables autologin.
- [ ] The menu item is absent unless `DRAGONFRUIT_DEV_RETURN` is set.
- [ ] The host DM configuration is byte-identical after a clean round trip.

## Test plan

- Headless: state-file arm/restore/clear and env propagation via T-12.1b's unit
  file harness.
- Hardware (T-159…T-161 rail): one real round trip plus one kill/restore.

## Hand-off

## Live visual check (required)

Before reporting done, run the app and **look at it**:

- Launch the nested session (`make demo`) with `DRAGONFRUIT_DEV_RETURN` set,
  capture the system menu showing **"Quit to <previous desktop>"**
  (`spectacle -b -n -f -o /tmp/<task>.png`), and confirm it is absent without
  the variable.
- Inspect the image: the item is present, correctly labelled, and no stray
  artifacts.
- A green `make e2e` is necessary but **not sufficient**: the headless suites
  render no pixels, so they miss exactly this class of bug.
- Note the capture path and your verdict in the Hand-off.
