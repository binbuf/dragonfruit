## Goal

A Launchpad-style **Applications** overlay that lists every launchable app the
app-index knows about, alphabetically by default, with a search field and
category filter pills, and launches an app on activate. It is the primary "start
an app" affordance the Dock's management picker deliberately is not.

## Context (read first)

- `docs/reference/macos/AppDrawer.md` — the near-verbatim target: title
  `Applications`, a search field, a category pill row, a 7-column grid of ~64px
  rounded tiles with centered single-line labels truncated with ellipsis.
- `shell/src/appindexclient.h` — `enumerate()` returns every installed record;
  `subscribe()` registers for the coalesced `Changed` signal so an
  install/uninstall updates the open drawer.
- `shell/src/apppicker.h` / `.cpp` — the pure list model precedent:
  `buildAppPickerList` drops `noDisplay`/non-launchable records, dedupes by
  desktop id, sorts by localized name with an id tiebreak. Mirror it; do **not**
  reuse the pin semantics.
- `services/app-index/src/view.rs` — each record already carries `name`,
  `iconPath` (themed, 128px), `categories`, `exec`, `terminal`, `noDisplay`.
- `shell/src/desktopentry.h` — `DesktopEntryIndex::isLaunchable` and the launch
  path (`buildLaunchCommand` + `appLaunchEnvironment`).
- `shell/src/shellcontroller.cpp` — the Control Center / Overview / switcher
  scenes show how a shell overlay is created as a `QQuickWindow` scene and
  toggled; copy that shape.
- `shell/src/shellprotocol.cpp` (`createOverviewSurface`, `createControlCenterSurface`)
  — how an overlay layer surface is created on `DF_SHELL_LAYER_OVERLAY` with the
  right keyboard-interaction mode and committed.
- `design-system/components/` — `SearchField`, `SegmentedControl`, `ScrollView`,
  `Skeleton`, `Icon`, and (from T-19.1) `SettingsCategoryIcon`.
- `shell/overview/CMakeLists.txt` — the module pattern to copy for the new
  `Dragonfruit.AppsDrawer` QML module.

## Reference UI/UX (macOS screenshots)

- Title `Applications`, leading launcher glyph, a large search field, a trailing
  three-dot menu (ours may omit the menu or use it for view options).
- A horizontal, scrollable row of pill-shaped category segments (`Developer
  Tools`, `Productivity & Finance`, `Utilities`, …). None selected by default in
  the reference; ours defaults to an explicit `All`.
- Grid: 7 columns of ~64px rounded tiles, label centered below, one line,
  ellipsis on overflow; flat with no grouping borders; scrollable.
- Light translucent chrome over a scrim; Escape or a click outside dismisses.

## Scope

- [ ] New shell module `shell/apps-drawer/` (`URI Dragonfruit.AppsDrawer`,
      `AppsDrawer.qml`), registered in `shell/CMakeLists.txt` and linked into
      the shell.
- [ ] New overlay layer surface `createAppsDrawerSurface` in
      `shell/src/shellprotocol.{h,cpp}` — role `apps-drawer`,
      `DF_SHELL_LAYER_OVERLAY`, full-screen, `KEYBOARD_INTERACTION_ON_DEMAND`,
      following `createOverviewSurface`.
- [ ] Toggle wiring in `ShellController` (show/hide, Escape + click-outside
      dismiss, reduced-motion fade/scale variant) exposed by a global shortcut
      and a menu-bar/status affordance. (A Dock Launchpad tile is optional and
      out of scope.)
- [ ] A pure `buildAppsDrawerList(entries, category, query)` helper in
      `shell/src/` (modeled on `buildAppPickerList`): drop
      `noDisplay`/non-launchable, dedupe by desktop id, sort by localized name
      (alphabetical default) with a stable id tiebreak, map the freedesktop
      `Categories` list to the pill set, and filter by the selected category and
      the search query (name or id, case-insensitive).
- [ ] The overlay renders the title, `SearchField`, category pills
      (`SegmentedControl`, default `All`), and the tile grid (themed `iconPath`
      with a Phosphor/`Icon` fallback), with hover/focus/selected states and
      keyboard navigation (arrows move, Return launches, Escape dismisses).
- [ ] Activation launches through `buildLaunchCommand` +
      `appLaunchEnvironment`, handing the launch origin to the compositor the
      way the Dock does; a failed launch raises the shell's existing failure
      notice, never a silent no-op.
- [ ] app-index absent renders an explicit `Application index unavailable` row,
      never a blank panel; the open drawer refreshes on app-index `Changed`.

## Out of scope

- The Spotlight-equivalent search pane and app-index-backed global search.
- App folders, pages/pagination, drag-to-reorder, uninstall, app badges.
- Dock pin/unpin management (that stays the Dock's Add Application picker).
- The category **icon** treatment itself (→ T-19.1).

## Design notes

- The shell never scans `.desktop` directories itself; app-index is the only
  corpus. The new list helper is pure and headless-testable (no QML/Wayland
  types), like `apppicker`.
- `Categories` is a semicolon-separated freedesktop list; define one mapping
  from the main categories to the pill set and drop unknown/`GTK`/`Qt`
  implementation categories. Record the mapping so it is greppable.
- Grid columns are a function of available width (7 at the reference width) but
  must not overflow at narrow outputs; keep tile size fixed and let columns
  change.
- app-index `iconPath` is a themed file path; render it as an image. Do not
  regenerate identity in the shell.
