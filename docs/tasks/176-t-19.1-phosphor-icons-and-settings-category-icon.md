## Goal

Vendor the [Phosphor](https://phosphoricons.com/) icon set (MIT) into
`assets/icons/phosphor/`, expose it to QML as a stable resource path, and add a
reusable `SettingsCategoryIcon` that composes the Dragonfruit-specific
container (rounded tile, category gradient, inner highlight, drop shadow) around
a Phosphor **foreground glyph** — then use it for the Settings category icons.
At the end, category icons are a themeable container + swappable glyph, not a
baked bitmap.

## Context (read first)

- `design-system/components/Icon.qml` — the inherited glyph vocabulary. It is
  **original geometry** and stays for menu-bar/Dock marks; this task adds a
  second, image-backed path for category tiles rather than editing it.
- `design-system/CMakeLists.txt` — the `qt_add_qml_module(URI Dragonfruit …)`
  that every component is registered in, plus `df_qml_lint`; the Phosphor
  resources and the new component both plug in here.
- `design-system/gallery/GalleryContent.qml` — where new components get a
  gallery section and a snapshot golden.
- `assets/fonts/Inter/` + `NOTICE` §Bundled assets — the precedent for a
  vendored third-party asset and its license/attribution bookkeeping.
- `docs/design/14-risks.md` §Intellectual property — the original-assets rule.
  Phosphor is MIT (not Apple's output), so it is permitted, but the departure
  from "all geometry is ours" is a decision that needs an ADR.
- `apps/settings/PaneHeader.qml` and `apps/settings/SettingsShell.qml` — where
  the Settings pane/category icon is currently an `Icon { name: pane.icon }`.

## Reference UI/UX (macOS screenshots)

Category tiles read as a **rounded square** with a saturated gradient, a subtle
top inner highlight, a small drop shadow, and a near-white glyph centered on
top. The glyph and the container are visually independent: the container is the
same shape/geometry for every category, only the gradient changes. Use Phosphor
`fill` (or `duotone`) — the reference has more visual weight than a thin
outline. Local captures in `docs/reference/macos/` are reference only.

## Scope

- [ ] Vendor a **pinned** Phosphor release under `assets/icons/phosphor/`
      (the chosen weight's SVGs + the upstream license file). Record the exact
      version and weight.
- [ ] Add Phosphor to `NOTICE` (Bundled assets) and `LICENSES/`, and add an ADR
      under `docs/design/adr/` recording the third-party-icon decision and the
      "glyph is a resource, styling stays in QML" rule.
- [ ] Expose the SVGs to QML through the design system's module resources
      (`qt_add_resources` with a stable prefix, referenced as
      `qrc:/icons/phosphor/<name>.svg`). A referenced glyph that does not exist
      must fail the build, not fall back silently.
- [ ] Add `design-system/components/SettingsCategoryIcon.qml` with properties
      `source` (glyph), `gradientStart`, `gradientEnd`, `symbolColor` (default
      near-white), `size`, `radius`, and an optional `glow`. Internally it draws
      the design-system `Shadow` (token elevation) + a rounded rect with a
      `LinearGradient` + a top inner highlight, then overlays the centered
      glyph, tinted to `symbolColor`.
- [ ] Register the component in `design-system/CMakeLists.txt`
      (`qt_add_qml_module` + `df_qml_lint`) and add a gallery section + snapshot.
- [ ] Adopt it for the Settings category/pane icons (sidebar row and
      `PaneHeader` hero) behind the pane's existing `icon`/color data, with a
      category→gradient mapping in one place. Keep `Icon.qml` as the fallback.

## Out of scope

- Replacing the shell's chrome glyphs (`Icon.qml`) or app icons; those stay
  original geometry / themed app icons.
- A dark/light *swap* of the icon set (both schemes use the same glyphs with
  the container's `symbolColor`/gradient adjusted).
- The Applications drawer's tiles (→ T-19.2); desktop item icons (→ T-19.3).

## Design notes

- **Keep the glyph and the styling separate.** Never bake the gradient or the
  rounded container into an SVG; the component owns all of it.
- Put the category→(glyph, gradient) table in exactly one QML/JS place so the
  visual treatment is themeable and the glyph set is swappable.
- Tinting: confirm how Qt 6.11 applies a color to a monochrome SVG (e.g.
  `MultiEffect` colorization) and use one mechanism consistently. If the chosen
  mechanism cannot tint reliably, ship near-white `fill` SVGs instead and say
  so in the Hand-off.
- Prefer design-system tokens for radius/elevation/spacing; the gradients are
  categorical brand values and may be literal, but keep them named constants.
- The build-time glyph check is what prevents a typo from shipping as a blank
  tile.
