# T182 — T-20.4 Multi-GPU composition, software fallback, golden determinism

## Goal
The liquid-glass material is correct and safe everywhere: it composes per GPU
under `renderer_multi`, falls back to the deterministic `Minimal` approximation
on the software/headless path, and its captures/goldens are stable enough for CI.
This closes the T-20 track.

## Context (read first)
- `docs/design/adr/0182-tahoe-liquid-glass-material-pass.md` · `docs/design/tracks/20-tahoe-liquid-glass.md`.
- T179/T180/T181 — the pass, the glass fields, and the rollout.
- `compositor/src/multi_gpu.rs` — `renders_locally`; Smithay 0.7

## Scope
- [ ] Under `renderer_multi`, the scene texture is owned per GPU; when an output
      is rendered by a GPU whose texture differs, copy the needed scene texture
      (or render the scene locally for that output). No cross-GPU texture
      sampling.
- [ ] The headless/software path renders `Minimal` (the deterministic feather
      stack) with no GPU readback; headless goldens stay exact. The nested/DRM
      `Full` path is capture-verified, not golden-compared.
- [ ] Make the material's captures reproducible: a fixed-seed/static backdrop in
      the capture driver, or tolerance-based image assertions, and document the
      choice. Keep the no-screencopy gate green.
- [ ] Instrument the pass: extend the render/degrade stats with blur passes,
      downsample factor, and per-tier counts; assert no idle wakeups
      (`backdrop_skipped=0`, zero damage while idle).
- [ ] Frame-budget trace on the recommended GPU with the material `Full` and a
      few live windows; record it and confirm the degrade ladder reacts.
- [ ] Document the recommended GPU baseline (GLES 3.x / Vulkan-capable) in
      `02-compositor.md` and the packaging/requirements docs.

## Out of scope
- New visual features; this task hardens and measures what T179–T181 built.
- Hardware-specific driver matrices (the T-16 hardware rail owns those).

## Design notes
- Prefer composing the blur on the GPU that owns the output over copying scene
  textures between GPUs; a copy is the fallback for a panel straddling outputs.
- The software path must remain a *quality* fallback, not a correctness one: it
  uses the same `MaterialRole`/`BackdropSpec` inputs and the `Minimal` mapping.
- Determinism: GL blur is driver-dependent. Keep headless on `Minimal` (exact)
  and treat the GPU material captures as inspected artifacts with a tolerance,
  not byte goldens.
