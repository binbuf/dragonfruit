## Goal

Vendor the [Phosphor](https://phosphoricons.com/) icon set (MIT) into `assets/`,
expose it to QML at a stable resource path, and add one reusable `PhosphorIcon`
primitive that renders a named glyph tinted to a color at a size. This is the
foundation the three migration units (T-19.1b/c/d) consume; it renders no
Dragonfruit chrome on its own.

## Context (read first)

- `design-system/components/Icon.qml` — the inherited **original-geometry**
  glyph vocabulary. It stays; this unit adds an image-backed path beside it.
- `design-system/CMakeLists.txt` — `qt_add_qml_module(URI Dragonfruit …)` and
  `df_qml_lint`; the new resource set and component register here.
- `assets/fonts/Inter/` + `NOTICE` §Bundled assets — the precedent for a
  vendored third-party asset and its license/attribution bookkeeping.
- `docs/design/14-risks.md` §Intellectual property — the original-assets rule.
  Phosphor is MIT (not Apple artwork), so it is permitted, but the departure
  from "all geometry is ours" needs an ADR.

## Scope

- [ ] Vendor a **pinned** Phosphor release under `assets/icons/phosphor/` (the
      chosen weight's SVGs + the upstream license). Record the version/weight.
- [ ] Add Phosphor to `NOTICE` (Bundled assets) and `LICENSES/`; add an ADR
      recording the third-party-icon decision and the rule that a glyph is a
      *resource* while all styling stays in QML.
- [ ] Expose the SVGs through the design-system module resources with a stable
      prefix, referenced as `qrc:/icons/phosphor/<name>.svg`. A referenced glyph
      that does not exist must fail the build, never fall back silently.
- [ ] Add `design-system/components/PhosphorIcon.qml`: properties `name`,
      `color` (default `Theme.color.textPrimary`), `size`, and an optional
      `weight`. It resolves the name to the resource path, tints the monochrome
      glyph to `color`, and keeps the glyph's aspect. Confirm the Qt 6.11 tint
      mechanism (e.g. `MultiEffect` colorization); if tinting is unreliable,
      ship near-white fills and document the choice.
- [ ] Register it in `design-system/CMakeLists.txt` (`qt_add_qml_module` +
      `df_qml_lint`) and add a gallery section + snapshot.

## Out of scope

- Any Dragonfruit chrome that *uses* the glyphs (→ T-19.1b/c/d).
- Replacing `Icon.qml`; it remains for marks not migrated.
- A dark/light swap of the glyph files (one tinted set serves both schemes).

## Design notes

- Keep the glyph and its styling separate: never bake a color/container into an
  SVG that the component should own.
- The existence check is the guard that stops a typo shipping as a blank mark.
- Keep the primitive dumb: no category gradients, no container — those belong
  to `SettingsCategoryIcon` (T-19.1b).

## Hand-off

**Pinned version/weight.** Phosphor **2.0.8** (`v2.0.8`, commit
`d42782b2abe747d904b971ccab48b182a1455f86`), the **`regular`** and **`fill`**
weights, vendored under `assets/icons/phosphor/` with upstream names:
`<name>.svg` for regular and `<name>-fill.svg` for fill (Phosphor v2's
per-weight filename convention). 111 curated glyphs (222 files) plus the
upstream `LICENSE` and a `README.md`. MIT; `NOTICE` §Bundled assets,
`LICENSES/Phosphor.txt`, `LICENSES/README.md`, and ADR
[0163](../design/adr/0163-phosphor-icons.md) record it. The set is curated, not
all 1,248 upstream icons, so the existence gate is meaningful; add a glyph by
copying both weight files and running `scripts/gen-phosphor-glyphs.py`.

**Tint mechanism.** A `ShapePath` with a bound `fillColor`, *not*
`MultiEffect`. Qt 6.11's `MultiEffect` colorization (and an `Image` over an
SVG) tints only on the GPU and silently rendered nothing under the headless
**software** scene graph the gallery and QML tests use — the same limit
`Shadow.qml` documents. The glyph path data is generated once from the vendored
SVG into the `PhosphorGlyphs` QML singleton; the SVG remains the shipped
resource at `qrc:/icons/phosphor/<name>[-<weight>].svg`. `PhosphorIcon`
exposes `name`, `color` (default `Theme.color.textPrimary`), `size`, an optional
`weight` (default `regular`), and an optional `accessibleName`; it draws no
container.

**Deviations.** (1) Two weights are vendored rather than one so the `weight`
property is real and T-19.1c (plain marks) and T-19.1b/d (near-white container
glyphs/app icons) both have their weight. (2) The primitive's default weight is
`regular`, so the task's `qrc:/icons/phosphor/<name>.svg` is literally the
regular path; `fill` is `<name>-fill.svg`. (3) The live visual check could not
run as specified: this is a headless host with no host Wayland/`spectacle`
session, so the nested `make demo` cannot be captured. The offscreen gallery
goldens are the visual artifact and were inspected with the vision model
(`/tmp/t176a-phosphor-dark.png`, `/tmp/t176a-phosphor-light.png`); glyphs
render crisp, centered, and correctly tinted with no artifacts. `make demo
DEMO_ARGS=--headless` runs green.

**Existence guard.** `make check-phosphor` (added to `make lint`) runs
`gen-phosphor-glyphs.py --check` (registry must match the SVG directory) and
`check-phosphor-icons.py` (every literal glyph name in first-party QML must be
vendored). A typo or a non-vendored weight fails the build.

**What T-19.1b/c/d must know.** Consume `PhosphorIcon` (and, for T-19.1b, wrap
it in the gradient container); never draw or tint SVG yourself. Add both weight
files and re-run the generator for any glyph not already vendored, or
`make check-phosphor` fails. The gallery page list lives in both
`GalleryContent.qml` and `scripts/check-gallery-snapshots.py`.
