## Goal

Windows appear with a scale/fade from the Dock tile origin, coordinated with the existing launch bounce.

## Scope

- Appear scale/fade from the Dock tile geometry via an additive shell-to-compositor request, centered origin when absent.
- Coordinated with the launch bounce and xdg-activation.
- Reduced motion: a single step through the same commit path.

## Explicitly deferred

- Minimize/restore, zoom, close (T-02.2 through T-02.4).

## Acceptance (agent-completable)

- [x] Appear plays from the tile origin and degrades to a centered origin in headless.
- [x] Reduced-motion variant verified.

## Test plan

  (`new`, `centered_origin`, `progress`, `is_done`, `frame`), `AppearFrame`

  `WindowModel::{set_appear, appear, appear_frame, step_appearances,

- **`compositor/src/state.rs`** — `pending_appear_origins` (bounded,

  `Rescale`+`Relocate` and faded via the surface-tree alpha.
  `titlebar_render_elements` now passes the appear frame to
  `TitlebarElement::render_elements`, which scales/fades its solid rects.
- **`compositor/src/backend/nested.rs`, `backend/drm.rs`** — new `Appear`
  render-element variant; both render the manual element list through their
  damage tracker (behaviour for a non-appearing window is identical to the
  space path).

Deviations / notes for later tasks:

- **The Dock does not yet call `setLaunchOrigin`.** The protocol request and
  the compositor path are complete and tested; the Dock's tile rectangle is
  not threaded from QML through `ShellController::launchDockAppWithFiles`
  yet, and mapping `desktopId` → compositor `app_id` is T-23's identity
  resolver. Until then a real launch degrades to the centered origin, which
  is the designed fallback. Wire this with the T-02.2 minimize hand-off
  (which needs the same tile lookup).
- The appear is render-only: the model geometry/input region never move, so
  the full job for the scale is `window_render_elements`. T-02.2/T-02.4 and
  T-04 reuse `AppearFrame` and the origin hand-off.
- Backends no longer use `space::render_output` for windows; if layer-shell
  or `space`-owned layers are ever introduced, `window_render_elements` must
  grow that handling.
