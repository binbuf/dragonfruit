## Goal

Retune the resting Dock's proportions to the mature reference capture
`docs/reference/macos/Dock.png`: visibly wider icon gaps, softer cross-axis
padding, a rounder plate, and the running indicator tucked close beneath the
artwork. T-14.7a/T-14.7j chose values against an older reference; this unit
reconciles the tokens with the new one and records the finals. No interaction
behavior changes.

## Context (read first)

- `design-system/tokens/tokens.json` → `component.dock` (`iconSize`,
  `padding`, `paddingAlong`, `gap`, `radius`, `indicatorSize`, `indicatorGap`,
  `divider`) and `primitive.radius.xl`. `scripts/gen-tokens.py` regenerates
  `Theme.qml` / `design_tokens.rs` (never edit generated files).
- `shell/dock/Dock.qml` — `plateRect` / `barThickness` /
  `indicatorSpace` / the `_baseline` layout. `barThickness` is
  `iconSize + indicatorSpace + 2 * padding`, so the cross-axis inset and the
  indicator band are currently additive (top inset = `padding`, bottom inset =
  `padding + indicatorSpace`).
- `shell/dock/DockEntry.qml` — `indicatorSize` / `indicatorSpace` /
  `artworkX`/`artworkY`; the running dot is drawn in the reserved band.
- `docs/captures/t14-dock-spacing-{bottom,left,right}-{light,dark}.png` and
  `t14-dock-tahoe-{light,dark,reduced}.png` — the shipped look to compare.
- Reference measurements from `docs/reference/macos/Dock.png` (device px at
  2×; halve for pt). Measured 2026-09-27 by pixel analysis, not the vision
  pass:

  | Property | Reference (pt) | Shipped token |
  |---|---|---|
  | Icon tile (visible) | ~49 | `iconSize` 48 |
  | Plate height | ~79.5 | 75 (`barThickness`) |
  | Plate corner radius | ~28–32 | `radius.xl` = 20 |
  | Artwork ↔ plate edge (cross-axis) | ~15.5 | `padding` 10 |
  | Plate end ↔ artwork (along-axis) | ~15.5–17 | `paddingAlong` 14 |
  | Icon tile-edge gap (along-axis) | ~15 | `gap` 8 |
  | Running dot diameter | ~4 | `indicatorSize` 4 |
  | Dot below artwork | ~8 | `indicatorGap` 3 |

## Current behavior (shipped after T-14.7j)

- `padding: 10`, `paddingAlong: 14`, `gap: 8`, `radius: primitive.radius.xl`
  (20), `indicatorSize: 4`, `indicatorGap: 3`; plate ~75 px tall.
- The resting Dock therefore reads tighter and squarer than the reference:
  gaps ~half the reference, cross-axis inset ~2/3, plate corner radius ~0.27
  of height versus ~0.35–0.40.

## Design notes

- All values stay in tokens; no literals in `shell/dock/*.qml`.
- The plate remains cosmetic (ADR 0089): the reserved zone follows the shell's
  exclusive zone, so the window layout is unaffected.
- The reference tiles fill ~49 pt with the artwork flush to the tile; measure
  whether our themed icons carry their own transparent margin before choosing
  the final `gap` (the token is the tile-to-tile pitch minus `iconSize`, not
  the visible-artwork gap).
- Keep the resting Dock free of labels/badges: the reference shows none. This
  unit changes spacing only.

## Hand-off

**Final token values** (`component.dock`): `padding` 15, `paddingAlong` 16,
`gap` 14, `radius` 28 (a literal replacing the old `primitive.radius.xl` ref of
20), `indicatorGap` 8; `iconSize` 48 and `indicatorSize` 4 unchanged. Against
the reference table: plate 78 px vs ~79.5, cross-axis inset 15 vs ~15.5, gap 14
vs ~15, dot 8 below the artwork vs ~8, radius 28 vs 28–32 — all within a pixel
or two. `radius` stayed a single static token (not a `ratio × barThickness`
value) because the same value drives the compositor's Dock backdrop
(`component::dock::RADIUS`, ADR 0102) and the gallery; a size-tracking radius
would need the compositor to know the panel thickness (deferred, T-16.1a).

**How the indicator band was reconciled.** `barThickness` is now
`iconSize + 2 * padding`, so `indicatorSpace` (dot 4 + gap 8 = 12) lives inside
the 15 px anchored-edge padding rather than in an added band. The entry's cross
extent is still `iconSize + indicatorSpace`, but `Dock.qml`'s `layout` anchors
the *artwork* on the anchored-edge side (bottom: `plate.bottom - padding -
size`; left: `plate.x + padding - indicatorSpace`; right: `plate.x + padding +
iconSize - size`). At rest the artwork keeps `padding` from both plate edges and
the dot sits 8 px below it; under magnification the artwork grows toward the
interior while the dot stays put. `indicatorSpace ≤ padding` holds at
`iconSizeMin`…`iconSizeMax`, so nothing clips.

**Material tokens: no change.** `plate.*` opacities and the `dock*` colors are
untouched; only geometry tokens moved. `component.dock.radius` is a geometry
token shared with the backdrop.

**What T-14.7v must know.** `gap` is now 14 (tile-to-tile pitch minus
`iconSize`), and `shellcontroller::computeDockOverflow` reads the QML `gap`
property at runtime, so the overflow budget shifted. The region divider(s) and
the extra gap around them must subtract from this wider baseline and keep the
`plateRect`/`reservedThickness` math (plate = `iconSize + 2 * padding`) intact.
The divider already draws in the plate interior (`barThickness - 2 * padding`).

**Live visual check.** Ran `make dock-spacing-capture` and
`make dock-tahoe-capture` on the host Wayland session (nested 1920x1200). Fresh
crops: `docs/captures/t14-dock-spacing-{bottom,left,right}-{light,dark}.png`
and `docs/captures/t14-dock-tahoe-{light,dark,reduced}.png`. Pixel analysis of
`t14-dock-spacing-bottom-light.png`: plate 78 px tall, corner inset 8 px at 8 px
below the top edge (r≈28), artwork top inset 15 px, 4 px dot with an 8 px gap
under the artwork and a 3 px margin to the plate edge; no clipping, no overlap.
Side-by-side inspection (vision pass) of the bottom and left crops against
`docs/reference/macos/Dock.png` confirms wider gaps, softer padding, a rounder
plate, and the dot tucked under the artwork. `make e2e` green + 53/53 ctest.

Tests: `ctest --test-dir build --output-on-failure` 53/53 (`tst_dock` 240,
`tst_dockcore` 112); `make e2e`; `make clippy`; `make fmt-check`;
`./scripts/gen-tokens.py --check`; `./scripts/check-design-tokens.sh`;
`./scripts/check-no-capture-grab.sh`; `./scripts/check-gallery-snapshots.py
