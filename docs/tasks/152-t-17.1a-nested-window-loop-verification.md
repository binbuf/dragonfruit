## Goal

## Scope

- Qt (SSD), X11, and CSD apps behave.

and `Desktop1.md`.

## Hand-off

**State: done.** The nested window loop passes with a committed capture.

Changes:

- `scripts/capture-t17-window-loop.sh` + `scripts/t17-window-loop-driver.py`
  (new) — the scripted nested loop capture. Launches `make demo` with the
  synthetic-input harness, starts a real third-party Qt SSD client (`kcalc`)
  against the private socket, and drives launch/appear → focus → move (exact
  titlebar drag) → zoom → minimize → restore → close on the Qt SSD window,
  plus the CSD-unaffected and X11 SSD checks. `make t17-window-loop-capture`.
- `docs/captures/t17-window-loop.{png,mp4,txt}` + the step stills
  (`-focused`, `-move`, `-zoom`, `-minimized`, `-restored`, `-closed`, `-csd`,
  `-x11`) — the committed capture and the machine transcript.
- `docs/captures/t17-window-loop.md` (new) — the reviewed loop/app-tier
  matrix, the live visual verdict, and the deviations.
- `docs/design/adr/0159-t17-nested-window-loop-capture.md` (new) — the harness
  and its evidence boundary.
- `docs/captures/README.md`, `docs/design/11-session-and-dev-workflow.md`,
  `Makefile` — the new capture and its reproduction command.

Deviations:

- Restore in the **agent capture** uses the compositor `restore <id>`
  primitive (the same lifecycle primitive a Dock tile invokes), not a
  synthesized Dock-tile click: `kcalc` is an unpinned running app, so
  minimizing makes its tile appear and the pinned tiles re-center, and a
  Dock-band pixel diff can point at a pinned app (observed: it launched an
  extra Files window). The Dock-tile click is covered by the headless T-01/T-02
  geometry suites and the human walkthrough.
- No new headless test: the loop's behaviours are already pinned by
  `window_conformance` (`traffic_lights_drive_zoom_minimize_and_close`,
  `titlebar_drag_and_double_click_move_and_zoom`,
  `window_menu_runs_zoom_minimize_close_and_move_to_space`,
  `ssd_toplevel_carries_a_titlebar_and_csd_does_not`,
  `decoration_tier_matrix_default_explicit_ssd_and_csd_side_by_side`),
  `xwayland_conformance` (`x11_traffic_lights_drive_zoom_minimize_and_close`),
  and `milestone_e2e`, all in `make e2e`.

Checks:

- `cargo test -p dragonfruit-compositor --test window_conformance --test
  xwayland_conformance --test milestone_e2e` — 37 + 9 + 1 passed.
- `make e2e` — exit 0; all 129 `test result: ok`.
- `bash scripts/capture-t17-window-loop.sh` — exit 0 (loop complete; close on

- Live visual check: `docs/captures/t17-window-loop.png` and the step stills,
  run through the vision model; menu bar and Dock present in every step, the
  Qt SSD client shows compositor traffic lights, and no blank/black/torn or

## Live visual check (required)

Before reporting done, run the app and **look at it**:

- Launch the nested session (`make demo`), open the surface this task changed,
  and capture it (e.g. `spectacle -b -n -f -o /tmp/<task>.png`).
- Inspect the image: all UI/UX must be present and read as intended in the
  compositor window — layout, materials, text, and no stray artifacts.
- A green `make e2e` is necessary but **not sufficient**: the headless suites
  render no pixels, so they miss exactly this class of bug. If the task has no
  surface of its own, still launch the demo and confirm the desktop renders.
- Note the capture path and your verdict in the Hand-off.
