**Apple-only (adapt or omit):** the `Learn more...` link in the header

## Hand-off

**Landed.** The Settings Notifications and Focus panes and the Control Center
Focus tile ship as one functional unit over the T-15.7a notifications adapter
(ADR 0131).

- The bridge host gained `services/system-status/src/notifications.rs`
  (`NotificationsHost` + `notifications_view`) and the
  `org.dragonfruit.SystemStatus1.Notifications` session-bus interface
  (`State`/`Refresh`/`SetFocusMode`/`SetFocusAllowList`); `main.rs` serves it
  and has `--print-notifications`.
- Four global presentation preferences are settingsd keys, schema revision 14
  (`notifications.showPreviews` text `always`/`when-unlocked`/`never` +
  `notifications.showWhenSleeping`/`WhenLocked`/`WhenMirroring` bools), with a
  new `notifications` key group. `docs/settings-keys.md` and
  `libs/settings-client/settingsclient.cpp` mirror them.
- `apps/settings/NotificationsPane.qml` (Notification Center group + read-only
  Application Notifications inventory) and `apps/settings/FocusPane.qml`
  (Off/Focus/DND selector + per-app allow list) bind the adapter through
  `NotificationsClient` / the `Settings` singleton; both panes are advertised
  (`SettingsPanes.shipped`) with real bodies. `Icon.qml` gained a `bell` glyph.
- The tile is the existing T-11.3b Focus tile: it reflects the same service
  policy the panes write, so no second tile or shell change was needed.

**Deviations / decisions.** The four presentation prefs are **stored policy**:
they apply to settingsd live and the pane reflects them, but the notification
service does not yet consult them to gate a banner — enforcement is a follow-up
(recorded in `docs/PROGRESS.md` under `## Follow-ups`). The per-app
"Application Notifications" rows are a read-only inventory (status + count, no
disclosure chevron): the macOS per-app detail sheet has no Linux provider, and
per-app policy is the Focus allow list. The `Learn more...` link, Apple-account
rows, and `?` help are omitted per ADR 0122/0118.

**Verification.** `cargo test -p dragonfruit-system-status` (39 lib + 4 test
binaries), `cargo test -p dragonfruit-settingsd`,
`ctest --test-dir build --output-on-failure -j4` (61/61), and `make e2e`
(EXIT 0) are green; `cargo fmt --all -- --check`, clippy
(`system-status`/`notify-adapter`/`settingsd`, `-D warnings`), the design-token
checks, and `./scripts/check-gallery-snapshots.py` (78) are clean.

**Live visual check.** `bash scripts/capture-t15-notifications-pane.sh` produced
`docs/captures/t15-7b-notifications-pane.png` (2088x1410),
`docs/captures/t15-7b-focus-pane.png` (2088x1410), and
`docs/captures/t15-7b-control-center.png` (360x1040). Vision confirmed the
Notifications pane's header, `Notification Center` (Show previews `When
Unlocked`, sleeping off, locked on, mirroring off) and the Application
Notifications rows (chat/Mail/Pager with Default/Default/Allowed); the Focus
pane's `Off`/`Focus`/`Do Not Disturb` selector (Focus selected) and Allowed
Apps rows (Pager on); and the Control Center panel with the Focus tile. The
first capture caught a genuine bug — the dynamic rows rendered at width 0
because the delegate used the non-visual Repeater's width; the fix and the new
`itemAt(0).width > 0` assertions are in `tst_settings_notifications.qml`.

**Next task.** T-15.8a (lock-screen policy adapter) is independent. The
settingsd/keys wiring, the host interface pattern, and the pane test layout are
reusable for the remaining T-15 panes.
