## Goal

Folder entries read like macOS: a clean folder silhouette with no cramped text
baked into the artwork, a click that opens the folder's contents, and an
obvious way to open the folder itself in Files. This fixes the current
Downloads stack label and the "folders don't launch" report.

## Context (read first)

- `shell/dock/DockGlyph.qml` — the `stack` block (`~103-141`): a folder drawn
  with a tab + body and a `Text` label **inside** the glyph (`y = 0.66 * s`,
  `font.pixelSize = 0.16 * s`, `elide` at `0.8 * s`). This is the ugly label.
- `shell/dock/DockStackPopover.qml` — the popover: header row (opens the
  folder), separator, up to `maxItems` rows, an "N more…" row, an "Empty"
  row; Escape closes.
- `shell/dock/Dock.qml` — `stackEntry` (`~317-323`), `activateEntry`
  (stack → `openStack()`, ~504-523), `openStack`/`stackAnchor`
  (`~616-626`), `stackMenuModel` (`~1226-1235`), spring-load
  (`~973-986`), external drop on the stack.
- `shell/src/downloadsmonitor.{h,cpp}` and `shell/src/shellcontroller.cpp`
  `onDownloadsChanged`/`onDockDownloadsFolderRequested`/`downloadsViewed`.
- `services/files-core` — the read-only listing the general folder stack will
  use (ADR 0092); the Downloads stack today is fed by `DownloadsMonitor`.
- Design-system components: `Popover`, `ContextMenu`, `Icon`.
- `tst_dock.qml` Downloads cases (`~1772-1856`).

## Current behavior (investigated, T101 era)

- The folder's name is drawn inside the artwork as very small text near the
  bottom edge and elides to a narrow width — it reads as broken/cheap next to
  the app squircles.
- Clicking the stack opens the popover, but the popover's folder-open action is
  a header tap that is easy to miss; "folders don't launch" is the user's read
  of the interaction.
- The popover caps at 8 rows; the empty and overflow rows exist but are plain.

## Scope

- [ ] Redraw the folder glyph from our own geometry: a macOS-like folder (back
      tab + front face, subtle vertical gradient, inner rim, rounded corners)
      sized like the app tiles; **no text inside the artwork**. Use tokens for
      every value; add the folder fill/rim tokens if needed.
- [ ] Click semantics (macOS-like, per ADR 0092):
      - single click opens the stack popover;
      - double-click opens the folder in Files;
      - the popover header and the context menu both keep an explicit
        **Open in Files** action (label unchanged), reachable by keyboard.
- [ ] Popover presentation: a clean header with the folder icon + elided name,
      a separator, scrollable rows with item icons/names, the overflow summary,
      and an "Empty" state; ensure the popover fits the overlay surface through
      the existing headroom path and does not clip.
- [ ] Verify the row click opens the item (file → default app, folder → Files),
      and that the new-items badge clears when opened.
- [ ] Verify the drag paths: spring-load opens the stack, files dropped on it
      move into the folder, and the failure path raises a notice (per
      T-14.7f); a folder dropped on it moves the folder (generalized in
      T-14.7k).
- [ ] Tests: `tst_dock.qml` for single/double click, the open-in-Files action,
      the empty/overflow rows, and no-text-in-artwork (the glyph has no child
      `Text`); `tst_dockcore` for any new folder-name/render helper.
- [ ] Capture `docs/captures/t14-dock-folder-stack.png` (resting, open,
      empty, long-list) and the `PROGRESS.md` note.

## Design notes

- The folder name belongs to the hover label and the popover, not the artwork;
  this is the aesthetic fix.
- Keep the Downloads stack working as a special case of the general folder
  stack so T-14.7k can unify rather than duplicate.
- The popover is the Dock overlay surface; reuse the `DockStackPopover` shape
  and its open/close motion tokens (reduced-motion aware).
- No hardcoded colors/radii/durations in QML.
