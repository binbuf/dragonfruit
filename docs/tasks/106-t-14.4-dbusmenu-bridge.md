## Goal

Apps exporting DBusMenu get a working menu through the bridge.

## Scope

- DBusMenu bridge into the menu-broker model.

## Explicitly deferred

- Legacy menu protocols beyond DBusMenu.

## Acceptance (agent-completable)

- [ ] A DBusMenu app's menu works, including enable/disable state.

## Test plan

- Integration with a mock DBusMenu app.

## Hand-off

- **Landed.** The DBusMenu/AppMenu bridge: `dragonfruit-app-index` serves
  `com.canonical.AppMenu.Registrar`, projects a registered window's
  `com.canonical.dbusmenu` `GetLayout` (reusing `tray::parse_layout`) into the
  menu-broker's `menus` shape, and pushes it with the new
  `org.dragonfruit.MenuBroker1.PublishDbusMenu`, which stores it at
  `Tier::DbusMenu`. A DBusMenu app's menu resolves with live enabled/disabled
  state and its `shortcut` rows become focus-scoped accelerators
  (`action: "dbusmenu:<id>"`). Contract in ADR
  [0098](../design/adr/0098-dbusmenu-bridge-in-app-index.md); design doc
  [06-global-menu.md](../design/06-global-menu.md) updated.
- **Real paths.** `services/app-index/src/menubridge.rs` (new pure bridge),
  `services/app-index/src/dbus.rs` (`AppMenuRegistrar` + new `AppIndex1`
  `AppMenuWindows`/`WindowMenu`/`WindowMenuEvent` + broker push/withdraw),
  `services/app-index/src/main.rs` (`--mock-menu`), `services/menu-broker/
  src/model.rs` (tiered publish) and `.../dbus.rs` (`PublishDbusMenu`).
- **Deviation.** The task's Area is `services/app-index` but populating
  `Tier::DbusMenu` required one additive method on the broker; the push (rather
  than a broker→app-index pull) keeps app-index the single compatibility host
  and the broker decoupled. The additive `RegisterWindowForApp(windowId, appId,
  path)` exists because the standard registrar body has no app id; the shell
  still has to map focus to the same key.
- **Commands.** `cargo test -p dragonfruit-app-index` (48+14),
  `cargo test -p dragonfruit-menu-broker` (26+6), `cargo test --workspace`,
  `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo fmt --all -- --check`, `ctest --test-dir build --output-on-failure`
  (53/53), `make e2e` (exit 0). Live proof on a private bus: broker `Resolve
  org.example.MockMenu` → `tier: dbusmenu`, File(`New` enabled/`Quit`
  disabled)/Edit, accelerator `dbusmenu:1 = Control+N`. Visual: `make demo`
  captured `/tmp/opencode/t106-desktop.png`; desktop renders normally (the
  bridge has no shell surface yet).
- **Not done (deferred, not required here).** The shell does not consume the
  bridge: mapping focus to a registration, rendering the projected menus, and
  routing `dbusmenu:<id>` back through `WindowMenuEvent` remain (T-14.6/T-14.7).
  Live re-projection on DBusMenu `about-to-show`/state-change is also deferred.
- T-14.5 adds XDnD.
