Decisions / gotchas for T-16.8b and later:

- **The compositor anchor is in the matrix as an outcome, not a recovery.** Its
  death is asserted to end the session and stop everything else; the
  compositor-death *behavior/restart-policy docs* remain T-16.8b.
- **Apps are not session services.** The shipped plan has no app entry; an app
  is a client the shell/compositor launches, so its kill is a plain `Never`
  exit in the session test and a real client-disconnect in the compositor test.
  Do not add apps to `SessionPlan`.
- **Adding a restartable session service now fails
  `the_restartable_set_is_exactly_the_shipped_services`** until the matrix
  covers it. Keep the session test derived from `default_session()`.
- **The real-binary `kill -9` drill is manual/VM** (no VM in CI); T-17.5a
  re-verifies a subset. Do not claim the live half was automated.

## Live visual check (required)

Before reporting done, run the app and **look at it**:

- Launch the nested session (`make demo`), open the surface this task changed,
  and capture it (e.g. `spectacle -b -n -f -o /tmp/<task>.png`).
- Inspect the image: all UI/UX must be present and read as intended in the
  compositor window — layout, materials, text, and no stray artifacts.
- A green `make e2e` is necessary but **not sufficient**: the headless suites
  render no pixels, so they miss exactly this class of bug. If the task has no
  surface of its own, still launch the demo and confirm the desktop renders.
- Note the capture path and your verdict in the Hand-off.
