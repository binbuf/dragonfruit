# T179 — T-20.1 Offscreen scene texture + GPU backdrop blur pass

## Goal
The compositor renders the scene into an offscreen GPU texture once per frame and
draws a real, sampled, token-driven blur under each chrome panel, so the menu bar
and the Applications drawer read as frosted glass over live content instead of a
flat feather approximation. This is the first slice of the T-20 material track.

## Scope
- [ ] New `compositor/src/window/blur.rs`: the compiled custom texture shader
      (downsample + Kawase or separable Gaussian), a `BlurSpec`, and a
      `BackdropBlur` value/element type. Keep the spec/geometry pure so it is
      unit-testable headless.
- [ ] `nested.rs` and `drm.rs`: render the scene elements (wallpaper, desktop,
      windows, shadows) into an output-sized offscreen `GlesTexture` once per
      frame, then compose the output from the scene texture + per-panel blurred
      elements + chrome Wayland surfaces.
- [ ] `render::chrome_backdrop_render_elements` resolves each `MaterialRole` to a
      blur spec from the generated material tokens and emits the sampled blur;
      `DegradeTier::Minimal` still emits the existing feather stack (no blur).
- [ ] Preserve the `BackdropPass` contract: one application per `(frame,
      output)`, `backdrop_passes`/`backdrop_skipped` counters, and zero idle
      wakeups (no pass when no chrome is mapped).
- [ ] Menu bar (persistent `Chrome`) and the Applications drawer get the sampled
      blur; the drawer declares its card with a new
      `df_layer_surface.set_panel_rect` call (`ShellProtocol::setAppsDrawerPanelRect`,
      mirroring `setDockPanelRect`).
- [ ] Blur radius comes from the existing `material.{chrome,popup,dock}Blur`
      tokens; no new literal.

## Design notes
- The blur samples the **live** scene texture inside the render pass — never a
  screenshot or screencopy (the no-screencopy gate must stay green).
- Composite the blurred panel with `TextureRenderElement` (or a small custom
  element) and clip it with the shared `CornerMask`, so the rounded edge matches
  the titlebar/shadow/backdrop geometry.
- Downsample the scene region per panel (e.g. half res, token-driven) and
  upsample on compose; map the token blur radius to the Kawase iteration count.
- The scene texture keeps client alpha; the chrome surface's own alpha composites
  over the blurred panel (FR-3 of the track).
- Keep the headless/software path on the deterministic `Minimal` path (no GPU
  readback) so headless tests stay reproducible.

## Hand-off

**What landed.** The nested proof of the two-pass GPU material:

- `compositor/src/window/blur.rs` (new): `BLUR_SHADER` (4-tap Kawase custom
  texture program), pure `BlurSpec` (token radius → bounded iteration count +
  downsample factor), the `BlurRenderer` seam, and `BackdropBlurElement`, which
  draws the downsampled scene region back over a panel clipped to the shared
  `CornerMask` spans.
- `compositor/src/backend/nested.rs`: renders the scene (wallpaper, desktop,
  windows, shadows, titlebars) into an output-sized offscreen `GlesTexture` once
  per frame, Kawase-downsamples each panel's region, and composes `chrome +
  blur + scene texture`. `NestedData` compiles the program once; if the driver
  refuses it the chain falls back to the built-in bilinear downsample. The
  single-pass feather path still runs when there is no blur (Minimal, no mapped
  chrome, pass already applied).
- `compositor/src/render.rs`: `BlurPanel` + `chrome_blur_panels`, which resolves
  each `MaterialRole` to a `BlurSpec` and takes the `material_pass` once per
  output (the one-pass/no-double-blur guard).
- `compositor/src/window/backdrop.rs`: `MaterialRole::Drawer` (namespace
  `apps-drawer`, popup blur tokens, `primitive.radius.XL`) and
  `MaterialRole::blur_spec`; `window/degrade.rs`: `DegradeTier::blur`.
- The Applications drawer declares its card via the new
  `ShellProtocol::setAppsDrawerPanelRect` (mirrors `setDockPanelRect`);
  `AppsDrawer.qml` exposes `panelRect()` and `shellcontroller.cpp` sends it
  before the buffer commit.
- `shell/menubar/MenuBar.qml`: the bar fill uses `Theme.material.chromeOpacity`
  so the material is visible (it was opaque, hiding every compositor backdrop);
  children stay opaque.

**Deviations.**
- DRM (`backend/drm.rs`) keeps the deterministic feather backdrop: that rail is
  `UdevRenderer`/`DrmCompositor`, not `GlowRenderer`, so the custom shader and
  `GlesTexture` path are not available there. Recorded as a T-20.4 follow-up.
- The blur chain is a halving Kawase/bilinear sequence, not a full Gaussian;
  the token radius only selects the (bounded) iteration count. Fine for the
  first slice; T-20.2/T-20.4 can refine.
- Blurred textures are allocated per panel per frame (no cache yet); a
  frame-budget follow-up.
- Refraction/specular/adaptive tint (T-20.2), the Dock/menus/OSD rollout
  (T-20.3), and multi-GPU/headless determinism (T-20.4) are untouched, per the
  task's out-of-scope.
