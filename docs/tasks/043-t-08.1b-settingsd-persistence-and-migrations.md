## Goal

Persist settings under XDG with a documented format, atomic writes, and startup migrations.

## Scope

- Persistence under `$XDG_CONFIG_HOME/dragonfruit/`: documented format, atomic writes, startup migrations.

## Explicitly deferred

- Consumer migration (T-08.2a through T-08.2c).

## Acceptance (agent-completable)

- [x] Round-trip persistence; a crash mid-write leaves the prior file intact; a migration fixture upgrades.

## Test plan

- Headless: atomic-write and migration unit tests.

## Hand-off

**Landed.** `settingsd` now owns `$XDG_CONFIG_HOME/dragonfruit/settings.json`.

- **`services/settingsd/src/persist.rs`** (new) — the documented
  `{"schema":N,"keys":{…}}` format (the shell's existing shape, adopted without
  conversion), atomic `save` (staged sibling + `sync_all` + `rename`, with a
  best-effort directory fsync), `load` with lossy-tolerant value fallback and
  unknown-entry preservation, `default_path()`, and the revision-0 → 1 startup
  migration (a file with no `schema` field; its `since`-driven default fill is
  the extension point for later revisions).
- **`dbus.rs`** — `Settings1` gained an optional `persistence`:
  `with_persistence(settings, persistence)`, `persistence()`; a real `Set`
  saves the store **before** emitting `Changed`. `dbus::run(settings,
  Option<Persistence>)`. The old `new`/`from_shared` remain in-memory.
- **`main.rs`** — resolves the path, loads, writes back a migrated file, runs
  on defaults when the file is unreadable/malformed, and reports. New
  `--config-path` debug flag.
- **`Cargo.toml`** — runtime dep `serde_json = "=1.0.151"`.
- Tests: 26 lib (8 new persist) + 4 session-bus (1 new: a `Set` persists and a
  restart reloads it). `make e2e` / `make lint` re-run below.
- ADR [0031](../design/adr/0031-settingsd-persistence-format-and-atomic-writes.md);
  track doc gained a persistence/atomic-writes/migrations section.

**Deviations.** None from scope. The `Set` save failure is logged, not fatal:
the in-memory value stays authoritative (the daemon never dies on disk errors).
The revision-0 migration is the additive-key mechanism the design describes;
v1 is the first revision, so the fixture is an unversioned file.

**Next:** T-08.2a deletes the shell's `DockSettings`/`DockPins` and its
`QFileSystemWatcher` when it binds the daemon. Until then the shell still
writes the same file; settingsd preserves unknown root/key entries so neither
clobbers the other, but do not run both as durable owners longer than the
transition.
