## Hand-off

T-16.2 landed the two hotplug correctness gaps that the nested/headless gates
can prove, plus their automated coverage. Chrome re-anchoring was already
covered by T-16.1a.

What landed:

- `compositor/src/workspace/mod.rs` — `add_output` now mirrors the existing
  displays' Space *shape* (list length + `fullscreen_for`) and adopts their
  active index instead of pinning a fresh list to index 0. Without this a
  switch after a hotplug advanced displays out of lockstep permanently.
- `compositor/src/state.rs` — `on_output_removed` calls the new
  `relocate_windows_off_output` before the output leaves the `Space`: windows
  mapped to (or geometrically on) the dead display are re-homed into the
  remaining primary's usable area — floating cascades, zoomed re-fits through
  the decoration insets, fullscreen fills the primary. The window's Space
  assignment migration is unchanged.
- `compositor/src/window/state.rs` — new `WindowStateMachine::relocate`, which
  moves the current state's geometry (a minimized window updates the geometry
  of the state it will restore to) so no state is left on the dead display.
- `compositor/tests/shell_protocol_conformance.rs` — new
  `workspace_switch_stays_lockstep_after_hotplug` (attach on Space 2, then
  Ctrl+Left must activate index 1 on *both* displays) and
  `hotplug_under_load_keeps_every_window_on_a_live_display` (two add/remove
  cycles with windows mapped on the removed display; every window stays
  tracked and inside the primary). Both were confirmed to fail with the fix
  disabled.
- Unit tests in `workspace/mod.rs`
  (`hotplugged_output_joins_lockstep_and_mirrors_a_fullscreen_space`) and
  `window/state.rs` (`relocate_rehomes_every_visible_state_and_the_restore_geometry`).
- `docs/design/02-compositor.md`, `docs/design/03-workspaces.md` updated;
  `docs/design/adr/0151-hotplug-lockstep-and-window-rehoming.md` added.

Decisions / gotchas for T-16.3a and later:

- **Hotplug joins lockstep.** `add_output` aligns to the first output's active
  index and mirrors fullscreen Spaces. `switch_all`/`activate_all` remain the
  only lockstep transition entry points; do not add a per-output activate path.
- **Relocation is geometry-only.** It does not touch Space assignment or the
  scene's stacking; `apply_workspace_layout` (via `after_workspace_change`)
  remaps at the new geometry. Zoomed re-fit uses `insets_for`, so keep that
  path in sync if insets change in T-16.3.
- **The nested backend has no output hotplug.** `DRAGONFRUIT_SYNTHETIC_OUTPUT`
  is installed by the **headless** backend only; hotplug visuals need the VM /
  DRM path. T-16.3's scaling matrix should reuse the same synthetic-output
  harness.
- **Remaining human step:** the real-hardware hotplug matrix (cable pull/push
  while dragging) is batched at the T-16 track sign-off (SLICING-REVIEW).
