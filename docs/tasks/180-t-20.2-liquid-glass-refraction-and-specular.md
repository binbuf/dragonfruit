# T180 — T-20.2 Tahoe liquid-glass: refraction, specular rim, adaptive tint

## Goal
The blurred chrome panels gain the parts of macOS Tahoe's Liquid Glass that a
plain Gaussian blur lacks: an SDF edge lens that refracts the backdrop near the
rim, a bright specular inner rim, and an adaptive tint sampled from the backdrop
luminance. All parameters are semantic material tokens, per scheme.

## Design notes
- The lens is an SDF effect on the panel's rounded rect, not a normal map asset
  (original assets only). Parameterise it so a future curved-edge look can reuse
  it.
- The adaptive tint reads the blurred backdrop's mean luminance and blends toward
  the scheme's surface/chrome tone; it must stay legible in light and dark and
  never invert label contrast.
- Reduced motion does not disable the material (it is not motion); the tier, not
  reduced-motion, owns the fallback.
- Headless unit tests assert the spec mapping and the tier behaviour; the pixel
  effect is verified by capture.

## Hand-off

**State: done.** The Tahoe liquid-glass signature landed on top of T-20.1's
GPU blur without re-architecting the pass: a second custom texture program
(`GLASS_SHADER`) composes each panel's blurred texture with an SDF edge lens, a
specular inner rim, and an adaptive tint, all token-driven per role and scheme.
`DegradeTier` owns the fallback. Nested light/dark/`Reduced` captures are
committed.

### Changes

- **Tokens** (`design-system/tokens/tokens.json`, regenerated
  `design-system/Theme.qml` + `compositor/src/design_tokens.rs`): twelve new
  `semantic.{light,dark}.material` tokens — `chrome/popup/dock` ×
  `Refraction`, `Specular`, `SpecularWidth`, `Tint`. Plus one existing
  component token retuned: `controls.appsDrawer.panelOpacity` 0.90 → 0.5 (the
  Dock's `dockOpacity` glass level) so the compositor material reads through
  the card.
- `compositor/src/window/blur.rs`: `GLASS_SHADER` (custom texture program with
  the `//_DEFINES_` marker, `tex`/`alpha`/`v_coords` contract, nine glass
  uniforms), `glass_uniform_names()`, `GlassSpec` (token → physical-uniform
  packing) with `tone_to_rgb`, and `BackdropBlurElement::with_glass`; the
  `BlurRenderer::draw_blur_span` seam now takes the program + uniforms. The
  lens falloff width and the tint adaptation scale are derived mapping
  constants (`LENS_BAND_FACTOR`, `TINT_ADAPT_SCALE`) passed as uniforms, so
  the shader holds no literal token value.
- `compositor/src/window/backdrop.rs`: `MaterialRole::glass_spec(scheme)`.
- `compositor/src/window/degrade.rs`: `DegradeTier::glass` — `Full` unchanged,
  `Reduced` zeroes refraction (keeps specular + tint), `Minimal` returns `None`.
- `compositor/src/render.rs`: `BlurPanel` carries the glass spec;
  `chrome_blur_panels` resolves it.
- `compositor/src/backend/nested.rs`: compiles `GLASS_SHADER` once per renderer
  (non-fatal fallback to the plain blurred compose) and passes it through
  `build_blur_elements`.
- `compositor/src/input/synthetic.rs`: `query material` now reports
  `tier=` and one `material glass role=...` line per role after the active
  tier (headless evidence for the mapping/fallback).
- `shell/apps-drawer/AppsDrawer.qml`: the card-fill comment now states the
  compositor material is the source and the fill its complement.
- `scripts/capture-t20-liquid-glass.sh` + `scripts/t20-liquid-glass-driver.py`
  (new) and `docs/captures/t20-liquid-glass-{menubar-{light,dark},drawer-{light,dark,reduced}}.png`
  (new); `docs/captures/README.md`, `docs/design/02-compositor.md`,
  `docs/design/adr/0182-tahoe-liquid-glass-material-pass.md` (Implementation
  (T-20.2)), `docs/PROGRESS.md`.

### Deviations / decisions

- **`panelOpacity` retuned.** The scope says the QML surfaces stay the
  complement, not the source. The menu bar already exposed the material
  (`chromeOpacity`, T-20.1); the drawer card's 0.90 fill hid it almost
  entirely, so the card fill was lowered to the Dock's glass level (0.5) for
  the proof surface. The remaining surfaces' QML complements are T-20.3.
- **Adaptive tint is a 3×3 mean of the blurred backdrop**, computed in the
  glass shader (no extra pass, no readback). It blends toward the scheme tone
  only in proportion to the luminance gap, so label contrast is never
  inverted.
- The status-popup QML background is still an opaque `Popup` component, so the
  dropdown capture shows the menu-bar strip's material, not the popup body
  (that is the T-20.3 rollout).
