## Hand-off

**Landed.** The integer-scale half of `docs/xwayland-scaling.md`:

- `XwaylandState::integer_scale = ceil(primary_output_scale).max(1)` computed
  and logged at `start()` (`compositor/src/xwayland.rs`). This is the value
  Smithay serializes as the integer `wl_output.scale`; no Xwayland command-line
  flag is involved (upstream has no `-scale`, and `-hidpi` is rootful-only).
- `render::accepts_fractional_scale` + `post_repaint`: X11 windows are never
  sent a fractional `preferred_scale`; Wayland windows are. Frame callbacks are
  unchanged. This is the effective "never advertise `wp_fractional_scale_v1` to
  Xwayland" (Smithay 0.7 has no per-client global filter).
- Headless fixture can boot at a chosen scale via `DRAGONFRUIT_HEADLESS_SCALE`
  (`compositor/src/backend/{mod,headless}.rs`), so the eager Xwayland starts
  against a scale-2 primary. New test
  `xwayland_conformance::x11_fixture_at_integer_scale_two` proves the X server
  screen and X11 geometry stay logical and zoom fills the logical usable area.
- `docs/xwayland-scaling.md` corrected, `docs/design/02-compositor.md` bullet,
  ADR 0152.

**Deviation / deferred.** The per-surface `wp_viewport` downscale is T-16.3b as
planned. Validating with a nested scale-2 session exposed a chrome bug outside
this task's scope: `render::wallpaper_render_elements` places the image in
physical pixels but sizes it in logical pixels, so at scale > 1 the wallpaper
image shows only in the top-left fraction. T-16.3b must fix it while sizing
chrome per output and add the nested scale seam (this task intentionally kept
nested at scale 1 so the demo renders cleanly).

**Live visual check.** `make demo`, capture
`/tmp/opencode/t145-demo-active.png` (2115x1437). Verdict: menu bar, Dock,
wallpaper, Settings window, and the X11 `xmessage` window all composite with no
clipping, tearing, oversized chrome, or stray artifacts. `Xwayland ready ...
integer scale 1` at the default nested scale.

**Commands.** `cargo test -p dragonfruit-compositor` (all green: bin 286,
xwayland 8, shell 39); `cargo clippy -p dragonfruit-compositor --all-targets --
-D warnings`; `cargo fmt --all -- --check`; `make e2e` EXIT 0
(`/tmp/opencode/t145-e2e-2.log`; one earlier run flaked in the unrelated
lock-auth `a_missing_user_is_a_usage_error` and passed on rerun).

T-16.3b adds the viewport pass and per-output chrome sizing.
