## Goal

Commit the selected app, cycle windows with Cmd+`, and stay interruptible while held.

## Scope

- Commit activates via `activate_app` (cross-Space, restore-if-minimized).
- Cmd+` cycles windows; interruptible while held; cancel on Escape.
- Commit `docs/captures/t06-*`.

## Explicitly deferred

- None (track complete).

## Acceptance (agent-completable)

- [x] Commit and cycling work by keyboard and pointer; cancel leaves no state.
- [x] Capture committed.

## Test plan

Deviations: the task text says "commit activates via `activate_app`". The
app-level default does exactly that; a Cmd+`-cycled window is activated by id
through the same `activate_window_id` (there is no window-addressed
`activate_app`). Protocol unchanged: the compositor resolves previews and
pointer hits, so the entry event needed no window handle.

Gotchas for later tasks:

- Cmd+` when the switcher is closed seeds on the focused app and opens the
  overlay; the app highlight never moves during within-app cycling.
- `switcher_candidates`/`switcher_frame` preview only the *cursor* window of
  the selected entry; the app's other windows are `alpha = 0` while the overlay
  owns the scene.
- Pointer commit only works while the switcher is active and only on a live
  preview rect; the shell card strip is a projection with no pointer handling.
