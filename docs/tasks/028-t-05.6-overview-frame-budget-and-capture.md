## Hand-off

- T-06 builds the switcher on the same transform. Read the gesture budget with
  `query gesture` / the `gesture budget` stats line; do not add a second timer
  or a second overview-active predicate (ADR 0020). The single per-frame seam
  is `DfState::observe_rendered_frame`.
- Degrade under pressure is already wired: the existing T-04.4a
  `DegradeController` is fed by the same seam and downgrades the grid material
  under load (nested runs settle at `tier=reduced`). T-06 inherits it for free.
- Captures: `docs/captures/t05-mission-control-live.{png,mp4}`,
  `t05-mission-control-live-reveal.png`, `-slide.png`, `-slide-settled.png`,
  and the `-reduced` set. Regenerate with `scripts/capture-overview.sh`
  (needs a host Wayland session + spectacle + Pillow; not part of `make e2e`).
- The nested gesture records an honest **shortfall** on the dev iGPU
  (e.g. `over_budget=1 dropped=2 max_frame_us=18273 held=0` on Mission Control;
  Desktop Reveal held the budget), which is the accepted outcome ("within budget
  or shortfall recorded"). Raw samples and session exit lines:
  `docs/captures/t05-gesture-budget-nested.txt`.
- Known gap (out of this task's scope): in the nested session the shell's
  overview chrome is an **offscreen scene-graph surface** that owns pointer
  focus but does not forward it to QML, so neither the compositor's
  `overview_begin_drag` hit-test (bypassed by `chrome_under`) nor the QML card
  `TapHandler`/`DragHandler` fires for a synthetic pointer. Live-window click
  selection and drag-between-Spaces remain verified headlessly
  (`window_conformance`: `overview_drag_moves_the_live_representation_between_spaces`,
  `overview_click_selects_and_focuses_the_live_representation`); the nested
  pointer path needs the shell's overview input region/forwarding wired
  (T-05.2/T-05.3 polish or T-11).
- `make e2e` (all suites + headless demo) and `make soak` (100 clean cycles)
  are green as of this task.
