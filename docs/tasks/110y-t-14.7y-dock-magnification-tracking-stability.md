## Goal

Hover magnification tracks the pointer without the visible shake/glitch: the
smoothed pointer no longer rings around the real position, the anchored tile no
longer flips frame to frame near a tile boundary, and the plate's top edge
moves as one smooth signal instead of jittering up and down by tiny amounts.

## Context (read first)

- `shell/dock/Dock.qml` — `smoothPointerAlong` (`~124-152`): a
  `NumberAnimation` retargeted on **every** pointer move with the
  `dockMagnify` bezier; `onPointerAlongChanged` restarts it from the current
  value to the new target. `motion.dockMagnify.curve` is
  `[0.34, 1.56, 0.64, 1.0]` — an **overshoot** curve
  (`design-system/tokens/tokens.json`). Retargeting an overshooting curve per
  input sample makes the smoothed value ring around the true position.
- `shell/dock/Dock.qml` — `anchorIndex` (`~1066-1083`) selects the nearest
  baseline center from **`smoothPointerAlong`** (not the raw pointer), so a
  ringing smoothed value can flip the anchored tile back and forth at a
  boundary; `layout` (`~2713-2817`) sizes every entry from that anchor and the
  smoothed pointer; `plateRect` (`~2850-2887`) takes `min()` over the magnified
  entries every frame, so any wobble in the peak icon modulates the plate's
  top edge.
- `shell/src/shellcontroller.cpp` `renderDock` (`~5930-5996`) commits the
  plate every frame (`setDockPanelRect` / `setDockInputRegion`).
- `Behavior on iconSize` uses the same `dockMagnify` overshoot — that one is a
  *discrete* change and should keep the overshoot; only the per-sample pointer
  tracking is the problem.
- `docs/PROGRESS.md` T-14.7b (smoothed pointer intent) and T-14.7c (frame
  discipline); T-14.7u retuned the metrics.
- Live report (2026-09-27): *"the app seems to shake or glitch as the mouse
  overs the tiles… the height of the dock background seems to rapidly grow or
  shrink by tiny bits back and forth"*.

## Current behavior (reproduced, T110u era)

- Moving the pointer slowly across the tiles makes the icon row visibly
  vibrate; at a boundary the peak tile can alternate. The plate's top edge
  oscillates instead of following the peak smoothly.

## Scope

- [ ] Replace the per-sample overshoot retarget with a tracker that cannot
      overshoot: a critically-damped / low-pass follow of the raw pointer
      (new token, e.g. `motion.dockMagnifyTrack` — short duration, no
      `y > 1` control point) or a directly-smoothed value with a small time
      constant. Keep `dockMagnify`'s overshoot only for discrete changes
      (`iconSize`, reveal). Reduced motion: track the raw pointer.
- [ ] Compute `anchorIndex` from the **raw** `pointerAlong`, not the smoothed
      value, so the anchor decision cannot oscillate with the filter. Keep the
      anchor rule intact: the tile under the pointer stays put.
- [ ] Derive a damped plate-top signal (a monotone follow of the peak entry
      top, with a small deadband) for `plateRect` instead of reading the raw
      per-frame `min()`; the plate still grows into the magnify band with
      magnification, but it no longer follows sub-pixel noise.
- [ ] Tests: a scripted pointer sweep across two tiles asserts (a) no anchor
      id flips that the pointer's own movement did not cause, (b) the plate
      top is monotone while the pointer moves one way (no reversals greater
      than a device pixel), and (c) the entry under the pointer stays
      anchored. Reduced motion tracks raw. Existing magnify geometry cases
      stay green.
- [ ] Capture a short slow-sweep strip (before/after) under
      `docs/captures/t14-dock-magnify-sweep-{light,dark}.png` and record the
      measured oscillation in the `PROGRESS.md` note.

## Explicitly deferred

- A physical spring model / pointer prediction (a tracker with momentum is not
  needed for correctness).
- A size-tracking plate radius (the T110u gotcha: the radius stays static;
  T-16.1a owns per-output chrome sizing).
- Glass refraction and icon masking (T-14.7w / ADR 0102).

## Design notes

- One smoothing source of truth: the pointer tracker is the only filter; do
  not add a second animation on top of it.
- Overshoot is a deliberate entrance effect, not a tracking filter — a
  retargeted overshoot is what rings. Keep the curve for one-shot changes.
- The plate follows magnification by design (T-14.7b); the fix is signal
  stability, not removing the growth.
- The token belongs in `motion` and is generated into `Theme.qml`; no literals
  in QML.

## Hand-off

Landed (T110y):

- **Tracker.** `smoothPointerAlong` now follows `pointerAlong` with the new
  `motion.dockMagnifyTrack` token (100 ms, curve `[0.2, 0.0, 0.0, 1.0]`, no
  overshoot; reduced duration 0). `motion.dockMagnify` keeps its overshoot only
  for the discrete `iconSize` spring and reveal. Reduced motion tracks raw.
- **Anchor.** `anchorIndex` is computed from the raw `pointerAlong`; the anchor
  rule (tile under the pointer stays put) is unchanged. The public property
  names are unchanged, so the shell controller needs nothing.
- **Plate edge.** `plateTrackRaw` derives the entry-union magnify edge (bounce
  added back); `smoothPlateTrack` is a peak-hold follow through the same token
  with a 0.75 px deadband, a `plateTrackEngaged` flag, and snaps on discrete
  magnify entry/exit and reduced motion. `plateRect` reads it on all positions.
  The plate still grows into the magnify band; it no longer follows the
  per-tile ripple or sub-pixel noise.
- **Tests.** `tst_dock` 256 → 260: `test_smoothed_pointer_never_overshoots_the_target`,
  `test_anchor_index_follows_the_raw_pointer`,
  `test_slow_sweep_has_a_stable_anchor_and_plate`,
  `test_plate_tracks_raw_under_reduced_motion`. All four fail on the pre-fix
  tree. Measured: pre-fix overshoot 11.0 px / 19 plate-top reversals (max
  1.108 px); fixed 0.
- **Captures.** `make dock-magnify-sweep-capture` →
  `docs/captures/t14-dock-magnify-sweep-{light,dark}.png` (before row over after
  row), `sweep-row-*-{before,after}.png`, `t14-dock-magnify-sweep-trace.txt`.
  Strip plate-top range: before 6 px → after 0–1 px.
- **Docs.** ADR 0111; `docs/design/04-shell.md` magnification paragraph;
  `docs/design/10-design-system.md` Motion rule; captures README.

Deviation: the scope suggested "a critically-damped / low-pass follow"; the
implemented tracker is a short non-overshoot low-pass retargeted per sample
(the suggested token shape), and the plate edge is a peak-hold rather than a
plain low-pass because a plain low-pass still followed the per-tile
magnification ripple (a settled 6 px swing) — that ripple is what read as the
plate growing/shrinking. No protocol, settings-key, or shell-controller change.

What T-14.7z must know: the plate edge is peak-held (not released) while the
pointer is on the Dock, so the drawn plate can be a few px taller than the
strict entry-union wrap between tiles; the compositor backdrop follows
`plateRect`, so frost alignment follows the held edge. If T-14.7z needs a
release, add a release deadband on `plateTrackRaw`. `motion.dockMagnifyTrack`
is the single shared token for the pointer tracker and the plate edge; do not
add a second animation on top.
