[macos-ui-inventory.md](../reference/macos-ui-inventory.md)); the design doc
owns the semantics ([09-files.md](../design/09-files.md#views)):

- **Icon view**: a centered grid of icon tiles (glyph over an up-to-two-line
  label), accent-tinted selection, rubber-band selection, per-folder icon
  size and spacing.
- **List view**: `Name` first, then optional Date Modified / Size / Kind
  columns with sortable headers, inline disclosure triangles for folders,
  full-row selection highlight, inline rename.
- The toolbar's segmented view control is the single switch between the
  shipped views, and the choice persists per location.

## Hand-off

**Landed.** Both views render the `files-core` model and switch via the
toolbar; selection survives the switch. The files-core bridge ADR 0048 deferred
is the hand-written C ABI in ADR
[0049](../design/adr/0049-files-core-c-abi-bridge.md):

- **`services/files-core/src/ffi.rs`** (new) — the C ABI: `df_files_begin`,
  `df_files_poll` (blocks for one listing event, returns the current ordered
  snapshot), `df_files_snapshot`, `df_files_set_sort`, `df_files_event_free`,
  `df_files_free`. `Cargo.toml` gained `crate-type = ["lib", "staticlib"]`;
  `lib.rs` exports `pub mod ffi`. Three unit tests.
- **`apps/files/ffi/files_core.h`** (new) — the mirrored C declarations.
- **`apps/files/FilesDirectoryModel.{h,cpp}`** (new) — a thin
  `QAbstractListModel` facade (`QML_ELEMENT`): `location`, `count`, `state`,
  `errorMessage`, `sortKey`/`sortAscending`/`foldersFirst`,
  `Q_INVOKABLE sortBy`. It polls the Rust worker from a 16 ms timer on the Qt
  thread and resets from the ordered snapshot; the timer stops on
  complete/error, so an idle window does not poll.
- **`apps/files/FilesIconView.qml`**, **`FilesListView.qml`** (new) — the
  grid (glyph + two-line label, accent-tinted selection) and the four-column
  table (`Name` / `Date Modified` / `Size` / `Kind`) with sortable headers.
  Both share the one model and the shell's `selectedId`; double-click opens a
  folder.
- **`apps/files/FilesShell.qml`** — `contentArea` now holds the
  `FilesDirectoryModel` and both views (only the active one visible); the
  empty/error state sits above them. Selection is `FilesShell.selectedId`,
  cleared on navigation.
- **`apps/files/FilesBridge.{h,cpp}`** — `viewFixtureUri`
  (`DF_FILES_VIEW_FIXTURE`, a real directory for the headless view tests) and
  `startView` (`DF_FILES_START_VIEW`, the capture seam).
- **`design-system/components/Icon.qml`** — a generic `file` glyph.
- **Tests** — `apps/files/tests/tst_files_shell.qml` gained four cases
  (icon view renders the listing, toggle swaps the visible delegate, selection
  survives the switch, list data has the columns); `tst_files_shell.cpp` now
  creates the fixture directory before the QML engine loads.

**Deviations.** `df_files_poll` delivers the whole ordered snapshot per batch
rather than an incremental diff: correct and one-collation, but O(n²) over a
large directory. **T-10.5 must replace it with incremental/windowed delivery**
(ADR 0049). The folder watcher is not wired, so external changes do not
repaint; file opening, context menus, multi-select, rubber-band selection,
column resizing, inline rename, icon-size gestures, and the search result set
are T-10.4c.

**Commands (repo root; `make` sets the toolchain env).**

- `CARGO_NET_OFFLINE=true cargo test -p dragonfruit-files-core` — 125 pass
  (57 unit incl. 3 ffi + 17 operations + 11 optimistic + 5 sorting + 6
  streaming + 13 trash + 12 watcher + 4 doctests).
- `make qml-test` — 32/32 ctest green; `tst_files_shell` 18 pass.
- `make lint` — fmt/clippy/qmllint/tokens/desktop-name gates green.
- `make e2e` — exit 0.

**Live visual check.** Captures `/tmp/opencode/t63-files-icon.png` and
`/tmp/opencode/t63-files-list.png` (1920x1200, nested demo launched with
`DF_DEMO_QT_APP=build/apps/files/dragonfruit-files`,
`DF_FILES_START_URI=file:///tmp/opencode/t63-files-fixture`, and
`DF_FILES_START_VIEW=icon|list`; the view seam is used because nested
synthetic pointer clicks reach the compositor but not a Qt client surface).
Raw observation on tight crops: the icon view is a grid of glyph tiles with
labels (`Archive`, `Photos`, `Projects`, `budget.xlsx`, `Notes.txt`,
`photo.png`, `Report.txt`); the list view has `Name` / `Date Modified` /
`Size` / `Kind` headers with a sort indicator on `Name` and rows carrying
`sizes` (`8.00 KiB`, `6 bytes`) and dates (`9/25/26`); sidebar, toolbar, and
path bar render cleanly with no stray artifacts. Vision is a supporting check.

**T-10.4c must know.** `FilesDirectoryModel` is the one listing seam; add
operations by extending the facade, not by reading the filesystem in QML. The
shell owns selection; multi-select extends `FilesShell.selectedId`. The
`contentArea` views already emit `selected(nodeId)` / `activated(uri, isDir)`;
context menus and optimistic UI hang off those. Per-location sort persistence
is not done (sort is global while a session lives).
