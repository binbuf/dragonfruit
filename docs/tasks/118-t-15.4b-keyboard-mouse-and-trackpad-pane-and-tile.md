**Apple-only (adapt or omit):** the `Dictation` section (Siri/Apple
Intelligence); the `⌘` glyph in `Press ⌘ key to` becomes Dragonfruit's keymap
label (Super/Meta, [keymap.md](../keymap.md)) — keep the row; captured Apple
device names like `Automatic (MacBook Pro Microphone)` become generic; `Force
Click and haptic feedback` is Apple hardware behavior, and our equivalent is
decided later; `Set Up Bluetooth Trackpad...` stays as the generic
device-setup action. Repeat rate/delay map to
`input.repeatDelay`/`input.repeatRate` (settingsd → compositor/input;
`docs/design/tracks/08-settingsd-live-settings.md`); `Tracking speed`,
scrolling, and `Tap to click` map to `PointerSettings` in
`compositor/src/input/settings.rs` (no settingsd keys yet; provider TBD
(T-15.4a)); all other rows are the pane's target UI, providers TBD (T-15.4a).

Decisions / gotchas for later tasks:

- **The adapter stays read-only.** The pointer preferences are settingsd keys
  (`input.pointerSpeed`, `input.naturalScroll`, `input.tapToClick`,
  `input.leftHanded`, `input.scrollMethod`), mapped to `PointerSettings` in
  `compositor/src/input/settings.rs`. **The compositor does not consume them
  yet**: `df_toplevel_manager.set_input_policy` carries only keyboard repeat
  and gesture gating. A later task must extend the protocol (append-only
  request) to apply them; until then the panes persist and apply live in
  settingsd but the pointer behavior is not yet changed in the compositor.
- **Keyboard brightness / emoji-key rows persist a preference**; the backlight
  and emoji-panel hardware bridges are deferred (same as the Sound alert
  engine).
- **QML integer writes** now coerce to the schema type in
  `libs/settings-client/settingsclient.cpp` (`coerceToSchema`); without it a
  slider writing `input.repeatRate` sends a D-Bus double and the daemon
  rejects it (`TypeMismatch`).
- **`DF_INPUT_FIXTURE`** drives the Settings pane inventory; `DF_STATUS_FIXTURE`
  drives the shell tile. Neither is set in `make e2e`.
- **The Control Center panel is now 360x880 and fixed.** Adding a tile to the
  panel requires re-checking `tst_controlcenter`'s fit test.
- Live visual check: `bash scripts/capture-t15-input-pane.sh` produced
  `docs/captures/t15-4b-keyboard-pane.png` (2088x1410) and
  `docs/captures/t15-4b-input-control-center.png` (360x880). Vision confirmed
  the Keyboard pane's `Devices` rows (`AT Translated Set 2 keyboard`,
  `Logitech USB Mouse`, `Synaptics TouchPad`), the `Key repeat rate` /
  `Delay until repeat` sliders, the `Keyboard Brightness` group, nothing cut
  off, and the Control Center's Keyboard tile
  (`1 keyboards, 2 pointing devices`, `Keyboard Settings…`) above an unclipped
  Clipboard tile.
