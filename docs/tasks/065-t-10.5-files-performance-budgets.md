## Goal

Meet the folder-open and large-list budgets with windowed rendering.

## Scope

- Warm 1k-item folder < 50 ms to first frame with streaming listing.
- 100k-item list scrolls at 60 Hz with flat memory (windowed rendering).
- Record raw numbers.

## Explicitly deferred

- Network-mounted performance (post-gate).

## Acceptance (agent-completable)

## Test plan

## Hand-off

**Landed.** Windowed/incremental listing delivery plus recorded budgets.

- `services/files-core/src/ffi.rs` — new delta ABI: `df_files_poll_delta`
  (streaming batches carry only the newly arrived nodes, at their final ranks;
  `reset == 0`) and `df_files_snapshot_delta` (full ordered model, `reset == 1`).
  A per-session `reported` id set guarantees each streamed node is serialized
  exactly once. `df_files_begin_synthetic` / `SyntheticSource`
  (`mock.rs`) is the disk-free 100k fixture. The old
  `df_files_poll`/`df_files_snapshot` snapshot ABI remains for the Rust unit
  tests; the Qt app uses only the delta functions.
- `services/files-core/src/listing.rs` — the worker's batch grows geometrically
  after the first frame (`DEFAULT_BATCH` … `MAX_BATCH = 8192`), so a 100k merge
  is ~20 passes instead of ~390. First frame is unchanged.
- `apps/files/FilesDirectoryModel.{h,cpp}` — applies a delta by merging the new
  nodes into its display order in one O(n+k) pass, emitting
  `beginInsertRows(oldCount, newCount-1)` + `dataChanged(0, oldCount-1)`; the
  reset path remains for sort/optimistic edits. `m_nodes` is now
  `std::vector<Node>`. Starts the synthetic session for a `/synthetic` location
  when `DF_FILES_SYNTHETIC_COUNT` is set.
- `apps/files/ffi/files_core.h` — mirrored.
- Tests: `services/files-core/tests/performance.rs` (budgets + raw numbers),
  two ffi unit tests (each node delivered once; sort => reset), and the QML
  `test_large_list_paints_fast_and_stays_windowed` /
  `test_large_list_scroll_sweep`.
- Docs: ADR [0051], `09-files.md` T-10.5 status, raw numbers in
  `docs/captures/t10-files-perf.txt`.

**Commands / raw numbers** (debug tree; full output in the capture):

- `CARGO_NET_OFFLINE=true cargo test -p dragonfruit-files-core --test
  performance -- --nocapture --test-threads=1` — warm 1k first frame
  0.57 ms (budget < 50); real-fallback 1k 1.80 ms; 100k stream 100000 rows
  delivered once in ~1.06 s; 40-row viewport read 2.2 µs (budget < 16.6 ms).
- `make qml-test` — 32/32 ctest green; `tst_files_shell` 28 pass. The 100k
  QML cases: first frame 21 ms, icon-view delegates 70 (48/49 after scroll),
  list-view delegates 24, 100 list jumps 999 ms.
- `make lint` green; `make e2e` exit 0.

**Deviations / decisions.** The ABI stayed hand-written C (no cxx-qt, offline
toolchain) — [0051] records the delta contract. The Qt model applies insertions
by declaring them appended (`beginInsertRows`) then `dataChanged` over the
shifted range; delegates are index-based and re-query `data`, so the painted
content is correct while the view keeps its scroll offset. The synthetic source
is test-only and gated to `/synthetic` so it can never shadow a real folder.

**Live visual check.** Launched the nested demo with the synthetic 100k list
(`/tmp/opencode/t65-capture.sh top`, stills `t65-files-100k-top.png`/`-scrolled.png`).
Vision on the window: title `synthetic`; sidebar FAVORITES/LOCATIONS; list
headers `Name` / `Date Modified` / `Size` / `Kind`; rows
`file-0000000.txt` … `file-0000016.txt`; breadcrumb `Computer > synthetic`; no
artifacts. The synthetic pointer axis cannot scroll a Qt client surface, so the
`scroll` still shows the top rows too (known T-10.4 limitation). Verdict:
renders as intended.

**Next task (T-10.6a).** The Dock's Trash source should list `trash://` through
`files-core` as a `DirectorySource`, not the app. The delta ABI is the stable
seam: a new source only needs `DirectorySource` + `df_files_begin`; the facade
and roles do not change. The folder watcher is still not wired to the facade —
external changes do not repaint until a later task drains `WatchHandle`.
