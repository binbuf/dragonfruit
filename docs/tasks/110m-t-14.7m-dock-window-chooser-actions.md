## Goal

Each window row in the Dock's chooser gains a destructive **Close** and a
stateful **Minimize / Restore** action, so a grouped app can be managed from
its popover without first focusing each window — closing the biggest usability
gap against a mature reference dock.

## Context (read first)

- `shell/dock/DockWindowChooser.qml` (236 lines) — the chooser: a
  `Show All Windows` header plus passive rows (`windowId`, `title`, minimized,
  focused, `workspaceName`). It emits `windowActivated` / `showAllWindows`; the
  shell performs the round-trips.
- `shell/src/shellprotocol.h` — `selectToplevel(windowId)` (`~421`) and
  `closeToplevel(windowId)` (`~425`) exist; **there is no per-window
  minimize/restore wrapper**.
- `protocols/dragonfruit-toplevel.xml:336-343` — `df_toplevel` already has
  `activate`, `close`, `minimize`, `unminimize`, `zoom`, `unzoom`, `fullscreen`,
  `unfullscreen`.
- `shell/dock/Dock.qml` `activateEntry` / `openChooser` / `closePopovers` — the
  single-popover-at-a-time host and the `windowActivated` signal.
- `shell/src/dockprojection.{h,cpp}` — chooser rows carry
  `{windowId, title, minimized, focused, workspaceIndex, workspaceName}`.
- `shell/tests/tst_dock.qml` — existing chooser/activation cases to extend.
- Reference behavior only (GPL, never copied): `WindowPreviewActionButton.qml`
  and `WindowPreviewCard.qml` in `~/repos/punchi-dock-remastered` show
  Close / Minimize-Restore / Maximize / Present buttons (icon + enabled state,
  destructive Close in red, stateful minimize/restore). We implement Close and
  Minimize/Restore only in this unit.

## Current behavior (investigated, T110 era)

- Chooser rows only activate a window on click; there is no way to close or
  minimize a specific window from the chooser. Closing requires focusing it, or
  quitting the whole app from the context menu.

## Scope

- [ ] `ShellProtocol`: add a per-window minimize/restore wrapper over
      `df_toplevel.minimize`/`unminimize` (one method with a bool, or two
      methods). Keep the `since` / protocol-version markers non-decreasing and
      bind at `min(version, …)` like the other requests; no protocol change is
      needed (`df_toplevel` is already v1).
- [ ] `ShellController`: handlers for the new chooser actions; after a
      Close/Minimize the chooser stays open and its rows update from the next
      projection (a closed window drops its row; a minimized one flips the
      button label). When the last window of the app closes, the chooser
      dismisses.
- [ ] `DockWindowChooser.qml`: per-row action buttons for Close (destructive)
      and Minimize/Restore (label/icon follows `minimized`), revealed on row
      hover/focus; keep the row click = activate. The buttons must not steal
      the chooser's keyboard focus and must not close the popover.
- [ ] Accessibility: the buttons carry names that include the window title
      ("Close <title>", "Minimize <title>"); the row's accessible name keeps its
      active/minimized state.
- [ ] Tests: `tst_dock.qml` for the new signals and the stateful label; a
      conformance case that the requests reach the client (extend
      `window_conformance.rs`/`shell_protocol_conformance.rs` if needed).
- [ ] Capture `docs/captures/t14-dock-chooser-actions.png` (hovered row with
      both buttons) and the `PROGRESS.md` note.

## Explicitly deferred

- Maximize/zoom and fullscreen per window: the protocol supports it; keep the
  chooser row uncluttered this unit (→ T-14.7n and later).
- "New Window" / `.desktop` actions (→ an app-index desktop-actions follow-up).
- Live thumbnails in the rows → the deferred preview-protocol work named in
  ADR 0103.
- Grouping rows by Space with headers.

## Design notes

- The chooser owns no authoritative state; it asks, the shell acts. Do not
  mutate `windowList` in QML — the next projection is the source of truth.
- Close is destructive: style it with the danger token and give it the same
  guard the Trash `Empty Trash` uses (it closes a window; no confirmation
  sheet, but the destructive color and accessible name are required).
- One popover at a time; adding buttons must not change the chooser's
  open/close behavior or the magnification suppression it already has.
- Held-over invariant from ADR 0100: actions use the pre-sized popover buffer;
  opening the chooser must not resize the surface.

## Hand-off

Implemented (T-14.7m, done):

- **`ShellProtocol::setToplevelMinimized(const QString &windowId, bool
  minimized)`** — one wrapper; `true` sends `df_toplevel.minimize`, `false`
  `df_toplevel.unminimize`. No protocol change (`df_toplevel` is already v1);
  `closeToplevel` is reused as-is.
- **`ShellController::onDockWindowCloseRequested` /
  `onDockWindowMinimizeRequested(windowId, minimized)`** wired to the Dock's
  new `windowCloseRequested(string)` / `windowMinimizeRequested(string,bool)`
  signals. Both schedule a render and leave the chooser open; the next
  running-app projection is the only source of truth.
- **`DockWindowChooser.qml`** — per-row `ChooserActionButton` inline component:
  icon-only, `activeFocusOnTab: false`, accessible names `"Close <title>"` /
  `"Minimize <title>"`/`"Restore <title>"`; a reserved right-hand slot holds
  both footprints so revealing them never resizes the popover (ADR 0100).
  Close is `Theme.color.danger` (destructive tint), minimize/restore uses
  `textSecondary`. Glyphs: `close`, `minimize`, new `restore` (added to
  `design-system/components/Icon.qml`). The row background uses
  `row.hovered`, which is `rowHover.hovered` or the capture seam index.
- **Chooser survival (`Dock.qml`)** — `onEntriesChanged:
  Qt.callLater(refreshChooserAfterProjection)` re-resolves `chooserEntry` and
  `chooserAnchor` by entry id after the projection and Repeater settle
  (`Qt.callLater` is required: reading `items` inside the signal handler still
  sees the pre-change binding). No matching id → `windowChooser.hide()`, so the
  chooser dismisses when the app's last window closes.
- **Capture seam `DF_DOCK_CHOOSER_FIXTURE`** + `Dock.openChooserFixture()`:
  retries until a running app with >1 window exists, opens its chooser, and
  sets `windowChooser.fixtureHoverIndex = 0` (reveals that row's actions).
  The seam is never a session value.

For T-14.7n (row discipline):

- **Do not mutate `windowList` in QML.** The action functions ask and return;
  the projection is the only writer. `refreshChooserAfterProjection` is the one
  rebind path; a bounded scroll viewport must keep using it.
- **`fixtureHoverIndex` and `DF_DOCK_CHOOSER_FIXTURE` are capture seams**, not
  session state. The hovered-row styling already keys off `row.hovered`, so a
  keyboard current-row index can reuse it.
- **The action slot width is reserved** (`2 * actionButtonSize + actionGap`);
  a scrollbar or count badge must not steal that slot or the popover will
  resize on hover. Per-window maximize/fullscreen stay deferred.
