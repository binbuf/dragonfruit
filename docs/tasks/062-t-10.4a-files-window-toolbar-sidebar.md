## Goal

The Files window with toolbar and sidebar.

## Scope

- Sidebar (Home, Documents, Downloads, Trash, mounted volumes), toolbar (back/forward, view toggle, search-local).
- Design-system components only.

## Explicitly deferred

- List/icon views (T-10.4b), context menus/multi-select (T-10.4c).

## Reference UI/UX (macOS screenshots)

Local art direction only: real macOS screenshots in `docs/reference/macos/`
(never shipped; see [14-risks.md](../design/14-risks.md)) and the distilled
[macos-ui-inventory.md](../reference/macos-ui-inventory.md). The Finder
window is the model; symbols and semantics stay ours:

- **Toolbar**: traffic lights, centered title, then left **back/forward
  chevron pills** (forward dimmed at the end of history), a **view segmented
  control** (icon/list/column/gallery glyphs) with a trailing dropdown, and a
  **right-aligned search field** (`Search` placeholder, magnifier glyph). The
  segmented control is the single view switch; per-location view state
  persists ([09-files.md](../design/09-files.md#views)).
- **Sidebar**: muted section headers (`Favorites`, `Locations`, `Tags`),
  icon+label rows, the selected row on a tinted rounded highlight with accent
  text, favorites drag-reorderable, `Trash` last. Our sections and defaults
  are the design doc's ([09-files.md](../design/09-files.md#sidebar)); the
  reference is the visual/interaction register.
- **Path bar**: a footer breadcrumb (`Computer > <user> > Desktop`) with
  chevrons between segments; segments are drop targets and history anchors.
- Not in this task: share/tag toolbar actions, Gallery/Column views (later,
  see T-10.4b), tabs.

## Hand-off

**Landed.** The Files window, toolbar, and sidebar are real. `apps/files` is
now a reusable QML module (`Dragonfruit.Files`) plus a thin executable,
mirroring Settings:

- **`apps/files/FilesBridge.{h,cpp}`** — the `Files` QML singleton: real XDG
  Favorites via `QStandardPaths` (Desktop, Documents, Downloads, Pictures,
  Music, Videos — only directories that exist; Home is a Location, per
  `09-files.md#sidebar`; Recents omitted, needs `recent://`/GVfs), mounted
  block volumes via `QStorageInfo` (root/system mounts excluded), Computer and
  Trash, `breadcrumb(uri)`, `displayName(uri)`, `isBrowsable(uri)`.
  `DF_FILES_FIXTURE` makes it deterministic for tests; `DF_FILES_START_URI`
  opens a set location.
- **`apps/files/FilesBrowser.qml`** — the browsing model: current URI,
  per-window back/forward history, per-URI view state (`navigate`/`back`/
  `forward`/`setView`). Independent of the directory listing on purpose.
- **`apps/files/FilesShell.qml`** — `AppWindow`+`TitleBar`+`Toolbar`+`Sidebar`
  + footer `PathBar`, design-system components only; Favorites (user folders,
  existing only) then Locations (Home, Computer, volumes, Trash last);
  back/forward, icon/list view switch, local search; Alt+Left/Right and
  Cmd+[ / Cmd+] history, Ctrl+F search.
- **`apps/files/PathBar.qml`**, **`FilesWindow.qml`** (frameless first-party
  window).
- **Design system** — `Icon` gained home/documents/downloads/music/movies/
  trash/computer/volume/folder/icon-view/list-view glyphs; `SegmentedControl`
  accepts an optional `icon` per entry; `Sidebar`/`SourceList` now draw
  selection instantly and animate only hover (a freshly opened window could
  otherwise paint a half-faded selection when the client was idle and no frames
  were delivered — it did, in the live capture).
- **Tests** — `apps/files/tests/tst_files_shell.{cpp,qml}`, 14 cases under
  `DF_FILES_FIXTURE=1` (platform seam, breadcrumb, sidebar selection and
  keyboard, toolbar history via the real buttons, view persistence per
  location, search wiring, path-bar navigation, AT-SPI roles, traffic lights).

**Deviations / deferred (recorded in ADR 0048).** No files-core/cxx-qt bridge:
this slice keeps the browsing model in QML so T-10.4b attaches the listing to
`FilesBrowser.currentUri` without a UI rewrite. The trailing view-options
dropdown is view-specific, so it lands with the views. Search is wired to
`FilesShell.searchText` but does not filter a listing yet (no listing). Sidebar
volumes are a plain `QStorageInfo` read until the GVfs volume monitor; drag
reorder / Add to Sidebar / eject are later.

**Commands (repo root; `make` sets the toolchain env).**

- `make cmake-build` — builds `dragonfruit-files`, the module, and the test.
- `make qml-test` — 32/32 ctest green, including `tst_files_shell` (14 pass)
  and `qmllint_app-files`.
- `make visual-test` — 72 gallery snapshots pass.
- `make lint` — fmt/clippy/qmllint/tokens/desktop-name gates green.
- `make e2e` — exit 0.

**Live visual check.** Capture `/tmp/opencode/t62-files-home.png` (and
`/tmp/opencode/t62-files-documents.png`, opened at Documents), 1920x1200
nested session launched with `DF_DEMO_QT_APP=build/apps/files/dragonfruit-files`.
Verdict: the window, toolbar (back/forward, two-segment view switch, `Search`
field), sidebar (`FAVORITES`: Desktop/Documents/Downloads/Pictures/Music/Videos;
`LOCATIONS`: user/Computer/Trash, Trash last) and footer path bar
(`Computer > user`) all render; the selected `user` row reads as a solid accent
highlight with white glyph/text; no clipping or stray artifacts in the window.
Raw observation after the selection fix: sidebar histogram top colors
`(248,246,250)` background and `(179,42,102)` selected row (1363 px) — exact
accent, not the muted `(231,228,232)` seen before the fix. The pre-existing X11
`xmessage` window is unaffected.

**T-10.4b must know.** Add the files-core bridge and feed
`FilesBrowser.currentUri`; do not duplicate the navigation/history/view-state
owner. `FilesBrowser.viewFor(uri)`/`setView` is the per-location persistence
seam named in `09-files.md#views`. The content area is a single `Item`
(`FilesShell.contentArea`) holding the placeholder `emptyState`; replace it
with the views. The `Date Modified`/`Size`/`Kind` list columns, icon-size
gestures, and the trailing view-options dropdown are all T-10.4b's.
