## Goal

When the pointer magnifies the Dock, the plate grows to wrap the magnified row
(both axes) and the compositor's frosted backdrop follows it exactly, so the
material stays under the artwork. The reserved zone stays baseline, so windows
never re-layout while the pointer sweeps the Dock. The magnification itself
reads smooth instead of raw pointer stepping.

## Current behavior (investigated, T101 era)

- `barRect` is explicitly derived from `_baseline` so magnification never grows
  the slab; the test above locks that in. Magnified artwork spills out of the
  plate instead.
- The compositor's backdrop panel is the input-region bbox intersected with the
  baseline reserved strip, so even a larger QML slab would sit on unblurred
  content.
- The magnification layout reads the raw pointer position every hover event; the
  design's short spring was never implemented.
- `magnifyBand` is already sized for `magnifyPeakMax` (2.2×), so there is room
  inside the surface for the plate to grow; no reconfigure is needed.

## Design notes

- The reserved zone stays baseline; the plate is cosmetic and grows inside the
  pre-reserved `magnifyBand`. Do not change `dock.size` or the surface
  thickness while magnifying.
- `plateRect` is the single source for drawing, input, and the panel request.
- The protocol change is additive per `docs/ipc-versioning.md`: never alter
  existing request semantics; only add members and bump the interface version.
- Keep `panel_bounds` as the fallback; only the Dock opts into the explicit
  panel rect.
- Reduced motion removes the spring, not the geometry.

## Hand-off

**State: done.** Protocol version: `df_shell` and `df_layer_surface` interface
`version="2"` (`set_panel_rect` is the v2 addition); `LOCKSTEP_VERSION` stays 1
(the lockstep test is green). The factory bumps in tandem because a Wayland
`new_id` inherits the parent's version, so `ShellProtocol::bindTrustedGlobals`
now caps `df_shell` at `df_shell_interface.version` instead of a hardcoded 1.

**Panel derivation.** The Dock sends its live `plateRect` (surface-local) on
every `renderDock()` commit via `ShellProtocol::setDockPanelRect` →
`df_layer_surface.set_panel_rect`. The compositor stores it on
`LayerSurfaceState.panel_rect` and `chrome_surfaces` uses
`window::explicit_panel_bounds(geometry, panel_rect)` (translate to output-local,
intersect with the surface geometry) as `ChromeSurface.panel`. When unset, the
existing `panel_bounds` (input-region bbox ∩ reserved strip) is unchanged, so the
menu bar and popovers keep their derived panel. `is_backdrop_panel`/`BackdropPass`
are untouched (one pass per output per frame; `backdrop_skipped` stays 0).

**QML.** `restingPlateRect` is the baseline plate (fixed anchored edge, carries
`hideX/hideY`); entry cross-axis positions are laid out against it so there is no
binding cycle. The live `plateRect` is the union of the entry rects plus
`padding`/`paddingAlong`, clamped to the surface, with launch/attention bounce
added back out; the anchored edge is fixed (bottom plate bottom =
`height − edgeMargin`; vertical plates anchor on their screen-edge side and grow
inward). `smoothPointerAlong` snaps on entry/mouse-out and under reduced motion,
and springs with `motion.dockMagnify` (160 ms, overshoot bezier) while magnifying.
Input region = live plate + magnified/bouncing entry rects.

**Frame numbers** (`docs/captures/t14-dock-magnify-frame-budget.txt`, nested):
2.21 s pointer sweep → `frames_rendered +175`, `frames_skipped_no_damage +0`,
`~79 fps`; compositor `animation_frames_stepped +0` because the magnify spring is
a shell-side QML animation, not a compositor-clock transition. `latency_dropped
+0`. Capture paths: `docs/captures/t14-dock-magnify-{left,center,right}-{dark,light}.png`
(plus a left-third montage check during sign-off showing the leftmost icon
largest when the pointer is at the left), via
`scripts/capture-dock-magnify.sh` / `make dock-magnify-capture`.

**What T-14.7c must know:** the plate's per-frame geometry is progress-based and
interruptible; bounce is deliberately excluded from the plate, and the panel
request is one rect per commit (no per-entry panel). Bounce-phase discipline and
popover headroom remain T-14.7c's. No new ADR — ADR 0089 already froze this
model; the design docs (`04-shell.md`, `02-compositor.md`, track 14) were
updated with the T-14.7b implementation note.
