# T183 — T-21.1a Chrome transport baseline and decision

## Goal

Produce a reproducible baseline of the shell chrome presentation path and a
recorded decision on how to replace it. No behavior changes in this task: it
measures the current `offscreen QPA → grabWindow() → QImage → wl_shm` path and
the compositor's chrome import/presentation cost, then fixes the transport
direction before T184–T186 touch it.

## Context (read first)

- `shell/src/main.cpp` — forces `QT_QPA_PLATFORM=offscreen` before the QML
  engine is created; this is the root of the transport choice.
- `shell/src/shellcontroller.cpp` — `onDockAfterRendering()` (~:6999),
  `scheduleDockRender()` (~:7010), `renderDock()` (~:7021), and `render()`
  (~:7144) are the per-surface readback/commit paths.
- `shell/src/shellprotocol.cpp` — `commitTo()` (~:1574) allocates a memfd or
  `/dev/shm` file, `mmap`s it, `memcpy`s the image, creates a fresh
  `wl_shm_buffer`, attaches, damages the whole buffer, and commits.
- `shell/src/framecommitgate.h` — the gate that suppresses the re-entrant
  `afterRendering` caused by `grabWindow()`.
- `compositor/src/render.rs` — `chrome_render_elements()`,
  `update_chrome_preferred_scale()`, and `post_repaint()` (the compositor
  advertises fractional scale to chrome but sends frame callbacks only to
  windows today).
- `compositor/src/state.rs` — `RenderStats`, `PresentationStats`, `dump_stats`;
  the `presentation stats` line already carries real vblank intervals on DRM.
- `docs/rendering.md` — R2.1 (confirm the scene-graph backend) and R2.3
  (remove full-surface copies).
- `docs/design/architecture-audit-native-rendering.md` — §5 (shell transport)
  and §9.5 (HiDPI).
- `scripts/native-capture.sh`, `scripts/t20-frame-budget.sh`,
  `scripts/capture-dock-magnify-sweep.sh` — existing capture/driver patterns;
  reuse the synthetic-input harness (`DRAGONFRUIT_SYNTHETIC_INPUT`).

## Scope

- [ ] Run a controlled shell restart with `QSG_INFO=1` (and
  `QT_LOGGING_RULES=qt.qpa.*=true` if useful). Record:
  - the active scene-graph backend (software / OpenGL / RHI),
  - the graphics API and swapchain details,
  - whether the process maps GLES/GL/DRI libraries (`/proc/<pid>/maps`),
  - the QML render-loop cadence while the Dock is idle and while it animates.
- [ ] Add opt-in shell transport counters behind
  `DRAGONFRUIT_CHROME_STATS=1` (default off, zero cost when unset):
  - `scene_frames` (QML scene-graph frames),
  - `commits` (chrome buffers attached/committed),
  - `grab_renders` (`grabWindow()` calls),
  - `shm_allocs` and `shm_bytes` (fresh buffers and bytes copied),
  - `commit_us` (render completion to `wl_surface.commit`) and
    `frame_callback_us` (commit to callback; expect no samples before T185),
  - `frame_callbacks` (if the shell already has any; expect 0),
  - per-surface `logical_size`, `buffer_size`, and `buffer_scale`.
  Emit a greppable `chrome stats` line on exit and on an installed `SIGUSR1`
  handler (or an equivalent opt-in trigger); keep the normal path unchanged
  when the variable is unset.
- [ ] Add opt-in compositor chrome counters (same `dump_stats` block):
  - `chrome_shm_imports`, `chrome_shm_bytes`, `chrome_dmabuf_imports`,
  - `chrome_frame_callbacks` (expected 0 before T185),
  - the existing `presentation stats` per output.
- [ ] Add `scripts/t21-chrome-baseline.sh` and
  `make t21-chrome-baseline`. It starts the nested demo with the synthetic
  input harness and records:
  - idle (5 s),
  - a slow Dock sweep (reuse the `motion-abs` pattern from
    `capture-dock-magnify-sweep-driver.py`),
  - menu-bar dropdown open/close,
  - Dock popover open/close,
  - an app launch (one window),
  - Mission Control with 10+ windows.
  Write `docs/captures/t21-chrome-baseline.txt` with the raw `chrome stats`,
  `frame timing`, `presentation stats`, `material stats`, and `degrade stats`
  lines plus host/GPU/driver and the exact commands.
- [ ] If a native session is available, run the same scenarios against
  `make native-capture` and include the output. If not, record the native half
  as `OPEN` in the same report; do not omit it silently.
- [ ] Record the transport decision in a new ADR (next free id; currently
  `0191`): prefer `QQuickRenderControl` + reusable GPU buffers/dmabuf for the
  GPU path, pooled `wl_shm` + frame callbacks as the fallback, and why the Qt
  Wayland platform plugin is or is not suitable for private layer surfaces.
  The ADR must include the measured numbers that justify the choice.

## Out of scope

- Fixing HiDPI or the transport (→ T184, T185, T186).
- Refresh-aware scheduling (→ T187, T188).
- Material cost/floor changes (→ T189, T190).
- Any renderer replacement. Skia/Impeller/Flutter are not candidates; the
  decision is about Qt Quick transport configuration.

## Design notes

- This is a **measurement** task. Do not change the default rendering path,
  buffer format, surface layout, or private protocol. Counters must be
  additive and opt-in.
- The baseline must distinguish **CPU work** from **presentation**:
  `frame timing` is compositor CPU duration; `presentation stats` is the
  actual vblank interval; `chrome stats` is the shell/transport cost.
- The report must state whether the shell is software-rendered. Do not assume
  it from `QT_QPA_PLATFORM=offscreen` alone; confirm with `QSG_INFO=1` and the
  process maps.
- A native capture is not required for this task, but if the native session is
  available, its `presentation stats` and `chrome stats` are the strongest
  evidence. If it is unavailable, say exactly why.
- Keep the report honest about the host: 4K @ 144 Hz is the dev panel; a
  nested run is not a native presentation measurement.

## Hand-off

Landed:

- Opt-in shell counters (`shell/src/chromestats.{h,cpp}`) behind
  `DRAGONFRUIT_CHROME_STATS=1`: `scene_frames`, `commits`, `grab_renders`,
  `shm_allocs`, `shm_bytes`, `frame_callbacks`, windowed `commit_us_*` /
  `frame_callback_us_*`, and per-surface `logical_size`, `buffer_size`,
  `buffer_scale`. Emitted as `chrome stats` / `chrome surface` lines on
  SIGUSR1 (self-pipe + `QSocketNotifier`) and clean exit; inert when unset.
- `FrameCommitGate` records the scene frames/readbacks and render-completion
  timestamp; `ShellProtocol::commitTo` records the fresh shm allocation, the
  copy bytes, and the render-completion-to-commit latency.
- Compositor `chrome stats` block in `dump_stats`: `chrome_shm_imports`,
  `chrome_shm_bytes`, `chrome_dmabuf_imports`, `chrome_frame_callbacks`, plus
  the existing `presentation stats`. Chrome imports are counted at
  above-window chrome-surface commit (the Files desktop layer is excluded).
- Numbered SIGUSR1 dumps (`SIGUSR1-<n>`) in both processes.
- `scripts/t21-chrome-baseline.sh` + driver + report generator and
  `make t21-chrome-baseline`; committed report
  `docs/captures/t21-chrome-baseline.txt` and stills
  `docs/captures/t21-chrome-baseline-{dock,menu,mission-control}.png`.
- ADR **0191** records the transport decision.
- `DF_SHELL_LOG` (dev tool, opt-in) splits the shell log from the compositor
  log so long stats lines cannot interleave. The soak/demo leak check now
  filters to the dev run's own process group, so `make e2e` can run inside a
  live native Dragonfruit session.

Measured baseline (nested, private bus, 1920×1200, `docs/captures/t21-chrome-baseline.txt`):

- Backend/API: `QSG_INFO=1` → `Loading backend software`; the shell maps
  `libEGL`/`libGLdispatch`/`libGLX` loaders but no DRI driver. Software scene
  graph, no GPU swapchain.
- Idle (5.3 s): zero shell scene frames/commits and zero compositor frames /
  client wakeups — zero-wakeup confirmed.
- Slow Dock sweep (2.7 s): 291 commits, 268,929,360 shm bytes; cadence
  193.9 scene frames/s (107.5 commits/s); `commit_us`
  p50/p95/p99 = 1069/1653/1943 µs; compositor `frame timing` p50/p95/p99 =
  10569/18445/23422 µs. The 1920×125 Dock bar is 960,000 bytes per commit
  (1920×125×4), matching the compositor's `chrome_shm_imports`/bytes exactly.
- Menu dropdown open: 68 commits / 26,307,008 bytes; commit p50/p95/p99 =
  957/1190/1393 µs. Mission Control (13 windows): 116 commits /
  130,760,400 bytes; commit p50/p95/p99 = 908/6766/7526 µs.
- `grab_renders` ≈ `commits` (the readback re-renders the scene);
  `frame_callbacks=0` and `frame_callback_us_samples=0` in both processes
  before T185.
- Nested `presentation stats` is explicitly unavailable (no hardware vblank).
  Native half: the host is already a native Dragonfruit session, but the
  running compositor is the installed release build without T-21.1a counters
  and without the synthetic-input harness; restarting it would end this
  session. Its own `presentation stats`/`frame timing` are included in the
  report, and the scenario-driven native chrome comparison is recorded
  **OPEN** for the T-21 hardware rail.
