# T186c — T-21.1d GPU transport: dmabuf ring, sync, and fallback

| | |
|---|---|
| **Track** | T-21 — Presentation foundation |

## Goal

Make the Dock dmabuf path production-safe: a small per-surface buffer ring returned by `wl_buffer.release`, resize recreation, and a correct sync policy before the compositor samples the buffer.

## Context (read first)

- Parent spec: `docs/tasks/0.1.1/reference/186-t-21.1d-gpu-backed-chrome-transport.md`.
- T186b single-buffer export/commit.
- T185 pool contract: `shell/src/chromebufferpool.{h,cpp}`, `shell/src/shellprotocol.cpp`.

## Scope

- [ ] Add a bounded 2-3 buffer per-surface dmabuf ring; `wl_buffer.release` returns a buffer to the ring; allocate only when the ring is empty or the surface size/format changes.
- [ ] Never write into a busy buffer; recreate the ring on resize/format change; keep the ring per surface, not global.
- [ ] Synchronize before the compositor samples the buffer (EGL/GL fence or explicit dmabuf sync); if only implicit sync is available, record it as a limitation and do not race.
- [ ] Fall back to T185 SHM on ring exhaustion/export/import/format failure with a `chrome stats` reason; never black.
- [ ] Add unit tests for ring reuse/busy/release/resize; nested GPU run with flat `dmabuf_buffers` after warm-up and a forced-fallback run.

## Out of scope

- Menu bar/popovers/overlays (T186d).
- Default-on or native acceptance (T191/T192).
- Multi-GPU/rotated output.

## Design notes

- Keep the Dock visual identical; this is transport only.
- The SHM path remains the contract when export is unavailable.
- Do not add a compositor-side copy to compensate.
- The ring is bounded; no per-frame allocation.

- [ ] Nested GPU and fallback captures/stats are committed; `dmabuf_buffers` is flat after warm-up.
- [ ] Hand-off filled in.
