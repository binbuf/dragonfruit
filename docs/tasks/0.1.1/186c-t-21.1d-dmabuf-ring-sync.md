# T186c — T-21.1d GPU transport: dmabuf ring, sync, and fallback

## Goal

Make the Dock dmabuf path production-safe: a small per-surface buffer ring returned by `wl_buffer.release`, resize recreation, and a correct sync policy before the compositor samples the buffer.

## Context (read first)

- Parent spec: `docs/tasks/0.1.1/reference/186-t-21.1d-gpu-backed-chrome-transport.md`.
- T186b single-buffer export/commit.
- T185 pool contract: `shell/src/chromebufferpool.{h,cpp}`, `shell/src/shellprotocol.cpp`.

## Scope

- [x] Add a bounded 2-3 buffer per-surface dmabuf ring; `wl_buffer.release` returns a buffer to the ring; allocate only when the ring is empty or the surface size/format changes.
- [x] Never write into a busy buffer; recreate the ring on resize/format change; keep the ring per surface, not global.
- [x] Synchronize before the compositor samples the buffer (EGL/GL fence or explicit dmabuf sync); if only implicit sync is available, record it as a limitation and do not race.
- [x] Fall back to T185 SHM on ring exhaustion/export/import/format failure with a `chrome stats` reason; never black.
- [x] Add unit tests for ring reuse/busy/release/resize; nested GPU run with flat `dmabuf_buffers` after warm-up and a forced-fallback run.

## Out of scope

- Menu bar/popovers/overlays (T186d).
- Default-on or native acceptance (T191/T192).
- Multi-GPU/rotated output.

## Design notes

- Keep the Dock visual identical; this is transport only.
- The SHM path remains the contract when export is unavailable.
- Do not add a compositor-side copy to compensate.
- The ring is bounded; no per-frame allocation.

## Done when

- [x] `make e2e` and `make qml-test` pass.
- [x] The ring/busy/release unit tests pass.
- [x] Nested GPU and fallback captures/stats are committed; `dmabuf_buffers` is flat after warm-up.
- [x] Hand-off filled in.

## Hand-off

**Landed.** The Dock dmabuf path is now a bounded three-slot per-surface ring:

- `ChromeDmabufRing` (in `shell/src/chromedmabuf.{h,cpp}`) owns the slot
  lifecycle: acquire, serial-tagged busy, release, abandon, size/format
  generation retirement, and bounded allocation/reuse counters. It never
  reuses a busy or retired slot.
- `GpuChromeFrameProducer` owns one FBO/export per slot. `exportFrame()` picks
  a free slot, renders once, syncs, caches the slot's dmabuf, and returns
  `ChromeDmabufFrame{slot, serial}`. `releaseDmabufFrame()` is the
  `wl_buffer.release` return path; `abandonDmabufFrame()` handles a
  deferred/failed commit. A resize/format change retires the old generation;
  free retired slots are destroyed now, busy ones after release.
- `ShellProtocol` keeps one reusable `wl_buffer` per `(surface, slot)` and
  emits `dmabufReleased(surface, slot, serial)` from `wl_buffer.release`.
  Serial changes no longer recreate the buffer; only slot size/format changes
  or import failures do. Import params/owners carry the slot.
- Sync: after each render the producer waits on a GL fence
  (`glFenceSync`/`glClientWaitSync`, 100 ms bound); if fences are unavailable
  it uses `glFinish`. A timed-out fence records `sync-timeout` and the frame is
  not committed. The compositor offers only implicit dma-buf sync (no
  `linux-drm-syncobj-v1`), so the exported buffer carries the driver's implicit
  dma-fence and the GL fence closes the producer-side race. This is recorded
  as the current sync limitation in ADR 0196 and `04-shell.md`.
- Fallback: ring exhaustion reads back the last complete frame and commits it
  through the T185 shm pool for that frame, records `ring-exhausted`, keeps the
  dmabuf rail enabled, and retries on release. Export/import/format failures
  abandon the rail for the session. Both are `dmabuf_fallbacks` with a
  `gpu_reason`; no path goes black.
- `chrome stats` now reports `dmabuf_buffers`, `dmabuf_allocs`,
  `dmabuf_reuses`, `dmabuf_sync`, `dmabuf_sync_waits`, and
  `dmabuf_sync_timeouts` globally and (for the first three) per surface.
- `scripts/t21-dmabuf-dock.sh` / `make t21-dmabuf-ring` drives two synthetic
  Dock sweeps and two `SIGUSR1` dumps, asserting flat `dmabuf_buffers` and
  `dmabuf_allocs` while commits/reuses advance. `make t21-dmabuf-dock` remains
  an alias. New artifacts: `docs/captures/t21-dmabuf-ring.txt`,
  `t21-dmabuf-ring.png`, `t21-dmabuf-ring-fallback.png`.

**Deviations / limits.** The ring is three slots, the maximum of the requested
2–3. Ring exhaustion is a counted transient fallback rather than a deferred
frame: the task explicitly asked for the T185 shm fallback on exhaustion, and
the capture records `gpu_reason=ring-exhausted` under the fast synthetic sweep.
The rail stays enabled and the next frame returns to dmabuf. Only implicit
dma-buf sync exists on this compositor; explicit `linux-drm-syncobj-v1` is not
advertised. The menu bar/popovers/overlays remain shm until T186d.
