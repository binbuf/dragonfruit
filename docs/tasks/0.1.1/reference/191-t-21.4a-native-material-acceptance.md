## Goal

Prove the default-on native material on the real DRM rail: the scene texture,
Kawase blur, glass compose, HiDPI chrome, and fallback behavior all work on
actual hardware without a black frame, crash, cursor loss, or input-lag spike.
This is the functional/visual gate that nested captures cannot satisfy.

## Scope

- [ ] Rebuild and install the release profile with **no material env flags**:
  `make native-rebuild`. Confirm the installed and running binaries are
  release, not debug, and the native session is the release profile.
- [ ] Capture a startup snapshot with `make native-capture`; read the latest
  report and record:
  - `material stats`: `path=gpu`, `blur_passes>0`, `blur_panels>=1`,
    `blur_draws>0`, `backdrop_skipped=0`;
  - `degrade stats`: `full` or `reduced`, not `minimal` at idle;
  - `presentation stats`: output name, mode, `refresh_hz`, `budget_us`,
    `missed`;
  - `chrome stats` (from T183/T185/T186): `path`, copies, frame callbacks.
- [ ] Visual sweep on the native seat:
  - light and dark wallpaper; Dock/menu bar over live content (video or
    moving window),
  - Dock magnification sweep, app launch, Dock popover, menu bar dropdown,
  - Applications drawer, Control Center, notification banner, OSD,
  - Mission Control with 10+ windows, multi-window minimize/restore,
  - fullscreen video/game (direct scanout where expected), lock/unlock.
- [ ] Confirm the blur samples **live** content behind the Dock/menu bar (move
  a bright window under the bar and observe the change), not a static image.
- [ ] Capture native visual evidence:
  - prefer a trusted, explicitly enabled capture path through the existing
    portal architecture or an isolated development-only KMS readback tool,
  - if that is not available, use external photographs/video of the actual
    panel plus the native diagnostics,
  - never label a nested screenshot as native proof.
- [ ] Record the exact evidence boundary: which stills are native, which are
  nested reference, and which claims are diagnostics-only.
- [ ] Exercise the rollback once: `DRAGONFRUIT_DRM_MATERIAL=0 make native-rebuild`
  (or `DRAGONFRUIT_DRM_GLASS=0`) and confirm the feather/milky fallback starts;
  then restore the default with `make native-rebuild`.
- [ ] If no free seat/VM is available, write an explicit
  `docs/captures/t21-native-material.open.txt` naming the blocker and the

## Out of scope

- Quantitative benchmark/soak (→ T192).
- Multi-GPU/rotated-output material (existing fallback; T193 records it).
- New material design or chrome features.
- A general-purpose screencopy protocol; the no-screencopy rule stays.

## Design notes

- `path=gpu` alone is not proof. Accept only `blur_draws>0` plus a visible
  live sample behind the panel.
- The default-on material path is single-GPU, normal-transform, local-route
  only (ADR 0189). A multi-GPU or rotated seat may legitimately fall back; if
  so, record the fallback reason and do not claim native glass for that output.
- Native capture is an evidence problem, not a reason to add unrestricted
  client screenshot access. The portal/trusted path or external evidence is
  acceptable; a nested screenshot is not.
- A failed material frame disables the sampled path for the session and the
  shell receives the fallback state. If that happens, record the trigger and
  the fallback; do not restart-loop to hide it.
- Cursor/fullscreen regressions are part of acceptance: the material path must
  not break hardware cursor assignment or direct scanout.
- The release profile matters on 4K/high-refresh panels; a debug run is not
  native acceptance evidence.
- If the session cannot start after a profile/material change, use
  `make native-recover` from a TTY before retrying. Do not leave the host
  preselect or runtime environment broken.

## Acceptance criteria

- [ ] Native `material stats` shows `path=gpu`, `blur_passes>0`,
  `blur_panels>=1`, `blur_draws>0`, and `backdrop_skipped=0`.
- [ ] The Dock/menu-bar blur visibly samples live content behind it in light
  and dark; the glass rim/refraction is present at the configured tier.
- [ ] No black frame, compositor crash, cursor loss, input-lag spike, or
  unhandled fallback during the full sweep.
- [ ] HiDPI chrome is sharp at the native scale (1x, 1.5x, or 2x as available);
  no compositor upscale blur.
- [ ] Fullscreen video/game behaves as expected (direct scanout where no chrome
  overlaps; no tearing/stall at the transition).
- [ ] The native evidence report states exactly what is native vs nested and
  includes the capture paths/commands.
- [ ] If hardware is unavailable, the `OPEN` artifact is committed with the
  exact blocker and rerun command.
