## Goal

Produce the quantitative evidence the architecture review asked for: Dock-sweep
frame-time p50/p95/p99, missed presentations, CPU-to-GPU copies, GPU render
time, idle wakeups, and compositor stability over an extended session. Compare
the v0.1.1 transport/scheduling/material changes against the T183 baseline.
Averages alone are not acceptance evidence.

## Out of scope

- Fixing regressions found here (file them as follow-ups; T193 records them).
- Packaging/driver-matrix breadth (T-16 hardware rail).
- New visual features or material design.
- A renderer comparison benchmark (Skia/Impeller/Flutter are out of scope).

## Design notes

- Report **p50/p95/p99** for compositor CPU frame duration, shell commit cost,
  and presentation interval; report missed deadlines as a count and a
  percentage. An average hides exactly the stutter this track exists to fix.
- Keep nested and native rows separate. Nested is useful for A/B on the same
  host; it is not native presentation evidence.
- GPU timer queries can perturb the result; run one warm-up pass and report
  whether queries were enabled. If the extension is missing, say so.
- The soak must include at least one idle settle after the animation to prove
  zero damage/wakeups; a busy loop that never idles is not enough.
- Memory growth must be compared at the same mode/scale and after warm-up.
  A one-time allocation at startup is not a leak.
- A regression in p95/p99 must be explained (e.g. more blur work) or fixed
  before T193; do not average it away.
- Use the existing `DRAGONFRUIT_FRAME_TRACE=1`, `DRAGONFRUIT_FRAME_BUDGET_US`,
  and synthetic-input hooks; do not add a second benchmark harness.

## Acceptance criteria

- [ ] The benchmark report contains the required scenarios and hardware, with
  p50/p95/p99, missed %, copy bytes, GPU time (or an explicit unavailable
  note), and idle/soak results.
- [ ] A Dock sweep at 144 Hz reports the real 6.94 ms deadline and a missed
  count; a 60 Hz run reports 16.67 ms. A 60 Hz animation on 144 Hz is not
  reported as healthy.
- [ ] The GPU-backed path shows zero CPU copies/readbacks in `chrome stats`;
  the fallback path shows at most one full-surface copy per frame.
- [ ] A 30–60 minute soak shows no unbounded RSS/GPU/fd/thread growth and no
  compositor crash/restart.
- [ ] Idle after the animation settles shows zero damage, zero client wakeups,
  and no new presentation samples.
- [ ] Baseline-vs-after deltas are recorded for the same scenarios; any
  regression is explained or filed.
- [ ] If hardware is unavailable, the OPEN artifact is committed with the
  exact blocker and rerun command.
