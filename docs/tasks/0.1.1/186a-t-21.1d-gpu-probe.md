## Hand-off

### What landed

- **Pure capability layer** — `shell/src/gpuchromecapabilities.{h,cpp}`:
  linux-dmabuf feedback-table parsing (16-byte format/padding/modifier
  records), EGL extension parsing, and deterministic format selection
  (`ABGR8888` then `ARGB8888`; linear, first explicit modifier, then
  `DRM_FORMAT_MOD_INVALID`). Unit test: `shell/tests/tst_gpucapabilities.cpp`.
- **Read-only runtime probe** — `shell/src/gpuchromeprobe.{h,cpp}` binds
  `zwp_linux_dmabuf_v1` (v4/v5 feedback) on the shell's existing `wl_display`
  through a temporary registry, copies the format table, queries the EGL
  export/import extensions on the same display, and logs one
  `chrome gpu probe (startup): ...` line plus a bounded format list. No
  `wl_buffer` is created or committed. `ShellProtocol::gpuCapabilities()`
  exposes the typed result for T186b.
- **GPU producer skeleton** — `shell/src/gpuchromeframeproducer.{h,cpp}` is a
  `ChromeFrameProducer` subclass (`Construction::External`) owning a
  `QOpenGLContext`, `QOffscreenSurface`, `QQuickRenderControl`, hidden
  `QQuickWindow`, reusable `QOpenGLFramebufferObject`, and a
  `QQuickRenderTarget` with `setDevicePixelRatio()`. The T185 producer's
  `window()/resize()/renderFrame()` became virtual; `gpuActive()` and
  `fallbackReason()` were added.
- **Nested GL smoke rail** — `shell/tests/t21-gpu-smoke.cpp` renders one
  inline QML scene at 160x90 logical / 320x180 physical (DPR 2), checks the
  four quadrant pixels, writes the PNG, and logs the probe. It has
  `--expect-fallback` for the no-GL rail. `scripts/t21-gpu-probe.sh`
  (`make t21-gpu-probe`) starts one nested compositor, runs both rails, and
  writes `docs/captures/t21-gpu-probe.txt` + `t21-gpu-smoke.png`.
- **Protocol** — vendored MIT `linux-dmabuf-unstable-v1.xml` (v5) under
  `protocols/wayland-protocols/`, generated into `build/protocols/` by the
  shell CMake. The private layer protocol is unchanged.
- **Docs** — new ADR 0194; R2.3 in `docs/rendering.md`; the shell known-limits
  note in `docs/design/04-shell.md`; `docs/captures/README.md`.

### Deviations / decisions

- The GPU producer is **not instantiated by the shell** in T186a. The normal
  path stays on T185 shm, `DRAGONFRUIT_CHROME_GPU` is unset by default, and
  no production commit path exists. The skeleton is exercised by the smoke
  rail, which is what the task scoped.
- The shell's forced `QT_QPA_PLATFORM=offscreen` cannot create a GL context.
  The nested GL smoke runs with `QT_QPA_PLATFORM=wayland` (Qt-side connection
  only; private chrome surfaces stay on the shell's libwayland connection).
  A `DRAGONFRUIT_CHROME_GPU=1` shell on the offscreen rail cleanly records
  `fallback reason=no-gl-context`.
- Key spike finding: `QQuickRenderControl`'s OpenGL RHI backend creates a
  **share context** and leaves it current after `initialize()`. FBOs and
  render targets must be created/read on that context, not on the context
  created and made current by the caller. Forcing the original context
  current produced a valid but fully transparent frame. The producer now
  stores `QOpenGLContext::currentContext()` after initialize and uses it for
  all GL work.
- "Whether the nested compositor imports dmabuf" is recorded as
  `compositor_import=advertised` from the global + non-empty feedback table,
  because T186a deliberately creates no buffer. The compositor exit stats show
  `chrome_dmabuf_imports=0`, confirming no commit path ran.
