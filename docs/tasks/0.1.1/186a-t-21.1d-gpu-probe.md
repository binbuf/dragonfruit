## Goal

Prove the GPU offscreen path and the compositor dmabuf capabilities on the nested GL rail. End with a working `QQuickRenderControl` GPU render and a logged capability verdict, but no production commit path.

## Context (read first)

- Parent spec: `docs/tasks/0.1.1/reference/186-t-21.1d-gpu-backed-chrome-transport.md`.
- T185 abstraction: `shell/src/chromeframeproducer.{h,cpp}`, `shell/src/shellprotocol.{h,cpp}`.
- Compositor dmabuf import and `zwp_linux_dmabuf_v1` feedback: `compositor/src/render.rs`, `compositor/src/state.rs`.
- T183/T185 stats: `shell/src/chromestats.{h,cpp}`.

## Scope

- [ ] Add a `GpuChromeFrameProducer` skeleton behind the T185 abstraction: OpenGL/RHI context, offscreen surface, `QQuickRenderControl`, hidden `QQuickWindow`, reusable FBO/`QQuickRenderTarget`, and device-pixel-ratio handling.
- [ ] Probe and log: `zwp_linux_dmabuf_v1` feedback, EGL export extension (`EGL_MESA_image_dma_buf_export` or equivalent), supported formats/modifiers, and whether the nested compositor imports dmabuf.
- [ ] Render one QML scene once and verify the pixels/DPR in a nested GL smoke run; no `wl_buffer` commit yet.
- [ ] Add a pure capability/format-selection unit test and keep `DRAGONFRUIT_CHROME_GPU` unset by default.

## Out of scope

- dmabuf export/commit and the Dock path (T186b).
- Rollout to all surfaces (T186c).
- Native acceptance (T191).

## Design notes

- Do not force a backend switch: the nested rail is GL, the software rail must stay on T185 SHM.
- A failed probe must be a clean fallback with a recorded reason, never a black surface.
- Keep the private layer protocol unchanged.
