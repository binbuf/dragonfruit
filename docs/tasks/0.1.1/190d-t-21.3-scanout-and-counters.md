## Hand-off

### What landed

- **Fullscreen chrome suppression + policy.** A settled fullscreen client that
  covers an output owns it; `DfState::visible_chrome_surfaces` hides the
  persistent `top` menu bar/Dock while transient `overlay` chrome (OSD, menus,
  notifications, popovers) still composites. The pure
  `window::scanout::direct_scanout_candidate` is the skip decision: fullscreen
  rect covers the output and no visible material panel intersects it. Render,
  input hit-testing, and `query scale` use the visible list; frame-callback
  bookkeeping and preferred-scale updates keep the unfiltered list so hidden
  chrome never waits forever.
- **Counters.** `material_frames` and `direct_scanout_candidates` are reported
  separately from `direct_scanouts`; `scanout stats` carries all three.
  `output material stats` adds the monotonic per-output split
  (`material_frames`, `direct_scanouts`, `direct_scanout_candidates`,
  `material_allocations`, last `material_region_px`/`material_region`). The
  real `direct_scanouts` is still advanced only from
  `PrimaryPlaneElement::Element`; nested records candidates and never fakes a
  scanout.
- **Evidence.** `make t21-scanout-counters` writes
  `docs/captures/t21-scanout-counters.txt`: 4K `MaterialRegion` arithmetic
  (Dock-only 2608x149 = 388 592 px vs 8 294 400 px full output; menu-bar +
  Dock union is the full output), a settled-Dock capture with two material
  snapshots asserting `material_allocations`/`material_region_px` flat, and a
  settled fullscreen capture where the bars are hidden, `material_frames` is
  flat, and `direct_scanout_candidates` advances. Stills:
  `t21-scanout-settled-1x.png`, `t21-scanout-fullscreen-1x.png`; stats:
  `t21-scanout-*-stats.txt`.
- **Native runner.** `make t21-direct-scanout-native` starts the DRM
  compositor on a free seat with an output-sized client and asserts the real
  `direct_scanouts>0`. This host's live session owns DRM master, so it wrote
  `docs/captures/t21-direct-scanout.open.txt` (probe + rerun) instead of a
  fake counter.
- **Docs.** ADR 0210, `docs/rendering.md` R1.3/R1.4,
  `docs/design/02-compositor.md`, `docs/captures/README.md`.

### Deviation / remaining work

- The committed nested trace cannot show `direct_scanouts>0`: the nested
  backend has no DRM primary plane. The real hardware trace is the explicit
  `t21-direct-scanout.open.txt`; T191a must run
  `make t21-direct-scanout-native` on a free seat and commit
  `docs/captures/t21-direct-scanout.txt` with `direct_scanouts>0`. No counter
  was faked.
- Fullscreen chrome auto-reveal is not implemented; the bars stay hidden until
  fullscreen exits. The shell still renders/commits hidden top chrome; the
  compositor filters it and answers its callbacks (transport optimization is a
  follow-up).
