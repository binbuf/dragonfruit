`ShellController::start()` (`shell/src/shellcontroller.cpp:1497`) and the whole
block is guarded by `qEnvironmentVariableIsSet(...)`. When unset, no timer is
created and no capture code runs. When set, it only schedules
`m_protocol->captureScreenshot(...)` on the existing trusted compositor
capture request; it does not enter the chrome producer, commit, or pacing
paths. `scripts/t21-live-capture.sh` is the only caller in the tree and it is
a capture script, not part of `make build`/`make e2e`. The extra
`ScreenshotBridge::checkService()` `qInfo` line is diagnostic only and does not
change normal chrome behavior.
