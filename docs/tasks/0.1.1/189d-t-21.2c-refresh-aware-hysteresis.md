## Goal

Make the 12/180 hysteresis refresh-aware so it does not flap or recover too quickly at 120/144 Hz.

## Context (read first)

- Parent spec: `docs/tasks/0.1.1/reference/189-t-21.2c-persistent-chrome-material-floor.md`.
- T189b per-role shell application.
- Degrade controller hysteresis.

## Scope

- [x] Replace fixed frame counts with time windows or period-scaled counts; keep 12/180 at 60 Hz as the reference.
- [x] Prevent Full↔Reduced oscillation during a steady pointer sweep.
- [x] Add forced-tier/load tests that pin Full, Reduced, and Minimal and verify the effective per-role state and shell properties.
- [x] Commit a load trace and docs/ADR updates.

## Out of scope

- Panel-region material cost (T190).
- New material design or tokens.

## Hand-off

### What landed

- `compositor/src/window/degrade.rs`: the fixed 12/180 frame counts are now
  wall-clock windows — `DOWNGRADE_WINDOW = 200 ms`, `UPGRADE_WINDOW = 3 s`
  (the 12/180 reference at 60 Hz). The EMA and 0.75 recovery ratio are
  unchanged. A downgrade within 10 s of an upgrade across the same boundary
  latches that boundary; recovery then needs `EMA < 0.4 × budget` for 10 s.
  A successful upgrade clears the latch; `force`/`release` reset the
  selection memory. `degrade stats` / `query degrade` add
  `down_window_us=200000`, `up_window_us=3000000`, and `latched=0|1`.
- `compositor/src/input/synthetic.rs`: `set degrade-frames <count>
  <microseconds>` feeds the real `observe_rendered_frame` path for headless
  load tests (test plumbing; no parallel controller).
- Tests:
  - pure 60/120/144 Hz window timing and a 60 s steady sweep bounded to
    `downgrades=2 upgrades=1 latched=1` at every rate, then idle recovery;
  - `shell_protocol_conformance::material_role_state_follows_a_refresh_aware_load_sequence`
    drives the headless compositor through steady over-budget, recovery,
    settle, sweep, flap, 20 s latched hold (no role events), idle recovery,
    and forced Reduced/Minimal/Full, asserting the per-role state each time;
  - `tst_materialpolicy`, `tst_dock`, and `tst_menubar` load-sequence cases
    drive the same policy through Full → Reduced → floor-missed → Reduced →
    Full on an already-created scene in light and dark.
- Load trace: `scripts/t21-degrade-load.sh` (`make t21-degrade-load`) writes
  `docs/captures/t21-degrade-load.txt` (doctor preflight, pure 60/120/144 Hz
  windows and sweeps, headless compositor role sequence, shell test result).
- Docs: ADR `0206-refresh-aware-hysteresis.md`, `rendering.md` R4.2,
  `02-compositor.md`, `04-shell.md`, `STATUS.md` G-12, `captures/README.md`,
  `docs/v0.1.1/progress/T189d.md`.

### Deviations

- The committed load trace is a deterministic headless simulation, not a
  nested/host capture. The task's design note makes `make t21-doctor` a
  preflight for host/nested runs; the script still runs it and records
  `PASS: 0 warning(s)`. A live 60 s Dock sweep belongs in the T191/T192 native
  evidence, where the real `degrade stats` counters can be compared.
- The latch is a bounded backoff, not a cost predictor. A pathological
  tier-cost ratio can still flap once per latch window; the steady-sweep test
  and trace cover the realistic case and `degrade stats` makes any residual
  flapping visible. No fallback-ladder or token changes were made.
