## Hand-off

### What landed

- New pure module `compositor/src/presentation.rs` (exported as
  `dragonfruit_compositor::presentation`):
  - `PresentationClock { last_presented, next_deadline, period, refresh_hz,
    vrr }` with `new(OutputRefresh)`, `with_period(Duration, VrrState)`,
    `set_refresh`, `note_presented(timestamp)`, `is_idle()`, `is_due(now)`,
    and `time_until_due(now)`.
  - `PresentationClocks`, a deterministic name-keyed map with `update`,
    `remove`, `clear`, `get`, `get_mut`, `note_presented`, `iter`, `len`,
    `is_empty`.
- `DfState` owns `presentation_clocks`; add/mode-change/resume install the
  effective refresh (including the diagnostic override), remove drops it, and
  a presentation racing removal is ignored rather than resurrecting a stale
  clock.
- DRM `frame_finish()` records the kernel monotonic vblank timestamp (or the
  compositor-clock fallback) only when `frame_submitted()` confirms a queued
  frame. Nested records `state.clock.now()` immediately after a successful
  damage `submit()`; the no-damage swap is not a presentation.
- Semantics: `note_presented(t)` sets `next_deadline = t + period`; a missed
  deadline stays due and re-anchors on the next presentation (no catch-up
  burst); a never-presented clock is due for its first frame and has no
  samples. Stale timestamps are ignored. `with_period(Duration::ZERO)` falls
  back to 60 Hz and out-of-range periods clamp to 24–500 Hz.
- Docs: ADR `0200-per-output-presentation-clock.md`, the animation-clock
  section of `docs/design/02-compositor.md`, `docs/rendering.md` R3.2, and
  `docs/design/STATUS.md` G-02. Progress notes in
  `docs/v0.1.1/progress/T188a.md`.

### Deviations

- None from the task scope. Scheduling, timers, frame requests, and render
  gates are deliberately unchanged; T188b consumes the new clock.
- The nested timestamp is documented as the `submit()` completion proxy
  because Smithay's winit `submit()` returns no platform timestamp. It is
  only recorded for a damage frame.
