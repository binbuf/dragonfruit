# T185 — T-21.1c Chrome SHM transport hygiene and frame pacing

| | |
|---|---|
| **Track** | T-21 — Presentation foundation |
| **Release** | v0.1.1 |
| **Depends on** | T183, T184 |
| **Blocks** | T186, T188 |
| **Hardware** | no |

## Goal

Make the fallback chrome transport cheap and correctly paced: render each QML
scene **once** per frame instead of rendering and then re-rendering it inside
`grabWindow()`, reuse a small pool of `wl_shm` buffers instead of allocating a
fresh one per commit, and drive QML updates from the compositor's
`wl_surface.frame` callbacks instead of a free-running timer.

This is the fallback contract for T186: when GPU/dmabuf export is unavailable,
the shell must still present correctly, with at most one full-surface CPU copy
per committed frame.

## Context (read first)

- `shell/src/shellcontroller.cpp` — `onDockAfterRendering()`,
  `renderDock()`, `render()`, and every other `render*()` path call
  `grabWindow()` after a scene-graph frame. `grabWindow()` renders the scene a
  second time; `FrameCommitGate` exists only to suppress the re-entrant
  `afterRendering`.
- `shell/src/shellprotocol.cpp` — `commitTo()` allocates a fresh memfd/
  `/dev/shm` buffer, `mmap`s, `memcpy`s, creates a `wl_shm_buffer`, attaches,
  damages the whole surface, and commits. It never waits for
  `wl_buffer.release`.
- `shell/src/framecommitgate.h` — the double-render workaround.
- `compositor/src/render.rs` — `post_repaint()` sends frame callbacks to
  windows only; `update_chrome_preferred_scale()` already visits chrome.
- `compositor/src/backend/drm.rs` — the no-damage path calls
  `render::send_frame_callbacks()`; it must also answer chrome callbacks.
- `docs/rendering.md` — R2.3 (remove full-surface copies).
- `docs/design/architecture-audit-native-rendering.md` — §5 (copies,
  allocations, no frame pacing).
- T183's `chrome stats` counters and baseline report.

## Scope

- [ ] Introduce one chrome frame producer abstraction (e.g.
  `ChromeFrameProducer` / `ChromeSurface`) used by every shell surface. It
  should own a `QQuickRenderControl`-backed offscreen scene using the backend
  confirmed by T183 (software or GL/RHI) and render exactly once per requested
  frame.
- [ ] Replace the `afterRendering → grabWindow()` double render in the Dock,
  menu bar, and popover paths first, then the other chrome surfaces. If a
  specific QML feature cannot render through `QQuickRenderControl` on the
  software backend, keep that surface on the old path and record the exception;
  do not silently double-render it.
- [ ] Add a per-surface `wl_shm` buffer pool:
  - N buffers (start with 2–3) reused across commits,
  - `wl_buffer.release` returns a buffer to the pool,
  - allocate only when the pool is empty or the surface size changes,
  - keep the pool bounded; never grow it without a corresponding release,
  - reuse `wl_shm_pool`/fd where practical; `memfd`/`mmap` only on allocation.
- [ ] Add `ShellProtocol::requestFrame(wl_surface *)` and a
  `framePresented(surface, time)` signal. Request the callback before the
  commit that should be paced; on the callback, schedule the next QML render.
- [ ] In the compositor, send chrome frame callbacks in `post_repaint()` and in
  the no-damage `send_frame_callbacks()` path. Count them in the T183
  `chrome_frame_callbacks` counter.
- [ ] Damage only the changed region where the shell can compute it; at
  minimum stop damaging the whole buffer when the scene did not change.
- [ ] Retire `FrameCommitGate` from the paths that no longer need it. Keep it
  only if a surface still uses `grabWindow()`; document why.
- [ ] Keep the private layer protocol and surface roles unchanged; the shell
  must remain independently restartable.

## Out of scope

- GPU/dmabuf rendering (→ T186).
- Per-output refresh scheduling (→ T187, T188).
- Compositor material cost (→ T190).
- New chrome visuals or layout changes.

## Design notes

- `QQuickRenderControl` renders a `QQuickWindow` scene without showing a
  platform window. It is the supported offscreen path; `grabWindow()` is not
  a frame source. Use `QQuickRenderControl::render()` and read the result from
  the render target, not `QQuickWindow::grabWindow()`.
- Do not force a backend switch in this task. T183's `QSG_INFO=1` evidence
  decides whether the confirmed backend is software or GL/RHI; the render
  control path must use it. T186 handles GPU dmabuf export.
- The buffer pool must be per surface, not one global pool: a Dock commit must
  not wait on a menu-bar buffer, and a surface resize must not invalidate
  another surface's buffers.
- Frame callbacks are presentation-paced: request the next frame after the
  compositor has presented the previous one. Do not busy-loop or use a 16 ms
  timer as the animation source.
- Send chrome callbacks with the presenting output as the primary scan-out
  output and without the window path's 1 s throttle; a chrome surface waiting
  on its callback is the shell's pacing source.
- Keep a safety timeout: if a compositor never answers a frame callback (a
  broken/degraded session), do not freeze the shell forever. A bounded
  fallback tick may render, but it must be visible in `chrome stats`.
- `wl_buffer.release` can arrive after the shell has moved on; never write into
  a buffer still marked busy.
- The buffer format remains `ARGB32_Premultiplied`/`WL_SHM_FORMAT_ARGB8888`
  unless a later task changes it. Avoid `convertToFormat` when the image is
  already in that format.
- The compositor's `render_elements_from_surface_tree` already honors damage
  and buffer release; do not add a compositor-side copy to compensate.

## Acceptance criteria

- [ ] In a Dock sweep, the Dock and menu-bar paths make **zero**
  `grabWindow()` calls (`chrome stats grab_renders=0`), and the scene is
  rendered once per committed frame.
- [ ] Steady-state animated Dock frames allocate **zero** new SHM buffers after
  warm-up (`shm_allocs` flat), and the pool stays within its bound.
- [ ] One animated Dock frame performs at most one full-surface CPU copy into
  the buffer; the report records bytes/frame before (T183) and after.
- [ ] The shell consumes `wl_surface.frame` callbacks; `chrome stats
  frame_callbacks` advances with presented chrome frames, and QML animation is
  no longer driven by a free-running 16 ms timer on the converted surfaces.
- [ ] No stale/tearing/black frames after rapid Dock magnification, popover
  open/close, menu open/close, or a surface resize.
- [ ] The private layer protocol is unchanged and the shell still restarts
  cleanly after a kill.
- [ ] If a surface cannot move to `QQuickRenderControl`, it is named in the
  Hand-off with a measured reason; the task is not silently partial.
