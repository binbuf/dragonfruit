## Goal

Apply the per-role material state to the persistent Dock and menu bar from one policy source. The popup/overlay family is T189c.

## Context (read first)

- Parent spec: `docs/tasks/0.1.1/reference/189-t-21.2c-persistent-chrome-material-floor.md`.
- T189a role-keyed protocol state.
- Shell material consumers: `shell/dock`, `shell/menubar`, popover/overlay QML, `shell/src/shellcontroller.cpp`.

## Scope

- [x] Read the role-keyed state in the shell and apply it to the Dock and menu bar from one policy source.
- [x] Verify the persistent roles never fall below `Reduced` while the sampled path is available, and use the milky fallback when even `Reduced` misses.
- [x] Add/extend `tst_dock` and `tst_menubar` tests and commit forced Full/Reduced/Minimal Dock/menu captures in light and dark.

## Out of scope

- Popup/overlay coverage (T189c).
- Refresh-aware hysteresis (T189d).
- Panel-region material cost (T190).
- New visual design.

## Design notes

- One effective state per role; no QML policy duplication.
- Keep the existing token values.
- The software path stays deterministic.

## Done when

- [x] `make qml-test` and `make e2e` pass.
- [x] The Dock and menu bar have a verified fallback.
- [x] Forced-tier captures are committed.
- [x] Hand-off filled in.

## Hand-off

**Landed**

- Added `shell/src/materialpolicy.{h,cpp}`, the one shell-side application
  policy for the v4 role table. `MaterialPolicy::applied(role)` returns a
  known role's state, falls back to the legacy v3 global snapshot only for a
  role that has not received a v4 state, forces `blurActive=false` for any
  explicit fallback reason (including `floor-missed`), and guards a persistent
  `Minimal` with no fallback into `tier=reduced`, `blur=false`,
  `fallback=floor-missed`. Token values and QML fallback fills are unchanged.
- `ShellProtocol` now exposes `materialRoleKnown(role)` so startup can seed
  the policy from role events already dispatched during authentication.
  `ShellController` owns one `MaterialPolicy`, seeds it before the first
  scene, applies `Chrome` to the menu bar and `Dock` to the Dock before their
  first commit, and connects `materialRoleStateChanged`. The legacy
  `materialStateChanged` event remains the compatibility path and cannot
  overwrite a known role.
- Extended `tst_dock.qml` and `tst_menubar.qml` with forced
  Full/Reduced/Minimal role-state cases in light and dark, including the
  persistent `floor-missed` and software fallbacks. Added
  `tst_materialpolicy` for the policy precedence, floor guard, and milky
  fallback.
- Added `scripts/capture-t21-material-tiers.sh` + driver and
  `make t21-material-tiers-capture`. It uses the compositor's own capture
  fixture (the host has no working `spectacle`) and reuses/restores the
  running settingsd scheme. Committed 12 crops and 4 review sheets plus
  `docs/captures/t21-material-tiers.txt`:
  - `docs/captures/t21-material-{menubar,dock}-{full,reduced,minimal}-{light,dark}.png`
  - `docs/captures/t21-material-{menubar,dock}-tiers-{light,dark}.png`
- Fixed the `DF_SCREENSHOT_CAPTURE_FIXTURE` seam to convert its logical output
  rect to physical pixels before `captureScreenshot`, matching the real
  screenshot path at 1.5x/2x.
- Docs: ADR 0204, `docs/design/04-shell.md`, `docs/design/02-compositor.md`,
  `docs/rendering.md` R4.3/R4.4, `docs/design/STATUS.md` G-12,
  `docs/captures/README.md`.

**Deviations**

- The capture path is the compositor capture fixture rather than `spectacle`;
  `spectacle` fails on this host session. The script still produces the
  required per-surface crops and records the forced `query degrade` state.
- The script temporarily sets the host settingsd's `appearance.colorScheme`
  (restoring the original value in `cleanup`) so the QML Theme and compositor
  scheme agree; a scratch settingsd is started only when none owns the bus.
