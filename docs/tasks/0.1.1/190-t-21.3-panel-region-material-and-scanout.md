# T190 — T-21.3 Panel-region material and direct-scanout preservation

| | |
|---|---|
| **Track** | T-21 — Presentation foundation |
| **Release** | v0.1.1 |
| **Depends on** | T189 |
| **Blocks** | T191, T192 |
| **Hardware** | optional (4K iGPU is the cost rail; native in T191/T192) |

## Goal

Stop paying for a full-output scene texture and a full-output material
composite when only the Dock/menu-bar panels need blur. Render the scene only
in the union of the material panels plus blur padding, keep the scene/panel
elements' IDs stable across frames, and preserve direct scanout for an
unobstructed fullscreen client. The visual result at the panel must stay
pixel-equivalent to the current full-output path.

## Context (read first)

- `compositor/src/backend/nested.rs` — `render_scene_offscreen()` allocates an
  output-sized `GlesTexture` and renders the full scene every frame;
  `blur_panel_texture()` samples a panel region of that texture.
- `compositor/src/backend/drm.rs` — the DRM two-pass path (`render_surface()`)
  uses the same full-output scene texture, then builds `BackdropBlurElement`s
  and `SceneTextureElement`; `DrmMaterialCache` owns the textures.
- `compositor/src/render.rs` — `chrome_blur_panels()` returns `BlurPanel {
  panel, spec, glass }`; `chrome_backdrop_render_elements()` is the feather
  fallback.
- `compositor/src/window/blur.rs` — `BackdropBlurElement` and
  `SceneTextureElement` create a new `Id::new()` per frame; `BackdropBlurElement`
  maps panel spans into the texture.
- `compositor/src/window/degrade.rs` — `BlurSpec` radius/iterations; the
  padding must come from the spec, not a literal.
- `docs/rendering.md` — R1.1 (panel-region scene rendering), R1.2 (stable IDs),
  R1.3 (allocation/sync audit), R1.4 (direct-scanout policy).
- `docs/design/architecture-audit-native-rendering.md` — §8 (resource and
  synchronization risks), §7.3 (direct scanout loss).
- T192 — the benchmark that measures the before/after cost.

## Scope

- [ ] Add a pure `MaterialRegion` helper:
  - union of every `BlurPanel.panel` on the output,
  - expand by the blur spec's padding (radius/iteration-derived; no literal),
  - clamp to the output rectangle,
  - return the region rect and texture size; unit-test empty, single-panel,
    multi-panel, clipped-at-edge, and scale/rounding cases.
- [ ] Render the scene into a region-sized texture (or update a cached full
  scene only in damaged regions) instead of the full output. Keep the scene
  texture in output coordinates for panel `src` mapping; translate the region
  origin correctly in `blur_panel_texture()` and `SceneTextureElement`.
- [ ] Reallocate the scene/panel textures only when the region size or output
  mode/scale changes; never per frame. Keep one cache per output (and per GPU
  where the backend requires it).
- [ ] Give the scene and each panel a stable `Id` per output/panel slot (or
  cache the element instances) so a stationary Dock with an unchanged wallpaper
  does not damage the full output every frame. Keep a stable `current_commit`
  where appropriate.
- [ ] Direct-scanout policy:
  - keep the feather/no-material path for direct scanout,
  - detect a fullscreen client with no overlapping visible chrome material and
    skip the sampled pass for that output-frame,
  - report `direct_scanouts` separately from material frames,
  - preserve the Dock/menu-bar frost when they are visible.
- [ ] Add allocation/synchronization counters: `material_allocations`,
  `material_region_px`, and a debug assertion/counter that stays flat after
  warm-up. Check `MultiFrame` synchronization and `GlesTexture` lifetimes under
  panel add/remove.
- [ ] Keep the full-output path available as a diagnostic/rollback switch
  (env flag) until the region path is accepted.

## Out of scope

- Glass/refraction redesign or new material tokens.
- Multi-GPU cross-device sampling or rotated-output material (existing
  fallback; T193 records it).
- Refresh scheduling (→ T187/T188) and persistent-floor policy (→ T189).
- A renderer replacement.

## Design notes

- The region must include enough padding for the blur chain; a panel-edge
  texture that samples outside its region will show a hard/transparent seam.
  Derive padding from `BlurSpec` and verify at the rounded corners and the
  Dock's left/right edges.
- `SceneTextureElement` geometry is output-local physical; if the texture is
  region-sized, its geometry is the region rect, and each panel's `src` is
  relative to the region origin. Do not leave a full-output `src` on a
  region-sized texture.
- A region-sized texture cannot also be the full-output scene base. Pick one
  correct shape: (a) keep the full-output scene texture and update only damaged
  regions, or (b) draw the window/desktop/wallpaper elements directly as the
  output base and use the region texture only as the blur source. Do not leave
  the output background empty or draw the windows twice.
- Stable IDs are a damage-tracker contract, not a cache trick: the scene
  content changes every animated frame, but the panel element identity should
  not force full-output damage when only the panel region changed.
- Direct scanout is a **policy** decision: a full-output scene texture forces
  composition. A fullscreen client with no overlapping chrome should take the
  no-material path and scan out; the Dock/menu bar must still frost when they
  are mapped over it.
- Do not trade correctness for a smaller region: a clipped panel or stale edge
  is worse than the full-output cost.
- Record the region size and texture allocation count in `material stats` so
  T192 can compare.

## Acceptance criteria

- [ ] A steady-state Dock magnification run has zero new scene/blur texture
  allocations after warm-up (`material_allocations` flat for 5 minutes).
- [ ] The panel-region path is pixel-equivalent to the full-output path at the
  panel (within the existing material tolerance); no seam, stale edge, or
  corner artifact at 1x/1.5x/2x.
- [ ] `material stats` reports either a region smaller than the full output or
  a full-output texture updated only in the damaged region for a Dock-only
  frame; the GPU work is materially below the full-output redraw (measured in
  T192; record the delta).
- [ ] A fullscreen video/game takes the direct-scanout path when no chrome
  material overlaps it; `direct_scanouts` advances. The Dock/menu bar still
  frost when visible.
- [ ] No cursor regression, no frame-callback stall, and no tearing at the
  direct-scanout/material transition.
- [ ] The full-output diagnostic path still renders correctly when forced.
