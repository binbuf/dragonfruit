# T186b — T-21.1d GPU transport: dmabuf export and single-buffer Dock commit

| | |
|---|---|
| **Track** | T-21 — Presentation foundation |

| **Hardware** | optional (nested GL first) |

## Goal

Export the rendered FBO as a dmabuf and commit it for the Dock behind `DRAGONFRUIT_CHROME_GPU=1` with one reusable buffer and a clean fallback. The ring, release handling, and sync hardening are T186c.

## Context (read first)

- Parent spec: `docs/tasks/0.1.1/reference/186-t-21.1d-gpu-backed-chrome-transport.md`.
- T186a probe and producer skeleton.
- T185 pooled-SHM fallback: `shell/src/chromebufferpool.{h,cpp}`, `shell/src/shellprotocol.cpp`.

## Scope

- [x] Create an EGLImage from the FBO, export with `eglExportDMABUFImageMESA` (or equivalent), and create `zwp_linux_buffer_params_v1`/`zwp_linux_dmabuf_v1` buffers with the negotiated format, modifier, stride, and offset.
- [x] Add `ShellProtocol::commitDmabufTo()` and commit one reusable dmabuf-backed Dock buffer; flush the GL/EGL work before the commit so the first frame is not raced.
- [x] Fall back to T185 SHM on any export/import/format failure and expose the reason in `chrome stats`; never black.
- [x] Add a format/commit unit test and nested runs with `DRAGONFRUIT_CHROME_GPU=1` (imports > 0) and `=0` (fallback).

## Out of scope

- Buffer ring, release handling, and explicit sync (T186c).
- Menu bar/popovers/overlays (T186d).
- Default-on or native acceptance (T191/T192).
- Multi-GPU/rotated output.

## Design notes

- Keep the Dock visual identical; this is transport only.
- The SHM path remains the contract when export is unavailable.
- Do not add a compositor-side copy to compensate.

## Done when

- [x] The format/commit unit test passes.
- [x] Nested GPU and fallback captures/stats are committed.
- [x] Hand-off filled in.

## Hand-off

**Landed.** The Dock now has a real GPU transport behind
`DRAGONFRUIT_CHROME_GPU=1`:

- `shell/src/chromedmabuf.{h,cpp}`: pure exported-frame validation against the
  compositor feedback table (exact FourCC/modifier), modifier hi/lo packing,
  and the single-buffer busy/reuse/fallback state machine.
- `shell/src/chromedmabufexport.{h,cpp}`: EGLImage from the FBO texture with
  `EGL_GL_TEXTURE_2D_KHR`, `eglExportDMABUFImageQueryMESA` /
  `eglExportDMABUFImageMESA` plane-0 export. It stores the EGL display/context
  from `QNativeInterface::QEGLContext` (the context is required; passing
  `EGL_NO_CONTEXT` crashed Mesa in `dri2_create_image_khr`).
- `GpuChromeFrameProducer` now exports the FBO without a readback
  (`exportFrame()`), keeps the export alive until the FBO is recreated, marks
  every export with a monotonic serial, and keeps `renderFrame()` as the
  readback path for the non-Dock surfaces.
- `ShellProtocol::commitDmabufTo()` / `commitDockDmabuf()` bind
  `zwp_linux_dmabuf_v1` on the shell's own connection, create one reusable
  `zwp_linux_buffer_params_v1` buffer with the exported format/modifier/
  stride/offset, and commit it through the Dock's viewporter source rect. The
  `y_invert` flag flips the GL-origin texture; without it the Dock was
  upside-down.
- The GPU rail is opt-in: `main.cpp` selects the Wayland QPA only when
  `DRAGONFRUIT_CHROME_GPU=1` and `WAYLAND_DISPLAY` is set; the default remains
  the offscreen QPA. The private chrome surfaces still use the shell's own
  libwayland connection. The scene-graph API is process-global, so all chrome
  scenes use the GPU producer; only the Dock commits dmabuf in T186b, the rest
  read back and keep the T185 shm commit.
- `chrome stats` gained `gpu=off|shm|dmabuf`, `gpu_reason=<token>`,
  `dmabuf_commits/bytes/deferred/fallbacks`; a failed export/import/format
  falls back to the already-rendered frame through the T185 shm path.
- `scripts/t21-dmabuf-dock.sh` + `make t21-dmabuf-dock` run the real shell
  twice (GPU and fallback) and write `docs/captures/t21-dmabuf-dock.txt` plus
  the two host stills. `t21-gpu-smoke --export` exercises the export directly.
- `tst_dmabufcommit` covers advertised-pair validation, unknown format/
  modifier, bad/oversized frames, modifier packing, and the busy/reuse/failure
  state machine.

**Deviations / limits.** The Wayland QPA opens a second Wayland connection for
the Qt GL context only (the private layer roles cannot use the Qt Wayland
plugin); this is recorded in ADR 0195. T186b commits **one** buffer every
frame with `glFinish()` before the commit. It does not yet have the 2–3 buffer
ring, release-driven reuse, or explicit fence/sync; that is T186c. The
non-Dock surfaces are still shm commits (T186d). The flag stays off by
default.
