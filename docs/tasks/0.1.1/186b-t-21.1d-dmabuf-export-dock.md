# T186b — T-21.1d GPU transport: dmabuf export and Dock commit

| | |
|---|---|
| **Track** | T-21 — Presentation foundation |
| **Release** | v0.1.1 |
| **Depends on** | T186a |
| **Blocks** | T186c |
| **Hardware** | optional (nested GL first) |

## Goal

Export the rendered FBO as a dmabuf and commit it for the Dock behind `DRAGONFRUIT_CHROME_GPU=1`, with a small buffer ring and a clean fallback.

## Context (read first)

- Parent spec: `docs/tasks/0.1.1/reference/186-t-21.1d-gpu-backed-chrome-transport.md`.
- T186a probe and producer skeleton.
- T185 pooled-SHM fallback: `shell/src/chromebufferpool.{h,cpp}`, `shell/src/shellprotocol.cpp`.

## Scope

- [ ] Create an EGLImage from the FBO, export with `eglExportDMABUFImageMESA` (or equivalent), and create `zwp_linux_buffer_params_v1`/`zwp_linux_dmabuf_v1` buffers with the negotiated format, modifier, stride, and offset.
- [ ] Add `ShellProtocol::commitDmabufTo()`; use a 2-3 buffer Dock ring returned by `wl_buffer.release`; recreate only on resize/format change.
- [ ] Synchronize before the compositor samples the buffer (EGL/GL fence or explicit dmabuf sync); record an implicit-sync limitation if that is the only path.
- [ ] Fall back to T185 SHM on any export/import/format failure and expose the reason in `chrome stats`; never black.
- [ ] Add unit tests for the dmabuf ring/format selection and nested runs with `DRAGONFRUIT_CHROME_GPU=1` (imports > 0) and `=0` (fallback).

## Out of scope

- Menu bar/popovers/overlays (T186c).
- Default-on or native acceptance (T191/T192).
- Multi-GPU/rotated output.

## Design notes

- Keep the Dock visual identical; this is transport only.
- The SHM path remains the contract when export is unavailable.
- Do not add a compositor-side copy to compensate.
