## Hand-off

### Landed

- `AnimationClock` owns the current tick interval (`frame_interval`, default
  `FRAME_INTERVAL`), with `set_frame_interval()`. `schedule_animation_timer()`
  and `poll_animations()` arm/re-arm from it instead of the 16 ms constant.
- `DfState` owns a `RefreshSchedule` and an optional `DRAGONFRUIT_REFRESH_HZ`
  override. `sync_refresh_policy()` applies the effective refresh (override →
  fastest active output → 60 Hz fallback) to both the clock and the degrade
  budget. Output add/remove, mode changes, scale/transform changes, hotplug,
  and resume recompute it. If the fastest period changes while an animation is
  live, the armed timer is cancelled and re-armed with the new interval; if it
  did not change, the timer is left alone (idle discipline preserved).
- `DegradeController::set_budget_from_deadline()` follows the fastest output's
  deadline. `DRAGONFRUIT_FRAME_BUDGET_US` is recorded as `budget_source=env`
  and pins the budget; synthetic `set degrade-budget` records
  `budget_source=manual`; normal policy is `budget_source=refresh`.
- `presentation stats` appends `refresh_hz=<Hz> source=mode|fallback|override`
  after the existing fields. `animation stats` appends `interval_us`; a new
  `refresh stats` line reports the effective refresh/interval/deadline,
  output count, and override flag.
- New `docs/captures/t21-refresh-144.txt` from `scripts/t21-refresh-144.sh`
  (`make t21-refresh-144`): a nested simulated-144 Hz run showing
  `refresh_hz=144.000 source=override interval_us=6944 deadline_us=6944` and
  `budget_us=6944 budget_source=refresh`, plus headless 144/60 Hz cadence
  controls (144 Hz delta=43, 60 Hz delta=18 over 300 ms).
- Docs: ADR 0199, `docs/design/02-compositor.md`, `docs/rendering.md`,
  `docs/design/STATUS.md` (G-02), `docs/captures/README.md`, and
  `docs/v0.1.1/progress/T187b.md`.

### Deviations / notes

- The 60 Hz degrade budget is now the real 16.666 ms deadline (16666 µs), not
  the old 16 ms constant. The existing conformance assertion was updated.
- Nested `animate-dummy` rendered cadence is host-vblank throttled on this
  dev/headless host (the nested window is not presented at 144 Hz), so the
  nested trace records the derived interval/budget; the headless controls and
  `compositor/tests/animation_clock.rs` prove the actual 6.944 ms stepping.
  This is recorded honestly in the trace, not hidden.
- `step_animations()` now copies the live interval onto the `mem::take`
  placeholder before stepping; without it the first tick reverted the clock to
  the default 16 ms interval.
