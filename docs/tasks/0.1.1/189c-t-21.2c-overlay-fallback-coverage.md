## Goal

Extend the per-role material application to the popup-family surfaces and prove every blur-assuming surface has a deliberate fallback.

## Context (read first)

- Parent spec: `docs/tasks/0.1.1/reference/189-t-21.2c-persistent-chrome-material-floor.md`.
- T189b Dock/menu application and the role-keyed protocol state.
- Popup/overlay QML: Dock/menu popovers, Control Center, notifications, OSD, Applications drawer.

## Scope

- [x] Apply the role-keyed state to Dock/menu popovers, Control Center, notifications, OSD, and Applications drawer; transient roles may reach `Minimal`.
- [x] Give every blur-assuming popup/overlay a deliberate milky fallback and a recorded fallback reason; do not leave a flat translucent slab.
- [x] Add/extend QML tests for the overlay family and commit forced Full/Reduced/Minimal captures in light and dark.

## Out of scope

- Dock/menu core application (T189b).
- Refresh-aware hysteresis (T189d).
- Panel-region material cost (T190).
- New visual design.

## Design notes

- One effective state per role; no QML policy duplication.
- Keep the existing token values.
- The software path stays deterministic.

## Done when

- [x] `make qml-test` and `make e2e` pass.
- [x] Every listed overlay has a verified fallback.
- [x] Forced-tier overlay captures are committed.
- [x] Hand-off filled in.

## Hand-off

**Landed**

- The popup family now consumes the v4 role state through the existing
  `MaterialPolicy`: `Popup` for menu-bar dropdowns/submenus, status menus, the
  tray context menu, every Dock popover (context menu, window chooser, stack,
  overflow, Trash-empty, app picker), Control Center, notification banners, and
  the OSD; `Drawer` for the Applications drawer. The Dock/menu-bar scenes expose
  `popupMaterial*`; the shell seeds it before the first commit and repaints an
  open overlay on change.
- `design-system/Material.qml` is the one QML complement: `popupFill()` /
  `drawerFill()` choose the sampled-glass scrim or the milky fallback, and
  `fallbackReason()` records the explicit wire reason or the tier reason
  (`minimal`/`blur-off`). Every surface exposes `materialFallbackReason`.
- `material.popupFallbackOpacity` added (0.92 light / 0.90 dark). Existing
  token values are unchanged; the fallback fill reuses `chromeFallbackFill`.
- `design-system/components/{Popup,Popover,ContextMenu,MenuBarMenu}.qml` carry
  the properties; `WifiMenu`/`VolumeMenu`/`BatteryMenu` forward the bar state.
- Capture seams: `DF_CONTROL_CENTER_FIXTURE=hold` and
  `DF_OSD_FIXTURE=hold` keep the transient panels visible while tiers cycle.
- Tests extended in `tst_dock`, `tst_menubar`, `tst_controlcenter`,
  `tst_notifications`, `tst_osd`, `tst_appsdrawer`, plus a
  `tst_materialpolicy` transient-fallback case.
- Captures: `scripts/capture-t21-material-tiers.sh` now writes
  `t21-material-{menubar,dock,dockpopover,menupopover,controlcenter,notification,osd,drawer}-{full,reduced,minimal}-{light,dark}.png`
  plus per-surface review sheets. `t21-material-tiers.txt` records
  `query degrade` and the shell's applied per-role `tier/blur/fallback` lines.
- Docs: ADR 0205, `04-shell.md`, `02-compositor.md`, `rendering.md` R4.4,
  `10-design-system.md`, `STATUS.md` G-12, `captures/README.md`.

**Deviations / notes**

- Added `popupFallbackOpacity` rather than reusing `chromeFallbackOpacity`:
  the drawer's sampled fill is 0.88, so the chrome value would make the
  fallback *less* opaque than the glass path in dark. The fill still reuses
  `chromeFallbackFill` (no second neutral).
- `DF_CONTROL_CENTER_FIXTURE=hold` / `DF_OSD_FIXTURE=hold` are capture-only
  seams; normal sessions are unchanged.
- No compositor policy changed; T189a's role state and T189b's policy are
  reused as-is.
