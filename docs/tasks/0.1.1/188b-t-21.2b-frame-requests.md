## Goal

Replace the global `needs_redraw` animation gate with per-output requests and earliest-deadline timer arming.

## Context (read first)

- Parent spec: `docs/tasks/0.1.1/reference/188-t-21.2b-presentation-paced-mixed-refresh.md`.
- T188a presentation clock.
- Compositor event loop/render gate.

## Scope

- [x] Separate urgent requests (input, client/chrome commit, resize) from animation requests; render an output when its own deadline is due.
- [x] A global scene change may mark all outputs urgent, but a 144 Hz tick must not force a 60 Hz output to present every 6.94 ms.
- [x] Arm the animation timer from the earliest due deadline; update the output clock after presentation and re-arm; never render a settled output.
- [x] In `frame_finish()`, update the clock and count a missed deadline at 1.5× the output period; include `refresh_hz` in the summary.
- [x] Add a pure scheduler test and a nested single-output trace.

## Out of scope

- VRR, chrome callbacks, and mixed 60+144 evidence (T188c).
- Material floor (T189).

## Design notes

- Urgent work must not wait for a deadline.
- Keep the existing missed-deadline rule.
- No busy-loop and no 16 ms global fallback.

## Hand-off

### What landed

- New pure module `compositor/src/frame_scheduler.rs` (exported as
  `dragonfruit_compositor::frame_scheduler`):
  - `FrameScheduler` with independent per-output `urgent` and `animation`
    requests plus an `in_flight` marker.
  - `should_present(output, now, clocks)` is the render gate: urgent is
    immediate; animation requires a request, no queued frame, and a due
    presentation clock.
  - `next_interval(now, clocks)` arms from the earliest due request. A
    never-presented clock yields zero for its first frame; a presented clock
    that is still due yields its period instead of zero (no busy loop).
- `DfState` owns the scheduler and reconciles animation requests after every
  step: window motions request their output, overview/workspace transitions
  request every output, and a scene-free animation falls back to every output.
  `needs_redraw` remains the global urgent form for input/commit/resize/scene
  changes; animation ticks no longer set it.
- `input::schedule_animation_timer()` arms from the earliest per-output
  deadline. Before the first tick it uses the animation clock interval; it
  cancels a stale timer when no request/active animation remains.
  `poll_animations()` steps, marks the moved outputs, requests one final frame
  for a transition that completes on that tick, and re-arms.
- `DfState::note_presentation()` updates the clock, re-arms immediately, and
  clears a settled output's animation request after its final frame.
  `note_output_frame()` consumes urgent and drains a settled request.
- Nested gates `render_frame()` per output; DRM `render_pending()` no longer
  renders every output for an animation tick, `render_surface()` gates per
  output and marks a queued frame in flight, and `frame_finish()` clears it,
  updates the clock, keeps the existing 1.5× missed-deadline rule, and
  re-arms. Initial/resume/retry frames force a render. Headless treats its
  render pass as the output's presentation timestamp.
- `dump_stats` adds `frame scheduler stats` and one `frame request` line per
  output with `refresh_hz`, period, last presentation, next deadline,
  idle/due, request bits, and in-flight.
- New nested trace `docs/captures/t21-frame-scheduler.txt`
  (`scripts/t21-frame-scheduler.sh`, `make t21-frame-scheduler`): nested
  144 Hz idle/live/settled request lifecycle plus headless 144/60 Hz cadence
  controls.
- Docs: ADR
  `0201-per-output-frame-requests-and-earliest-deadline.md`,
  `docs/design/02-compositor.md`, `docs/rendering.md` P4/R3.2/R3.3,
  `docs/design/STATUS.md` G-02, `docs/captures/README.md`.

### Deviations

- `frame_finish()` already had the T188a clock update and the
  `PresentationStats` 1.5× missed rule with `refresh_hz` in the summary; T188b
  keeps that rule, adds the in-flight clear, and re-arms from the updated
  clock. No rule was changed.
- The nested host on this machine throttles `submit()` to roughly 1 Hz, so the
  nested trace records the request lifecycle and a host-throttled step count
  (4 steps for a 600 ms animation), not a cadence number. Headless 144/60 Hz
  controls are the cadence evidence; native mixed-refresh evidence remains
  T188c.
- Per-output urgent is exposed in the scheduler and checked by the backend
  gate, but existing event paths still use the global `needs_redraw` form
  (which marks every output urgent). That is the documented "global scene
  change" case; no event path was converted to a narrower per-output urgent
  request in this task.
- DRM mixed-refresh was not run on hardware; the DRM path is compile-checked,
  while the 60/144 deadline logic is covered by the pure scheduler tests.
