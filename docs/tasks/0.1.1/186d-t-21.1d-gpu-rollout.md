## Goal

Move every chrome surface to the GPU producer behind the flag, make the stats/docs honest, and keep the SHM path as the fallback contract.

## Context (read first)

- Parent spec: `docs/tasks/0.1.1/reference/186-t-21.1d-gpu-backed-chrome-transport.md`.
- T186b Dock dmabuf path.
- T185 `ChromeFrameProducer` and `chrome stats`.

## Scope

- [x] Roll the GPU producer out to the menu bar, popovers, overlays, lock surface, and remaining chrome; name any surface that cannot move and keep it on SHM.
- [x] Report `path=dmabuf|shm`, buffer counts, copies, and failure reasons in `chrome stats`; a GPU frame must have no CPU readback/copy.
- [x] Update the transport ADR, `docs/rendering.md` R2.3, `04-shell.md` known limits, and `docs/captures/README.md`.
- [x] Capture nested GL stills/stats for Dock, menu bar, popover, and lock, plus a forced-SHM fallback run; keep the default off until T192/T193 accept it.

## Out of scope

- Native material acceptance (T191).
- Benchmark/soak (T192).
- Default-on switch.

## Design notes

- One producer abstraction, one fallback contract.
- Never silently double-render a surface that cannot use the GPU path.
- Do not change chrome visuals or layout.

## Done when

- [x] `make e2e` and `make qml-test` pass.
- [x] Every surface is covered or named as a measured exception.
- [x] GPU/fallback captures and stats are committed; docs updated.
- [x] Hand-off filled in.

## Hand-off

### Landed

- Every chrome scene now commits through one `commitChromeScene()` path:
  menu bar + dropdown, Dock + popover, Mission Control, app switcher,
  notification banner, Control Center, OSD, chooser, screenshot selection,
  ScreenCast picker, polkit, Applications drawer, and the session-lock
  surfaces.
- `ShellProtocol` gained `commitDmabufFor(label, ...)` and
  `commitLockDmabuf(id, ...)`, so the controller addresses a surface by its
  stable `chrome stats` label or lock configure id; the private protocol and
  surface roles are unchanged.
- A shared scene (bar + popup, Dock + popover) renders once, exports once, and
  commits the same frame to both surfaces. `ChromeDmabufReleaseTracker` holds
  the producer ring slot until the last `wl_buffer.release`. If any target
  cannot express the commit, the whole scene renders once through T185 shm;
  no successful dmabuf frame is ever read back or copied.
- `chrome stats` per-surface lines now carry `path=dmabuf|shm`,
  `gpu_reason`, `dmabuf_buffers`/`dmabuf_allocs`/`dmabuf_reuses`, and
  `copy_bytes`. A dmabuf frame reports `copy_bytes=0`; a fallback names
  `ring-exhausted`, `sync-timeout`, `no-viewporter`, `import-failed`, ...
- `DRAGONFRUIT_CHROME_GPU_SURFACES` is a capture-only surface filter. The
  shipping default is still all surfaces; the flag stays off by default.
- Regression coverage: `tst_dmabufcommit` gained the shared-release tracker
  cases (two-surface release waits for the last user, stale serial ignored).
- Captures: `docs/captures/t21-gpu-rollout.txt`, `-dock.png`, `-menubar.png`,
  `-popover.png`, `-lock.png`, `-fallback.png`; `make t21-gpu-rollout` runs
  `scripts/t21-gpu-rollout.sh`.
- Docs: ADR 0197, ADR 0196 cross-reference, `docs/rendering.md` R2.3,
  `docs/design/04-shell.md`, `docs/captures/README.md`.

### Deviations / measured exceptions

- The compositor still offers only implicit dma-buf sync. On this shared host
  a shared scene can fill its three-slot ring (`ring-exhausted`) or record a
  `sync-timeout` before the compositor releases the previous frame. Those
  frames are counted shm fallbacks and retry on release; they are not black
  surfaces or silent copies. The clean menubar and lock dumps in
  `t21-gpu-rollout.txt` show `copy_bytes=0` for the dmabuf frames. Explicit
  sync remains the T192/T193 acceptance boundary.
- The capture script isolates one surface per run with
  `DRAGONFRUIT_CHROME_GPU_SURFACES` because the host GPU is shared with the
  live session; the shipping default remains all surfaces.
- Ring capacity stays 3 (T186c contract). No new default-on switch.
