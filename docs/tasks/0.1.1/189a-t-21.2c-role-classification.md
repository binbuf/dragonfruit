## Goal

Add the persistent/transient material role classification and the per-role effective state over the protocol, with tests.

## Context (read first)

- Parent spec: `docs/tasks/0.1.1/reference/189-t-21.2c-persistent-chrome-material-floor.md`.
- Compositor material/degrade controller.
- `df_output.material_state` protocol and conformance test.

## Scope

- [x] Classify `MaterialRole` as persistent (`Chrome`/`Dock`) or transient (`Popup`/`Drawer`).
- [x] Compute an effective state per role: persistent never below `Reduced` while the sampled path is available; transient may reach `Minimal`; use the milky fallback with an explicit reason when even `Reduced` misses.
- [x] Extend `df_output.material_state` additively (v4) with a role/namespace field, keep change-only emission, and update the conformance test.
- [x] Add pure floor tests; no shell QML application yet.

## Out of scope

- Shell application and fallback coverage (T189b).
- Refresh-aware hysteresis (T189c).
- Panel-region material cost (T190).

## Design notes

- Do not duplicate the degrade policy in QML.
- Keep existing fields’ meaning and change-only emission.
- Software/headless stays `Minimal` with the deterministic milky plate.

## Hand-off

**Landed**

- `MaterialRole` classification: `Chrome`/`Dock` are persistent,
  `Popup`/`Drawer` transient; `wire()`/`from_wire()` fix 0=chrome, 1=dock,
  2=popup, 3=drawer, with `ALL`/`COUNT` as the stable role table.
- `EffectiveMaterial::resolve_for_role()` applies the floor. Persistent roles
  never select below `Reduced` while the sampled path is available; a selected
  `Minimal` resolves to `tier=reduced`, `blur_active=false`, and
  `MaterialFallback::FloorMissed` (wire 4, `floor-missed`) so the surface uses
  the deliberate milky plate. Transient roles reach `Minimal`. Software/
  headless stays `Minimal` + `software` for every role. `EffectiveMaterial::
  resolve()` keeps the old global (unfloored) meaning for the legacy v3 event.
- `DfState::effective_material_for_role()`/`effective_materials()` expose the
  role table. `render::chrome_backdrop_render_elements`,
  `render::chrome_blur_panels`, and the DRM sampled-path gate now resolve each
  panel through its role state, so the floor is applied to the actual
  backdrop/blur pass, not only the protocol.
- `df_output` is v4. Additive `material_role_state` carries
  `role/tier/blur_active/fallback`; it is emitted per output resource only for
  roles whose effective state changed. The legacy v3 `material_state` keeps
  its global meaning and change-only rule. `ShellProtocol` parses/stores the
  role table, exposes `materialRoleTier/BlurActive/Fallback(role)`, and emits
  `materialRoleStateChanged`; QML application is intentionally not wired here.
- Synthetic test plumbing: `set material-path gpu|software` and
  `set material-blur-supported on|off`. Headless starts `software`; the new
  conformance test uses the hooks to exercise the sampled-path floor.
- Tests: pure floor tests in `window/degrade.rs`; protocol conformance
  `shell_protocol_conformance::material_role_state_is_per_role_floor_aware_and_change_only`
  covers initial software state, GPU full/blur, forced Minimal (chrome/dock
  `reduced/0/4`, popup/drawer `minimal/0/0`), duplicate-tier change-only,
  Reduced, no-sampled-blur, and return to software.
- Docs: ADR 0203, `rendering.md` R4.1/R4.3, `02-compositor.md`,
  `04-shell.md`, `STATUS.md` G-12, `docs/v0.1.1/progress/T189a.md`.

**Deviations**

- The role state is a second event (`material_role_state`, since=4) rather
  than extra arguments on `material_state`. This keeps the v3 message
  signature valid for older clients, which the parent spec explicitly allows.
- The role cache is keyed by `df_output` protocol id (not output name) so
  multiple clients/output resources each get their initial table.
- The render path consumes the role state in this task because the protocol
  must not report `blur_active=1` for a pass the compositor skipped. Shell/QML
  application remains for T189b/T189c.
