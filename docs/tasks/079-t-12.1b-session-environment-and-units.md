What landed:

- **`services/session/src/env.rs`** (new) — `SessionEnvironment` (`new`,
  `default_socket`, `with_x11_display`, `with_launch_token`,
  `with_generated_token`, `base`, `trusted`, `base_value`,
  `x11_display_from_handoff`), `generate_launch_token`, and the variable-name
  constants. Base = `XDG_CURRENT_DESKTOP=dragonfruit`,
  `XDG_SESSION_TYPE=wayland`, `WAYLAND_DISPLAY=<socket>`, `DISPLAY=<:N>` when
  X11 exists; trusted = base + `DRAGONFRUIT_LAUNCH_TOKEN`.
- **`services/session/src/plan.rs`** — `ServiceSpec` gained `trusted`; the
  compositor and shell are trusted. `SessionPlan::with_environment` /
  `default_session_for` attach the environment (base everywhere, token on
  trusted services). Restart policies/stages unchanged.
- **`services/session/units/`** (new) — `dragonfruit-session.target`
  (`WantedBy=graphical-session.target`, requires the compositor, wants the
  rest) plus the seven service units. Compositor `Restart=no` (`--backend
  drm`), shell `Restart=always`, others `Restart=on-failure`. Every
  non-compositor unit gates on
  `ExecStartPre=/usr/bin/dragonfruit-session --wait-socket dragonfruit-wayland`,
  sets the static environment, and `PassEnvironment=DISPLAY
  DRAGONFRUIT_LAUNCH_TOKEN`.
- **`services/session/src/main.rs`** — `--print-env [--socket-name NAME]
  [--x11-display DISPLAY]` (base + fresh token, for the session entry), and
  `--wait-socket NAME [--timeout SECS]` (the unit gate; absolute path or bare
  name under `XDG_RUNTIME_DIR`).
- **Tests** — `tests/environment.rs` 6 cases (trusted child sees all five
  variables; untrusted child sees none of the token; `--wait-socket`
  success/timeout; `--print-env` contract + 64-hex token) and
  `tests/units.rs` 6 cases (unit set, target pulls the composition, anchor
  `Restart=no`, per-service policies, environment/gate on every service,
  dependency closure). `cargo test -p dragonfruit-session` — 30/30.
- **Docs** — `11-session-and-dev-workflow.md` (environment contract + shipped
  units + the units-based second-VT workflow), `testing-ladder.md` rung 2,
  ADR 0065.

Commands that work (repo root):

- `cargo clippy -p dragonfruit-session --all-targets -- -D warnings` and

Deviations / notes for the next task:

- **No `.desktop` session file or DM entry here** — that is T-12.2. The
  session entry imports `--print-env` and starts `dragonfruit-session.target`.
- **The compositor is `Type=simple`; it does not `sd_notify`.** The readiness
  gate is the `--wait-socket` `ExecStartPre`, not systemd `Type=notify`.
- **`DRAGONFRUIT_LAUNCH_TOKEN` is minted by `--print-env` and passed through
  the user manager** (`PassEnvironment=`). The compositor pre-mints it
  (`shell::provision` already reads `DRAGONFRUIT_LAUNCH_TOKEN`) and writes the
  `<socket>.launch-token` file; the shell reads it from its environment.
- **The fixed socket name is `dragonfruit-wayland`** (env
  `DEFAULT_SOCKET_NAME`); the units and `WAYLAND_DISPLAY` must stay in
  lockstep. The nested dev tool keeps `dragonfruit-dev-<pid>`.
- **`--wait-socket` tests file existence, not a connect.** A stale path is the
  compositor's teardown bug; T-12.2/T-12.6 can tighten it.
