## Goal

Open the window menu (Move to Space, Minimize, Zoom, Close) from a right/Control-click on the titlebar, routed through the existing state machine.

## Scope

- Right/Control-click the titlebar opens the window menu using design-system menu components.
- Move to Space, Minimize, Zoom, Close route through existing state-machine primitives (no new state).
- Escape / click-away / focus-loss dismissal; keyboard operable.

## Explicitly deferred

- Decoration themes (T-14).
- Window-menu animation (T-02).

## Acceptance (agent-completable)

- [ ] All four commands work through the UI on a Wayland and an X11 window.
- [ ] Dismissal matches the design-system menu rules.

## Test plan

- Headless: drive each menu command and assert the transition; nested walkthrough for the visual.

## Hand-off

**State: done.** All acceptance criteria met; `make e2e` green.

What landed:

- **`compositor/src/window/menu.rs`** — the compositor-owned window menu:
  `WindowMenu` (geometry, hit-testing, highlight, submenu, keyboard) and
  `WindowMenuRow`/`MenuRow`. Rows are Move to Space (a submenu of the
  window output's Spaces), Minimize, Zoom, Close. Geometry is
  `component.contextMenu` (`padding` 6, `rowHeight` 26, `minWidth` 180) plus
  the `component.window.borderWidth` border; the panel flips/clamps to stay
  inside the output. Dismissal/keyboard mirror `ContextMenu.qml`: Escape
  closes the submenu then the menu, Up/Down/Home/End move the highlight,
  Right/Left open/close the submenu, Enter/Space activates. Rendering is a
  flat token fill (surface elevated + accent highlight); real labels are
  T-04, the same placeholder stage as the T-01.1 glyphs.
- **`compositor/src/state.rs`** — `DfState::window_menu: Option<WindowMenu>`
  plus `open_window_menu`, `close_window_menu`, `window_menu_open`,
  `window_menu_click`, `window_menu_key`. Every row routes through
  `window_menu_command` (the existing `WindowMenuCommand` primitives —
  `move_window_to_space`, `minimize_window`, `zoom/unzoom_window`,
  `close_window`). Focus loss dismisses the menu in `focus_changed`.
- **`compositor/src/input.rs`** — a right-click (`BTN_RIGHT`) or
  Control-left-click on a titlebar opens the menu (same client-surface
  priority as a left titlebar press; a revealed fullscreen titlebar wins);
  while open the menu is modal — pointer presses are consumed inside it and
  dismiss it outside, and every key is intercepted (menu keys navigate).
- **Rendering** — `render::window_menu_render_elements`, composited above
  the titlebars in the nested and DRM backends.
- **Test plumbing** — the synthetic harness accepts `query window-menu`
  (open/window/rect/highlight/submenu rect) and the `query decorations`
  report gained a trailing assigned-Space id so Move to Space is observable.
- **Tests** — `window_conformance::window_menu_opens_dismisses_and_is_keyboard_operable`
  (right-click opens; Escape, click-away dismiss; Down/Down/Enter zooms),
  `window_conformance::window_menu_runs_zoom_minimize_close_and_move_to_space`
  (all four commands for a Wayland window), and
  `xwayland_conformance::x11_window_menu_runs_all_four_commands` (all four
  plus Escape for an X11 window). 153 compositor unit tests (9 new in
  `window::menu`).
- **Docs / ADR** — `docs/design/05-window-decorations.md` behavior + status
  updated. ADR `0002-window-menu-ownership.md`: the menu is compositor-owned
  and shell-independent; T-04 replaces the flat fill, T-14 reuses the model.

Deviations / notes:

- The scope said "using design-system menu components"; the compositor has no
  QML or text renderer, so it reproduces the `ContextMenu` token geometry and
  interaction rules in Rust instead of instantiating the QML component. The
  shell `ContextMenu` is not involved. ADR 0002 records the ownership; T-04
  draws the labels and T-14 reuses the menu.
- `active_space` is not used to mark the current Space in the submenu (no
  check glyph yet); T-04/T-14 can add the check state.
- Right-click opens the menu but does not start a drag; a left titlebar press
  is unchanged. A Control-left-click now opens the menu instead of dragging
  the window.
- The menu snapshots the output's Spaces when it opens; a workspace change
  while it is open leaves it stale until dismissed (acceptable: any focus
  change dismisses it).

Gotchas for later tasks:

- The menu is clamped to the output that contains its anchor
  (`window_menu_render_elements`); a window whose titlebar spans outputs draws
  the menu only on the anchor's output.
- While open, the menu intercepts *every* key before the shortcut engine, so
  a global shortcut cannot fire underneath it.
- The X11 menu test creates three windows in sequence because Minimize and
  Move to Space remove the window's titlebar; each phase reconnects to reset
  the per-client `toplevel_close_count`.
