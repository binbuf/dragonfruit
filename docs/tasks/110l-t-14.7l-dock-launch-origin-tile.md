## Goal

When the Dock launches an app, hand the tapped entry's tile rectangle to the
compositor over `df_toplevel_manager.set_launch_origin` (v4) so the window's
appear/minimize/restore/close motion originates from and returns to the real
icon instead of the centered fallback. The protocol, the compositor store, and
the motion path already exist; only the shell plumbing is missing.

## Context (read first)

- `docs/PROGRESS.md:3572` — "the shell still must thread the Dock entry's tile
  rectangle from QML through `ShellController::launchDockAppWithFiles` to
  `ShellProtocol::setLaunchOrigin` … Until then real launches use the centered
  fallback."
- `protocols/dragonfruit-toplevel.xml:175` — `set_launch_origin(app_id, x, y,
  w, h)`, additive in v4. Keyed by the window's Wayland `app_id`.
- `compositor/src/state.rs` — `DfState::dock_tiles` (`~448`) and
  `set_launch_origin` (`~2213`); `compositor/src/window/motion.rs` consumes it
  for appear/minimize/restore.
- `shell/src/shellprotocol.h:397` / `shellprotocol.cpp:1630` — the shell wrapper
  exists and has **no caller**.
- `shell/src/shellcontroller.cpp` — launch paths `launchDockApp`,
  `launchDockAppWithFiles` (`~4576`), and the `activateAppOrFallback` fallback
  launch (`ADR 0101`); `setDockPanelRect` shows the existing Dock geometry
  channel.
- `shell/dock/Dock.qml` — `layout` / `restingPlateRect` are the per-entry
  rects; entries carry `id`, `desktopId`, `appId`.
- `shell/src/desktopentry.h` — `DesktopEntry{id, name, startupWmClass, …}`;
  `DesktopEntryIndex::resolve` matches a window `app_id` to a desktop id (the
  inverse mapping is the open question below).
- Reference behavior only (GPL, never copied): `~/repos/punchi-dock-remastered`
  publishes each delegate's geometry to the compositor so minimize/restore
  animations target the icon (`TaskDelegateGeometryPublisher.qml`,
  `src/taskgeometryownershipbridge.cpp`). Clean-room: implement with our own
  protocol and QML.

## Current behavior (investigated, T110 era)

- `ShellController::launchDockAppWithFiles` never calls `setLaunchOrigin`, so
  `DfState::dock_tiles` is empty for real launches and the appear/minimize/
  restore motion uses the centered, slightly-shrunk fallback.
- The Dock already reports its *plate* rect (`setDockPanelRect`) but nothing
  per-entry.

## Scope

- [ ] QML→shell: report the tile rectangle of the entry the user acted on. Add
      one Dock signal (e.g. `entryTileRect(string id, real x, real y, real w,
      real h)`) emitted on activation and launch, in output coordinates; keep it
      one rect, not a stream. Re-emit on re-layout while the rect is stale.
- [ ] Shell: keep a small bounded `desktopId → rect` map (or resolve directly at
      launch); on `activateAppOrFallback`'s launch branch and on
      `launchDockApp`/`launchDockAppWithFiles`, call
      `ShellProtocol::setLaunchOrigin(appId, rect)` before the child is spawned.
- [ ] Resolve the `app_id` key. Determine the compositor-visible `app_id` for the
      launched entry from the app-index record (`startupWmClass` when present,
      else the id stem). If the nested launch test shows the announced `app_id`
      does not match, extend the app-index record with an explicit resolved
      `appId` field rather than guessing in the shell.
- [ ] Fallback: an unknown/unresolvable key or a missing rect leaves today's
      centered behavior; never send a garbage rect.
- [ ] Tests: `tst_dockcore` for the key derivation and rect-map bounds;
      `tst_dock.qml` for the signal/rect payload; a compositor/shell conformance
      case that a launch with a tile recorded before mapping uses it (extend
      `window_conformance.rs` if the existing hand-off case does not cover the
      shell path).
- [ ] Capture `docs/captures/t14-dock-launch-origin.png` (window appearing from
      the icon) and the `PROGRESS.md` note; update [04-shell.md](../design/04-shell.md)
      if the seam is described there.

## Explicitly deferred

- Cross-output launch geometry (one output; the rect is clamped to it).
- A continuous per-entry geometry stream (a single last-interaction rect is
  enough for a launch/appear).
- Thumbnails and live previews (T-14.7m deferred list).

## Design notes

- The compositor is the sole motion owner; the shell supplies geometry only,
  mirroring `set_panel_rect`. Do not expand the request with state.
- `activate_app` already answers with `activation_result` (ADR 0101); that is
  the "found/not found" channel and must not be conflated with the tile rect.
- The tile rect is the icon's rect (not the whole plate) so appear/minimize
  read as landing on the icon.
- Keep the map bounded and drop entries when the pinned set changes; a stale
  rect for an uninstalled app is harmless but should not grow without bound.

## Acceptance (agent-completable)

- [ ] Nested: launching a pinned app shows its window appearing from the
      entry's icon; minimizing and restoring it target the icon too.
- [ ] A launch with no recorded rect still uses the centered fallback (no
      crash, no garbage geometry).
- [ ] `ctest --test-dir build -R "tst_dock|tst_dockcore"`, `cargo test
      --workspace`, `make qml-test`, `make e2e`, `make check` unchanged.
- [ ] Capture committed; `PROGRESS.md` note; Hand-off filled in.

## Test plan

- `tst_dockcore`: `desktopId`→key derivation, rect clamping, map bounds.
- `tst_dock.qml`: the Dock emits the entry rect on activation.
- Compositor conformance: the shell-recorded tile drives appear/minimize/
  restore (or a focused unit asserting `dock_tiles` is populated on launch).
