## Goal

One command that builds the tree, launches the nested compositor with the shell and two clients, and prints the demo checklist, on the same path CI uses.

## Scope

- `make demo` target: build (cargo + CMake), nested launch, shell, one Qt/Wayland app, one X11 app.
- Deterministic teardown; non-zero exit if any child fails; CI invokes the same target.
- Printed checklist of the steps the human will perform at track sign-off.

## Explicitly deferred

- The Dock/menu-bar integration walkthrough itself (T-01.6b).

## Acceptance (agent-completable)

- [ ] `make demo` exits 0 on a clean tree and prints the checklist.
- [ ] CI invokes the same target for the scripted half.

## Test plan

- Headless: `make demo` smoke in `make e2e` (launch + teardown, assert no leaked socket).

## Hand-off

**State: done.** `make demo` builds the tree and runs the T-01 loop demo; the
same target runs headless as the CI scripted half and is part of `make e2e`.

What landed:

- **`Makefile`** — new `demo` target (`demo: build` →
  `cargo run -p dragonfruit-dev -- dev --demo $(DEMO_ARGS)`), a `DEMO_ARGS`
  variable, and `make e2e` now depends on `build` and ends with
  `$(MAKE) demo DEMO_ARGS=--headless`. `make demo` with no host Wayland
  session (CI) auto-selects headless.
- **`tools/dragonfruit-dev/src/demo.rs`** (new) — app/QML-path discovery
  (`DF_DEMO_QT_APP` → `build/apps/settings/dragonfruit-settings` → Files;
  `DF_DEMO_X11_APP` → `xmessage` on `PATH`; `DF_QML_IMPORT_PATH` →
  `build/qml`), the printed checklist, and the scripted settle. 3 unit tests.
- **`tools/dragonfruit-dev/src/main.rs`** — new `dev --demo` subcommand.
  Refactored the session lifecycle into shared `start_session` /
  `launch_program` / `launch_shell` / `teardown_session` /
  `wait_for_compositor_exit`, used by both `run_dev_session` and the new
  `run_demo_session`. Demo launches the shell, a Qt/Wayland client
  (`QT_QPA_PLATFORM=wayland`, `QML_IMPORT_PATH`, software rendering when
  headless), and an X11 client; nested blocks until the window closes,
  headless settles, asserts every child is alive, tears down, and asserts no
  socket/process leaked. Exit is non-zero on any launch failure, an early
  child death in the scripted half, or a dirty teardown. 3 new unit tests.
- **CI** — `.github/workflows/ci.yml` installs `xwayland`/`x11-utils` and
  runs `make demo` after the Qt build (the scripted half).
- **Docs** — `docs/design/11-session-and-dev-workflow.md` documents the
  harness; `README.md` mentions `make demo`.

Commands that work (from the repo root; `make` sets the toolchain env):

- `make demo DEMO_ARGS=--headless` → exit 0, prints the checklist, launches
  shell + Qt + X11, `all children alive after settle`, clean teardown.
- `make demo` (host Wayland session) → nested, all three children, Ctrl-C /
  window close tears down cleanly, no socket leak.
- `make e2e` → exit 0 (7 suites + the demo smoke).
- `cargo test -p dragonfruit-dev` → 6 unit tests.
- `make clippy`, `cargo fmt --all -- --check`, `make soak SOAK_CYCLES=3` clean.

Deviations / notes for the next task:

- **Fixed a pre-existing `--launch` parser bug**: every `--launch` flag used
  to overwrite the previous group, so only one extra app could ever launch.
  Repeated `--launch` now accumulates; covered by a unit test.
- The demo **auto-launches** both clients (the scope says launch them); the
  checklist still tells the human to click the Dock, and the apps' Dock
  entries appear as they map. The Dock/menu-bar walkthrough and capture stay
  T-01.6b.
- The first-party Qt apps need `QML_IMPORT_PATH=build/qml` at runtime (the
  shell bakes an equivalent define in; the apps do not). The harness exports
  it. A future unit could add the define to the apps' CMake instead.
- X11 half is skipped with a note when Xwayland or `xmessage` is absent; CI
  installs both, but a Wayland-only run is still a valid `make demo`.
- CI runs the demo Wayland+X11 on ubuntu-latest with `xwayland`/`x11-utils`
  added; if Xwayland cannot start there the demo skips the X11 half rather
  than failing.
