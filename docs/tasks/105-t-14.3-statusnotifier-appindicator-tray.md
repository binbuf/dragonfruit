## Goal

Tray items from third-party apps render in the bar with working menus.

## Scope

- StatusNotifier/AppIndicator tray items in the menu bar.

## Explicitly deferred

- Tray icon animation polish.

## Acceptance (agent-completable)

## Test plan

- Integration with a mock tray app.

## Hand-off

**Landed.** SNI/AppIndicator tray items render in the menu bar and their
DBusMenu works, end to end.

- app-index is now also the tray host. `services/app-index/src/tray.rs` (new)
  is the pure registry + DBusMenu projection; `dbus.rs` adds the
  `org.kde.StatusNotifierWatcher` object, the
  `TrayItems`/`TrayMenu`/`TrayMenuEvent`/`TrayActivate` methods, the
  `TrayChanged` signal, and a `NameOwnerChanged` cleaner. The watcher name is
  taken best-effort: on a session where another host owns it, the watcher
  object still answers at `/StatusNotifierWatcher`, so items can register
  directly against app-index.
- The shell renders tray items in the one status row (`shell/src/trayclient.*`,
  new; `MenuBar.qml`/`StatusItem.qml`), opening a design-system `ContextMenu`
  anchored to the slot and routing a chosen row back with `TrayMenuEvent`.
- Contract in ADR [0097](../design/adr/0097-statusnotifier-tray-host-and-dbusmenu-projection.md);
  `docs/design/06-global-menu.md` updated.

**Tests (`cargo test -p dragonfruit-app-index`):** 42 unit + 12 session-bus
cases, including `a_mock_tray_item_registers_and_its_menu_round_trips` (a mock
SNI item + DBusMenu on a private bus: item resolves, its themed icon resolves,
the layout projects, and `TrayMenuEvent` reaches the mock) and
`a_path_registration_is_namespaced_by_the_sender`. Shell:
`tst_dockcore` decodes the item/menu views; `tst_menubar` opens the tray menu
and asserts the trigger carries the registered name + DBusMenu id.

**Deviation / deferred.** Live `NewIcon`/`NewToolTip`/`NewStatus` signals are
not subscribed; the shell re-reads every 2 s. Icon animation polish stays
deferred as stated. A tray item whose icon is pixmap-only falls back to the
`application` glyph (only `IconName` is resolved to a file); `IconThemePath`
is not consulted. Left-click always opens the menu (no separate primary
activate) until a later task needs it.

**T-14.4.** Reuses `tray::MenuNode`/`TrayMenu` as the DBusMenu bridge for the
global application menu; do not build a second parser.

**Live check.** Nested `make demo` with `dragonfruit-app-index` +
`dragonfruit-app-index --mock-tray firefox` on the session bus: the Firefox
tray icon rendered in the bar (orange pixels at output x≈1688), clicking it
opened a three-row menu (`Show Window` / separator / `Tools › Preferences`),
and clicking `Show Window` delivered `Event(1, "clicked")` to the mock
(`/tmp/opencode/t105/traymenu4.png`; the vision inspection confirmed the tray
icon and the open dropdown). Note the active-window capture trim is flaky on
this KWin host; the reliable evidence is the shell/DBus logs plus the pixel
check.

Before reporting done, run the app and **look at it**:
