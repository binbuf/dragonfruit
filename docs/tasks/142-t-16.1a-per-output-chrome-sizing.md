## Hand-off

**Landed.** Reserved zones are now resolved per output and window usable
geometry follows the window's own display; `matches_output` is the filter.
Chrome geometry (`chrome_surfaces`) was already per-output and now shares the
same zone map.

Real paths:

- `compositor/src/shell/layer.rs` — `aggregate_reserved_for(output_name,
  layers, zones)` (filters with `matches_output`, deepest reserve per edge) and
  a shared `reserve` helper; `aggregate_reserved` is the global-union fallback.
  4 new unit tests: per-output scoping, deepest-reserve, per-output geometry at
  two scales.
- `compositor/src/shell/mod.rs` — `ShellProtocolState.output_reserved:
  HashMap<String, ReservedZones>`; `reserved_zones_for(name)`;
  `refresh_reserved_zones` builds the per-output map (global union kept as
  `reserved`/`reserved_zones` fallback); `send_output_properties` and
  `broadcast_reserved_zones` send each output its own zones.
- `compositor/src/state.rs` — `usable_geometry_for` subtracts the zones of
  `output_name_for(window)`, not the global union.
- `protocols/dragonfruit-shell.xml` — the `get_layer_surface` description no
  longer claims NULL means "the primary output"; it documents the all-output
  rule the code has used since T-09.
- `docs/design/adr/0149-per-output-chrome-reserved-zones.md` (new).
- `compositor/tests/shell_protocol_conformance.rs` — new
  `per_output_chrome_reserves_are_scoped_and_scale_aware`: two outputs at
  scales 1 and 2, a primary-pinned bar (28) plus an all-output bar (24); the
  primary keeps 28, HDMI-A-1 receives 24 and never 28, and the scale-2 output
  announces geometry 960x540 and scale 2.0. The harness now binds `wl_output`.

Commands / results:

- `cargo test -p dragonfruit-compositor` — green (unit + all integration
  suites; the new test passes).
- `cargo clippy -p dragonfruit-compositor --all-targets -- -D warnings` —
  clean; `cargo fmt --all -- --check` — clean.
- `make e2e` — EXIT 0 (`/tmp/opencode/e2e-t142.log`).
- Live visual check: nested `make demo` + `spectacle` →
  `/tmp/opencode/t142.png` (2115x1437). Vision confirmed the menu bar, Dock,
  wallpaper, and client windows composite with no blank areas, clipping,
  tearing, or stray artifacts; the demo log shows `menu bar configured
  1920x28` and `output reserved zone edge=0 thickness=28`.

Deviations / gotchas:

- **One surface, one configure.** A chrome surface created without an output
  is still a single `wl_surface`; its `configure` size is still resolved
  against the primary output. The anchor/margin **geometry**, the reserved
  strip, and the reserve event are all per output, but a genuinely per-output
  client buffer needs one layer surface per output in the shell — a follow-up,
  not claimed here (see ADR 0149). This is the one place the task's "chrome
  sizes per output" is only partly met.
- **Reserved thicknesses are logical**, so scale does not change them; the
  geometry they are subtracted from does. The new test pins this with a
  scale-2 second output.
- T-16.1b can now rely on `usable_geometry_for` being per-output: new windows
  land on the focused output and Zoom there subtracts only that display's
  chrome.
