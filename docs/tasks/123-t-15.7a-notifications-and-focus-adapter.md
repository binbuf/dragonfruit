## Goal

Backend adapter for Notifications and Focus over the host stack (notification service), with state, events, and absent-daemon behavior.

## Scope

- Adapter over the host stack (reuse, never reimplement).
- State + events + absent-daemon behavior, unit-tested.

## Explicitly deferred

- Settings pane and Control Center tile (T-15.7b).

## Acceptance (agent-completable)

- [x] Adapter reports state and events against a mock; absence is a normal state.

## Test plan

- Headless: adapter mock drives the states.

## Hand-off

**Landed.** New crate `dragonfruit-notify-adapter` (`services/notify-adapter`),
a projection adapter over the already-shipped notification service
(`services/notifications`) — no second queue, history, or policy. It reuses the
service's `FocusMode` and shell-facing JSON views and exposes the
`dragonfruit-system-adapters` contract:

- `NotificationsSource` seam + `MockNotifications` (`kill`/`restart`/`push`
  and the two write stubs); `NotificationsData`/`NotificationRecord`;
  `FocusOutcome {Applied, Absent, Failed}`.
- `NotificationsSnapshot` (`FocusSnapshot` mode/allow_list/batched, active
  banners, history, derived `AppNotifications`) and a pure
  `NotificationsChange` diff.
- `NotificationsAdapter<S>` with `refresh`, `set_focus_mode`,
  `set_focus_allow_list`, `drain_changes`; `Adapter` id
  `AdapterId::NOTIFICATIONS`.
- `DbusNotifications` live session-bus source (`new()`/`at(addr)`): reads
  `FocusPolicy()`/`Banners()`/`History()`, writes `SetFocusMode`/
  `SetFocusAllowList` from `org.dragonfruit.Notifications1`.

**Deviations.** None from the Scope. No settingsd keys were added: the global
notification preferences the macOS pane shows (`Show previews`,
sleeping/locked/mirroring) have no owner in the service today and are T-15.7b
settingsd work, deliberately kept off the adapter.

**Evidence.**
- `cargo test -p dragonfruit-notify-adapter` — 31 lib + 5 `session_bus` green
  (the session-bus tests stand up a private `dbus-daemon` and drive the real
  service).
- `cargo test -p dragonfruit-system-adapters` — green.
- `make e2e` — EXIT 0 (now includes `cargo test -p dragonfruit-notify-adapter`).
- `cargo fmt --all -- --check`, clippy `-D warnings` on both crates — clean.
- `make check-design-tokens check-tokens check-no-capture-grab` — clean.
- `make lint` fails only on the pre-existing `check-desktop-names` lines
  (unchanged).
- Live visual check: `bash scripts/capture-t15-notify-adapter.sh` produced
  `docs/captures/t15-7a-notify-adapter.png` (3840x2160). The adapter has no
  surface of its own, so the capture confirms the nested desktop renders;
  vision found the menu bar, Dock, wallpaper, and windows composited with no
  clipping or stray artifacts (the flagged dark area is the host screen outside
  the nested output).

**Next (T-15.7b).** Add the host seam (mirror bluetooth/storage/battery:
