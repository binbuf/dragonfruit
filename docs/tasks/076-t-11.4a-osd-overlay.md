## Hand-off

Landed: the brief volume/brightness OSD on the active output, reduced-motion
and fullscreen aware.

- `shell/src/osdmodel.{h,cpp}` (new, dockcore) — the pure presentation model
  (present/tick/deadline, coalescing, fullscreen suppression, fade with a
  reduced-motion 1.0 path).
- `shell/osd/Osd.qml` (new module `Dragonfruit.Osd`) — the card view.
- `shell/src/shellprotocol.{h,cpp}` — centered unanchored `overlay` surface
  (`namespace "osd"`), plus `fullscreenOverlayActive()`.
- `shell/src/shellcontroller.{h,cpp}` — the offscreen scene, the 16 ms
  visible-only timer, and the volume/mute/brightness triggers.
- `design-system/tokens/tokens.json` — `component.osd` / `motion.osd`
  (regenerated into `Theme.qml` and `design_tokens.rs`).
- Tests: `tst_dockcore` OsdModel tests, `tst_osd` QML tests. `make e2e`,
  `make lint`, `make qml-test` (38/38) green.
- ADR [0062](../design/adr/0062-osd-overlay.md); `04-shell.md` T-11.4a status.

Deviations / notes:

- The OSD triggers are the shell's own gestures (Control Center sliders,
  menu-bar volume menu, mute). Hardware media keys are not wired (no
  compositor input action yet); external volume pushes deliberately do not
  present the OSD to avoid a double-show after our own write.
- The surface is unanchored so the compositor centers it; active-output
  targeting uses the per-output overlay rule (single output is exact).
- `DF_OSD_FIXTURE=volume|brightness` is the capture-only presentation seam.
- Live check: `make demo` + Control-Option-C + drag the Sound slider; the OSD
  card rendered with the glyph, accent level bar, and percentage, no artifacts
  (`/tmp/opencode/t76-osd.png`). The still is not committed.

T-11.4b adds the keyboard/AT-SPI pass and commits the capture set; the view
already carries an `Accessible.Alert` name to build on.
