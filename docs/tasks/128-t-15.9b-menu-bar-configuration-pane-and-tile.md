## Hand-off

**Landed.** The Settings Menu Bar pane (`apps/settings/MenuBarPane.qml`) and the
Control Center Menu Bar tile ship as one functional unit, shell-native plus
settingsd keys (ADR 0135), exactly as T-15.9a anticipated. Revision 16 adds
eleven `menu.*` keys; the pane writes them, the shell applies the clock options,
the background material, and the per-control `menu.control.*` visibility live,
and `shell/src/controlcenterpolicy.cpp::menuBarView` projects the tile locally
(`Never` / `Always` / `In Full Screen Only`). Absence is a missing settings
daemon: the rows stay live on the schema defaults with a one-line note; the
tile has no separate absence because the shell always holds the projection.

**Verified.** `cargo test -p dragonfruit-settingsd` (incl. `schema_doc`),
`ctest --test-dir build --output-on-failure -j4` (63/63), `make e2e` (EXIT 0),
`cargo fmt --all -- --check`, clippy on `dragonfruit-settingsd`, the token and
capture-grab checks, and the 78 gallery snapshots are all green. `make lint`
fails only on the pre-existing `check-desktop-names` lines (unchanged).

**Deviations (recorded, not re-litigated).** Apple-only controls (AirDrop,
Screen Mirroring, Display) and Spotlight are omitted; the `Add Controls...` /
`Battery Options...` buttons and the `Show When Active` popups have no Linux
provider and are omitted rather than dead; the recent-items stepper is a
`Select` because the design system has no stepper. `menu.autoHide` and
`menu.recentItems` are stored policy (see `## Follow-ups` in PROGRESS.md).

**Visual.** `bash scripts/capture-t15-menubar-pane.sh` produced
`docs/captures/t15-9b-menu-bar-pane.png` (2088x1410) and
`t15-9b-menu-bar-control-center.png` (360x1160). The pane scrolls (the Settings
window is a fixed 800×640); Accessibility is below the fold but a scrolled
verification confirmed it renders. Vision read the tile (`In Full Screen Only`,
link present) and found no clipping/overlap in the panel. Human sign-off is
batched at the track boundary.

**For T-15.10a (General/About/Updates) and later.** The Control Center panel is
now at the nested-output height ceiling (360×1160 in a 1920×1200 output leaves
1164 px below the bar). A further tile must make the panel scroll or grow the
nested output rather than bump `kControlCenterHeight`. Do not add a second bar
model or a menu resolver; the adapter stays read-only and the pane writes keys.
