## Hand-off

**Status: done.** The Settings app now applies settings live through settingsd,
and the `--placeholders` window is confirmed replaced (the T-09.1a shell).

What landed (repo root):

- **`libs/settings-client/`** (new) — the former `shell/src/settingsclient.{h,cpp}`
  moved here as the static library `dragonfruit-settings-client`; the shell's
  `dragonfruit-shell-dockcore` links it `PUBLIC`, so shell behavior is
  unchanged. One client for the shell and the app (ADR 0036).
- **`apps/settings/SettingsBridge.{h,cpp}`** (new) — the C++ QML singleton
  **`Settings`** in `Dragonfruit.Settings`: reactive `values`, `available`,
  `value(key, fallback)`, `set(key, value)`, `refresh()`, `keys()`. Panes bind
  to `values` and write through `set`; no pane opens D-Bus.
  `DF_SETTINGS_FIXTURE` selects the deterministic mock (headless QML tests).
- **`apps/settings/tests/tst_settings_live.cpp`** (new) — binds a stock
  design-system `Toggle` to `accessibility.reduceMotion` and round-trips it
  through (a) the fixture, (b) a fake `org.dragonfruit.Settings1` on a private
  bus, and (c) the real `dragonfruit-settingsd` binary. This is the task's
  "representative control round-trips through settingsd".
- **Docs** — ADR [0036](../design/adr/0036-shared-settings-client-and-qml-singleton.md);
  track 09 live-apply section (with the two-way binding pattern); track 08
  consumer note.

Commands that work (all green):

- `ctest --test-dir build -R tst_settings_live --output-on-failure` — 3/3.
- `make qml-test` — 23/23; `make lint` green; `make e2e` green.
