## Hand-off

**State: done** (with one honest deviation, below). A real Flatpak browser
(`org.mozilla.firefox`) file-chooses, screenshots, and screen-shares through
the real `xdg-desktop-portal` frontend into the Dragonfruit backend. The
capture is committed.

What landed:

- **`scripts/capture-portals.sh`** (new) — the T-13.7 capture. A private
  session bus runs the real frontend + Dragonfruit backend + `settingsd` +
  notifications; a host presenter stands in for the shell; the driver runs
  **inside** `flatpak run org.mozilla.firefox`. Writes
  `docs/captures/t13-portals.txt` (round-trips) and `t13-portals.png` (the
  shell's picker raised by the Flatpak FileChooser, private bus exported into
  `make demo`). Not in `make e2e` (needs a host seat, Flatpak, spectacle).
- **`scripts/flatpak-portal-driver.py`** (new) — presenter / client / trigger
  roles; one file for the host and the sandbox.
- **`docs/captures/t13-portals.txt`** — FileChooser `uris`, Screenshot `uri`,
  ScreenCast `streams` (`df_stream_mode=stills`), frontend-reported versions.
- **`docs/captures/t13-portals.png`** — 1920×1200; vision verdict: menu bar +
  Dock render; centered picker titled "Open a file from the Flatpak browser",
  breadcrumb `/home/user`, folders-first rows, Cancel/Open; no black regions.
- **Real-frontend bugs fixed** (found only by this task):
  1. `portal/data/dragonfruit.portal` and `dragonfruit-portals.conf` used `;`
     comments; GLib key files need `#`. (These edits were already in the tree
     when the session started and are now validated.)
  2. The impl interfaces exported `Version` (zbus default); the standard is
     lower-case `version`. The frontend read 0 and disabled cursor modes, the
     Screenshot `uri` result, and persistence. Fixed with
     `#[zbus(property, name = "version")]` on Settings/Screenshot/ScreenCast/
     GlobalShortcuts; FileChooser's non-standard `Version` property removed.
     Pinned by `the_standard_interfaces_expose_the_lowercase_version_property`
     (`portal/tests/portals.rs`).
- **`docs/design/adr/0085-real-frontend-portal-compatibility.md`** (new) and a
  "Flatpak validation (T-13.7)" section in `07-system-integration.md`.

Commands that work (repo root):

- `cargo test -p xdg-desktop-portal-dragonfruit` — 58 lib + 5 filechooser + 4
  screenshot + 4 screencast + 4 portals + 4 session_bus, all pass.
- `cargo clippy -p xdg-desktop-portal-dragonfruit --all-targets -- -D warnings`
  — exit 0; `cargo fmt -p ... -- --check` — exit 0.
- `./scripts/check-no-capture-grab.sh` — "no capture-grab protocol references".
- `bash scripts/capture-portals.sh` — exit 0; `CLIENT: RESULT: PASS`; writes
  both captures. Build note (unchanged): `export
  PKG_CONFIG_PATH=$HOME/.local/df-devroot/lib64/pkgconfig:$PKG_CONFIG_PATH` and
  `RUSTFLAGS="-L $HOME/.local/df-devroot/lib64"` (or just `make`).

Deviation: clipboard. There is no clipboard portal by design (ADR 0082), so a
Flatpak app's clipboard is the Wayland data device through the sandbox proxy,
not a portal call. That is covered by T-13.5a's compositor conformance (native
clients); a Flatpak-vs-native nested clipboard capture was not added. Nothing
else is required for T-14's zoo.

Gotchas for later tasks:

- **The private bus must also carry `settingsd`** or the shell stops before it
  maps its chrome (no menu bar/Dock). `capture-portals.sh` starts it.
- **`Version` is not `version`.** Any new impl portal `version` property must
  name the wire property `version`; the data files must use `#` comments.
- **Run `spectacle` on the host bus** (`unix:path=$XDG_RUNTIME_DIR/bus`), not
  the private one.
- The ScreenCast stream is still the named stills fallback; a live PipeWire
  producer extends `portal::stream::StreamTransport`.
