## Hand-off

**Status: done.** The menu-broker is a real service and the fixed application
menu carries live Hide/Hide Others/Show All state.

Landed:

- `services/menu-broker/src/model.rs` (new) — pure `Broker`: parses the
  ADR-0041 published model (`PublishedModel::parse`), derives the hide verbs
  from the window list (`Visibility`, `WindowState`, `HideVerbs`), synthesizes
  the fixed application menu, rewrites only the three hide rows on a published
  menu, and resolves the focused app (`resolve`/`resolve_focused`/`fixed_menu`).
- `services/menu-broker/src/dbus.rs` (new) — `org.dragonfruit.MenuBroker1` at
  `/org/dragonfruit/MenuBroker1`: `Publish`/`Withdraw`, `SetFocusedApp`/
  `SetWindowStates`, `Resolve`/`ResolveFocused`/`Policy`,
  `PublisherCount`/`Revision`, and a `Changed` signal. Malformed publishes are
  rejected (never clobber a good model).
- `services/menu-broker/src/{lib,main}.rs`, `Cargo.toml` — lib+bin; `--fixed
  <appId>` / `--resolve <appId>` debug helpers.
- `services/menu-broker/tests/session_bus.rs` (new) — private-`dbus-daemon`
  fixture export → expected menu model, live-state matrix, Files desktop,
  malformed publish/withdraw.
- `shell/src/menubrokerpolicy.{h,cpp}` (new) — the shell's pure fallback: maps
  the Dock running projection to the same live flags and builds the fixed
  application menu. `applyAppMenuLiveState` rewrites a published menu.
- `shell/src/shellcontroller.cpp` — `applyFocusedApp` publishes the live fixed
  menu; `onDockStateChanged` re-publishes so minimize/restore/open/close update
  the verbs. The old static `applicationMenu` helper is deleted.
- `shell/tests/tst_dockcore.cpp`, `shell/tests/tst_menubar.qml` — live-state
  policy + rendering (a disabled verb refuses to dispatch).
- `docs/design/adr/0095-menu-broker-resolution-and-fixed-menu.md` (new) and
  `docs/design/06-global-menu.md` updated.

Deviations / what to know:

- **The shell does not yet talk to the service.** No first-party app publishes
  to the broker yet, so the demo reads its live state from the shell's own
  `menubrokerpolicy` fallback. The broker's D-Bus surface is exercised only by
  its private-bus tests. T-14.2b (accelerators/toggle) should wire the shell to
  push window state and consume `Resolve`, and wire Settings' `publishedModel`.
- **Actual hide/hide-others/show-all window operations are not implemented.**
  T-14.2a only reflects live state; the actions still log. Hiding an app's
  windows needs a new compositor window-state request.
- The `DbusMenu` tier is defined but not populated (T-14.4).
- Live check: `make demo` + synthetic click at the app menu (x≈64,y≈14) →
  captured `/tmp/opencode/t103-menu-open.png`; the dropdown shows the fixed
  application menu with `Show All` visibly dimmed while `Hide`/`Hide Others`
  are bright. A Qt app and `xmessage` are both running, so Hide Others is
  enabled. Captures also in `/tmp/opencode/t103-bar-idle.png`.
