## Hand-off

**Landed.** `services/files-core/src/ops.rs` (new module, re-exported from
`lib.rs`):

- `FileOps` — the one operations seam: `rename`, `create_dir`, `copy`,
  `move_to`, `delete`, `exists`, plus the provided `new_folder`.
- `StdFsOps` — the sanctioned `std::fs` backend (same degradation as listing,
  ADR 0043); resolves only `file://`. Recursive copy recreates symlinks
  without following them; cross-device move is copy-then-delete; `delete` is
  permanent and recursive.
- `generated_name` — the one next-available-name helper (`untitled folder`,
  `untitled folder 2`, …), raw-byte preserving. `NEW_FOLDER_BASE`.
- `OperationError` — typed failures (`AlreadyExists`, `NotFound`,
  `NotADirectory`, `DirectoryNotEmpty`, `InvalidName`, `UnsupportedScheme`,
  `PermissionDenied`, `Io`) with `from_io` classification.
- `Location::parent()` added (file paths and foreign-scheme URIs); fixed
  `Location::child` for an authority-only foreign root (`trash:///`), which
  previously dropped the `://` and made `scheme()` panic.

**Tests (acceptance).** `services/files-core/tests/operations.rs` — 17 cases
covering the full matrix against temp dirs: rename (contents, conflict,
missing, empty name), new-folder numbering, create-dir conflict, file/dir
copy, symlink recreation, non-UTF-8 name, missing source / bad destination /
conflict / self-copy, move file + dir, move self/conflict, delete file + tree
+ missing, broken-symlink `exists`, and every operation refusing `trash://`.
Unit tests cover `generated_name`, name validation, `from_io`, and
`Location::parent`/foreign `child`.

- `cargo test -p dragonfruit-files-core` — 66 pass (36 unit + 17 operations +
  5 sorting + 6 streaming + 2 doctests). Plain `cargo` hung here until
  `CARGO_NET_OFFLINE=true` was set; use `make` (or the offline flag).
- `make lint` — 31/31 ctest, clippy and all checks green.
- `make e2e` — exit 0 (`E2E_EXIT=0`).

**Deviations / decisions.** ADR
[0044](../design/adr/0044-files-core-operations-seam.md): synchronous
primitive layer, permanent delete, conflict-as-error, raw-byte generated
names. `docs/design/09-files.md` gained a T-10.2a implementation-status
paragraph. Nothing for T-10.2b to undo: it wraps `FileOps` with optimistic
semantics — do **not** bypass the seam. `delete` stays permanent; `trash://`
remains `UnsupportedScheme` until T-10.3a.

**Live visual check.** `bash /tmp/opencode/t58-capture.sh` → nested demo on
the host session, still `/tmp/opencode/t58-desktop.png` (1920x1200). Vision
raw observation: "no clipping, blurring, or missing elements"; the Settings
window, X11 demo window, and Dock/taskbar all render; no stray artifacts.
files-core has no surface of its own, so this only confirms the session still
renders (supporting check).
