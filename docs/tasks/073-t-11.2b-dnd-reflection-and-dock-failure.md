## Goal

Reflect DND/Focus in the menu bar and replace the Dock's failure path with a notification.

## Scope

- The menu-bar item reflects DND/Focus state.
- Replace the Dock's launch-failure path with a real notification.

## Explicitly deferred

- Control Center (T-11.3a).

## Acceptance (agent-completable)

- [ ] Bar state tracks policy; launch failure notifies.

## Test plan

- Headless: toggle policy and assert bar; launch-failure produces a notification.

## Hand-off

Landed: the menu bar reflects the notification service's Focus/DND policy, and
the Dock launch-failure path is a real notification (the T-11.1b notification
is unchanged; the transient Dock mark is only cosmetic). Contract frozen in
[adr/0059](../../design/adr/0059-menu-bar-focus-reflection.md).

Files:

- `shell/src/notificationclient.{h,cpp}` — the seam gains
  `setFocusMode(mode)` and a `focusPolicyChanged(json)` signal; `refresh()`
  now also reads `FocusPolicy()`. The live `DbusNotificationClient` calls
  `FocusPolicy`/`SetFocusMode`; `MockNotificationClient` maintains the mode
  (rejecting unknown names, clearing the batch on `off`) and mirrors the
  T-11.1a `setDoNotDisturb` bool onto it.
- `shell/src/notificationmodel.{h,cpp}` — `applyFocusPolicyJson`,
  `focusPolicy()`; malformed/missing payload clears the policy.
- `shell/src/focusstatus.{h,cpp}` (new, dockcore) — `focusStatusItem(policy)`:
  hidden for `off`, crescent for `focus`, `selected` for `dnd`, label =
  `batchedCount` when non-zero, accessible name always carries the mode/count.
- `shell/src/shellcontroller.{h,cpp}` — connects `focusPolicyChanged`, decodes
  it, rebuilds the status row; `applyStatusItems()` now derives the `focus`
  item from the model instead of a hardcoded hidden slot. `DF_FOCUS_FIXTURE`
  starts the `DF_NOTIFY_FIXTURE` mock in a given mode (capture/demo only).
- Tests: `tst_notificationmodel` (policy decode + safe default),
  `tst_dockcore` (`focusStatusItem` mapping; mock `setFocusMode` /
  compat `setDoNotDisturb` round-trip), `tst_menubar.qml` (renders the three
  states). `ctest` 35/35.
- Docs: `04-shell.md` T-11.2b status; ADR 0059.

Commands that work (repo root; `make` sets the toolchain env):

- `LD_LIBRARY_PATH=$HOME/.local/df-toolchain/usr/lib64 ctest --test-dir build -R "tst_notificationmodel|tst_dockcore|tst_menubar"` — pass.
- `make qml-test` — 35/35.

Live visual check: `/tmp/opencode/t73-capture.sh` runs `make demo` with
`DF_NOTIFY_FIXTURE=1 DF_FOCUS_FIXTURE=dnd`, then `/tmp/opencode/t73-driver.py`
crops the nested menu bar to `/tmp/opencode/t73-focus.png`. Verdict: the
accent-tinted crescent renders left of the clock, then the Control Center and
Mission Control marks; no clipping or artifacts.

Next: T-11.3a builds the Control Center panel; it should reuse
`focusStatusItem`'s `selected`=DND convention and `focusPolicyChanged`.
