## Goal

When the running groups do not fit on the Dock, reserve the last slot for an
**overflow cell** (a grid glyph with the hidden-group count) that opens a "More
windows" list; a group chosen from the list opens its chooser anchored to the
overflow cell. Pinned apps are never hidden; the icon-size clamp stays the last
resort for extremes.

## Context (read first)

- `shell/src/dockmodel.{h,cpp}` — `applyDockOverflow` implements legacy T-10
  §5.1: clamp `dock.size` at layout, shrink temporary/recent first, never drop
  pinned, no affordance. The pure function and its `tst_dockcore` cases are the
  place to add the overflow entry.
- `shell/dock/Dock.qml` — `items`/`appEntries`/`minimizedEntries` regions,
  the `stackEntry`/`trashEntry` synthetic-entry pattern, activation, and the
  chooser host (`openChooser`) that the overflow list reuses.
- `shell/dock/DockWindowChooser.qml` — T-14.7m/n gave it per-window actions and
  a bounded viewport; the overflow list is a separate, simpler list.
- `shell/dock/DockGlyph.qml` — the `stack`/`trash` kinds show how a synthetic
  entry draws original artwork; add an `overflow` kind (grid glyph), not text in
  the artwork (ADR 0092).
- `shell/tests/tst_dockcore.cpp` — existing overflow clamp cases to update;
  `shell/tests/tst_dock.qml` for rendering/activation.
- Reference behavior only (GPL, never copied):
  `TaskOverflowPopup.qml` / the `overflow` DockItem in
  `~/repos/punchi-dock-remastered` reserve exactly one physical slot, name the
  cell `"N more window groups"`, and list the groups (single-window rows get
  inline actions; multi-window rows open the grouped popover).
- Reference capture `docs/reference/macos/Dock.png` (local; never shipped):
  ~15 entries with three regions and no overflow cell. The cell is only shown
  when the running groups genuinely do not fit, so it is absent from the
  reference resting state; do not reserve a slot when everything fits.

## Current behavior (investigated, T110 era)

- Overflow clamps the icon size and hides temporary/recent entries with a
  once-per-session log; the hidden groups are unreachable from the Dock.
- Legacy T-10 §5.1 explicitly chose "no affordance for MVP"; this unit revisits
  that decision for the running-groups case (ADR 0103).

## Scope

- [ ] Pure planner (`dockmodel`): when the running groups exceed the fit,
      produce a terminal `overflow` entry carrying the hidden groups (name,
      icon, `windowCount`, rows) instead of only dropping them; pinned entries
      are never in the overflow set; the existing clamp remains the outer
      fallback when even one overflow cell cannot fit.
- [ ] Dock: render the overflow cell (grid glyph + count badge from T-14.7o's
      token/badge path); it is the last app-region item before the divider; it
      is not reorderable and not pinnable.
- [ ] Popover: a "More windows" list anchored to the cell; a single-window row
      activates its window (or shows the inline actions from T-14.7m); a
      multi-window row opens the chooser anchored to the overflow cell.
- [ ] Accessibility: the cell's accessible name states the hidden-group count;
      list rows carry the group name and window count.
- [ ] Tests: `tst_dockcore` for the overflow entry and pinned exclusion;
      `tst_dock.qml` for the cell, the popover, and activation; a case that no
      entry is lost silently (every hidden group is reachable).
- [ ] Capture `docs/captures/t14-dock-overflow.{light,dark}.png` (a full Dock
      with the cell and the open list) and the `PROGRESS.md` note.

## Explicitly deferred

- Pinned-app overflow (pinned entries are never hidden).
- A user-tunable max group count (the fit is computed; keep a token ceiling if
  needed).
- Overflow for the minimized or folder regions.
- Cross-output overflow.

## Design notes

- This supersedes legacy T-10 §5.1 for running groups only and must say so in
  the PROGRESS note and [10-dock.md](../tasks/legacy/10-dock.md) if that file is
  still referenced as the design source; ADR 0103 records the change.
- The overflow cell participates in the same layout/magnification as a real
  entry but never enters `dock.pinned`.
- Keep the pure planner authoritative: QML renders what the model emits, so the
  dockcore tests can prove "nothing is lost".
- One popover at a time; the list must not fight the hover-open chooser from
  T-14.7p.

## Hand-off

**Landed.** The terminal `kind: "overflow"` entry, its grid artwork and count
badge, the `DockOverflowPopover.qml` "More Windows" list, single/multi-window
activation, and the capture are all in.

**Entry shape (pure model, `shell/src/dockmodel.{h,cpp}`).** `applyDockOverflow`
still clamps `dock.size` first (the outer fallback). Only when even `iconMin`
overflows does it fold the running groups that do not fit into one overflow
entry: `{ id: "__overflow__", kind: "overflow", hiddenCount, windowCount,
groups: [temporary-entry, ...] }`. Every group map keeps its original fields
plus `overflowGroup: true`, so the chooser can re-resolve it after a projection.
The entry is the last app-region item, inserted immediately before the first
minimized entry. `DockOverflowResult` gained `overflowShown` (the cell's group
count, 0 = no cell) so the shell's Repeater reset also fires when the cell's
presence changes without the raw hidden counts changing. Pinned/minimized/fixed
entries are never in the overflow set; recents are still dropped silently (they
are suggestions, not running groups).

**Fit rule.** Let `nonDroppable = pinned + fixedCount + 1 (divider) + minimized`.
`maxVisible` is the largest count fitting at `iconMin`; `capacity = maxVisible -
nonDroppable`. Keep `min(T, capacity)` temporaries and fill the rest with
recents. When temporaries are hidden and `capacity >= 1`, free exactly one
temporary slot (the freed group joins the cell) so the cell itself fits; the
cell lists the hidden temporaries. When `capacity == 0` not even a cell fits —
legacy silent drop plus `overflowed`. When `maxVisible < nonDroppable`,
`overflowed` and nothing is hidden.

**Dock terminal state.** `Dock.qml` grew `overflowOpen`/`overflowAnchor`/
`overflowEntryRef`/`overflowGroups`, `openOverflow`, `activateOverflowGroup`,
`openOverflowGroupChooser`, `refreshOverflowAfterProjection`, and
`openOverflowFixture` (the capture seam). `entryHoverBegan`/`isDraggable`/
`openEntryMenu`/`publishEntryTile` all treat `kind === "overflow"` as inert for
drag, context menu, and tile reporting; a click opens the list. `popoverOpen`
and `activePopoverRect` include the list, so one-popover-at-a-time holds and the
hover-open chooser cannot fight it. A multi-window choice opens the chooser with
`chooserEntry` = the group and `chooserAnchor` = `chooserAnchorProxy` captured
from the overflow cell; `refreshChooserAfterProjection` re-resolves an
`overflowGroup` entry from the fresh overflow entry (or dismisses when the cell
is gone).

**Shell.** `m_dockOverflowShown` mirrors `overflow.overflowShown` in the
Repeater-reset decision; `warnDockOverflow`'s wording mentions the cell. The
`DF_DOCK_OVERFLOW_FIXTURE=1` capture seam (constructor + `rebuildDockEntries` +
`computeDockOverflow`) injects eight synthetic running groups and caps the
effective axis at 480 px so a genuine overflow appears at the normal nested
size. Never set in a normal session.

**Follow-up for T-14.7r.** The overflow cell is deliberately excluded from the
stacks/trash/folder regions and from cross-output overflow. `DockEntry.
showWindowBadge` now has an `isOverflow` branch; if T-14.7r touches badge
precedence, keep the overflow count ≥ 1 rule. `hiddenTemporary` now counts the
groups in the cell (which is one more than the groups that would have been
dropped, because the cell itself costs a slot).
