## Hand-off

**State: done.** The ScreenCast stream is now negotiated through one transport
seam, and this build ships the *named* stills fallback — the timeboxed answer
the track design explicitly allows. Contract frozen in ADR
[0081](../design/adr/0081-screencast-stream-negotiation-and-stills-fallback.md).

What landed:

- **`portal/src/stream.rs`** (new) — `StreamMode` (`pipewire`/`stills`),
  `FallbackReason` (`ProducerUnavailable`/`SourceUnavailable`), `StreamSource`,
  `NegotiatedStream` (`live`/`stills`), the one `StreamTransport` trait,
  `StillsTransport` (the shipped impl, always `ProducerUnavailable`),
  `StreamNegotiator` (per-source `negotiate` + `destroy`), and
  `stream_properties` (the `df_stream_mode` / `df_fallback` wire extensions).
- **`portal/src/screencast.rs`** — `ScreenCastStream` gained `mode` / `fallback`
  (and `from_wire` defaults a missing mode to `stills`, so an old peer can never
  look live); `ScreenCastSession::streams` takes the negotiator;
  `ScreenCastRegistry` owns a `StreamNegotiator`, remembers live node ids per
  session, and releases them on `close_session`; new `with_transport` /
  `stream_mode`.
- **`portal/src/dbus.rs` / `interfaces.rs`** — diagnostic
  `ScreenCastStreamMode` reports the negotiated mode; `Start` negotiates.
- **Shell** — `ScreenCastBridge` gained `streamMode` / `streamNote`; it reads the
  diagnostic asynchronously (a missing service/method leaves `stills`).
  `ScreenCastPicker.qml` shows the note; `ShellController::applyScreenCastData`
  forwards it.
- **Tests** — 5 `stream` unit tests (modes round-trip; live transport yields a
  node; shipped transport names the fallback; refused source is a named
  fallback; wire properties), `screencast` unit tests for the live node +
  release, `portal/tests/screencast.rs` asserts mode/reason on the wire and the
  diagnostic; `tst_screencast.cpp` adds the no-portal fallback case;
  `tst_screencastui.qml` asserts the note is visible/hidden.

Deviations / what later tasks need:

- **No live PipeWire producer is built.** This is deliberate and documented, not
  silent: every stream reports `df_stream_mode = stills` with a `df_fallback`
  reason, the diagnostic `ScreenCastStreamMode` says `stills`, and the picker
  says so before the user chooses. A real producer only implements
  `portal::stream::StreamTransport`; the session, picker, and diagnostic
  surfaces do not change. This is the timeboxed path T-13's design names.
- **The stream properties are Dragonfruit extensions**, ignored by the standard
  frontend; geometry/cursor metadata can be added by a real producer without a
  backend version bump.
- **T-13.5 adds clipboard.** T-13.7 owns real `xdg-desktop-portal` routing and
  the Flatpak browser walkthrough (which will exercise this fallback).
