## Test plan

## Hand-off

**State: done.** The one change monitor landed in `services/files-core`:
`FolderWatcher`/`WatchReader` (sibling of `DirectorySource`), the
`InotifyWatcher` sanctioned fallback (Linux inotify over `libc`, marked for
replacement with `SANCTIONED_WATCHER_FALLBACK_MARKER`), a `MockWatcher`
headless fixture, `DirectoryModel::begin_watch`/`apply_watch`/`drain_watch`/
`node_id_for_uri`, and `OptimisticModel` forwarding plus confirm/revert
reconciliation. Events fold incrementally and never re-list; a rename keeps the
node id. See ADR [0047](../design/adr/0047-files-core-folder-watcher-seam.md)
and the `docs/PROGRESS.md` "T61" section.

Verification: `CARGO_NET_OFFLINE=true cargo test -p dragonfruit-files-core` —
122 pass (12 watcher: scripted create/delete + rename-id + modify-refresh +
stale-generation + optimistic confirm/revert, and real-inotify create/delete,
rename-id, `new_folder_via`); `make lint` 31/31; `make e2e` exit 0.

Live capture: `/tmp/opencode/t61-desktop.png` (1920x1200, nested demo). Raw
vision observation: menu bar, Settings window, X11 demo window, and the Dock
render; the only artifacts are the pre-existing X11 window clipping and Dock
label truncation seen since T57. files-core has no surface of its own, so this
only confirms the session still renders.

Deviations / notes: `libc` is a Linux-only dependency; the watch is
non-recursive, matching one-monitor-per-visible-directory. A self delete/move
of the watched folder is not surfaced yet (follow-up in PROGRESS.md). The
optimistic watcher reconciliation has no timeout policy (fine while `*_via`
resolves synchronously).

- T-10.4 renders the model; drain watch events per frame and add no matching
  logic in C++/QML.
