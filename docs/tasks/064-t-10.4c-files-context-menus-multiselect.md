## Hand-off

**State: done.** Multi-select (Cmd-toggle, Shift-range, Cmd+A), the Finder
context menus (item / multi / background), inline rename, and optimistic
rename/trash/new-folder all work and are covered by headless tests. The
`files-core` C ABI gained an operations worker so the optimistic edit paints
before the real `FileOps`/`TrashOps` call and confirms or snaps back on a
later poll (ADR 0050). `FilesDirectoryModel` now keeps its session after the
listing completes, so sort and operations work on a loaded folder.

- What landed: `services/files-core/src/ffi.rs` (optimistic ABI + op worker),
  `apps/files/ffi/files_core.h`, `FilesDirectoryModel.{h,cpp}`,
  `FilesShell.qml`, `FilesIconView.qml`, `FilesListView.qml`,
  `FilesBridge.{h,cpp}`, tests, ADR 0050, and the `09-files.md` T-10.4c
  paragraph.
- Deviations: selection stays in QML (`FilesShell.selectedIds`), not the Rust
  `Selection`, because node ids are per-listing and both views already share
  the shell's set. Rename is inline in the views rather than a dialog.
  `Open in New Window` is present but disabled; `Open` is enabled for folders
  only. File opening / Open With / Get Info / Copy / Duplicate / Compress /
  Make Alias and rubber-band selection remain deferred (T-10.4c+).
- Verification: `cargo test -p dragonfruit-files-core` 128 pass;
  `make qml-test` 32/32 (tst_files_shell 26); `make lint` green;
  `make e2e` exit 0. Live capture: `/tmp/opencode/t64-capture.sh <mode>`
  (`multiselect|context|background|rename`) → `/tmp/opencode/t64-files-*.png`;
  vision confirmed three highlighted rows, the item/background menu items, and
  the inline rename editor.
- T-10.5 measures the model. The stable seam is the whole-snapshot
  `df_files_poll` delivery; the QML roles and the `df_files_begin_*` /
  `pendingOps` operation contract must not change. Do not re-free the session
  on `DONE`.
