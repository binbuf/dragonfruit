## Hand-off

**State: done.** The design calls for clipboard history (ADR 0082's accepted
consequences name T-13.5b's history with clear-on-lock and size caps; legacy
T-29 specifies it), so it is implemented, not declined. The shell observes the
selection through the vendored `wlr-data-control` client protocol, feeds a
pure bounded store, renders it in the Control Center, and forwards a chosen
entry. Contract frozen in ADR
[0083](../design/adr/0083-clipboard-history-store-and-observer.md).

What landed:

- **`shell/src/clipboardhistory.{h,cpp}`** (new, dockcore) — `ClipboardHistory`:
  classifies `text`/`image`/`files`/`other`, dedups by content hash (promoting
  a re-copy and preserving its pin), caps at 50 entries / 1 MiB each / 8 MiB
  total (evicting oldest unpinned), refuses the common password-manager secret
  hints, clears unpinned on lock (pinned survive), searches, and round-trips
  best-effort JSON.
- **`protocols/wayland-protocols/wlr-data-control-unstable-v1.xml`** (new,
  vendored MIT) + `shell/src/CMakeLists.txt` generation of its client bindings.
- **`shell/src/shellprotocol.{h,cpp}`** — binds
  `zwlr_data_control_manager_v1`, gets a device for the seat, reads the
  supported MIME payloads on `selection`, emits
  `clipboardObserved(mimes, payloads)`, and re-serves an entry with
  `offerClipboard(mimes, payloads)` (a `zwlr_data_control_source_v1` +
  `set_selection`). The clipboard is never replaced while idle (ADR 0082).
- **`shell/src/shellcontroller.{h,cpp}`** — owns the store, persists it under
  the app data dir, clears unpinned on `onSessionLocked`, feeds the Control
  Center, and handles copy/pin/clear requests. Logs one line per observed
  selection.
- **`shell/control-center/ControlCenter.qml`** — a Clipboard section (5 entries
  max) with previews, Pin/Unpin, and Clear; the five-tile model is unchanged.
  The panel grew 520 → 780 px to fit it.
- **Tests** — `shell/tests/tst_clipboardhistory.cpp` (13 cases) and two new
  Control Center QML cases.

Commands that work (repo root):

- `cargo test -p dragonfruit-compositor --test shell_protocol_conformance
  clipboard_round_trips_text_image_and_uri_list` — passes (unchanged).
- `ctest --test-dir build --output-on-failure` — 51/51 (adds
  `tst_clipboardhistory`; `tst_controlcenter` now 20 cases).
- `make lint` — exit 0; `make e2e` — exit 0.
- Build note (unchanged): `export PKG_CONFIG_PATH=$HOME/.local/df-devroot/lib64/pkgconfig:$PKG_CONFIG_PATH`
  and `RUSTFLAGS="-L $HOME/.local/df-devroot/lib64"` (or just `make`).

Live check: `DF_STATUS_FIXTURE=1 make demo DEMO_ARGS="--socket-name
dragonfruit-t97-capture"`, opened the Control Center through the real
Control-Option-C shortcut via `DRAGONFRUIT_SYNTHETIC_INPUT`, captured with
`spectacle -b -n -a`. A seeded `clipboard-history.json` gave three entries so
the store/load path was exercised. Vision (`/tmp/opencode/t97/panel-wide.png`):
all five tiles (Wi-Fi/Focus/Sound/Display/Dark Mode) above a Clipboard section
showing the pinned text entry with "Unpin", the uri-list entry
"shot.png, notes.txt" with "Pin", the text entry "hello from the clipboard
observer" with "Pin", and a fully visible "Clear Clipboard" link; panel bottom
inside the frame, no clipping.

Gotchas for later tasks:

- **The store never owns the selection while idle.** It only calls
  `offerClipboard` when the user copies an entry; forwarding is the one
  ownership hand-off (ADR 0082).
- **`wlr-data-control` primary selection is ignored** (the offer is destroyed);
  only the clipboard is stored.
- **Persistence path** is `QStandardPaths::AppDataLocation` →
  `~/.local/share/dragonfruit/dragonfruit-shell/clipboard-history.json`;
  loading is tolerant and a missing/unwritable file is not an error.
- **Control Center is now 780 px tall** (`kControlCenterHeight`); a future
  taller section should make the content scroll rather than grow the surface
  without bound.
- T-13.6 (polkit) is next; T-13.7 is the real frontend/Flatpak walkthrough.
