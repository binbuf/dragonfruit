Decisions / gotchas for T-15.9b:

- **Reuse is load-bearing.** The adapter projects the shell menu bar
  (`shell/menubar/MenuBar.qml`) and the menu-broker; do not re-render the bar
  or re-resolve a menu.
- **The adapter is read-only.** The durable preferences are settingsd's (the
  `menu.*`/clock keys T-15.9b declares) and the shell applies them live.
  T-15.9b is expected to be shell-native + settingsd keys (the T-15.5b /
  T-15.8b precedent), not a system-status host; do not add a write to the
  adapter.
- **Control ids are the shell status-item ids** (`clock`, `wifi`, `bluetooth`,
  `battery`, `volume`, `focus`, `accessibility`); `Sound` uses the audio
  adapter's `volume` id. Use these for settings key values and the wire.
- **Per-control absence is not adapter absence.** A missing control daemon is
  an absent `MenuBarControlState` slot inside an `Available` snapshot; the
  whole adapter is `Unavailable` only when the menu-bar bridge is missing.
- **Not modelled:** richer clock options and the Apple-only controls (recorded
  under `docs/PROGRESS.md` `## Follow-ups`).
- Live visual check: `bash scripts/capture-t15-menubar-adapter.sh` produced
  `docs/captures/t15-9a-menubar-adapter.png` (3840x2160). The adapter has no
  surface of its own, so the capture confirms only that the nested desktop
  renders; vision found the menu bar, Dock, wallpaper, and open windows
  composited with no blank regions, clipping, z-order issues, or stray
  artifacts. Verdict: pass.
