## Hand-off

Landed:

- `scripts/zoo/sdl_zoo.c` now presents a frame every loop. Root cause of the
  T-14.6a SDL Wayland "did not map" gap was the sample, not the compositor:
  SDL's Wayland backend only attaches its first `wl_buffer` when the app draws,
  and the compositor only maps a toplevel that has a buffer.
- `scripts/zoo/zoo-run.sh` runs SDL on the nested Wayland socket
  (`SDL_VIDEODRIVER=wayland`, `SDL_APP_ID=game.zoo.sdl`) instead of Xwayland;
  `scripts/zoo/zoo-driver.py` expects the Wayland row (SSD). The regenerated
  `docs/captures/t14-zoo-matrix.{md,json}` / `t14-zoo.png` record the Wayland
  SDL row; `make zoo-run` is exit 0 with all six rows passing.
- Compositor hardening: `DfState::send_pending_frame_callbacks` answers a
  buffer-less toplevel's `wl_surface.frame` from the commit handler. The zoo's
  Wayland trace showed SDL requests a callback before its first buffer; the
  mapped-window frame paths (`post_repaint`, `send_frame_callbacks`) only walk
  `Space`, so such a request previously went unanswered.
- Regression test `sdl_style_pre_map_frame_callback_is_answered_and_then_maps`
  in `compositor/tests/window_conformance.rs` reproduces SDL's exact sequence
  (pre-role buffer-less commit → configure → pre-map frame request → first
  buffer); it fails without the compositor fix (verified by disabling it).
- Docs updated: `docs/design/02-compositor.md` (new T-14.6b note),
  `docs/design/tracks/14-global-menu-app-index-compat.md` (new T-14.6b note),
  `docs/captures/README.md`.
