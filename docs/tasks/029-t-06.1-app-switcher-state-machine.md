## Goal

Implement the compositor-side switcher state: open on Cmd+Tab, cycle, reverse, commit, cancel.

## Scope

- Open on Cmd+Tab; Tab/Shift+Tab cycle; arrows reverse; commit on modifier release; Escape cancels.
- Drive from the compositor's shortcut engine (it owns the chord), not a client.
- Recency order from `WindowModel`; `app_switcher` protocol conformance.

## Explicitly deferred

- Per-app badge counts (post-gate).

## Acceptance (agent-completable)

- [x] State machine unit tests pass; modifier release commits exactly once; Escape cancels with no focus change.

## Test plan

## Hand-off

**State: done.** The compositor-side switcher state machine is real and
tested; the shell overlay is still T-06.2.

What landed:

- `compositor/src/app_switcher.rs` (new) — `AppSwitcher` (pure machine:
  `open`/`step`/`commit`/`cancel`, `selected_app`/`selected_window`/
  `direction`), `SwitchStep` (`Forward`/`Backward`, `direction()`), and
  `SwitcherApp { app_id, window }`. Open's first selection steps one app away
  from the focused app (wraps; a single app selects itself); an empty list
  stays closed. 7 unit tests.
- `compositor/src/input.rs` — the keyboard filter resolves Cmd+Tab /
  Cmd+Shift+Tab through the shortcut engine and calls
  `DfState::app_switcher_key`; while open it consumes Tab, the arrows, and
  Escape (and their releases); any Command release calls
  `DfState::app_switcher_modifier(mods.logo)` which commits exactly once.
- `compositor/src/input/shortcuts.rs` — added the Cmd+Shift+Tab →
  `AppSwitcher` binding; the input path derives the direction from Shift.
- `compositor/src/state.rs` — `DfState::app_switcher: AppSwitcher`;
  `app_switcher_entries` (one entry per app in `WindowModel::recency` order,
  carrying the most recent window), `focused_app_id`, `app_switcher_key`,
  `app_switcher_modifier`, `app_switcher_commit` (activates through
  `activate_window_id`: cross-Space, restore-if-minimized, focus),
  `app_switcher_cancel`.
- `compositor/src/shell/mod.rs` — removed `AppSwitcherState` (the duplicate
  shell-side state); `broadcast_app_switcher` now projects the one machine;
  the `cycle_app_switcher` request drives the same machine with the shell
  trigger (cycling never focuses).
- `compositor/src/input/synthetic.rs` — new `query switcher`
  (`switcher active=.. app=.. direction=.. selected=.. count=.. focus=..` plus
  one `switcher app <i> <app_id> <window>` line per recency entry) + parser
  test.
- `compositor/tests/window_conformance.rs` — new
  `app_switcher_opens_cycles_commits_once_and_escape_cancels` (32/32 green):
  Cmd+Tab opens, Tab/Shift+Tab/Up/Down cycle and wrap, the Command release
  commits to the selected window exactly once, a stray second release does
  nothing, and Escape cancels with no focus change.
- Docs: `02-compositor.md` "App-switcher state (T-06.1)"; `04-shell.md` app
  switcher paragraph; ADR `0021-app-switcher-state-machine.md`.

What the next task (T-06.2a, overlay) must know:

- The shell event `df_toplevel_manager.app_switcher` now fires on open/cycle/
  commit/cancel from `AppSwitcher` (`active`, `app_id`, `direction`). The
  shell's `onManagerAppSwitcher` is still a no-op; consume it there.
- Selection is app-level: `app_switcher_entries` gives one entry per app
  (most-recent window). The shell must not re-derive recency or group windows.
- Cycling does **not** focus; only commit activates (one
  `activate_window_id`). The overlay's live previews therefore must read the
  committed surfaces, not expect a focus change per cycle.
- Within-app Cmd+` window cycling is T-06.2b; it must extend
  `AppSwitcher`/the input path, not add a second binding path.
- The initial selection skips the focused app; in headless tests with two
  fresh windows there is no focused window yet, so the first selection is the
  most recent app.
