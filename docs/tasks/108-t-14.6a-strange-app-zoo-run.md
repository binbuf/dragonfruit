## Hand-off

**State: done.** The zoo run and matrix are committed. `scripts/zoo/zoo-run.sh`
(`make zoo-run`) launches a nested session and drives Firefox (X11), xterm, a
Steam-`WM_CLASS` stand-in, GNOME Calculator (GTK4 via flatpak), an SDL2 sample
via Xwayland, and an Electron client, recording launch / raw identity /
app-index resolution / SSD-CSD / menu-broker tier per app.

Artifacts:

- `docs/captures/t14-zoo-matrix.md` (matrix), `t14-zoo-matrix.json`
  (machine-readable), `t14-zoo.png` (nested desktop with the zoo mapped;
  inspected — wallpaper, windows, titlebars render cleanly, no stray
  artifacts).
- `scripts/zoo/` — `zoo-run.sh` (orchestrator), `zoo-driver.py` (poller +
  matrix), `sdl_zoo.c`, `x11_zoo.c`, `electron/main.js`, `steam.desktop`.

Real paths changed:

- `compositor/src/input/synthetic.rs` — new read-only `query identity` command
  (`identity <id> <app_id|-> <title>`), so a Wayland app's raw `app_id` is
  observable too (X11 `WM_CLASS` was read with `xprop`).
- `services/app-index/src/main.rs` — `--resolve-window <class> [instance]`
  (the instance is needed for Firefox X11: class `org.mozilla.firefox`,
  instance `Navigator`).
- `compositor/tests/xwayland_conformance.rs` — new test
  `identity_query_reports_x11_wm_class`.

Findings for T-14.6b (all six rows pass identity resolution):

- Firefox X11 presents `WM_CLASS = "Navigator", "org.mozilla.firefox"` and gets
  **CSD** (GTK draws its own frame); no compositor titlebar.
- xterm / Steam stand-in / SDL (all X11) get **SSD**.
- GTK4 Calculator (Wayland) gets **CSD**; Electron (Wayland) gets **SSD**
  (Chromium negotiates server-side decoration).
- Every zoo app falls back to the fixed menu (`tier: none`); none exports a
  native or DBusMenu menu, so the menu tiers are covered by the T-14.4
  `--mock-menu` tests, not here.
- **SDL2's Wayland backend connected but never mapped a window** on the nested
  compositor (it stops after the registry roundtrip); the run uses SDL's X11
  driver instead. This is the one compatibility gap surfaced for T-14.6b.
- **Steam is a stand-in** (raw X11 window with `WM_CLASS=Steam` and a faithful
  `steam.desktop`); Steam is not installable in this environment.

Commands that work (repo root):

- `make zoo-run` — exit 0, writes the matrix and still (needs a host Wayland
  session, spectacle, Pillow, gcc+SDL2/X11 headers, an Electron install and
  the Calculator flatpak; missing apps are recorded as "not run").
- `cargo test -p dragonfruit-compositor --lib` (11 xdnd) and `--test
  xwayland_conformance` (7); `cargo test -p dragonfruit-app-index` (14
  session-bus).
- `cargo fmt --all -- --check`; `cargo clippy --workspace --all-targets -- -D
  warnings`; `make e2e` — all green.
- Build note unchanged: `export
  PKG_CONFIG_PATH=$HOME/.local/df-devroot/lib64/pkgconfig:$PKG_CONFIG_PATH` and
  `RUSTFLAGS="-L $HOME/.local/df-devroot/lib64"` (or just `make`).
