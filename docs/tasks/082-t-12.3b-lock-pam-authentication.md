## Goal

Authenticate through PAM via a small helper; never a custom credential store.

## Scope

- Authentication via PAM through a small helper; never a custom credential store.

## Explicitly deferred

- Input capture and kill-resistance (T-12.3c).

## Acceptance (agent-completable)

- [ ] Correct credentials unlock; wrong ones do not; no credential storage.

## Test plan

- Headless: helper success/failure paths against a PAM test service.

## Hand-off

Landed: `services/lock-auth` (crate `dragonfruit-lock-auth`) with the
`PamAuthenticator` library seam and the `dragonfruit-pam-helper` binary;
`shell/src/lockauth.{h,cpp}` (`LockAuthenticator`, the helper process
boundary); `ShellController::submitLockPassword` + success/failure handlers
that unlock only on PAM success; the dev tool exports `DF_PAM_HELPER`. ADR
[0068](../../design/adr/0068-lock-pam-helper.md) freezes the contract.

Commands: `cargo test -p dragonfruit-lock-auth` (11/11), `make qml-test`
(41/41, adds `tst_lockauth`), `make e2e`, `make clippy` — all pass. Live check
captured at `/tmp/opencode/t82-lock.png`; the lock screen renders with the
auth-enabled password field and no menu bar/Dock.

T-12.3c: route the typed password into `ShellController::submitLockPassword`
and call the `LockAuthenticator`; do not add PAM or a credential store. The
PAM service is `dragonfruit` (fallback `login`); packaging must install the
helper on `PATH` and may add `/etc/pam.d/dragonfruit`.
