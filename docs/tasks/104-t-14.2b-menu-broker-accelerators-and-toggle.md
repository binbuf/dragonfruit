## Hand-off

Landed: focus-scoped accelerators and the global-menu toggle (ADR
[0096](../design/adr/0096-focus-scoped-accelerators-and-global-menu-toggle.md)).

- The menu-broker owns `services/menu-broker/src/accelerators.rs`: it parses
  published `shortcut`/`action` rows into a per-app table, resolves only the
  focused app, and lets a reserved system chord win. `Resolve` carries the
  table; `Dispatch`, `Accelerators`, `FocusedAccelerators`, and
  `SetSystemAccelerators` are additive D-Bus methods.
- The compositor admits the table over `df_toplevel_manager.set_app_accelerators`
  (protocol **v7**, one `action<TAB>chord` per line) into its existing engine
  and delivers a match as the existing `app_accelerator` event; the shell routes
  it through the same `dispatchAppAction` seam a menu click uses.
- `menu.global` (settingsd schema **v6**, default on) is the toggle; the shell's
  `applyMenuBarPolicy` sets `MenuBar.globalMenuEnabled`, which suppresses the
  focused app's exported menus while keeping the fixed system and application
  menus. The Settings control ships in `DesktopDockPane.qml`'s new "Menu Bar"
  group (the dedicated pane is T-15.9b).

Deviations / still open (also in `docs/PROGRESS.md` Follow-ups):

- The shell computes its accelerator table from the menu it renders
  (`fixedApplicationMenu` + `demoAppMenu`) rather than reading the broker's
  `Resolve`; Settings still does not `Publish` its model. The T-14.2a
  shell↔broker transport is the same remaining wiring.
- A non-shell action (e.g. `edit.undo`) reaches `dispatchAppAction` but only
  logs: the compositor→shell dispatch is real and tested, the shell→app action
  channel is not built yet.
- Hide/Hide Others/Show All still reflect live state but do not minimize
  windows (unchanged from T-14.2a).
