## Reference UI/UX (macOS screenshots)

Near-verbatim target: the real macOS screenshots in `docs/reference/macos/`
(never shipped; see [14-risks.md](../design/14-risks.md)), distilled in
[System_Preferences.md](../reference/System_Preferences.md).

**Sections and rows (observed order):** Bluetooth toggle card — icon,
`Bluetooth` toggle, and the caption `This <device> is discoverable as
"<device>"` while the pane is open; `My Devices` — device rows with name,
connection state (`Not Connected`), and a circular info button; `Nearby
Devices` — `Searching...` with a spinner. The pane maps to the BlueZ adapter
(T-15.1a) and ships with the Control Center tile as one unit; the
quick-settings sheet shows the same toggle plus the connected-devices list,
with `Bluetooth Settings...` opening the pane.

**Adapt or omit (Apple-only):** the `Learn more...` web link, the `?` help
button, and the Apple Account sidebar row. The captured device names are
generic Bluetooth names (`WF-1000XM6`, `WH-1000XM6`) and can stay as
fixture-like examples.

## Hand-off

**State: done.** The Bluetooth pane and Control Center tile ship as one unit over
the `dragonfruit-system-status` bridge host (ADR 0118). The pane applies live
(power, discovery, connect) and the tile reflects state and writes the radio.
Absence follows the adapter's two hide rules (`bluetoothd` gone, or no
controller) and is tested in the pane, the tile, and the absent-pane matrix.

What landed:

- **Bridge host** — `services/system-status/src/bluetooth.rs` (new):
  `BluetoothHost<B>` + `bluetooth_view`/`bluetooth_report`; a fourth D-Bus
  interface `org.dragonfruit.SystemStatus1.Bluetooth` in `dbus.rs`
  (`State`/`Refresh`/`SetPowered`/`SetDiscovering`/`Pair`/`SetConnected`);
  `main.rs` `--print-bluetooth`; `tests/bluetooth.rs` (new).
- **Shell** — `systemstatusclient.{h,cpp}` (four writes + `bluetoothState` +
  fixture), `systemstatusmodel.{h,cpp}` (kind + `present:false` hide rule),
  `shellcontroller.{h,cpp}` (tile data + handlers), and the Control Center
  Bluetooth tile in `ControlCenter.qml` (toggle, known-device rows,
  `Bluetooth Settings…`).
- **Settings app** — `BluetoothClient.{h,cpp}` (new; D-Bus + `DF_BLUETOOTH_FIXTURE`
  mock), `SettingsBridge` `bluetooth`/`bluetoothAvailable` + four writes,
  `BluetoothPane.qml` (new: toggle card + discoverable caption, `My Devices`,
  `Nearby Devices` with a spinner; discovery runs while the pane is open),
  catalog/registry/CMake wiring.
- **Docs** — `07-system-integration.md` "The Bluetooth pane and tile (T-15.1b)",
  ADR `0118-bluetooth-pane-and-tile.md`, `docs/captures/README.md`.
- **Captures** — `scripts/capture-t15-bluetooth.sh` (new);
  `docs/captures/t15-1b-bluetooth-pane.png`,
  `docs/captures/t15-1b-bluetooth-control-center.png`.

Verified commands (repo root):

- `cargo test -p dragonfruit-system-status` — 17 lib + 4 bluetooth + 9 host,
  green.
- `ctest --output-on-failure -j4` (in `build/`) — 54/54 green.
- `make e2e` — EXIT 0.
- `make lint` — only the pre-existing `check-desktop-names` lines fail
  (StatusNotifier/zoo/apppicker), unchanged.

Deviations / next task must know:

- The `Bluetooth Settings…` link (pane and tile) is an entry point that logs
  until T-16 launches Settings on a named pane, matching the Wi-Fi/Focus/
  Appearance links.
- The menu-bar Bluetooth status slot stays hidden: the task owns the Control
  Center tile and a visible slot with no Bluetooth menu would be a dead control.
- The default Settings pane is pinned to `appearance` (the first catalog row is
  now Bluetooth; opening Settings must not auto-start a discovery inquiry).
- Live capture: `bash scripts/capture-t15-bluetooth.sh`; the vision tool
  returned HTTP 429, so the pixel statistics and headless tests are the
  evidence. `tst_controlcenter` asserts the panel content fits the 780 px
  surface.
