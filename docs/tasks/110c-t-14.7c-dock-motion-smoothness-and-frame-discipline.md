## Goal

Continuous Dock motion reads smooth: launch/attention bounces update phases
without rebuilding the entry model, popovers do not resize the offscreen window
mid-gesture, discrete layout changes animate with the design-system motion
tokens, and the whole set holds the frame budget with an idle Dock that does
nothing.

## Current behavior (investigated, T101 era)

- Every animation tick rebuilds the full `QVariantList` (`withBounce` /
  `buildDockEntries`) and reassigns the Repeater model: all delegates are
  recreated (~37× per 600 ms launch bounce), hover/press/lift state is lost,
  and the shell allocates a fresh model each tick.
- The bounce is a free-running 16 ms `QTimer`, not aligned with committed
  frames.
- Opening a context menu/chooser/stack can `resize()` the offscreen
  `QQuickWindow` on the open frame (render-target reallocation).
- `dock.size` changes (settings slider or divider release) and the drag-gap
  collapse snap unless dragging; the legacy design asks for the
  `dock-magnify` spring.

## Scope

- [ ] Keep `entries` stable during bounces: update only a per-entry phase
      (e.g. `dock.setBouncePhases({id: phase})`, or an invokable the delegate
      reads) instead of reassigning the model; assert delegates are not
      recreated (`Component.onCompleted` count / `itemAt` identity stable) and
      that hover/press state survives a bounce.
- [ ] Advance phases from committed frames (`afterRendering`) or a precise
      timer synchronized to the render path; stop the timer when no bounce or
      attention clock is active, so the idle Dock stays zero-wakeup.
- [ ] Pre-size the popover headroom so opening a menu/chooser/stack never
      resizes `m_dockWindow`; if the extra readback cost shows in the trace,
      split the popover into its own fixed-size offscreen window instead and
      document the choice.
- [ ] Re-audit Behaviors now that FR-14 commits every frame: animate
      `dock.size`/overflow-driven size changes and the drag-gap collapse with
      `dockMagnify`/`dockReveal` (reduced motion = 0 duration); keep a snap for
      the first configure only; update the stale comment and
      `test_entries_snap_to_layout_after_configure` if needed.
- [ ] Extend the frame trace: launch bounce + attention bounce + a divider-size
      change + popover open/close; assert no dropped frames on baseline and
      record raw numbers; confirm the idle trace is unchanged.
- [ ] New `tst_dock` cases: "a bounce does not rebuild the entry model",
      "popover open does not resize the scene" (expose the sizes through the
      existing test seams), "a size change animates then settles".
- [ ] Capture/record: `docs/captures/t14-dock-motion-trace.txt` plus a short

## Design notes

- The compositor is the animation clock authority; the Dock must not invent a
  free-running timer that drifts from committed frames.
- Reduced motion keeps every state legible with duration 0; never remove the
  state change itself.
- No idle wakeups: the timer must stop (the Dock currently stops only when both
  bounce maps are empty).
- Prefer updating existing delegates over resetting models; the Repeater model
  is the expensive thing.

## Hand-off

Landed (T-14.7c, done):

- **Bounce phases are a separate map.** `shell/src/shellcontroller.cpp` no
  longer folds `bounce`/`attention` into the entry list; `rebuildDockEntries()`
  builds the stable entries and `publishDockBouncePhases()` pushes an
  `entry id -> { phase, attention }` map as the QML `bouncePhases` property
  (only when it changes). `onDockAnimationTick` advances that map and stops the
  16 ms timer when both clocks are empty; `onDockLaunchTick` only rebuilds on a
  real launch-state change; `clearAttention`/`onDockAttention` publish the map
  instead of rebuilding. `withBounce` was deleted.
- `shell/dock/Dock.qml` reads phases through `entryPhase`/`entryAttention`
  (entry-embedded `bounce` still wins) and injects `bouncePhase`/
  `bounceAttention` into each delegate via new `DockEntry` properties, so the
  Repeater model is untouched by a bounce.
- **Pre-sized popover buffer.** `kDockPopoverHeadroom`/`kDockPopoverGutter`
  (320 each, C++ constants) size the Dock window once at configure and the
  Dock item sits at that constant offset. `Dock.qml` gains
  `popoverHeadroom`/`popoverGutter` and clamps every popover into the budget
  (`clampPopoverX`/`clampPopoverY`); a zero budget (QML default / standalone
  tests) keeps the legacy unbounded placement. No `QQuickWindow::resize` on a
  popover open.
- **Behaviors.** Root `Behavior on iconSize` (disabled while `resizing` and
  before `laidOutOnce`) animates `dock.size`/overflow changes with
  `motion.dockMagnify`; per-entry x/y Behaviors now also cover the drag-gap
  close (`dragSettling`). The stale on-demand-renderer comments are gone.
- Contract in [ADR 0100](adr/0100-dock-motion-phase-map-and-popover-buffer.md);
  docs/design/04-shell.md "Dock motion and frame discipline";
  docs/captures/README.md T-14.7c paragraph.

  incl. the new delegate-identity, phase-map, size-animation, and

- `make e2e` — exit 0; `make soak SOAK_CYCLES=5` — 5 clean cycles, zero

  `over_budget=+0`, idle `frames_rendered=+0 over_budget=+0`; the whole run

- Live visual check: the menu still shows the context menu cleanly above an
  intact plate; the resized still shows larger, settled icons with no clipping.
  Verdict: intended.

Chosen headroom strategy + judgment call: pre-size the existing Dock window
(per the task's preferred option) rather than split the popover into its own
window. The trace shows the extra readback did not trip the degrade controller
(0 downgrades), so the split stays a follow-up if a real-hardware trace ever
shows a tier downgrade.

What T-14.7d must know:

- Send per-frame entry state through `bouncePhases` (or a sibling map), never
  by rebuilding `entries`; `tst_dock::test_bounce_does_not_rebuild_the_entry_model`
  and `test_attention_phase_rides_the_phase_map` are the guard.
- Popovers must be placed through `clampPopoverX`/`clampPopoverY` with the
  shell-set `popoverHeadroom`/`popoverGutter`; do not compute headroom in the
  shell.
- `laidOutOnce` (first configure snaps) and `dragSettling` are the motion
  contract; a real reorder still resets the model through the shell, so the
  gap-close spring only covers the cancel/snap-back path today.
