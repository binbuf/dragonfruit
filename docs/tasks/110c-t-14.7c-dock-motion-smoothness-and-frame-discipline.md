## Goal

Continuous Dock motion reads smooth: launch/attention bounces update phases
without rebuilding the entry model, popovers do not resize the offscreen window
mid-gesture, discrete layout changes animate with the design-system motion
tokens, and the whole set holds the frame budget with an idle Dock that does
nothing.

## Current behavior (investigated, T101 era)

- Every animation tick rebuilds the full `QVariantList` (`withBounce` /
  `buildDockEntries`) and reassigns the Repeater model: all delegates are
  recreated (~37× per 600 ms launch bounce), hover/press/lift state is lost,
  and the shell allocates a fresh model each tick.
- The bounce is a free-running 16 ms `QTimer`, not aligned with committed
  frames.
- Opening a context menu/chooser/stack can `resize()` the offscreen
  `QQuickWindow` on the open frame (render-target reallocation).
- `dock.size` changes (settings slider or divider release) and the drag-gap
  collapse snap unless dragging; the legacy design asks for the
  `dock-magnify` spring.

## Scope

- [ ] Keep `entries` stable during bounces: update only a per-entry phase
      (e.g. `dock.setBouncePhases({id: phase})`, or an invokable the delegate
      reads) instead of reassigning the model; assert delegates are not
      recreated (`Component.onCompleted` count / `itemAt` identity stable) and
      that hover/press state survives a bounce.
- [ ] Advance phases from committed frames (`afterRendering`) or a precise
      timer synchronized to the render path; stop the timer when no bounce or
      attention clock is active, so the idle Dock stays zero-wakeup.
- [ ] Pre-size the popover headroom so opening a menu/chooser/stack never
      resizes `m_dockWindow`; if the extra readback cost shows in the trace,
      split the popover into its own fixed-size offscreen window instead and
      document the choice.
- [ ] Re-audit Behaviors now that FR-14 commits every frame: animate
      `dock.size`/overflow-driven size changes and the drag-gap collapse with
      `dockMagnify`/`dockReveal` (reduced motion = 0 duration); keep a snap for
      the first configure only; update the stale comment and
      `test_entries_snap_to_layout_after_configure` if needed.
- [ ] Extend the frame trace: launch bounce + attention bounce + a divider-size
      change + popover open/close; assert no dropped frames on baseline and
      record raw numbers; confirm the idle trace is unchanged.
- [ ] New `tst_dock` cases: "a bounce does not rebuild the entry model",
      "popover open does not resize the scene" (expose the sizes through the
      existing test seams), "a size change animates then settles".
- [ ] Capture/record: `docs/captures/t14-dock-motion-trace.txt` plus a short
      clip or stills; `PROGRESS.md` note.

## Design notes

- The compositor is the animation clock authority; the Dock must not invent a
  free-running timer that drifts from committed frames.
- Reduced motion keeps every state legible with duration 0; never remove the
  state change itself.
- No idle wakeups: the timer must stop (the Dock currently stops only when both
  bounce maps are empty).
- Prefer updating existing delegates over resetting models; the Repeater model
  is the expensive thing.
