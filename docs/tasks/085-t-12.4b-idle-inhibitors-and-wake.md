## Hand-off

**State: done.** Idle inhibitors and wake restore wrap the T-12.4a engine in
`dragonfruit-session`. Contract frozen in ADR
[0071](../design/adr/0071-idle-inhibitors-and-wake-restore.md).

What landed:

- **`services/session/src/idle.rs`** — `IdleController` wraps `IdleTimers`
  with an `IdleInhibitors` registry and returns `IdleEvent`
  (`Enter(stage)` / `Restore(stage)`). `InhibitorId` (opaque handle),
  `IdleInhibitors` (`new`, `acquire`, `release`, `is_inhibited`, `count`,
  `contains`, `clear`, `iter`), `IdleEvent::stage`. Controller API:
  `new`, `timers`, `policy`, `stage`, `last_activity`, `idle_for`,
  `inhibitors`, `is_inhibited`, `inhibitor_count`, `acquire_inhibitor`,
  `release_inhibitor`, `clear_inhibitors`, `activity`, `poll`, `next_deadline`,
  `set_policy`. `IdleTimers::replace_policy` was added (store without
  evaluating) so a policy change while inhibited cannot advance the chain.
- **Semantics** — while any inhibitor is held, `poll` is a no-op and
  `next_deadline` is `None`; acquiring an inhibitor wakes an idle chain
  (`Restore(prior)`); activity wakes and reports `Restore(prior)`; releasing
  an inhibitor does not move the chain or reset the clock, so an overdue chain
  catches up on the next poll; waking from `Lock` reports `Restore(Lock)` but
  never unlocks (the lock UI owns that).
- **`services/session/src/lib.rs`** — re-exports `IdleController`,
  `IdleEvent`, `IdleInhibitors`, `InhibitorId`.
- **Tests** — `idle::tests` 6 new unit (inhibitor freezes until released,
  activity wake names the restore stage, acquire wakes, multiple inhibitors
  reference-counted, stale handle no-op, policy change while inhibited does not
  advance); `services/session/tests/idle_inhibitors.rs` (new) 4 integration
  (inhibitor blocks every stage until release, wake restores, lock wake is not
  an unlock, multiple inhibitors).
- **Docs** — ADR 0071; `11-session-and-dev-workflow.md` idle section extended.

Commands that work (repo root):

- `cargo test -p dragonfruit-session` — 29 unit + 4 `idle_inhibitors` (+ the
  existing integration suites: 3 idle, 6 environment, 3 logout, 8 restart, 4
  session_entry, 6 units).
- `cargo clippy -p dragonfruit-session --all-targets -- -D warnings` and
  `cargo fmt -p dragonfruit-session -- --check` — exit 0.
- `make e2e`, `make lint` — exit 0.

Live check: `make demo DEMO_ARGS="--socket-name t85-idle"` (nested), captured
`/tmp/opencode/t85-idle.png`; vision confirms the nested desktop renders (menu
bar, Dock, Settings, demo window) with no artifacts, and the dev tool reported
a clean teardown. This task changes no UI, so the demo is a regression check.

Gotchas for later tasks:

- **No production consumer yet.** Nothing constructs `IdleController`; the
  compositor still has no dim/blank path and no idle service binds
  `ext-idle-notify`. T-12.5a is the first consumer: drive suspend from
  `Enter(Suspend)`, resume/restore from `Restore(Suspend)`. T-12.5b calls
  `set_policy` with `IdlePolicy::from_keys`.
- **Handles are registry-scoped.** An `InhibitorId` is only meaningful to the
  `IdleInhibitors` that minted it; across an idle-service restart create a new
  controller or call `clear_inhibitors` rather than reusing a handle.
- **Wake from `Lock` is a screen restore, not an unlock.** Do not treat
  `Restore(Lock)` as an unlock signal; the lock UI/PAM path owns unlocking.
- **The compositor's `idle-inhibit` state is protocol-level** and is not read
  by the session wrapper; the idle service is the adapter that maps surfaces to
  `InhibitorId` handles.
- T-12.5a adds suspend/resume; T-12.5b adds the settingsd keys.
