## Goal

When a window minimizes, its app entry (and, optionally, the immediate
neighbours) gives a short acknowledgment bounce, so the window's destination is
legible at the Dock. Opt-in (`dock.minimizeReaction`, default off) and disabled
under reduced motion.

## Context (read first)

- `shell/src/dockprojection.{h,cpp}` — the projection carries per-window
  `minimized` state and the grouped entry's window list; a minimize is a state
  change in the next projection.
- `shell/dock/Dock.qml` / `DockEntry.qml` — the bounce-phase injection map
  (`bouncePhases`, ADR 0100) shows how a transient per-entry animation is driven
  without rebuilding the Repeater; reuse that pattern.
- `design-system/tokens/tokens.json` — `motion.*` and `component.dock.*`; add
  the reaction amplitude/duration tokens and a reduced-motion variant (duration
  0 → no translation).
- `services/settingsd/src/schema.rs`, `docs/settings-keys.md`,
  `apps/settings/DesktopDockPane.qml` — add the `dock.minimizeReaction` key
  (off/on; keep the effects set small) following T-14.7k's key plumbing.
- ADR [0100](../design/adr/0100-dock-motion-phase-map-and-popover-buffer.md) —
  the phase-map rule later units must follow.
- Reference behavior only (GPL, never copied): `MinimizeItemReaction.qml` in
  `~/repos/punchi-dock-remastered` offers `slowBounce` (the minimized item) and
  `lateralRipple` (items within two positions), axis-aware, skipped when
  `Kirigami.Units.longDuration === 0`.

## Current behavior (investigated, T110 era)

- Minimizing a window has no Dock acknowledgement; only the compositor's own
  minimize ghost (whose target is improved by T-14.7l) reflects it.

## Scope

- [ ] Detect a minimize: the projection comparison in the shell (a window
      entering `minimized`, or an entry's minimized count increasing) produces a
      one-shot per-entry pulse id/phase; the Dock maps it onto the entry without
      rebuilding `entries`.
- [ ] Reaction: a bounded vertical bounce on a horizontal Dock (horizontal on a
      vertical Dock) with the axis and direction following the Dock position;
      amplitude/duration/easing from tokens; no neighbor ripple in this unit.
- [ ] Setting `dock.minimizeReaction` (bool, default `false`): settingsd schema,
      persistence, `Changed`, `docs/settings-keys.md`, and a Desktop & Dock pane
      toggle. Absent settingsd degrades to off.
- [ ] Reduced motion: the reaction is removed (no translation); the running
      indicator/minimized state still update, so the change stays legible.
- [ ] Accessibility: the entry's accessible name keeps carrying the window
      count/state; the reaction is decorative.
- [ ] Tests: `tst_dockcore` for the minimize detection/pulse; `tst_dock.qml`
      for the bounded animation, axis/direction, off-by-default, and reduced
      motion; settingsd/pane round-trip.
- [ ] Capture `docs/captures/t14-dock-minimize-reaction.png` (mid-bounce) and
      the `PROGRESS.md` note.

## Explicitly deferred

- Neighbour lateral ripple (the reference's second mode): add only if the single
  bounce proves too subtle, and as its own token-gated unit.
- Sounds and desktop notifications.
- The compositor-side minimize target geometry → T-14.7l.

## Design notes

- Default **off**: macOS has no such reaction; this is an opt-in delight, not
  part of the click contract.
- Follow the ADR 0100 phase-map rule: drive the phase from the shell each
  committed frame; never rebuild the entry model to animate.
- Bounded: one short hop, amplitude a fraction of the icon size; never repeat
  and never outlive the minimize.
- Exactly one pulse per minimize event; coalesce rapid minimizes into the last.
