## Goal

Honor the decoration tier: SSD clients get our titlebar, CSD clients keep theirs, X11 Tier-2 gets ours, with no double decoration.

## Scope

- SSD client → our titlebar; CSD client → no titlebar; X11 Tier-2 → our titlebar.
- Verify X11 configure uses the titlebar insets through `configure_window_size`.
- Guard against double decoration in both directions.

## Explicitly deferred

- Fractional-scaled X11 (T-16).

## Acceptance (agent-completable)

- [ ] Qt (SSD), X11 (Tier-2), and CSD apps render correctly side by side.
- [ ] `xwayland_conformance` stays green.

## Test plan

- Headless X11 path via `x11rb`; nested three-client capture.

## Hand-off

**State: done.** The decoration tier is honored for all three client classes
and the X11 configure uses the titlebar inset through the single
`configure_window_size` path.

What landed:

- **`compositor/src/state.rs`** — `DfState::set_decoration_tier(window, tier)`
  is now the one entry point for a mapped tier change: it updates the model
  and, when the reserved inset changes, reflows a zoomed window through
  `reapply_insets` (re-using the `usable_geometry_for` + `insets_for` math and
  `configure_window_size`). `apply_decoration_mode` routes through it.
- **`compositor/src/xwayland.rs`** — an X11 `_MOTIF_WM_HINTS` update now calls
  `set_decoration_tier`, so an X11 window that toggles its own decoration
  while zoomed reflows correctly. Tier mapping unchanged: motif decorations=0
  → Tier 3, everything else → Tier 2.
- **Tests** —
  `window_conformance::decoration_tier_matrix_default_explicit_ssd_and_csd_side_by_side`
  (default SSD + explicit `ServerSide` + explicit `ClientSide` in one session;
  exactly two titlebars, the CSD client keeps its full size);
  `window_conformance::runtime_decoration_tier_change_reflows_a_zoomed_window`
  (flip CSD/SSD while zoomed, content toggles between the full output and the
  inset size);
  `xwayland_conformance::x11_decoration_tier_follows_motif_hints_and_configures_insets`
  (undecorated X11 gets no titlebar; a runtime flip zooms/reflows; the real X
  server window size is the inset-adjusted size).
- **Docs** — `docs/design/05-window-decorations.md` gains the T-01.5 tier/X11
  section. No ADR: this applies the policy already recorded there. Commands:
  `make e2e`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo fmt --all -- --check` all clean.

Deviations / notes for the next task:

- The tier matrix and X11 correctness are proven headlessly; the "three apps
  side by side" *capture* remains T-01.6b's nested walkthrough (this unit has
  no capture artifact).
- `_NET_FRAME_EXTENTS` is not published to X11 clients yet (they cannot see
  the 40 px titlebar strip); recorded as deferred to T-16 compatibility
  polish, not a regression here.
- Floating windows reserve no inset, so a tier flip on a floating window only
  adds/removes the titlebar above the content; no resize is sent. Only zoomed
  windows reflow.
- T-01.6 (demo harness) bundles the visual demo.
