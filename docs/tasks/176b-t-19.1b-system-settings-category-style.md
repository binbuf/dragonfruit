## Goal

Add `SettingsCategoryIcon`, the gradient-backed category tile the Track-19
advice describes — rounded container, category gradient, inner highlight, drop
shadow, near-white Phosphor glyph — and adopt it for the **System Settings**
category/pane icons. This is the *only* surface that gets this container style;
everywhere else a migrated icon is a plain glyph sized for its place.

## Context (read first)

- `design-system/components/PhosphorIcon.qml` (from T-19.1a) — the glyph
  primitive this component wraps.
- `design-system/components/Shadow.qml`, `Theme.qml` — token elevation, radius,
  and color groups the container must consume.
- `apps/settings/PaneHeader.qml` — the current pane hero icon
  (`Icon { name: pane.icon }`), the first adopter.
- `apps/settings/SettingsShell.qml` — the sidebar rows built from `pane.icon`;
  the second adopter.
- `design-system/gallery/GalleryContent.qml` + `snapshots/` — where the section
  and golden live.

## Scope

- [ ] Add `design-system/components/SettingsCategoryIcon.qml`: properties
      `source` (Phosphor glyph name), `gradientStart`, `gradientEnd`,
      `symbolColor` (near-white default), `size`, `radius`, optional `glow`.
      Internally: design-system `Shadow` (token elevation) + rounded rect with a
      `LinearGradient` + a top inner highlight, and a centered `PhosphorIcon`
      tinted to `symbolColor`.
- [ ] Define the category→(glyph, gradient) mapping in exactly one place and
      drive it from the pane's existing `icon`/identity, keeping `Icon.qml` as
      the fallback for panes without a Phosphor mapping.
- [ ] Adopt it in `PaneHeader.qml` (hero) and the `SettingsShell.qml` sidebar

- [ ] Register the component in `design-system/CMakeLists.txt`
      (`qt_add_qml_module` + `df_qml_lint`); add a gallery section + snapshot.

## Out of scope

- The **app icon** for System Settings (Dock/drawer/menus) → T-19.1d.
- Menu-bar glyphs → T-19.1c; Dock/Files artwork → T-19.1d.
- Any gradient container outside System Settings.

## Design notes

- The container is the differentiator, not the glyph: the same rounded geometry
  and elevation for every category, only the gradient changes. Never bake the
  gradient into an SVG.
- Prefer tokens for radius/elevation/spacing; the categorical gradients may be
  literal but must be named constants in one table.
- Verify the container's shadow/highlight render under the headless software
  scene graph used by the QML tests (see `Shadow.qml`'s documented tier limits),
  or assert what can be asserted and cover the rest in the live visual check.

## Hand-off

**State: done.**

Landed the System Settings category tile and adopted it for the pane hero and
the sidebar rows. Changes:

- `design-system/components/SettingsCategoryIcon.qml` (new): an `Item` with
  `source` (Phosphor name), `gradientStart`, `gradientEnd`, `symbolColor`
  (default `primitive.color.neutral50`), `size`, `radius` (default
  `round(size * settingsCategory.radiusRatio)`), and optional `glow`. It draws
  the design-system `Shadow` (`level: "low"`), a rounded `Rectangle` with a
  vertical `Gradient`, a top inner highlight (white wash, token ratio/opacity),
  and a centered `PhosphorIcon` in the `fill` weight. The optional glow is a
  second wide `Shadow` tinted to `gradientStart`. Registered in
  `design-system/CMakeLists.txt` (`qt_add_qml_module` + `df_qml_lint`).
- **The category mapping is in exactly one place, app-side**:
  `apps/settings/SettingsPanes.qml` gains `categoryStyles` (keyed by each
  pane's existing `icon` identity) and `categoryStyle(pane)`. Values are
  `{ source, gradientStart, gradientEnd }`; 21 of the 22 shipped panes are

**Shadow/tint approach:** the container uses the design-system layered `Shadow`
(software-renderable, unlike `MultiEffect`) and a `Rectangle.gradient` + a
white top highlight; the glyph is a `ShapePath` tint, all of which render under
the headless software scene graph. The component uses `Shadow level: "low"`
(blur 8) rather than the default `high` (blur 40), which is too large for a
20–48px tile.

**Deviation:** the mapping table lives in `SettingsPanes.qml`, not in the
design-system component, so the design system stays category-agnostic; the
static `check-phosphor-icons.py` scan therefore only sees the gallery's literal
`source` names, and the app-side table is validated by the Settings test (the
sanctioned path for dynamic names).

**Live visual check:** `scripts/capture-t19-settings-category.sh` (new) starts a
scratch settingsd, launches the nested demo with `DF_SETTINGS_START_PANE=general`,
zooms Settings, and captures the active window. Captures:
`docs/captures/t19-settings-category-light.png` and
`docs/captures/t19-settings-category-dark.png` (1920x1200). Verified by pixel
analysis (vision was HTTP 429 on this host): the sidebar shows the mapped
gradient tiles (18/22 distinct gradients located, near-white glyph pixels in the
dark capture) and the General hero shows a rounded ~48px gray tile with a
near-white gear glyph (rounded corners + gear shape visible in a pixel map).
Tiles are contiguous, corner-rounded, and legible in both appearances.
