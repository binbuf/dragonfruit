## Goal

The desktop-settings provider with named, schema-documented keys and get/set/change signals.

## Scope

- Provider for Dock, workspaces, gestures, appearance dark/light/accent, animation policy, input repeat.
- `org.dragonfruit.Settings1`: named schema-documented keys; get/set; change signals (no polling); additive-only within a release.

## Explicitly deferred

- Persistence, atomic writes, migrations (T-08.1b).

## Acceptance (agent-completable)

- [x] D-Bus get/set and change signals work; the key set is documented in code.

## Test plan

- Headless: integration test drives the interface over the session bus.

## Hand-off

**Landed.** `services/settingsd` is now a lib+bin crate
(`dragonfruit-settingsd`), not a stub:

- `schema::KEYS` — the named, schema-documented key table (11 Dock, 1
  workspaces, 3 gestures, 2 appearance, 1 animation, 2 input keys) with each
  key's D-Bus type, default, range/enum, and owner/consumer pair;
  `SCHEMA_VERSION = 1`; a frozen v1 key manifest test enforces
  additive-only.
- `model::Settings` — in-memory store, schema validation on every write,
  change detection (repeat writes are silent no-ops).
- `value::{Value, SettingsError}` — the five value shapes
  (`b`/`d`/`x`/`s`/`as`) and typed errors.
- `dbus` — `org.dragonfruit.Settings1` at `/org/dragonfruit/Settings1`:
  `Get`, `Set`, `GetAll`, `ListKeys`, `SchemaVersion` property,
  `Changed(key, value)` signal (emitted only on a real change). Errors are
  `org.dragonfruit.Settings1.Error.{UnknownKey,TypeMismatch,OutOfRange,
  NotAllowed}`. `dbus::run()` serves it on the session bus; the binary
  supports `--print-keys` / `--print-schema`.
- Tests: 16 lib tests + 3 integration tests in
  `tests/session_bus.rs` (private `dbus-daemon`, second connection drives the
  real interface). `make e2e` now runs `cargo test -p dragonfruit-settingsd`.
- ADR [0030](../design/adr/0030-settingsd-schema-and-dbus-surface.md); track
  doc 08 gained the key table and surface section.

**Deviations / decisions.** Values travel as typed D-Bus variants, not JSON
strings (ADR 0030). `appearance.accent` accepts any text (empty = token
default); it is not range/hex-validated because the design-system accent is
still token-driven. `dock.pinned` defaults to an empty list; the shell still
seeds installed-app defaults.

**Not done (by scope).** Persistence, atomic writes, migrations, and
`$XDG_CONFIG_HOME` are T-08.1b. No consumer has migrated yet: the shell still
owns `DockSettings`/`DockPins` and its `QFileSystemWatcher`; the compositor
still uses its own defaults. T-08.1b must not add a second writer; T-08.2a
deletes the shell classes in the same change it wires the daemon.

**Live visual check.** The task has no UI surface. `make demo` was run
(headless scripted half) and the desktop renders; see PROGRESS.md T42 for the
command and the capture/verdict.
