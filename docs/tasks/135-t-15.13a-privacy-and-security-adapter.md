## Hand-off

**Landed.** New workspace crate `dragonfruit-privacy-adapter`
(`services/privacy-adapter`): `PrivacyAdapter<S>` over the T-07 contract
(`AdapterId::PRIVACY`), `MockPrivacy`, and the live `HostPrivacy` over the
**xdg-desktop-portal PermissionStore**
(`org.freedesktop.impl.portal.PermissionStore`, session bus,
`/org/freedesktop/impl/portal/PermissionStore`). State + events + absence are
unit-tested; the acceptance test is `tests/read_path.rs` (11 tests) plus 38 lib
tests. ADR 0142; design 07/08 updated; `make e2e` green; capture
`docs/captures/t15-13a-privacy-adapter.png` (2115x1437, adapter has no surface
of its own, desktop renders clean). Details in
`docs/PROGRESS.md` under `## T135`.

**Deviation from the plan.** The task's parent routes the surface to
"settingsd + host services (Secret Service, polkit) and portals". This adapter
implements the **portals** half only — the portal PermissionStore, the honest
Linux owner of per-application privacy permissions. Secret Service and polkit
are not projected here; a later task may add a read-only Secret Service
projection if a pane row needs it.

**What T-15.13b must know.**

- Project `PrivacySnapshot` through the bridge host (`PrivacyHost` in
  `services/system-status`, interface `org.dragonfruit.SystemStatus1.Privacy`),
  not by linking the Rust crate; add `DF_PRIVACY_FIXTURE` on the Settings
  client and a shell fixture like the other T-15 adapters.
- Categories are the 14 `KNOWN_TABLES` portal tables (all rows always present,
  empty = `None`); do not invent macOS rows with no Linux owner.
- `PermissionState` is the tristate (`allowed`/`denied`/`ask`/`unset`) with raw
  `permissions` preserved; a write is `set_permission`/`delete_permission`.
- Absence: no bus or no store owner → hidden (`Unavailable`); empty store →
  available, hide the tile on `present() == false`; unreadable store → `Error`.
- No `org.gnome.*`/`org.kde.*` in code (the desktop-name gate greps `-w`).

The Settings pane and Control Center tile are T-15.13b.
