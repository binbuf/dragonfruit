## Hand-off

**Done.** `dragonfruit-storage` (`services/storage`, workspace member) is the
UDisks2 adapter behind the shared contract: state + events + absent-daemon
behavior, unit-tested. No shell wiring — T-15.2b renders it.

- Read: one `ObjectManager.GetManagedObjects` at `/org/freedesktop/UDisks2` on
  the system bus (`src/udisks.rs`), flattened into `StorageData`; `src/model.rs`
  joins blocks to drives and derives `StorageSnapshot`.
- Writes: `mount`/`unmount` (block's `Filesystem`) and `eject` (drive), one
  call each, addressed by object path; `StorageOutcome::{Accepted,Denied,Absent,Failed}`.
- Absence: UDisks2 absent ⇒ `Unavailable`; present with no mountable volume ⇒
  `Available` + `present() == false`.
- Contract: new `AdapterId::STORAGE`; `make e2e` runs the crate.

Deviation: the design reference names "UDisks2 + GIO/GVfs", but the adapter
consumes **UDisks2 only** — it already carries the block enumeration, the
user-interesting hints, and the mount operations, so GIO/GVfs would be a second
source of truth; it stays in the Files sidebar (`files-core`). See ADR 0119.

Tests (repo root): `cargo test -p dragonfruit-storage` — 30 lib + 10
integration green; `cargo test -p dragonfruit-system-adapters` — 4 green;
`make e2e` — EXIT 0 (first run hit the known flaky `dragonfruit-lock-auth`
test, isolated pass + green rerun); `cargo fmt --all -- --check` and
`cargo clippy -p dragonfruit-storage --all-targets -- -D warnings` clean.

Live visual check: the adapter has no surface, so `scripts/capture-t15-storage.sh`
launched the nested demo (`DF_STATUS_FIXTURE=1`) and captured the full desktop
at `docs/captures/t15-2a-storage-adapter.png` (3840x2160, 455 585 unique
colours, luminance sigma 95.5; menu-bar / dock / client-window crops all
non-uniform; log shows Xwayland ready + clean exit). The vision tool returned
HTTP 429 and hung on retry, so the pixel statistics plus the headless suites are
the evidence. Verdict: the desktop renders as intended; the adapter is proven
headlessly.

T-15.2b adds the pane and tile over `StorageAdapter`; T-15.16 adds the Storage
column of the absent-daemon matrix.
