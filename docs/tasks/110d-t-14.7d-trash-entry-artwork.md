## Goal

A designed, original Trash tile that matches the app tiles in quality: solid
readable silhouette, clean proportions, and empty/full/unavailable states that
read at a glance from 32 to 64 px, in light and dark.

## Context (read first)

- `shell/dock/DockGlyph.qml::trash` (`~143-196`) — the current glyph.
- `shell/dock/DockEntry.qml` — artwork box, hover highlight, status badge,
  indicator (`~85-326`); the glyph receives `size: root.iconSize`.
- `design-system/tokens/tokens.json` — `controls.dock.trashSize: 44` (~line 414)
  is currently unused; semantic colors live under `semantic.color`
  (`Theme.color.*`), primitives under `primitive.color.*`.
- `shell/src/trashbridge.{h,cpp}` — `trashFull`/`trashCount`/`trashAvailable`
  feed the entry; `Dock.qml` (`~312-316`) injects them.
- `shell/tests/tst_dock.qml` — glyph smoke test (`~1903-1915`); the Dock↔Files
  trash walkthrough in `t10-files-dock-trash.png`.
- Legacy design §16: the icon reflects empty vs non-empty; unavailable dims;
  never a crash or a blocking state.

## Current behavior (investigated, T101 era)

- The bin is outline-only: three `textSecondary` rectangles (handle, lid, body
  border) with a transparent body and two vertical ribs that read as a "+"
  sign; the rim/border changes to the accent color when full.
- Nothing suggests glass/metal or contents; it visually disagrees with the
  colorful app tiles, and it does not use `trashSize`.
- Full/empty differ only by stroke color; unavailable is a 0.4 opacity.

## Scope

- [ ] Redesign the glyph from our own geometry (no Apple artwork):
      - a body with a subtle vertical fill/gradient and a light rim/highlight;
      - a lid that reads at small sizes and overhangs the body slightly;
      - a clean handle; no "plus" ribs;
      - empty state: tidy, neutral;
      - full state: crumpled-paper / overflowing-content silhouette behind the
        rim plus a full-capacity accent cue (not a whole-tile tint);
      - unavailable: keep the dim + badge behavior.
- [ ] Draw in a `trashSize`-derived box (44 at the default icon size),
      baseline-aligned/centered inside the entry's `iconSize` box so app tiles
      and the Trash still share one baseline.
- [ ] Add the minimum semantic tokens needed for the fill/rim/paper colors in
      light and dark to `tokens.json` (referencing primitives), regenerate
      `Theme.qml`; no literals in QML.
- [ ] Keep the existing motion/interaction untouched (hover highlight, press
      scale, launch-failure/missing badge, indicator rules).
- [ ] Tests in `tst_dock.qml`: pixel presence at 32/48/64; empty vs full
      differ in a sampled region (and both are non-null); unavailable renders
      dimmer; both color schemes render; a full-vs-empty capture pair is
      legible.
- [ ] Capture `docs/captures/t14-dock-trash-{empty,full,unavailable}.png`
      (light and dark) and add the `PROGRESS.md` note.

## Design notes

- Original geometry and original materials: reproduce the *interaction model,
  never Apple's bitmap output* (`14-risks.md`).
- The glyph must survive `Image`-less rendering (pure QML rectangles/shapes) so
  it works headless and at any DPI.
- Full state must not rely on color alone: add a shape/silhouette change so it
  is legible in grayscale and for color-vision differences; the accessible
  name already says unavailable.
- Reuse the Dock's existing border/rim idiom (`controlFill`, `border`,
  `chrome`) rather than introducing a new visual language.
