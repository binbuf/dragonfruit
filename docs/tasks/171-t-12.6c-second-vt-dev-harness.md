## Goal

Test a real Dragonfruit session on the workstation **without logging the host
out**: it stays on its VT and Dragonfruit runs on a second VT as a dedicated
user.

## Scope

- `dragonfruit dev --real [--user dfdev]`: bootstrap/verify the dedicated user
  once, find a free VT via `loginctl`, and start the real DRM session there with
  its own `XDG_RUNTIME_DIR`/user services.
- Return is a VT switch; the host session is untouched. A one-key teardown
  (or `loginctl terminate-session`) ends the Dragonfruit session cleanly.
- Runbook in the testing-ladder / dev-workflow docs: prerequisites, the
  dedicated-user rationale, how to add a session entry for that user, and how
  to read the failure output.
- Captures of both TTYs at the switch, committed under `docs/captures/`.

## Explicitly deferred

- Multi-GPU, dock, and NVIDIA behavior (T-16 hardware rail).
- Fast user switching in the shipped product (T-12 track, out of scope).

## Acceptance (agent-completable)

- [ ] The harness refuses to run for a user with an active seat-holding
      graphical session and explains the dedicated-user requirement.
- [ ] A real session starts on a free VT and returning leaves the host session
      running and undisturbed.
- [ ] Teardown leaves no orphaned process, socket, or VT master.
- [ ] The runbook is reproducible from a clean checkout on the reference host.

## Test plan

- Headless: VT-selection and preflight logic against a mocked `loginctl`.
- Hardware (T-159…T-161 rail): one start → switch → return → teardown cycle.

### What landed

- **`tools/dragonfruit-dev/src/second_vt.rs`** (new; `mod second_vt;` in
  `main.rs`) — the pure second-VT policy. `LogindSession` +
  `is_seat_graphical`/`vt`, `parse_session_ids`, `parse_show_session`,
  `preflight` (`Preflight::{Ready,Refuse}` with the dedicated-user rationale and
  `sudo useradd -m dfdev` bootstrap), `select_free_vt` (smallest free VT in
  `2..=12`, never guessing VT1), `session_on_vt`, `passwd_ids`/`lookup_user`,
  `create_user_command`, and `SecondVtPlan` (`switch_command`/`start_command`/
  `return_command`/`marker`). `Logind` runs `loginctl` with an injectable
  command; `DF_LOGINCTL`/`DF_PASSWD`/`DF_SESSION_ENTRY` are the test/validation
  seams.
- **`tools/dragonfruit-dev/src/main.rs`** — `--real` without a round-trip flag
  is the T-12.6c mode. `run_second_vt` snapshots `loginctl`, runs the
  preflight, **refuses** a colliding user with the explanation, resolves the
  dedicated user, picks the free VT, prints the host's VT and the return key,
  and (`--plan`) prints the exact commands without starting anything. Without
  `--plan` it `chvt`s to the VT and starts the shipped session entry as a
  `PAMName=login` session through `systemd-run --uid`, waits for the
  compositor socket, blocks until the session ends, then tears down.
  `run_second_vt_teardown` (`--teardown`) runs before the preflight so it works
  while the session is still up, terminates every session of the user, and
  fails dirty on an orphaned `dragonfruit*` process.
- **`scripts/second-vt-validation.sh`** + **`make second-vt-validation`** —
  records the refusal (real `loginctl`, the host user), the preflight/VT
  selection against a **mocked** `loginctl` (host desktop on VT2 → `dfdev`
  gets VT3), and (with a free seat + dedicated user) one real cycle. Writes
  `docs/captures/t171-second-vt.txt` when the cycle runs, otherwise the explicit
  `t171-second-vt.open.txt`. Always exits 0.
- **Docs** — ADR `docs/design/adr/0175-second-vt-dev-harness.md` (new);
  `docs/design/11-session-and-dev-workflow.md` Mode A and "Second VT, with
  isolation"; `docs/testing-ladder.md` rung 2; `docs/runbook-drm-session.md` §1
  + the harness troubleshooting bullets; `docs/captures/README.md`.
- **Artifacts** — `docs/captures/t171-second-vt.open.txt` (refusal PASS +
  mocked VT3 selection PASS + no-seat/no-user OPEN),
  `docs/captures/t171-second-vt-nested-check.png` (required live visual check).

### The run on this host

- Preflight refusal: `dev --real --plan --user user` →
  `Second VT: REFUSE user=user (exit 64)` with the dedicated-user rationale.
- Mocked preflight/VT selection: host desktop on VT2 →
  `Second VT: START user=dfdev uid=1001 vt=3 seat=seat0 socket=dragonfruit-wayland`
  and a `systemd-run … PAMName=login` plan.
- The real cycle is OPEN: the seat is busy (the host desktop owns DRM master)
  and `dfdev` does not exist here.

### Deviations

- **The harness verifies, it does not create, the dedicated user.** Auto-running
  `useradd`/`passwd` silently from a dev command was rejected as too invasive;
  the harness prints the exact bootstrap command instead (documented). The
  scope's "bootstrap/verify once" is satisfied by the verify + explicit
  bootstrap seam.
- **The start mechanism is `systemd-run` + PAM login on the free VT**, which
  gives the dedicated user its own logind session, user manager, and
  `XDG_RUNTIME_DIR`; it is unvalidated on hardware (no free seat), and the
  runbook records the manual equivalent as the known-good fallback.
- **The global orphan check is `soak::dragonfruit_processes()`** (not filtered
  by user), the same check `make soak` uses; a host already running a
  Dragonfruit process would false-fail, which is the intended "session hygiene"
  behavior.
