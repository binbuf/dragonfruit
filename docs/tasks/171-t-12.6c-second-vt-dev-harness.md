## Goal

Test a real Dragonfruit session on the workstation **without logging the host
out**: it stays on its VT and Dragonfruit runs on a second VT as a dedicated
user.

## Scope

- `dragonfruit dev --real [--user dfdev]`: bootstrap/verify the dedicated user
  once, find a free VT via `loginctl`, and start the real DRM session there with
  its own `XDG_RUNTIME_DIR`/user services.
- Return is a VT switch; the host session is untouched. A one-key teardown
  (or `loginctl terminate-session`) ends the Dragonfruit session cleanly.
- Runbook in the testing-ladder / dev-workflow docs: prerequisites, the
  dedicated-user rationale, how to add a session entry for that user, and how
  to read the failure output.
- Captures of both TTYs at the switch, committed under `docs/captures/`.

## Explicitly deferred

- Multi-GPU, dock, and NVIDIA behavior (T-16 hardware rail).
- Fast user switching in the shipped product (T-12 track, out of scope).

## Acceptance (agent-completable)

- [ ] The harness refuses to run for a user with an active seat-holding
      graphical session and explains the dedicated-user requirement.
- [ ] A real session starts on a free VT and returning leaves the host session
      running and undisturbed.
- [ ] Teardown leaves no orphaned process, socket, or VT master.
- [ ] The runbook is reproducible from a clean checkout on the reference host.

## Test plan

- Headless: VT-selection and preflight logic against a mocked `loginctl`.
- Hardware (T-159…T-161 rail): one start → switch → return → teardown cycle.

## Hand-off

- The T-17 hardware gates can use this as the low-friction entry to a real
  session.

## Live visual check (required)

Before reporting done, run the app and **look at it**:

- Launch the nested session (`make demo`) and capture the desktop
  (`spectacle -b -n -f -o /tmp/<task>.png`); then perform the real second-VT
  cycle and capture both TTYs, recording the paths.
- Inspect the images: Dragonfruit renders fully on the second VT, and the host
  desktop is unchanged after returning.
- A green `make e2e` is necessary but **not sufficient**: the headless suites
  render no pixels, so they miss exactly this class of bug.
- Note the capture path and your verdict in the Hand-off.
