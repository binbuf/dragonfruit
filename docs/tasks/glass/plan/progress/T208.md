## Reusable facts / gotchas

- The DRM backend's `df_toplevel_manager.capture_screenshot` returns **"the
  DRM backend does not implement capture yet"**. Do not use the shell capture
  fixture or `grim` for native stills; use the KMS readback.
- The KMS readback PPM must be written top-to-bottom; the EGL texture is
  already top-down. The first T208 attempt wrote bottom-up and produced an
  upside-down desktop (Dock at top, menu bar at bottom). Fixed in
  `scripts/t208-kms-readback.c`.
- The compositor's primary plane is AB24 with AMD three-plane DCC modifier
  `0x0200000440517901`; `drmModeGetFB2` returns one `modifier` for all planes
  (not per-plane). Import all three handles with the same modifier.
- `pidfd_getfd` works for the same-user compositor; the card node is
  `/dev/dri/card1` fd 27/28/29/30 (pick the first).
- To drive fullscreen, stop `dragonfruit-shell.service`, wait for the
  compositor to write a fresh `dragonfruit-wayland.launch-token`, then run
  `scripts/t208-shell-fullscreen.c` with that token. The old token is
  `token-consumed`; the compositor logs "reissued launch token after shell
  disconnect". Restart the shell afterwards.
- Do not set `DF_LOCK_UNLOCK_MS` shorter than the lock configure time and do
  not restart the shell while locked: the old shell can restart before the
  timer fires and leave the session locked. Recovery is a shell restart with
  `DF_LOCK_FIXTURE=1000 DF_LOCK_UNLOCK_MS=8000`; the compositor logs
  `session unlocked`.
- The native release's shell fixtures for status menus/Dock chooser/hover are
  no-ops (pre-T202); do not claim them. Desktop/menu/Control Center/
  notification/Mission Control/lock fixtures work.
- `CHROME_GPU_SURFACES=all make t21-presentation-bench` overwrites
  `docs/captures/t21-presentation-bench-dock.png` and
  `-mission-control.png` even when `OUT`/`RAW_DIR` point elsewhere; restore
  those tracked files if you run a shortened reproduction.
- The full-rail shortened run's main scenario set completes; the 300 s timeout
  hits the refresh matrix. Use a longer timeout or `SKIP_TIERS`/a narrower
  scenario set if re-running.
