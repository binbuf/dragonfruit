# T204 — Notification Center mapping and action routing

## What landed

- **Trusted overlay.** `ShellProtocol` creates a top-right
  `notification-center` `overlay` layer surface with its own panel-sized input
  region, `ON_DEMAND` keyboard interaction and an exclusive grab while open
  (`setNotificationCenterKeyboardGrab`). The compositor's existing per-output
  overlay rule anchors it on the invoking output; no second hidden layer.
- **One entry route.** `MenuBar.clockActivated` -> `onClockActivated` and the
  compositor `notification-center` input action (Control-Shift-N and any
  configured hot corner) -> `onInputAction` both use
  `ShellController::toggleNotificationCenter()`; the view's close path calls
  `hideNotificationCenter()`.
- **History controller.** `shell/src/notificationcenter.{h,cpp}` normalizes the
  decoded service history into stable-keyed rows:
  - `key` = service id (selection follows this, not the row index);
  - `active` only when `reason`/`closedAt` are unset and `suppressed` is false;
  - `canAct`/`actions` only for active rows; history-only rows keep display
    text and `status` (`expired`, `dismissed`, `closed`, `suppressed`,
    `undefined`) but no stale actions;
  - Up/Down/Home/End traversal, Return = default action or dismiss, Delete/
    Backspace = dismiss selection, Escape = close.
- **QML view.** `shell/notifications/NotificationCenter.qml` renders the stable
  rows, active-only action/dismiss controls, accessible empty state
  ("No notifications") and unavailable state ("Notifications unavailable").
  The shell sets `history`, `selectedIndex` and `available`.
- **Service behavior stays put.** Banners, expiry, replacement, urgency,
  Focus/DND and badges remain in `services/notifications`. The Center only
  calls the existing `NotificationClient::invoke`/`dismiss` methods. Absence
  clears stale rows; `availableChanged` + `History()` repopulates after a
  restart.
- **Close/teardown.** Escape, outside focus loss, lock, output removal,
  compositor layer close and competing overlays (Control Center, apps drawer,
  Mission Control, app switcher, chooser, screenshot, ScreenCast, polkit) close
  the Center, clear the input region and release keyboard focus to the active
  window. `ShellProtocol` gained an internal `outputRemoved` signal and a
  dedicated notification-center layer-closed handler.
- **Tests/docs.** `tst_notificationcenter` (new), extended
  `tst_notificationmodel`, `tst_notifications`, `tst_menubar`, compositor
  hot-corner unit/conformance coverage, `docs/design/04-shell.md` T204 status,
  `docs/private-protocols.md` layer/namespace note, and ADR 0223.

## Reusable facts / gotchas

- Namespace is exactly `notification-center`; the compositor already maps it to
  `Preset::NotificationStack` in `render::default_preset`.
- The surface uses no explicit output. Do not create a hidden second layer for
  another display: the compositor filters per-output overlays through
  `chrome_focus_output`.
- `setNotificationCenterInputRegion(0, 0)` is the close contract; call it before
  `hideNotificationCenter()`. The keyboard grab is toggled separately.
- `NotificationCenter::setHistory()` ignores payloads while `available` is
  false, so a late reply from a dead service cannot resurrect stale rows.
- `NotificationCenter::normalizeHistory()` is the single active/history rule.
  Do not re-derive it in QML; the QML `actions` list is already filtered.
- `MockNotificationClient` now mirrors the service admission rule: `off`
  admits everything, `focus` admits critical (empty allow list), `dnd` admits
  nothing; suppressed notifications stay in history with `suppressed: true`.
- The QML root has a 360x620 standalone default; the shell overrides it via
  `prepareChromeScene`. Tests need a non-zero item size to click delegates.
- The Center currently uses the shared Popup role material; T205 owns the
  `notificationStack`/`notificationLowerPanel` regions and calibration.

## Follow-ups

- T205: declare the notification stack/lower-panel material regions and
  calibrate the banner/stack/lower-panel presets on this surface.
- Keyboard access currently traverses rows and dismisses/activates. If action
  buttons need independent Tab focus, add a focus ring/action traversal and
  extend `tst_notifications`.
- Exact multi-output anchoring for a keyboard shortcut follows the compositor's
  pointer output; if the focused-window output is required instead, extend the
  `input_action` event (or add a shell output pin) rather than duplicating
  surfaces.
- The service history is in-memory; a real service restart loses history
  (banners are transient by design). Persisting it belongs to the service, not
  the shell.
- No T204 live capture was added: T205 owns the visual material calibration and
  the existing `tst_*`/conformance rails provide the integration evidence.
