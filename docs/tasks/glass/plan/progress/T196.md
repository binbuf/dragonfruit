# T196 — live Appearance/Accessibility settings and the compositor bridge

## What landed

- **settingsd schema revision 18** (`services/settingsd/src/schema.rs`):
  - `appearance.transparency` — double, 0.0–1.0, default `0.5255`,
    owner `apps/settings`, consumer `shell/design-system Glass,
    compositor/material`.
  - `accessibility.reduceTransparency` — bool, default false.
  - `accessibility.increaseContrast` — bool, default false.
  - `settingsclient.cpp` mirrors the same defaults; the schema-doc test keeps
    `docs/settings-keys.md` in lockstep.
- **Settings UI**:
  - `AppearancePane.qml` adds an attached-menu transparency slider. `moved`
    updates the preview immediately and restarts a 60 ms timer; `committed`
    stops the timer and flushes the final 4-decimal value through
    `Settings.set`. The knob binding is suspended while dragging/pending so a
    coalesced write cannot yank it back.
  - The preview calls `Glass.resolve("menuAttached", …)` with the live scheme,
    rollout, slider and both overrides; it shows the resolved mode + percent.
    `previewRollout` lets tests/captures select the replacement look without
    changing the process-wide switch.
  - `AccessibilityPane.qml` adds Reduce Transparency and Increase Contrast
    toggles plus a resolver-backed preview. They remain available with the
    AT-SPI host absent and are independent of the appearance rollout.
  - `SettingsShell.qml` mirrors `appearance.transparency`,
    `accessibility.reduceTransparency` and `accessibility.increaseContrast`
    onto the app-local `Glass`, and reads `Settings.glassRollout`
    (`DRAGONFRUIT_GLASS_ROLLOUT`) so the preview matches the shell.
- **Shell bridge**:
  - `ThemeBinding` writes `Glass.slider` / `reduceTransparency` /
    `increaseContrast` from the same settings client; `Theme.dark`,
    `accentOverride`, `reducedMotion` and the host `auto` path are unchanged.
  - `compositorpolicy` gained the three values with a safe 0.5255 fallback for
    malformed/non-finite sliders and clamped out-of-range values.
  - `ShellProtocol::setAppearancePolicy` forwards one v9 snapshot;
    `ShellController::applyCompositorPolicy` sends it on startup, every
    settings `changed`/`refreshed`, and host `colorSchemeChanged` (Auto).
- **Protocol/compositor**:
  - `df_toplevel_manager` is version 9. Additive
    `set_appearance_policy(color_scheme, transparency_millionths,
    reduce_transparency, increase_contrast)` carries the resolved scheme,
    exact slider value (525500 = 0.5255), and both overrides.
  - `DfState::set_appearance_policy` validates before applying: unknown scheme
    keeps the current scheme, non-finite slider falls back to 0.5255, range is
    clamped. It advances `material_revision` and sets `needs_redraw` only when
    something really changed; no work-area reconfigure and no frame cadence.
  - `DfState::resolve_glass_preset` feeds the same `material_preset` resolver
    from the live scheme/slider/overrides/backend/tier/rollout. `query policy`
    reports `transparency`, both overrides and `material-revision`; `query
    material` adds `material preset=… look=… mode=… alpha=… …` lines for the
    attached menu and Dock.
- **Docs**: `docs/settings-keys.md`, `docs/design/10-design-system.md`,
  `docs/design/04-shell.md`, `docs/design/08-settings.md`, ADR 0034 updated;
  new ADR `docs/design/adr/0215-glass-live-settings-and-appearance-policy.md`.

## Effective contract

- Precedence is unchanged from T195: Reduce Transparency (opaque plate, solid,
  no sampling, slider ignored) → rollout look → light `menuAttached` slider →
  Increase Contrast (edge/foreground/edge width, also on the opaque plate) →
  backend/tier. Reduce Motion is orthogonal.
- `appearance.transparency` only changes the light attached-menu preset. The
  control text says so and names the Dock/menu bar/windows/panels as
  unaffected.
- Both accessibility overrides apply in the legacy and replacement looks.
  Reduce Transparency + Increase Contrast together are covered by QML and the
  compositor conformance test.
- Accent, Auto scheme, Reduce Motion and Control Center Dark Mode keep their
  existing paths (the Control Center still writes only
  `appearance.colorScheme`).

## Version behavior

- `SCHEMA_VERSION` is 18; a schema-17 file gains the three defaults during
  migration without losing its existing values. A rejected write leaves the
  store untouched.
- The private protocol is additive at manager version 9. Older compositors
  ignore `set_appearance_policy` and keep the v5 motion path. The shell still
  sends the v5 `set_motion_policy` for compatibility.
- Service absence: the client serves the schema defaults; both panes stay
  interactive and write in memory. The compositor keeps its safe local
  defaults when no shell snapshot arrives.

## Reusable facts

- Default slider = `Theme.glass.slider.defaultPosition` = 0.5255; the light
  anchors are 0.0 / 0.5255 / 1.0.
- Wire encoding is millionths (`525500`); do not switch to `fixed` without
  losing the exact default.
- `Glass.resolve("menuAttached", { scheme, rollout, slider,
  reduceTransparency, increaseContrast, tier, software, sampledBlur })` is the
  shared input shape. Pass explicit options in tests; the singleton defaults
  are process state.
- `query policy` prints `transparency=<4dp> reduce-transparency=<0|1>
  increase-contrast=<0|1> material-revision=<n>`; `query material` prints
  `material preset=… mode=… alpha=…` for `menuAttached` and `dock`.
- `material_revision` is the no-op detector: a repeated snapshot must not
  advance it.

## Follow-ups

- T197+ consume `resolve_glass_preset` / `Glass.resolve` at the render
  boundary; the current task only carries and resolves the policy, it does not
  retune any surface optics.
- T197 should include the material policy revision (or the resolved preset
  inputs) in its panel blur cache key if the sampled pass ever depends on
  tint/alpha; the current cache key covers scene/source/spec/scale, and the
  draw layer applies tint/alpha separately.
- T208 still flips the rollout default; keep `DRAGONFRUIT_GLASS_ROLLOUT` as the
  rollback/diagnostic switch. While legacy is selected the transparency slider
  is a durable preference with a mode/percent readout, not a visible optical
  change.
- `docs/design/10-design-system.md` and ADR 0215 are the policy references;
  do not add a second slider curve in settingsd or the shell.
