# T199 — Dock magnification, envelope, and tooltip

## What landed

- **Spatial raised cosine.** `shell/dock/Dock.qml` now evaluates
  `0.5 * (1 + cos(pi * |d| / R))` over the resting tile centres with the
  absolute `component.dock.magnifyInfluence = 125.1` pt. It is exactly zero at
  `R`, flat at both ends, and independent of the live icon pitch.
- **Peak anchors.** `component.dock.magnifyPeak = 1.217` (default
  `magnification` 0.5) and `magnifyPeakMax = 2.047` (diagnostic 1.0). A
  smoothstep segment through `(0, 1)`, `(0.5, 1.217)` and `(1, 2.047)` keeps
  the live mapping monotone and C1 at both anchors.
- **Temporal envelope.** `motion.dockHover` is 135 ms with Bezier control
  points `(1/3, 0)` / `(2/3, 1)`, exactly `3u² − 2u³`. The existing
  `Behavior` retargets from the current value; quick enter/leave reversals
  continue from the visible state.
- **Tooltip.** `component.tooltip.dwell` is 1400 ms, `paddingV` is the 8 pt
  spacing step (≈33 pt capsule, half-height radius), and the Dock anchors it
  8 pt above the **plate** while following the tile horizontally. The Dock no
  longer opts into the tail. `Tooltip.qml` gained an optional `anchorRect`
  override. `showTooltip`/`refreshTooltipAfterProjection` validate the entry
  id and the raw-pointer anchor, so a reorder/pin change dismisses a stale
  label instead of firing it.
- **Genie timing.** New `motion.windowGenie` = 450 ms with the same smoothstep
  control points. `window::motion::motion_token` selects it only for
  minimize/restore while `dock.minimizedAnimation=genie`; scale keeps
  100/160 ms and none keeps the collapse. `WindowMotion::new_with_motion`
  carries the explicit token.
- **Launch lift.** `component.dock.launchLift = 15` pt replaces the
  bar-relative quarter amplitude. The existing three-hop shape/total clock is
  unchanged; the unresolved multi-bounce is not re-invented.
- **Live settings.** `dockConfigFromValues` clamps `dock.size` and
  `dock.magnification` to 0..1 and normalizes `dock.position` to
  bottom/left/right.
- **Calibration evidence.** `scripts/t199-dock-motion.py`
  (`make dock-motion-calibration`) fits the controlled reference sweep and
  checks the tokens; `docs/captures/t199-dock-motion.md` records the fit.
- **Sweep capture fix.** `scripts/capture-dock-magnify-sweep-driver.py` now
  detects the nested window by non-black content instead of a fixed wallpaper
  colour, crops from the window bottom, closes the demo's client windows via
  `query decorations` + `close`, and the shell script requests
  `DRAGONFRUIT_NESTED_SIZE=1920x1200`.

## Capture notes / gotchas

- Run the sweep on a host with `kwin_wayland` available:
  `kwin_wayland --virtual --fullscreen 1 --scale 1 --socket <s> --width 3840
  --height 2446 --no-lockscreen --no-global-shortcuts --no-kactivities`, then
  `XDG_RUNTIME_DIR=/run/user/<uid> WAYLAND_DISPLAY=<s> make
  dock-magnify-sweep-capture`.
- The nested compositor reports a 1920×1200 physical output but the shell's
  overview is 1280×800; the driver's pointer positions are normalized, so the
  sweep still crosses the Dock. The crop is bottom-relative to avoid the host
  titlebar.
- The driver closes the demo's Settings/X11 windows before sweeping; otherwise
  the Settings pane sits behind the glass in every crop.
- The reference checkout is `../macos-liquid-glass`; the calibration script
  only needs the sibling `analysis/` JSON files and stdlib Python.

## Follow-ups

- Genie still renders as the existing per-window scale transform; the warp
  itself remains the documented material-pass follow-up (ADR 0005/0034).
- The reference launch multi-bounce is unresolved; only the 15 pt first lift
  is adopted.
- 1.5×/2× Dock optics MTF remains T198's open scale-path item; T199's motion
  capture is 1×.
- The optional Tooltip tail remains in the design-system component for other
  consumers even though the Dock no longer uses it.
