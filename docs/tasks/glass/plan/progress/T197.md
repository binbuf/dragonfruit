# T197 — compositor material geometry and composition

## What landed

- Protocol v3 additive `df_layer_surface` requests:
  - `set_panel_region(key, preset, x, y, w, h, tl, tr, br, bl, overscan)`.
  - `clear_panel_regions()`.
  - `set_panel_rect` is unchanged and still the legacy single-rect path.
  - Requests are appended after the existing request list (opcodes do not move)
    and are commit-latched by `commit_chrome_panel`.
- `compositor/src/shell/layer.rs`:
  - `PanelRegion`, `panel_region(...)`, `valid_region_key`.
  - `MAX_PANEL_REGIONS = 8`, key length 64, overscan ≤ 512, radius ≤ 4096.
  - `LayerSurfaceState.panel_regions: Option<Vec<PanelRegion>>`; `Some(empty)`
    is an explicit empty panel set.
- `compositor/src/shell/mod.rs`:
  - `ChromeRegion` output-local, clipped to the surface and owning output.
  - `ChromeSurface.regions` plus the legacy `panel` union.
  - Incremental update semantics: first region request after a commit starts
    from the committed list; use `clear_panel_regions` to remove.
- `compositor/src/window/corner.rs`:
  - `CornerRadii`, `rounded_rect_spans_with_radii`.
  - `rounded_rect_spans` now delegates to the per-corner implementation.
- `compositor/src/window/blur.rs`:
  - `RegionFilter::{Filtered, Sharp}`.
  - `GlassSpec::sample_padding_px()` (lens/refraction reach).
  - `BackdropBlurElement` takes `texture_region` + `CornerRadii`; a sharp
    element can sample the whole padded scene region directly.
- `compositor/src/render.rs`:
  - `BlurPanel` now carries corners, overscan, filter, `RegionPaint`.
  - `default_preset(namespace, layer)` maps known namespaces to T195 presets.
  - `chrome_blur_panels` resolves each region's preset live, selects
    filtered/sharp, and only counts filtered regions as blur passes.
  - Fallback feather elements are per-region/per-corner.
- `compositor/src/window/material_region.rs`:
  - Region padding is `BlurPanel::sample_padding_px()`:
    max(blur radius, Kawase footprint, refraction/lens reach) + declared
    overscan; sharp = 1 + overscan.
- `compositor/src/window/material_cache.rs`:
  - `PanelKey::for_region(namespace, layer, surface_id, region_key)`.
  - `RegionSample { spec, padding, filter }` in `PanelBlurKey`; damage in the
    declared overscan invalidates.
  - `PanelPaintKey` tracks scheme/preset/tier/mode/paint/corners/output
    generation/revision; paint-only changes advance the element commit but
    reuse the filtered texture.
- Backends (`nested.rs`, `drm.rs`):
  - Filtered path unchanged Kawase + glass.
  - Sharp path clones the scene texture, sets `texture_region` to the material
    region, clips per-corner, allocates no blur chain.
  - DRM records `material_frames` for sharp-only frames; `blur_draws` stays 0.
  - `chrome_blur_panels` now returns empty when `material_blur_supported` is
    false, preserving multi-GPU/rotated/failed-material fallback even for veil.
- Tests:
  - Unit: per-corner spans, sample footprint, region keys, padded damage,
    paint-only reuse, sharp/filtered cache separation.
  - Conformance: `multi_region_metadata_is_commit_latched_bounded_and_legacy_compatible`
    covers latching, two keys, invalid metadata, 8-region bound, empty removal,
    legacy `set_panel_rect` fallback.
  - `query scale` now prints `scale region <namespace> <key> preset=…
    logical=… physical=… corners=… overscan=…` per region.
- Docs: ADR 0216, `docs/private-protocols.md`, `docs/design/02-compositor.md`,
  `docs/rendering.md`.

## Reusable facts

- Protocol version is now `df_shell`/`df_layer_surface` v3; `LOCKSTEP_VERSION`
  stays 1.
- Known namespace → preset mapping is `render::default_preset`:
  `dock`, `menubar`, `menubar-popup`, `dock-popup`, `control-center`,
  `notification`, `notification-center`, `osd`, `apps-drawer`; unknown
  persistent → `windowChrome`, unknown overlay → `menuDetached`.
- Region keys must be stable across frames to preserve element id/texture. The
  legacy key is literally `panel`.
- Incremental update: send one `set_panel_region` per changed card without
  resending siblings; use `clear_panel_regions` before a fresh list.
- `PanelPaintKey` deliberately excludes geometry and source damage; those are
  in `PanelBlurKey`. Do not move tint/alpha into the blur key or a tint change
  will rebuild Kawase.
- `MAX_PANEL_REGIONS` is duplicated as `compositor_max_regions()` in the
  conformance test because that test binary does not link the compositor lib.
- `wayland-scanner` macros do not reliably track XML mtime in incremental
  builds. After editing `protocols/dragonfruit-shell.xml`, `touch
  compositor/src/shell_protocol/mod.rs` and
  `compositor/tests/shell_protocol_conformance.rs` before rerunning; a clean
  build is unaffected. The scanner's `since version not increasing` warnings
  are ordering warnings (pre-existing `ack_configure` case); the build passes.
- Commands used:
  - `cargo test -p dragonfruit-compositor --bin dragonfruit-compositor`
  - `cargo test -p dragonfruit-compositor --test shell_protocol_conformance`
  - `cargo clippy -p dragonfruit-compositor --all-targets -- -D warnings`
  - `cmake --build build --target dragonfruit-shell -j 2`
  - `make gates`
