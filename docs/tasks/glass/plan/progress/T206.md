# T206 — Settings and Files app-local chrome

## What landed

- **Presets** in `design-system/tokens/tokens.json` (17 total):
  `settingsSidebar`, `settingsToolbar`, `filesSidebar`, `filesToolbar`.
  - Settings Light 0.986/0.857 sidebar, 0.961/0.965 toolbar (measured).
  - Settings Dark 0.935/0.218, 0.900/0.247 (`adapted` from Finder).
  - Files Light 0.985/0.858, 0.994/0.922; Dark 0.935/0.218, 0.900/0.247
    (measured).
  - `role: chrome`, `render: solid`, `slider: none`, `blur: 0`.
- **QML**:
  - `Material.appChromeResolution/appChromeFill/appChromeBorder`.
  - `Glass.appChromeSupported` (client-alpha capability).
  - New `ChromeSheet.qml`: one ShapePath fill with per-corner radii.
  - `AppWindow.chromeTransparent` + opaque titlebar backing.
  - `Sidebar.fillColor/bottomLeftRadius`, `Toolbar.fillColor/borderColor`,
    `Files/PathBar.fillColor/bottomRightRadius`.
  - `SettingsShell`/`FilesShell` bind `Theme.dark`, `accentOverride`,
    `reducedMotion`, `Glass.rollout/slider/reduceTransparency/
    increaseContrast/appChromeSupported`; both expose `windowActive` bound
    from `Window.active`.
- **Files process settings**: `apps/files/FilesSettings.{h,cpp}` is a
  `Settings` QML singleton over the shared settings client (mock under
  `DF_SETTINGS_FIXTURE`), linked via `dragonfruit-settings-client`.
- **Compositor**: `window::shadow::shadow_elements_outside()` subtracts the
  window's rounded body from shadow spans; `render::push_window_shadow` uses
  it. The QML `Shadow` is hidden when `chromeTransparent`.
- **Evidence**: `scripts/t206-first-party-chrome.py`,
  `scripts/capture-t206-first-party-chrome.sh`, Makefile
  `first-party-chrome-check` (in gates) / `first-party-chrome-capture`.
  `t21-live-capture.sh` states `settings-window`/`files-window`, private-bus
  `--services full` app rail, `UNFOCUS`, and `query decorations` in QUERY_OUT.
- Docs: ADR 0225, `docs/design/{02-compositor,05-window-decorations,
  08-settings,09-files,10-design-system}.md`.

## Commands / facts

- `make first-party-chrome-check` — static preset/QML/fallback check.
- `make first-party-chrome-capture` — 22 nested cases; needs host Wayland or
  `kwin_wayland`. `SETTLE=4 ONLY=<label>` is the fast retake path.
- Capture manifest: `docs/captures/t206-first-party-chrome-capture.json`;
  scored report: `docs/captures/t206-first-party-chrome.json`/`.md`.
- The app rail needs settingsd on the private bus:
  `make demo DEMO_ARGS="--socket-name $SOCKET --private-bus --services full"`
  with `DF_DEMO_QT_APP=build/apps/{settings,files}/...`; seed
  `$XDG_RUNTIME_DIR/$SOCKET.session/config/dragonfruit/settings.json`
  (schema 18) before launch. Remove `$socket.session` after each case or the
  runtime tmpfs fills.
- `DF_APP_CHROME_SOLID` must be **unset** for normal rows; the bridge checks
  `qEnvironmentVariableIsSet`, so `DF_APP_CHROME_SOLID=0` still forces the
  opaque plate.
- `query decorations` gives the CSD window content rect; `query scale` gives
  its physical rect. The scorer uses the physical rect and samples the
  sidebar/toolbar at the 2–6 px padding, the detail sheet at the bottom-right,
  and the Files path bar at the bottom-right.
- The compositor shadow is drawn **behind** the window, so translucent chrome
  samples it unless the shadow is emitted as a ring. This was the cause of the
  initial Dark fit error (~0.02–0.05); `shadow_elements_outside` fixed it.
- The scalar token tint cannot carry the reference chroma pickup; the report
  marks this unresolved rather than fitting it away.

## Follow-ups

- Controlled System Settings Dark recapture; replace the adapted
  0.935/0.218 and 0.900/0.247 only if the reference gains independent fits.
- A chroma/tint transport for the muted sidebar (the measured pickup is
  currently not reproduced).
- If a future app adds a third chrome surface, extend the four presets/helper
  rather than re-deriving alpha in QML.
- A general client backdrop protocol would supersede this app-local path; it
  remains out of scope.
