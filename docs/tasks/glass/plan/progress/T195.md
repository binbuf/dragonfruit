# T195 — role presets and material resolution

## What landed

- `design-system/tokens/tokens.json` gained the top-level `glass` group:
  - 13 optical presets: `dock`, `menuBarVeil`, `menuAttached`,
    `menuDetached`, `statusMenu`, `tooltip`, `controlCenterOuter`,
    `controlCenterModule`, `controlCenterExpanded`, `notificationBanner`,
    `notificationStack`, `notificationLowerPanel`, `windowChrome`.
  - Per scheme, each preset records `role`, `render` (`sampled`/`veil`/`solid`),
    `slider` support, neutral alpha/tint, a separate perceptual fit and weight,
    blur, edge/edge-width/foreground contrast, sRGB colour space, provenance and
    confidence (`measured`, `measured-effective`, `observed-luma`, `adapted`,
    `baseline`).
  - The three measured light File anchors (0.0/0.5255/1.0 -> alpha
    0.732/0.552/0.415, tint 0.953/0.993/0.997), the Reduce Transparency opaque
    fills, the Increase Contrast boosts, and the rollout default.
- `scripts/gen-tokens.py` validates the group on every run/`--check` (finite
  values, ranges, required presets, provenance/confidence, anchor positions,
  midpoint equality, distinct dark attached/detached) and generates
  `Theme.glass` plus `design_tokens::glass`.
- `scripts/material_presets.py` is the Python reference resolver/CLI
  (`--check`, `resolve`). It keeps the legacy appearance mapped to the existing
  `semantic.*.material` role tokens.
- `design-system/Glass.qml` is the QML resolver singleton; it exposes the
  rollout, scheme, slider, accessibility, backend and tier inputs and returns
  `sampled-glass` / `no-blur-veil` / `solid` / `software-fallback`.
- `compositor/src/material_preset.rs` is the Rust resolver (exposed from
  `compositor/src/lib.rs`). It reads the generated `glass` module and defines
  `Preset`, `Role`, `Scheme`, `Rollout`, `RenderMode`, `Backend`, `Tier`,
  `Accessibility`, `ResolveInput`, `ResolvedPreset`.
- One rollout switch: `DRAGONFRUIT_GLASS_ROLLOUT=legacy|replacement`, default
  `legacy` until T208. The shell controller sets `Glass.rollout` from it and
  logs the selection; the compositor logs `glass rollout=<mode>` at startup and
  the resolver exposes `Rollout::from_env()`. Unset/unknown is always legacy.
- Tests:
  - `tests/glass/test_material_presets.py` (151 checks) — schema/ranges/finite
    values, anchors, unmeasured roles, dark attached/detached, accessibility
    precedence, veil vs unsupported, persistent floor, rollout default.
  - `compositor/tests/material_presets.rs` (7 cases, wired into `make e2e`).
  - `design-system/tests/tst_design_system.qml` `test_glass_*` (10 cases).
  - Unit tests in `material_preset.rs` (13 cases, run by `cargo test --lib`).
- Docs: `docs/design/10-design-system.md` gained the preset/resolution section
  and quality-gate row; ADR
  `docs/design/adr/0214-glass-role-presets-and-resolution.md` records the
  decisions.

## Resolution policy

Highest precedence first:

1. Reduce Transparency: opaque scheme plate, `solid`, no blur/lensing, slider
   ignored.
2. Rollout: `legacy` uses the existing per-role material tokens; `replacement`
   uses the optical preset.
3. Light `menuAttached` slider: piecewise through the three measured anchors.
   Dark and every other preset keep their named baseline.
4. Increase Contrast: edge/foreground/edge-width boost after the fill decision,
   so it also applies with Reduce Transparency.
5. Backend/tier: `sampled-glass`, `no-blur-veil`, `solid` or
   `software-fallback`. A veil is always `no-blur-veil`, even with no sampled
   pass. Unsupported sampled paths use the opaque scheme plate and a named
   reason. Persistent chrome keeps its sampled floor at `Minimal`; transient
   popups may become `solid`.
6. Reduce Motion is accepted but has no optical effect.

## Reusable facts

- Commands: `make check-tokens`, `make check-design-tokens`,
  `make glass-presets-check`, `python3 scripts/material_presets.py resolve
  --preset dock --scheme light --rollout replacement --backend gpu-sampled`.
- The generated QML path is `Theme.glass.presets.<name>.<light|dark>`.
- The generated Rust path is `design_tokens::glass::presets::<snake_name>`.
- The legacy values come from `semantic.<scheme>.material`; do not add a second
  copy of the old opacities to the glass group.
- `DRAGONFRUIT_GLASS_ROLLOUT=replacement` is the fixture/native selection;
  `legacy` (or unset) is the T208-safe default.

## Follow-ups

- T196 adds `appearance.transparency`, `accessibility.reduceTransparency` and
  `accessibility.increaseContrast` and must feed the same resolver inputs; do
  not add a second slider curve in settingsd or the shell.
- T197 should map the existing `DegradeTier`/`MaterialRole` to
  `material_preset::Tier`/`Preset` at the render boundary; the resolver stays
  pure and renderer-free.
- T198–T206 consume `Theme.glass`/`Glass.resolve` or the Rust resolver per
  surface. Keep the veil path distinct from a missing sampled pass.
- T205 still needs controlled dark banner/lower-panel and dark attached-menu
  recaptures; the current values are explicitly `baseline`/`adapted`.
- T208 flips `glass.rollout.defaultMode`; keep `DRAGONFRUIT_GLASS_ROLLOUT` as
  the rollback/diagnostic switch.
- `make check-i18n` currently reports an unrelated pre-existing `Monitor %1`
  template move (`ShellSurfaceBuffer` vs `shellprotocol`); T195 does not touch
  either file.
