## Hand-off

**Landed.** The Settings app now publishes its native menu model, and the
shell's menu bar consumes it.

- **`apps/settings/SettingsMenu.qml`** (new, QML singleton) — the single source
  of Settings' menus: the fixed `applicationMenuItems` (About/Settings/Hide/
  Hide Others/Show All/Quit) and `menus` (`File`/Close Window, `Edit`/standard
  verbs + separator, `View`/Enter Full Screen + a `Settings Pane` submenu,
  `Window`/Minimize/Zoom/Bring All to Front, `Help`/Settings Help), in the
  design-system normalized, JSON-serializable entry shape with an `action`
  string per row. `publishedModel` is the wrapper; `actionFor(menuIndex,
  itemIndex)` follows the `MenuBarMenu` `triggered` contract; `activate(action,
  item)` emits `activated`.
- **`SettingsShell.qml`** exposes `menuModel: SettingsMenu.publishedModel`;
  **`SettingsWindow.qml`** wires `activated` to the app's window verbs
  (close/minimize/zoom/fullscreen) and pane jumps (`pane.*`). The `edit.*`
  verbs are the standard editing actions the broker will route to the focused
  text input (T-14.2b).
- **Consumption** — the shell's `MenuBar` accepts the published model unchanged
  as `applicationMenuItems` + `appMenuModel`. The production cross-process
  transport (focus → app → model) is the menu-broker's job (T-14.2a); until then
  the shell keeps the fixed application menu, per the task's "fixed app menu is
  enough until then." ADR
  [0041](../design/adr/0041-native-menu-model-publication-shape.md) fixes the
  payload and the consumption surface but leaves the channel to T-14.2a.
- **Tests** — `apps/settings/tests/tst_settings_menu.{cpp,qml}` (10 cases):
  model shape, JSON-serializability, `actionFor`/`activate`, and the headless
  round-trip — the exact `publishedModel` injected into a real shell `MenuBar`
  renders File…Help at indices 2..6 and routes an activated row's `action`.
  Command + result:
  `ctest --test-dir build -R tst_settings_menu` → 1/1 passed (10 QTest cases,
  `Totals: 10 passed, 0 failed`).
- **Gate** — `make lint` green (30/30 ctest incl. `qmllint_app-settings`,
  clippy, token/desktop-name gates), `make e2e` exit 0.
- **Live visual check** — `/tmp/opencode/t54-capture.sh`, stills
  `/tmp/opencode/t54-desktop.png`, `/tmp/opencode/t54-window.png`,
  `/tmp/opencode/t54-menubar.png`: nested demo with Settings open on the
  Appearance pane. Raw observation: the menu bar renders the brand mark +
  application menu + File/Edit/View and the right-side clock/status icons; the
  Settings window shows the sidebar (Appearance selected / Desktop & Dock /
  Displays / Wallpaper), the Appearance header, the Light/Dark/Auto segmented
  control, and the accent swatches with no clipping or overlap. The published
  menus do not appear in the bar yet — that is the deferred transport (T-14.2a).

**Deviations.** None. No schema change (no settingsd key), so
`docs/settings-keys.md` and `SCHEMA_VERSION` are untouched. The transport
decision is recorded in ADR 0041 rather than implemented here, because
discovery (focus → bus name) is exactly what T-14.2a builds.

**Next task (T-09.6b)** adds the absent-provider matrix and the wave captures.
It must not edit the published model's shape; extend `SettingsMenu` only if a
new pane adds a menu verb. The pre-existing `AppearancePane` `controlData:` bug
(T-09.3 follow-up (a)) is still open and is not this task's.
