## Hand-off

**Landed.** `services/files-core`:

- `src/optimistic.rs` (new) — `OptimisticModel` wraps a `DirectoryModel` +
  `Selection`. `begin_rename` / `begin_new_folder` / `begin_delete` edit the
  model synchronously (visible before any confirmation) and return an `OpId`;
  `confirm(op)` keeps the painted result and `revert(op)` restores the
  captured node, arrival position, and selection. The `rename_via` /
  `new_folder_via` / `delete_via` methods run the real `FileOps` call and
  reconcile in one synchronous call, retargeting a confirmed create/rename to
  the `Location` the op returned. `begin`/`apply`/`drain`/`set_sort` pass
  through.
- `src/selection.rs` (new) — `Selection`, an insertion-ordered set of
  `NodeId` with O(1) membership; `select` ignores `NodeId::UNSET`.
- `src/model.rs` — new mutation API (`insert_node`, `restore_node`,
  `remove_node`, `replace_node`, `rename_node`) that re-sorts the projection
  without renumbering ids. `src/node.rs` — crate-private name/URI setters.
- ADR [0045](../../design/adr/0045-files-core-optimistic-layer.md);
  `docs/design/09-files.md` T-10.2b status paragraph.

**Tests (acceptance).** `cargo test -p dragonfruit-files-core` — 86 pass,
including 11 new cases in `tests/optimistic.rs`: optimistic rename visible
then confirm and revert; new-folder folders-first, generated numbering, and
revert; selection survives delete/revert/re-sort; `rename_via`/`delete_via`/
`new_folder_via` against a real temp tree; failed rename/delete/foreign-scheme
revert. `make lint` 31/31 and `make e2e` exit 0.

**Live visual check.** `/tmp/opencode/t59-capture.sh` →
`/tmp/opencode/t59-desktop.png` (1920x1200). Nested demo renders the Settings
window, menu bar, and Dock; the only reported oddity is the pre-existing X11
demo-window clipping (same as T57/T58). files-core has no surface of its own,
so this only confirms the session still renders.

**Deviations.** None. `begin_delete` is the permanent-delete optimistic path;
T-10.3a's trash reuses it. Reconciliation is driven by the operation result
until T-10.3b's watcher exists.

**Next (T-10.3a adds trash).** Add `trash://`/Put Back/Empty through `FileOps`
(or a sibling seam) and reuse `begin_delete`/`revert` for the optimistic
window; `delete` stays permanent.
