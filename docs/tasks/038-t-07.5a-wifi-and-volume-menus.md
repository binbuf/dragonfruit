## Hand-off

**State: done.** Wi-Fi list/join and volume slider/mute are live UI in
design-system popovers, served by a new session-bus bridge host over the
T-07.2/T-07.3 adapters.

Landed:

- **`services/system-status/`** (new crate `dragonfruit-system-status`):
  `StatusHost` (adapter-only core, JSON views + actions; 7 lib tests),
  `dbus.rs` (`org.dragonfruit.SystemStatus1` at
  `/org/dragonfruit/SystemStatus1`, `Wifi`/`Audio` interfaces:
  `State`/`Refresh`/`Join`/`SetVolume`/`SetMute`/`ToggleMute`), `main.rs`.
  `tests/host.rs` (4) proves both menus' actions apply through the adapters
  and that an absent daemon hides both.
- **Shell**: `shell/src/systemstatusmodel.{h,cpp}` (JSON → menu model;
  `tst_statusmodel`, 9 cases), `shell/src/systemstatusclient.{h,cpp}`
  (`DbusSystemStatusClient` + `MockSystemStatusClient`), `WifiMenu.qml`,
  `VolumeMenu.qml`, and `MenuBar.qml`/`StatusGlyph.qml`/`ShellController`
  wiring. `shell/tests/tst_menubar.qml` gained 10 cases (menu models, join
  incl. secured password prompt, read-only, slider/mute, click-opens-popover).
- **Docs**: `07-system-integration.md` "The status bridge host (T-07.5a)";
  ADR `0029`.
- **Capture**: `docs/captures/t07.5a-wifi.png` / `t07.5a-volume.png` via
  `scripts/capture-status-menus.sh`; vision-checked — the Wi-Fi popover lists
  `home`/`dragonfruit-guest`/`NeighbourNet` with signal bars, the Sound popover
  shows the slider at 60% with "Built-in Speakers" and a Mute button.

Commands: `cargo test -p dragonfruit-system-status` (7+4 green),
`make e2e` green, `cargo clippy -p dragonfruit-system-status --all-targets --
-D warnings` and `cargo fmt --all -- --check` clean, `make qml-test` green.

What T-07.5b must know:

- The battery interface is not in the host yet: add a `Power` interface to
  `services/system-status` (the `dragonfruit-power` crate is ready) and render
  it in its own popover. Battery hides both on `AdapterState::Unavailable` and
  on `PowerSnapshot::present() == false`.
- `--placeholders` still exists and now drives `MockSystemStatusClient` (the
  demo's data); removing the flag must not remove the fixture client, which
  the headless tests and captures rely on.
- The live path is `--placeholders`-off → `DbusSystemStatusClient`; nothing
  launches `dragonfruit-system-status` yet. Launch it on the session bus when
  placeholders are removed.
- **Deferred bridge work (T-07.6)**: daemon-signal-driven refresh. Today the
  host re-reads on open/action; the adapters' live sources still need their
  daemon subscriptions (NetworkManager signals, `pw-mon`, UPower
  `PropertiesChanged`) wired to `refresh()`. No poll loop may be added above
  the adapter.
