## Goal

Animate minimize into and restore out of the owning Dock entry's tile.

## Scope

- Shell → compositor tile geometry hand-off (additive, optional; degrade to centered origin in headless).
- `dock.minimizedAnimation=scale`; `none` is the reduced-motion fallback.
- No orphaned ghost and no stale Dock entry after the sequence.

## Explicitly deferred

- Genie minimize (post-gate).

## Acceptance (agent-completable)

- [ ] Minimize→restore resolves with no orphan and no stale entry.
- [ ] Reduced-motion variant passes.

## Test plan

- Headless: drive minimize/restore, assert final geometry and outbox events.

## Hand-off

Landed:

- `compositor/src/window/motion.rs` (renamed from `appear.rs`):
  `WindowMotion` / `WindowMotionKind` (`appear`/`minimize`/`restore`) /
  `MotionFrame`. Appear and restore interpolate `origin → target`; minimize is
  the exact reverse. One frame type serves all three. `WindowModel`
  `set_motion`/`motion`/`motion_frame`/`step_motions`/`motions`/`active_motions`.
- `DfState::minimize_window` unmaps and broadcasts state immediately, then
  starts a `Minimize` motion (origin = Dock tile, target = restore geometry).
  `restore_window` maps immediately and starts a `Restore` motion.
  `dock_tiles` (was `pending_appear_origins`) is now remembered, not consumed,
  so minimize/restore reuse the launch tile; absent → `centered_origin`.
- `render::{window_render_elements,titlebar_render_elements}` render a
  minimizing window as a ghost from `WindowModel::active_motions` even though
  it is unmapped from `Space`; `titlebar_element_for_motion` lays out its SSD
  titlebar as floating. One `window_motion_driver` closure steps every motion
  once per frame (fixes one-driver-per-motion over-stepping).
- Shell protocol unchanged: `set_launch_origin` (v4) and
  `df_toplevel.minimize`/`unminimize` already route to these primitives.
- Synthetic hooks: `query motion` (`query appear` kept as an alias),
  `query events` (peek the window outbox), `minimize <id>`, `restore <id>`.
- `broadcast_window_events` no longer drains the window outbox when no trusted
  manager is connected, so a headless test can observe what the shell would
  learn (a late-bound shell replays the scene).
- Tests: `compositor/tests/window_conformance.rs` —
  `minimize_and_restore_play_through_the_dock_tile_and_resolve_cleanly`,
  `reduced_motion_minimize_and_restore_take_a_single_frame`; T-02.1b tests
  updated to `query motion`.
- Docs: `docs/design/02-compositor.md` "Window lifecycle motion";
  `docs/design/adr/0005-minimize-restore-motion-and-ghost.md`;
  `docs/private-protocols.md`; `protocols/dragonfruit-toplevel.xml` description.

Deviations / not done:

- The shell does **not** call `setLaunchOrigin` yet: the Dock tile rect is not
  threaded from QML to `ShellController::launchDockAppWithFiles`, and
  `desktopId` → compositor `app_id` is the T-23 resolver. Real launches and
  minimize use the centered fallback; the compositor side is complete.
- `dock.minimizedAnimation` is not plumbed over the protocol: `scale` is the
  only implemented value and `none` is exactly the reduced-motion collapse, so
  no new request was needed. Genie remains post-gate.
- No nested capture was committed (task/goldens are batched at the track
  boundary).

T-02.3: use `WindowMotionKind` + `WindowMotion` for zoom/fullscreen; they are
render-only (never unmap mid-motion) and run on the same clock. Reuse
`MotionFrame`/`window_render_elements`; do not add a second effect path.
