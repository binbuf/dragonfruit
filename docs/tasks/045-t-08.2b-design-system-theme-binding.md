## Hand-off

**Landed.** The design-system `Theme` singleton's `dark`/`reducedMotion` are
now bound to settingsd. `shell/src/themebinding.{h,cpp}` (new) is the single
writer: it consumes the same `SettingsClient` the Dock does (ADR 0032 — no
second bus connection, watcher, or timer) and maps
`appearance.colorScheme` → `Theme.dark` and `accessibility.reduceMotion` →
`Theme.reducedMotion`, reacting to `changed`/`refreshed`. `auto` follows the
host and stays live via `QStyleHints::colorSchemeChanged`; the pure resolver
is `ThemeBinding::darkForScheme`. `ShellController` creates it after the QML
engine (one per process) and no longer writes `Theme.reducedMotion` from the
Dock reconfigure path. ADR
[0033](../design/adr/0033-theme-binding-single-writer.md); the track doc 08
gained a "design-system Theme follows settingsd" section.

**Deviation / scope.** The binding lives in the shell, not in
`design-system/` (area label): the settings client and its lifecycle are the
shell's (ADR 0032), and the design system stays D-Bus-free. No `Theme.qml`
change was needed — `dark`/`reducedMotion` were already writable.
`appearance.accent` is **not** consumed: `Theme.color.accent` is a read-only
scheme token, so an override is a design-system change; T-09.2 (Appearance
pane) is the natural owner. Compositor motion/input is T-08.2c.

**Gotchas for later tasks.**

- One writer: do not reintroduce a `Theme.dark`/`reducedMotion` assignment in
  shell QML or `ShellController`; `ThemeBinding` owns both.
- A new appearance key needs a branch in `ThemeBinding::apply` (and
  `settingsSchemaDefaults()`), not a second connection.
- `Theme.reducedMotion` still reaches the compositor only through
  `ShellProtocol::setReducedMotion` in `applyDockSettings`; T-08.2c should
  mirror `appearance.colorScheme` the same way.
