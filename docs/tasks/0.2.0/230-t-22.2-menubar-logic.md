# T230 — Menu bar business logic and global menu completion

## Goal

Make the menu bar complete: focus-driven application menus, DBusMenu consumption and click routing, hide/show verbs, services, dynamic items, and keyboard/accelerator behavior.

## Scope

- [ ] Route focus → app identity → menu-broker registration → shell menu model; clear on focus loss.
- [ ] Consume DBusMenu projections and route `dbusmenu:<id>` clicks back through the window/menu event path.
- [ ] Implement Hide, Hide Others, Show All as compositor window operations.
- [ ] Add Services, Recent Items, dynamic window lists, and accelerator dispatch.
- [ ] Add keyboard navigation: arrows, Return, Escape, type-ahead, submenu direction, disabled reasons.
- [ ] Check the liquid-glass menu/bar material tasks first; do not duplicate or regress them.

## Out of scope

- A second menu model or app-specific menu hacks.
- Changing the app menu publication format (T-14.2a).

## Design notes

The menu bar is shell-owned chrome; the app model comes from menu-broker. A menu row must have a command or be disabled with a reason. Accelerators must match the published model and the compositor keymap. The fixed application menu is synthesized for apps that export nothing. Menu open/close motion uses the measured token; the material comes from the glass path.
