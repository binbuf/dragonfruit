# T229a — Settings panes: Wallpaper, Notifications, Focus, and Lock Screen

## Goal

Bring the remaining first-party Settings panes to the total-experience bar:
Wallpaper, Notifications, Focus, and Lock Screen, with live apply, absence
states, and the reference information architecture.

- `apps/settings/WallpaperPane.qml`, `NotificationsPane.qml`, `FocusPane.qml`,
  `LockScreenPane.qml`
- `services/wallpaperd/`, `services/notifications/`, `services/settingsd/`,
  `services/session/`
- Existing T-09.3/T-15.7/T-15.8/T-18 work.

## Scope

- [ ] Wallpaper: current preview, show on all workspaces, built-in/featured/
      custom sources, screen saver/clock links, provider offline/empty state.
- [ ] Notifications: previews, show when asleep/locked/sharing, per-app list,
      per-app style/sound/badge, Focus link, service-absent state.
- [ ] Focus: modes, allowed people/apps, schedule, shortcut, active state,
      service-absent state.
- [ ] Lock Screen: display-off timers, require password, user name/photo,
      password hints, lock message, login-window style, power buttons,
      accessibility options.
- [ ] Live apply, validation, revert, keyboard/AX, long-string layout.
- [ ] Tests and captures for each pane plus one absence state.

## Out of scope

- The wallpaper provider fetch/cache (T-18; existing).
- The notification service policy engine (existing T-11).
- The lock/PAM enforcement (existing T-12; T245 covers the runtime).

## Design notes

The map's row-level owners are authoritative. Wallpaper and Notifications are
existing panes; this task closes the gaps rather than rebuilding them. A
provider/service that is absent shows a note and disables only the affected
rows. Focus and Notifications share one policy source. Lock Screen writes
`settingsd` and the compositor observes; the pane never enforces the lock
itself. Check the liquid-glass Settings chrome task (T206) before styling.
