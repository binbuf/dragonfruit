# T256 — Users/groups, admin auth, and polkit

## Goal

Ship user/group management and admin authentication through accountsservice, the distro adapter, and polkit/PAM.

## Context (read first)

- T221 adapters; T229 Users & Groups pane
- `services/account-adapter/`, `services/lock-auth/`, `shell/src/polkitagent.*`
- `docs/design/distro-compatibility.md` users/auth section

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] List users/groups; add/edit/delete user/group; password change.
- [ ] Admin group detection (`wheel`/`sudo`/`admin`); never hardcode.
- [ ] Autologin for GDM/SDDM/LightDM/greetd.
- [ ] Polkit/PAM prompts; no setuid, no direct `/etc/shadow` edits.
- [ ] Fast user switching where the DM supports it.
- [ ] Tests/absence on each distro.

## Out of scope

- A new account database.
- A custom password prompt outside PAM/polkit.

## Design notes

accountsservice is the read model; the distro adapter is the write path. Passwords are never logged. A missing fingerprint reader hides the biometric controls. A DM that cannot autologin hides the row. The admin group mapping is detected, not assumed.
