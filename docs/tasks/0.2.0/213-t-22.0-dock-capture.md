# T213 — Capture: Dock behavior matrix

## Goal

Capture the Dock’s full state and behaviour matrix, including motion, multi-display, keyboard, drag/drop, stacks, Trash, and the window chooser.

## Context (read first)

- T209/T210 inventory and harness
- `docs/dock.md`, `docs/dock-learnings.md`, `docs/design/04-shell.md`
- Liquid-glass Dock measurements/ADR 0218

## Reference UI/UX (macOS screenshots)

- Host: **macOS**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Capture `S-DOCK-01..34`: rest/hover/magnified/pressed/tooltip, positions, size/magnification extremes, running/focused/minimized, chooser, stacks, Trash, badges, overflow, context menus, picker, keyboard.
- [ ] Capture launch bounce, minimize genie/scale, restore, auto-hide reveal/hide, reorder settle, chooser open/close, Trash empty as 120 fps motion.
- [ ] Capture multiple displays/fullscreen where available; otherwise `OPEN`.
- [ ] Capture AX geometry for every tile and the window chooser.
- [ ] Capture reduced motion and accessibility variants.

## Out of scope

- Implementing the Dock (T236–T239).
- Changing Dock defaults to match the capture.

## Design notes

Record the Dock tile count, icon size, magnification, position, auto-hide state, and display arrangement with every run. Use the AX tree for geometry and verify against pixels. The existing liquid-glass captures remain the material source; this task focuses on behaviour/state. Do not invent a launch multi-bounce or interactive auto-hide curve if the capture cannot resolve it; write `OPEN`.
