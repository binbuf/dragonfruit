# T222 — Settings business-logic map and pane catalog

## Goal

Make the Settings map executable: the pane catalog, row owners, shipped flags, and absence paths match the design doc and cannot drift.

## Context (read first)

- `docs/design/settings-business-logic-map.md`
- `apps/settings/SettingsPanes.qml`, `SettingsShell.qml`
- `services/settingsd/src/schema.rs`

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Align the `SettingsPanes` catalog with the map: pane id, label, icon, shipped flag, owner, deep link.
- [ ] Add row-level metadata (owner, key/API, absence kind) where the UI needs it.
- [ ] Remove/hide unowned rows; mark omitted panes explicitly.
- [ ] Add a test that every shipped pane has a body and every visible row has an owner.
- [ ] Add the map to the docs index and link it from the Settings app help/debug view.

## Out of scope

- Implementing each pane (T223–T229).
- Adding rows that are not in the map.

## Design notes

The map is the source of truth for the catalog. A row may be visible but disabled with an explanation; it may not be a fake toggle. The `shipped` flag and the body must land together. Existing 22 panes keep their ids; new panes use the map names.

- [ ] Every omitted pane is absent from the sidebar and documented.
- [ ] The Settings app exposes a debug view of pane/row owners.
- [ ] Docs touched: the design doc(s) this task implements and the relevant `docs/design/STATUS.md` row.
