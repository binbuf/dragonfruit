# T245a — System dialogs, sheets, alerts, and pickers

## Goal

Ship the shared system dialog language: file open/save, print, color picker,
emoji & symbols, alerts, sheets, confirmations, progress dialogs, and the
screen-saver runtime, using the design system and the host services behind
them.

## Scope

- [ ] File open/save panel: chrome, sidebar/places, search, recent, filename,
      file type, overwrite/confirm, keyboard.
- [ ] Print dialog: printer, presets, copies, pages, orientation, preview,
      progress/error; delegate printing to CUPS.
- [ ] Color picker: tabs, palette, eyedropper, opacity, recent; delegate color
      profiles to colord where applicable.
- [ ] Emoji & symbols: search, categories, skin tones, insert/copy, keyboard.
- [ ] Alerts/sheets/confirmations: default/destructive button order, checkbox,
      progress, cancel, error, accessibility.
- [ ] Screen saver runtime: style, clock, idle start, password/lock hand-off,
      reduced motion, multi-display.
- [ ] Keyboard/AX/reduced-motion tests and captures for each dialog.

## Out of scope

- A new print engine, color-management engine, or emoji database.
- Apple-specific dialog artwork or wording.
- The Settings panes that configure these features (T225–T229).

## Design notes

The design system owns the dialog/sheet anatomy; each dialog consumes it rather
than cloning a macOS window. Sandboxed apps use the portal file chooser; the
first-party dialog is the same UI for unsandboxed apps. The screen saver is a
shell/compositor surface, not a screensaver daemon; idle policy comes from
`settingsd`/logind. A dialog that cannot act (no printer, no color profile)
shows the absence state and disables only the affected control. The print/color
backends stay host services.
