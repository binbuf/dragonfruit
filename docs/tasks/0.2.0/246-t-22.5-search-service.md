# T246 — Search service: app-index, file index, actions, and previews

## Goal

Build the Search service behind the Spotlight-equivalent: app results from app-index, optional file indexing, actions, previews, privacy, and honest absence.

## Context (read first)

- T216 captures; T220 naming; T221 adapters
- `services/app-index/`, `docs/design/14-global-menu-app-index-compat.md`
- `docs/design/settings-business-logic-map.md` Search section

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Define the search query/result/action API and ranking.
- [ ] App results from app-index (name/id/keywords/recency).
- [ ] File index: built-in filename index by default; optional Tracker/Baloo/Recoll backend.
- [ ] Actions: open, reveal in Files, copy path, web search, calculation, definition.
- [ ] Preview integration (T244); privacy/excluded paths; indexing status/error/absent.
- [ ] Performance budget and tests for large corpora.

## Out of scope

- A new file indexer if the built-in filename index is sufficient for the first pass.
- Cloud/network indexing.

## Design notes

The index is local by default. A backend that is absent falls back to the built-in index; it is not an error. Results must carry their source and action. Do not show a result that cannot act. The service is separate from the UI and from app-index.
