# T224 — Settings live apply, validation, admin auth, and absence

## Goal

Make every Settings control apply live or explicitly, validate, revert on failure, use the system auth prompt, and degrade honestly when the owner is absent.

## Context (read first)

- T222 map, T223 IA
- `apps/settings/SettingsBridge.*`, `services/settingsd/`, `shell/src/polkitagent.*`
- `docs/design/08-settings.md` absence matrix

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Add a common apply path: optimistic UI, owner write, success/failure, revert with a message.
- [ ] Add validation for ranges/enums and surface the error next to the control.
- [ ] Use polkit/PAM for privileged actions; never a custom password field.
- [ ] Implement the absence kinds: live-on-defaults, disabled-with-reason, hidden, read-only, delegated.
- [ ] Add tests for failure, cancel, wrong password, service disappearance, and restart resync.

## Out of scope

- Pane-specific controls (T225–T229).
- A second settings daemon.

## Design notes

No control may write directly to a file or run a command from QML. A failed write must not leave the UI claiming success. A service that disappears while the pane is open flips to its absence state without losing the other controls. The settingsd restart resync is already defined; reuse it.

## Done when

- [ ] The common apply/validate/revert path is used by at least three panes.
- [ ] Polkit/PAM prompts work for one privileged action.
- [ ] Absence tests cover all five kinds; no fake toggle remains.
- [ ] Docs touched: the design doc(s) this task implements and the relevant `docs/design/STATUS.md` row.
- [ ] Hand-off filled in below.

## Live visual check (required)
