# T255 — Startup apps and login items

## Goal

Ship startup-app management: XDG autostart, systemd user units, enable/disable, and absence across distros.

## Context (read first)

- T221 adapters; T226 Login Items pane
- `services/session/`, `services/settingsd/`
- `docs/design/distro-compatibility.md` startup section

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Read `~/.config/autostart`, `/etc/xdg/autostart`, and systemd user units.
- [ ] Enable/disable without editing system files; write user overrides.
- [ ] Respect Hidden/OnlyShowIn/NotShowIn/TryExec and avoid double launch.
- [ ] Show the source, command, and state; hide unavailable entries.
- [ ] Tests with fixtures and real units on each distro.
- [ ] Session-plan integration for the desktop process (G-09).

## Out of scope

- A second autostart format.
- Starting apps without the user’s consent.

## Design notes

XDG autostart and systemd user units are both first-class. The Settings toggle writes a user override, not the system file. A unit that requires admin uses polkit. The session plan must start the desktop process as a unit, not a dev-only token.
