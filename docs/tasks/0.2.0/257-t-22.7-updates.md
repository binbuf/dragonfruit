# T257 — Software updates and package management

## Goal

Ship the Updates pane with a distro-neutral provider, real check/install/progress/reboot, and Flatpak/Snap source labels.

## Context (read first)

- T221 adapters; T226 Updates pane
- `services/update-adapter/`
- `docs/design/distro-compatibility.md` updates section

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Define the UpdateProvider trait and native/PackageKit backends.
- [ ] Check, list, install, progress, cancel where supported, reboot-required.
- [ ] Automatic-update policy; offline-update behavior where available.
- [ ] Flatpak/Snap updates with source labels.
- [ ] Absence: no backend, no network, auth failure, partial failure.
- [ ] Tests on Fedora/Ubuntu/Debian/Arch.

## Out of scope

- A new package manager.
- Silently enabling automatic updates.

## Design notes

Never parse human-readable output when a machine API exists. Never run a package manager from QML. The default follows the distro policy. A partial failure lists which updates failed and why. The reboot prompt is explicit; no surprise reboot.

- [ ] Flatpak/Snap source labels work where installed.
