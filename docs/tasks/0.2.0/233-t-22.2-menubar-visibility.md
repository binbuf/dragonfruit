# T233 — Menu bar visibility, auto-hide, notch/overflow, and multi-display

## Goal

Make the menu bar behave correctly when space is tight: auto-hide, fullscreen reveal, notch/overflow priority, and per-display ownership.

## Context (read first)

- T230/T231 menu bar
- `shell/menubar/MenuBar.qml`, `shell/src/shellcontroller.cpp`
- Compositor reserved zones/layer surfaces

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Implement auto-hide modes (always/never/in fullscreen) with measured reveal/hide delay and motion.
- [ ] Handle fullscreen apps: reveal on top edge, hide after leave, no reserved strip.
- [ ] Implement notch/overflow: prioritize system items, move extras into an overflow menu, never clip.
- [ ] Per-display: one bar per display; active display owns the app menu; status items follow policy.
- [ ] Update the Menu Bar pane rows (auto-hide, background, recent items, controls) to match the implemented behavior.
- [ ] Add tests for reserved zones, input regions, fullscreen, hotplug, and multi-display.
- [ ] Check the liquid-glass veil/visibility tasks (T200/T201) first.

## Out of scope

- A second menu bar per display implementation.
- Changing the compositor layer protocol.

## Design notes

The bar’s reserved zone and input region must match the visible bar; a hidden bar reserves nothing. The veil is a visual extent, not a hit target. Overflow must be deterministic and stable across focus changes. A third-party item can be hidden but not silently dropped without an overflow entry.
