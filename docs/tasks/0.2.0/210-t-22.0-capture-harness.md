# T210 — Capture harness: animation, HUD, and accessibility evidence

## Goal

Extend the macOS capture harness so motion, HUDs, accessibility trees, and manifests are reproducible by script rather than ad-hoc screenshots.

## Context (read first)

- T209 manifest and inventory
- `macos-liquid-glass-review/tools/capture.py`, `coverage_capture.py`, `uictl.swift`, `sweep.py`, `temporal.py`
- `macos-liquid-glass-review/docs/CAPTURE-PLAN.md` §§5–7 and §18

## Reference UI/UX (macOS screenshots)

- Host: **macOS**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Add `macos-liquid-glass-review/tools/experience_capture.py` orchestration skeleton with per-surface stages.
- [ ] Add `macos-liquid-glass-review/tools/motion_extract.py` for `ffmpeg`/`ffprobe` frame + timestamp extraction.

## Out of scope

- Surface-specific sweeps (T211–T217).
- Dragonfruit implementation.

## Design notes

Prefer 120 fps; record the actual frame timestamps. Use 500 ms pre-roll and 1 s post-roll. Log the trigger in the same run. Never crop the source. HUD capture must use the real key path (volume/brightness/backlight keys, power plug) where possible; if the hardware is missing, write an `OPEN` row. The harness must restore wallpaper/appearance/accessibility/Dock/menu-bar state even after a failed stage.
