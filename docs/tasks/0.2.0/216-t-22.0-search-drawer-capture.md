# T216 — Capture: Search and Applications drawer

## Goal

Capture Search (Spotlight-equivalent) and the Applications drawer in every query, category, result, preview, and launch state.

## Context (read first)

- T209/T210 inventory and harness
- `docs/reference/macos-ui-inventory.md` (Spotlight/Launchpad sections)
- `services/app-index/`

## Reference UI/UX (macOS screenshots)

- Host: **macOS**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Capture `Q-SP-01..15`: closed, empty, app/file/calculation/definition/web results, categories, top hit, preview, actions, no results, indexing, privacy, keyboard, multi-display.
- [ ] Capture `Q-AD-01..11`: all apps, search, category, many apps/scroll, folder, launch, keyboard, no apps, multi-display.
- [ ] Capture `Q-AP-01..04`: picker open/search/pin/absent.
- [ ] Capture open/close/result-update/launch as 120 fps motion.
- [ ] Dump AX labels/order for the result list and drawer grid.

## Out of scope

- Implementing Search/drawer (T246–T248).
- Indexing private user data; use a scratch corpus.

## Design notes

Record the query, result set, selected index, and source (app/file/action/web). Search on macOS 27 may be Siri-integrated; if the separate Spotlight surface is unavailable, mark `OPEN` and capture what the build exposes. The drawer is the Launchpad analogue; capture its category pills, page dots, and folder state.
