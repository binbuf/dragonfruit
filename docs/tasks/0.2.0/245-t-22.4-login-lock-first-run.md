# T245 — Login, lock, and first-run experience

## Goal

Complete the login/lock/first-run experience: lock screen, password/fingerprint, login window, fast user switching, power actions, and Welcome.

## Context (read first)

- T215 captures; T228 biometrics
- `shell/lock/`, `services/lock-*`, `docs/design/11-session-and-dev-workflow.md`
- Existing T-12 lock/idle/session work

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Lock screen: clock, user, background, password, fingerprint, error, unlock animation.
- [ ] Login window: user list/name+password, session choice, accessibility, power buttons.
- [ ] Fast user switching and switch-user lock behavior.
- [ ] Power actions: sleep/restart/shut down/log out with confirmations and logind.
- [ ] Welcome/first-run: language, network, account, privacy, appearance, done.
- [ ] Reduced motion, keyboard/AX, and failure states.

## Out of scope

- A new display manager; integrate GDM/SDDM/LightDM/greetd.
- A full account/OAuth setup beyond the host services.

## Design notes

Lock is fail-secure; no crash path unlocks. PAM is a helper. The login window follows the configured style and hides unsupported options. Welcome is a shell/app flow, not a second Settings app. Power actions use logind, not shell commands. A fingerprint failure falls back to password.
