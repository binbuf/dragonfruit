# T260 — Motion/pixel acceptance harness and CI

## Goal

Make the total-experience acceptance measurable: pixel/geometry/motion comparisons, tolerances, golden artifacts, and CI gates.

## Context (read first)

- T219 schema; T218 motion database
- `analysis/compare.py`, `scripts/t20-material-compare.py`, design-system gallery
- `docs/design/evidence-and-acceptance.md`

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Add still comparison with registration/ICC/material masks.
- [ ] Add motion trace comparison (duration/curve/overshoot) against the database.
- [ ] Add geometry/typography checks for key surfaces.
- [ ] Define golden artifacts and tolerance reporting; fail on regression.
- [ ] Wire the deterministic checks into CI; keep native/hardware checks separate.
- [ ] Document how to update a golden.

## Out of scope

- Pixel-perfect macOS screenshots.
- Native DRM proof in ordinary CI.

## Design notes

Nested captures are reference evidence, not native proof. The harness must report the metric, crop, tolerance, and diff image. A tolerance change requires a design note. Goldens are our implementation, not Apple screenshots. Keep the harness fast enough for PRs.

- [ ] The update procedure and evidence rules are documented.
