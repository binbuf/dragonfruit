# T231 — Menu-bar extras framework and Date & Time/Calendar

## Goal

Introduce one status-item registry for system and third-party extras, and make the clock/date/calendar a first-class extra.

## Context (read first)

- T212 captures; T230 menu bar
- `shell/menubar/StatusItem.qml`, `MenuBarClock.qml`, `shell/src/trayclient.*`
- `docs/reference/macos-ui-inventory.md` menu bar/clock sections

## Scope

- [ ] Define a status-item model: id, icon, tooltip, menu, priority, visibility, state, accessible name.
- [ ] Migrate Wi-Fi/Bluetooth/Battery/Sound/Search/Quick Settings/Notifications to the registry.
- [ ] Add the Date & Time item with date/time formats, seconds, 24-hour, and the calendar popover.
- [ ] Add third-party StatusNotifier items through the registry with ordering/overflow rules.
- [ ] Add keyboard access and AX names for every item.
- [ ] Check the liquid-glass menu/popover material tasks before styling.

## Out of scope

- Implementing each service menu (T232).
- A second tray implementation.

## Design notes

The registry owns order and visibility; `settingsd` owns the user’s menu-bar choices. An absent service item hides or shows an explicit unavailable state. The clock popover is a panel, not a menu; it uses the popover material and keyboard dismissal. Third-party items never outrank system items in the overflow policy.
