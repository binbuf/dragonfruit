# T253 — IME integration

## Goal

Integrate ibus/fcitx5 so CJK/complex input works in shell fields and apps, with input-source settings and a candidate window.

## Context (read first)

- T229 Keyboard pane; T221 adapters
- `compositor/src/state.rs` text-input/input-method registration
- `docs/design/status` G-20

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Detect ibus/fcitx5; start/stop one framework; never both.
- [ ] Compositor text-input/input-method protocol path and candidate window.
- [ ] Settings input sources, framework choice, per-window state.
- [ ] Focus/commit/preedit behavior in shell fields and apps.
- [ ] Absence state and tests; CJK input capture.

## Out of scope

- Writing a new IME engine.
- Supporting every IME framework.

## Design notes

The compositor already advertises text-input/input-method but ships no IME UI (G-20). This task either integrates the framework candidate window or a minimal first-party one; decide and record. Input sources come from the framework/locale adapter. The IME must not break non-IME typing or shortcuts.

- [ ] Input-source settings and absence state work.
- [ ] A capture shows preedit/candidate/commit.
- [ ] Docs touched: the design doc(s) this task implements and the relevant `docs/design/STATUS.md` row.
