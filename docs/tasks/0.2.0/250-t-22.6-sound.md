# T250 — UI sound design and feedback

## Goal

Add a coherent, original UI sound language: startup, alerts, errors, volume feedback, toggles, notifications, and lock/unlock.

## Context (read first)

- T217 captures; T249 HUD
- `sound.*` settings keys
- `docs/design/interface-naming-and-licensing.md` asset policy

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Define the sound set and when each plays; avoid sound spam.
- [ ] Source/create original or permissively licensed sounds; record provenance/license.
- [ ] Wire `sound.uiEffects`, `sound.volumeFeedback`, `sound.alertVolume`, `sound.playOnStartup`.
- [ ] Mix at consistent loudness; no clipping; respect mute.
- [ ] Tests for settings, absence, and no-sound-on-mute.
- [ ] Captures/recordings and docs.

## Out of scope

- Apple sounds or close derivatives.
- A new audio stack.

## Design notes

Sound confirms, never startles. Do not play a sound for every hover. The sound must not delay the visual feedback. The setting is live. The startup sound is optional and follows the setting. The alert sound is per-app where the notification service exposes it.

## Done when

- [ ] The sound set is documented with licenses and wired to settings.
- [ ] Volume feedback/UI effects/startup/alert respect the toggles.
- [ ] A recording demonstrates the set and the mute behavior.
- [ ] Docs touched: the design doc(s) this task implements and the relevant `docs/design/STATUS.md` row.
- [ ] Hand-off filled in below.

## Live visual check (required)

- [ ] Toggle UI sounds/volume feedback, change volume, trigger an alert, and lock/unlock; listen and compare.
