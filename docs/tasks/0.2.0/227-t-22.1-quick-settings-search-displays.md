# T227 — Settings panes: Appearance, Quick Settings, Search, Screen Saver, Desktop & Stage, Displays advanced

## Goal

Complete the shell-owned settings panes and the advanced display controls that the shell/compositor own.

## Context (read first)

- T222 map, T224 apply path
- `shell/control-center/`, `shell/src/controlcenterpolicy.*`, `compositor/src/backend/drm.rs`
- `docs/reference/System_Preferences.md` Control Center/Displays/Desktop & Dock

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Appearance: light/dark/auto, accent/highlight, sidebar icon size, wallpaper tint, transparency, scroll bars, motion link; live theme.
- [ ] Quick Settings: module list, menu-bar-only items, add/remove/reorder, per-display behavior.
- [ ] Search: categories, indexed locations, shortcut, web search, indexing status.
- [ ] Screen Saver: style, idle time, clock, options.
- [ ] Desktop & Stage: desktop items, click-wallpaper, Stage Manager, recent apps, widgets.
- [ ] Displays advanced: night light, color profile, HDR, VRR, rotation, arrangement, refresh, brightness.
- [ ] Add pane tests, compositor policy tests, and absence captures.

## Out of scope

- Implementing the underlying Night Light/HDR/VRR if the compositor does not expose it; mark `OPEN` and hide the row.
- Stage Manager implementation (T242).

## Design notes

Do not advertise a display capability that is not implemented. The Displays pane is the most likely place for fake controls; every row must read/write a real compositor/colord API. Quick Settings customization writes `settingsd`, and the shell observes it. Search settings write the search service, not the UI.

## Done when

- [ ] Each pane renders and applies; unsupported display rows are hidden or disabled with a reason.
- [ ] Quick Settings customization changes the live panel.
- [ ] A capture shows the pane and the live result.
- [ ] Docs touched: the design doc(s) this task implements and the relevant `docs/design/STATUS.md` row.
- [ ] Hand-off filled in below.
