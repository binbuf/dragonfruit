# T218 — Motion measurement and timing database

## Goal

Fit every captured transition into a timing/curve database and identify conflicts with the existing motion tokens.

## Context (read first)

- T212–T217 motion artifacts
- `docs/design/motion-and-feedback.md`
- ADR 0218 and the existing T-02/T-05/T-06/T-11 tokens

## Reference UI/UX (macOS screenshots)

- Host: **macOS/Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Extract frames/timestamps; identify trigger, first change, last change, and settle.
- [ ] Fit duration, easing/spring, overshoot, and trigger-to-first-change latency.
- [ ] Record dropped/duplicated frames and discard runs with >5% loss.
- [ ] Produce `macos-liquid-glass-review/analysis/experience/motion.json` and a human-readable `macos-liquid-glass-review/docs/experience/motion.md`.
- [ ] Compare to the existing tokens; list agreements, conflicts, and `OPEN` rows.

## Out of scope

- Implementing the animations (T237/T240/T241/T243/T249).
- Inventing a curve where the capture is ambiguous.

## Design notes

Use the measured frame timestamps, not nominal fps. Report p50/p95 and the fit residual. A spring is used only if it fits better than a bezier. Preserve existing measured values unless the new capture is from the same build/display and is clearly better. The database is the input to the motion token change, not the token change itself.

## Done when

- [ ] `macos-liquid-glass-review/analysis/experience/motion.json` validates and covers every `A-*` id or an `OPEN` row.
- [ ] Each entry has duration, curve, overshoot, latency, frames, fps, and residual.
- [ ] Conflicts with existing tokens are listed with a recommended resolution.
- [ ] Docs touched: the design doc(s) this task implements and the relevant `docs/design/STATUS.md` row.
- [ ] Hand-off filled in below.
