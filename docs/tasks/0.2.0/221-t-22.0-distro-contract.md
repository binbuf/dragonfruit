# T221 — Cross-distro compatibility contract

## Goal

Turn the distro compatibility doc into an adapter contract with trait stubs, a distro matrix, and absence rules that the Settings panes can consume.

## Context (read first)

- `docs/design/distro-compatibility.md`
- `docs/design/07-system-integration.md`, `docs/design/12-packaging.md`
- Existing adapters under `services/`

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Define Rust traits for updates, firewall, users/groups, time, locale, autologin, default apps, and app discovery.
- [ ] Add stub implementations for Fedora/Ubuntu/Debian/Arch with the correct commands/APIs and a `not supported` error.
- [ ] Define the required/recommended/optional dependency sets and the absence behavior.
- [ ] Add adapter contract tests and a mock backend.
- [ ] Document the CI matrix and the clean-VM smoke plan.

## Out of scope

- Implementing each backend (T254–T259).
- Replacing NetworkManager/BlueZ/PipeWire/UPower/UDisks2.

## Design notes

The UI never shells out to a distro command. Each trait method returns a typed result; absence is a state, not an error dialog. The adapter is selected at startup by `/etc/os-release` + service detection, not by a hardcoded distro list. A missing optional service disables only the affected feature.
