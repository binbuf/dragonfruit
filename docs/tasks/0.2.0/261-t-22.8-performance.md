# T261 — Performance budgets for new surfaces

## Goal

Measure and enforce per-surface budgets for the new animations and chrome without regressing the T-21 presentation path.

## Context (read first)

- T237/T240/T241/T249; T-21 presentation work
- `docs/rendering.md`, `docs/ROADMAP.md` budgets
- Existing perf harnesses (`make t21-presentation-bench`, idle trace)

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Define per-surface budgets: Dock, menu bar, Overview, switcher, Search, drawer, HUDs, notifications.
- [ ] Measure p50/p95/p99, missed deadlines, CPU/GPU time, copies, idle wakeups.
- [ ] Test 60/120/144 Hz, 1×/1.5×/2×, light/dark, Full/Reduced/Minimal.
- [ ] Run a 30–60 minute soak with the new surfaces.
- [ ] Add regression thresholds and a report.
- [ ] Fix or document any surface over budget.

## Out of scope

- Optimizing the compositor renderer beyond the T-21 path.
- Claiming native numbers without native evidence.

## Design notes

Averages are not acceptance. A surface that misses p95/p99 is over budget even if the mean is fine. Idle must stay zero-wakeup. The new surfaces share the animation clock; do not add private timers. If a budget cannot be met on the dev GPU, record the hardware and mark the recommended-GPU row `OPEN`.

## Done when

- [ ] The budget table and report are committed.
- [ ] New surfaces meet the budget on the reference hardware or have an `OPEN` row.
- [ ] Idle/soak/regression checks pass.
- [ ] Docs touched: the design doc(s) this task implements and the relevant `docs/design/STATUS.md` row.
- [ ] Hand-off filled in below.
