# T220 — Naming, licensing, and third-party equivalence

## Goal

Land the generic naming map, asset provenance policy, third-party equivalence table, and the review gate before new user-facing strings or assets are added.

## Context (read first)

- `docs/design/interface-naming-and-licensing.md`
- `docs/licensing.md`, `NOTICE`, `LICENSES/`
- `scripts/check-desktop-names.sh` and the design-system icon/font assets

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Finalize the naming map for every user-facing term in the shell, Settings, and packaging.
- [ ] Decide the open questions: nearby transfer, search backend, backup UI, online accounts, accessibility depth, IME, display manager, firewall.
- [ ] Add an asset manifest (source/license) for icons, fonts, sounds, cursors, wallpapers, and illustrations.
- [ ] Extend `scripts/check-desktop-names.sh` to cover user-facing strings and package metadata.
- [ ] Update `NOTICE` and the packaging dependency markers for the chosen optional services.

## Out of scope

- Implementing the features (T225–T258).
- Copying Apple assets or code.

## Design notes

The naming map is normative for UI strings; internal code names may remain for continuity. GPL/LGPL services are separate processes or dynamically linked with notices; no GPL code in MIT files. Verify the actual package license at packaging time. The default position is the safest permissive/optional path; record final decisions in ADR 0220 or a follow-up ADR.
