# T232 — Wi-Fi, Bluetooth, Battery, Sound, Search, and Quick Settings extras

## Goal

Bring each core menu-bar extra to behavior parity: live state, menu content, actions, settings links, and absence.

## Context (read first)

- T231 registry; T230 menu bar
- `shell/menubar/WifiMenu.qml`, `BatteryMenu.qml`, `VolumeMenu.qml`, `StatusItem.qml`
- `docs/design/07-system-integration.md`

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Wi-Fi: on/off, current, known, available, join, details, settings link, scanning/error.
- [ ] Bluetooth: on/off, devices, connect/disconnect, settings link, discovery.
- [ ] Battery: percentage/time, charging/low/full, power mode, settings link.
- [ ] Sound: output device, volume, mute, settings link.
- [ ] Search: invoke Search, show/hide menu-bar item.
- [ ] Quick Settings: open panel, module state, settings link.
- [ ] Add absence/error states and keyboard/AX for each.

## Out of scope

- Implementing the underlying adapters (T225/T229).
- A second Control Center.

## Design notes

Each extra reads the same adapter state as its Settings pane; no duplicated polling. The menu content follows the reference order/labels from the map. A click that cannot act is disabled with a reason. Settings links deep-link to the correct pane. Check the glass popover material first.
