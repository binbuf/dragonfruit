# T219 — Surface/state schema and acceptance thresholds

## Goal

Freeze a machine-readable surface/state/axis schema and the acceptance thresholds so implementation and CI share one contract.

## Context (read first)

- T209–T218 artifacts
- `docs/design/evidence-and-acceptance.md`
- Existing material schema and design-system tokens

## Reference UI/UX (macOS screenshots)

- Host: **Linux**. Reference inventory: `macos-liquid-glass-review/docs/SURFACE-INVENTORY.md`; capture plan: `macos-liquid-glass-review/docs/CAPTURE-PLAN.md`.
- Local macOS captures are reference only and never ship. Record the build/axes for every artifact.

## Scope

- [ ] Define the schema for surface id, state, axes, evidence class, trigger, and acceptance metric.
- [ ] Define per-surface thresholds (material, geometry, typography, motion, latency, contrast, performance).
- [ ] Map each id to the Dragonfruit test/capture that will verify it.
- [ ] Add a validator and a CI check for the schema/manifest.
- [ ] Write `docs/design/experience-schema.md` (or extend the evidence doc) with the contract.

## Out of scope

- Implementing the surfaces (T222+).
- Changing thresholds to make a failing surface pass.

## Design notes

Thresholds are starting points from the reference campaign; a task may tighten but not silently loosen them. The schema must support `OPEN` rows. Do not encode macOS-only fields in the Dragonfruit runtime; the schema is an evidence/CI contract, not a shipping dependency.

- [ ] The thresholds are referenced by T260.
- [ ] Docs touched: the design doc(s) this task implements and the relevant `docs/design/STATUS.md` row.
