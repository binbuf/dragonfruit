## Hand-off

**Done.** `dragonfruit-power` (`services/power`) grew from the read-only T-07.4
battery item into the battery **and** power-profiles adapter. Backend only; the
pane and tile are T-15.6b.

What landed:

- `src/source.rs` — `PowerData.profiles: Option<PowerProfilesData>`; new
  `PowerProfilesData` / `PowerProfileData` raws; `PowerDeviceData` gains
  `capacity` (f64) and `charge_cycles` (i32); new `ProfileOutcome`
  (`Applied`/`Absent`/`Failed`) and the default `PowerSource::set_active_profile`
  write; `MockPower` gains `fail_writes`, `profile_writes`, and a mutating
  write.
- `src/model.rs` — `PowerProfile` (`power-saver`/`balanced`/`performance`,
  stable ids/labels/glyphs), `PowerProfilesSnapshot`, `BatteryHealth`
  (documented 80% threshold), `Battery.capacity`/`charge_cycles`, and the pure
  `PowerSnapshot::changes(previous) -> Vec<PowerChange>` event diff.
- `src/adapter.rs` — previous-snapshot diffing into `drain_changes`, plus
  `set_active_profile` (snapshot-neutral; resyncs on absence).
- `src/upower.rs` — live source now reads UPower **and**
  power-profiles-daemon, probing both `net.hadess.PowerProfiles` and
  `org.freedesktop.UPower.PowerProfiles`; implements the one write.
- Tests: 45 lib + 12 read_path, including per-daemon absence, both-absent
  `Unavailable`, profile write round-trip, and the change stream.
- Docs: `docs/design/07-system-integration.md` power section rewritten; ADR
  `docs/design/adr/0128-battery-power-profiles-adapter.md`.

Deviation from the T-07.4 note / parent track: **absence is per daemon**, not
one `Unavailable`. UPower absent hides the battery; power-profiles-daemon
absent is carried in the snapshot (`profiles: None`) and only disables the
profile control. `Unavailable` is reserved for **both** daemons unreachable.
This is the honest reading of two independent system-bus daemons (ADR 0128).

For T-15.6b: extend the `dragonfruit-system-status` `Battery` host view (or add
a sibling interface) with the profile list, active profile, degradation, and a
`SetActiveProfile` write over this adapter; the shell bridge/pane/tile then
follow the input/overview shape. The profile glyph names
(`power-saver`/`power-balanced`/`power-performance`) are the adapter's
projection and need `Icon.qml`/`StatusGlyph.qml` entries in T-15.6b. Holding a
profile is read (`holds`) but not written.
