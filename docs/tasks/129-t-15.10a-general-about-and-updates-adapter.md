## Hand-off

**Landed.** New workspace crate `dragonfruit-update-adapter`
(`services/update-adapter`), the backend adapter for General, About, and
Updates over the host stack. It projects two halves behind its own
`SystemSource` seam: the always-read host **identity** (release, kernel,
architecture, DMI model/serial, processor, memory, computer name — the
About/General rows) and the distribution **update provider** (`UpdatePhase`,
the offered list with severity, last-check time, message — the Updates half)
behind `UpdateProvider`. `AdapterId::UPDATES` (`"updates"`) joins the shared
ids. `make e2e` runs `cargo test -p dragonfruit-update-adapter`.

**Deviations from the plan.** The task says "over the host stack (distro update
provider)". The distro provider is deliberately left as a seam
(`UpdateProvider` + `MockUpdateProvider`); the concrete provider is
distro-specific and `docs/design/12-packaging.md` puts the `SystemProvider`
belonging with packaging (T-16.9/T-16.10). So `HostSystem` ships the real,
root-configurable identity read and runs with `updates: None` (a normal layered
absence) until packaging attaches a provider. This is recorded in ADR 0136 and
under `## Follow-ups` in `docs/PROGRESS.md`.

**What the next task must know.**

- **Absence is layered.** A host that answers but has no update provider is
  `Available` with `updates: None`; the About rows stay live and only the
  update controls disable. The whole adapter is `Unavailable` only when neither
  half is reachable. A present-but-unreadable provider is `Error` (visible,
  inert with the message).
- **The writes are `check`/`install`/`reboot`** on `UpdateAdapter`, one
  request each, returning `Applied`/`Absent`/`Failed`; they invent no snapshot,
  so the host re-reads after the provider pushes.
- **Do not add a package manager here.** Attach a `Box<dyn UpdateProvider>` to
  `HostSystem` (or have the bridge host read one).
- **T-15.10b** adds the Settings `General` pane (About + Software Update) and
  the Control Center `Software Update` tile. Per the T-15.9b note the Control
  Center panel is at the nested-output height ceiling (360×1160 in a 1920×1200
  output); a new tile needs a scrolling panel or a taller output.
- The `AdapterId::UPDATES` spelling is `"updates"`, not `"general"`.
