  `hot-corners`, `tablet-pen`, `non-us-layout`), `SeatInventory`,
  `Coverage::{Device, Headless, Gap(NoDevice|NoSeat)}`, `InputValidation::
  classify(seat_owned, inventory)` with `marker()`/`lines()`, and
  `layout_keysym_for_evdev(layout, evdev)` which compiles the pinned RMLVO path
  with an explicit layout. Re-exported from `compositor/src/lib.rs`.
- **`compositor/tests/input_validation.rs`** (new, in `make e2e`; 6 tests) —
  pins the six ids, the full-seat `READY` result, the no-seat `headless`
  coverage for the router classes, the pen gap (`no-device`/`no-seat`), the
  one-line markers, and the German (QWERTZ) y/z swap.
- **`scripts/input-validation.sh`** + **`scripts/input-validation-probe.py`**
  (new) + **`make input-validation`** — derives seat ownership from the T-03.2

### The matrix on this host

`make input-validation` prints `Input validation: OPEN (1 gap: tablet-pen)`.
`mouse`, `keyboard`, `touchpad-gestures`, `hot-corners`, and `non-us-layout`
are `headless` (the compositor input router is exercised by the
libinput-equivalent synthetic harness; the German layout is exercised by the
new test); `tablet-pen` is a `gap (no-device)` because the synthetic wire
format has no pressure axis and no tablet is attached. Real `device`
confirmation needs a free seat.

### Deviations

- Real-device validation is **not** performed; the unit is marked open with a
  committed matrix, not silently skipped. This is the task's explicit
  hardware-unavailable branch.
- I did **not** run the logind/libseat path (it would steal the live host
  session's seat); seat ownership is inferred from the T-03.2 `libdrm` master
  probe, the same non-disruptive proxy.
- The `device` vs `headless` split is the model's honesty seam: a synthetic
  pass never stands in for a real pen, which is why `tablet-pen` can never be
  `headless`.
