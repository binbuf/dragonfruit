## Goal

Backend adapter for Sound and routing over the host stack (PipeWire/WirePlumber), with state, events, and absent-daemon behavior.

## Scope

- Adapter over the host stack (reuse, never reimplement).
- State + events + absent-daemon behavior, unit-tested.

## Explicitly deferred

## Acceptance (agent-completable)

## Test plan

## Hand-off

**Landed.** The existing `dragonfruit-audio` crate (T-07.3, ADR 0028) now
covers input devices and default-device routing, still over WirePlumber's
`pw-dump`/`wpctl` behind the `AudioSource` seam. Additive public surface:
`SourceData`, `Source`, `AudioData::{default_source,sources}`,
`AudioSnapshot::{sources,default_source}`, `AudioSnapshot::default_source_device`
/`default_source_name`/`source_count`, and `AudioAdapter::set_default_sink(id)`
/ `set_default_source(id)`. The model resolves each default independently
(falling back to the first device in that list). Both routing writes map to
`wpctl set-default <id>`; an unknown id is `Failed`, an absent daemon is
`Absent` and hides the item.

**Deviations from the plan.** None material. Scope is backend-only as the task
says; `services/system-status`'s `audio_view` still serialises only `sinks`, so
T-15.3b must extend the bridge with the input list and the routing writes
(follow the Bluetooth/Storage `*Host` precedent, ADR 0118/0120) plus the shell
and Settings clients. Per-application stream routing is deliberately not
implemented (no consumer in T-15.3b; add behind the same seam later).

**Evidence.** `cargo test -p dragonfruit-audio` — 38 lib + 6 read_path + 6
routing_path + 6 volume_path green. `cargo test -p dragonfruit-system-status` —
green. `make e2e` — EXIT 0 (one pre-existing flaky `dragonfruit-lock-auth`
`helper` run; rerun green). `cargo fmt --all -- --check` and both crates'
`clippy -D warnings` clean. New `services/audio/tests/routing_path.rs` drives
the mock through output/input switching, no-invent, a failed id, and absence.

**Live visual check.** Backend has no surface; `bash
scripts/capture-t15-audio-routing.sh` launched the nested demo and saved
`docs/captures/t15-3a-audio-routing.png` (3840x2160). Vision confirmed the
composited desktop, menu bar, Dock, and client windows render with no blank
areas, clipping, or stray artifacts.

**Next task must know.** T-15.3b adds the pane and tile over the status bridge;
selecting a device = `set_default_*`, then volume/mute target
`@DEFAULT_AUDIO_SINK@`. New public type `Source` and `SourceData` are exported
from `dragonfruit_audio`. ADR `0121-sound-routing-adapter.md`.
