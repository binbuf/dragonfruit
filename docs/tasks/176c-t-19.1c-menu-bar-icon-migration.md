## Goal

Swap every menu-bar status mark from the original-geometry Canvas in
`shell/menubar/StatusGlyph.qml` to Phosphor glyphs, rendered as plain monochrome
marks sized for the bar (no container). Keep the Dragonfruit system-menu logo
(`design-system/components/DragonfruitLogo.qml`) exactly as it is.

## Context (read first)

- `shell/menubar/StatusGlyph.qml` — the current marks and their state variants:
  `wifi` (+ `wifi-secure`, `wifi-off`, `wifi-disabled`, `wifi-connecting`,
  `wifi-error`), `bluetooth`, `volume` / `volume-muted`, `battery` /
  `battery-charging` (with a continuous `level`), `focus`, `accessibility`,
  `control-center`, `mission-control`.
- `shell/menubar/StatusItem.qml` / `MenuBar.qml` — how a status item sizes and
  places its glyph; the migrated glyph must keep the same footprint so the bar
  layout does not shift.
- `shell/tests/tst_menubar.qml` — the existing glyph/state assertions that must
  be updated rather than deleted.
- `design-system/components/PhosphorIcon.qml` (from T-19.1a).

## Scope

- [x] Rewrite `StatusGlyph.qml` to render a Phosphor glyph per state through
      `PhosphorIcon`, keeping its public API (`name`, `color`, `size`, `level`,
      `backgroundColor`) so `StatusItem`/`MenuBar` need no changes.
- [x] Map each state to a Phosphor glyph, confirming names against the pinned
      set (indicative): `wifi-high` / `wifi-low` / `wifi-slash` / `wifi-x`;
      `bluetooth`; `speaker-high` / `speaker-x`; `moon` (focus); `person`
      (accessibility); `sliders-horizontal` (control center);
      `squares-four` (mission control).
- [x] Preserve state legibility where Phosphor has no direct variant:
      `wifi-connecting` may be `wifi-high` at reduced opacity (static under
      reduced motion) and `wifi-error` `wifi-x`; document the choices.
- [x] Battery keeps a **continuous** level: compose a Phosphor battery outline
      with the token level fill overlay and a charging bolt (or, if quantizing
      to Phosphor's fixed levels, state that explicitly in the Hand-off).
- [x] Keep the marks monochrome in `color`; do not introduce the Settings
      gradient container here.
- [x] Update `tst_menubar.qml` for the new rendering and add a state-coverage
      case (every `name` produces a non-empty mark).

## Out of scope

- The system-menu **logo** — `DragonfruitLogo.qml` is unchanged.
- Control Center / OSD glyphs that are not in the menu bar (`Icon.qml` path) →
  not this unit; migration there is a follow-up.
- Dock artwork / app icons → T-19.1d.

## Design notes

- A menu-bar glyph is a plain mark: no tile, no gradient. It should read at the
  same optical weight as today; if Phosphor's `fill` weight is too heavy at
  `Theme.controls.menuBar.iconSize`, use the `regular`/`bold` weight and record
  it.
- A state with no Phosphor equivalent must still be visually distinct.
- The existing test asserts real pixels under the headless scene graph; keep
  that property.

## Hand-off

**Done.** `shell/menubar/StatusGlyph.qml` renders every state from Phosphor
through `PhosphorIcon`; no Canvas geometry remains. Public API and slot
footprint unchanged, so `StatusItem`/`WifiMenu`/`VolumeMenu`/`BatteryMenu` and
the bar layout are untouched. `DragonfruitLogo.qml` unchanged.

**Glyph mapping** (`fill` weight unless noted):
`wifi`/`wifi-secure` → `wifi-high`; `wifi-off`/`wifi-disabled` → `wifi-slash`
(dimmed 0.4, as before); `wifi-connecting` → `wifi-high` (dimmed 0.5, static —
the original pulse replaced by a reduced-motion-safe state); `wifi-error` →
`wifi-x`; `bluetooth` → `bluetooth`; `volume` → `speaker-high`;
`volume-muted` → `speaker-x`; `focus` → `moon`; `accessibility` → `person`;
`control-center` → `sliders-horizontal`; `mission-control` → `squares-four`.

**Battery (continuous, not quantized).** `battery` composes the Phosphor
`battery-empty` outline (regular weight) with a plain `Rectangle` level fill
overlay inside the cell (Phosphor viewBox x 40..192, y 88..168, times `level`).
`battery-charging` uses Phosphor `battery-charging` (outline + bolt) with no
level fill, matching the original geometry. See ADR
`docs/design/adr/0165-menubar-phosphor-marks.md`.

**Deviations / why.** The level fill is plain token geometry rather than a
clipped `battery-full` Phosphor glyph: Qt Quick's ancestor `clip` is not applied
to a child `Shape` under the headless software scene graph the tests run on, so
a clipped full-battery glyph rendered unclipped. The outline is still Phosphor.
`backgroundColor` is retained for API compatibility but unused (Phosphor's
`moon` needs no background cut-out).

**Checks.** `ctest --test-dir build` 72/72; `make e2e` green; `make
check-phosphor`, `gen-phosphor-glyphs.py --check`, `check-design-tokens.sh`,

`i18n-extract.py --check`, `check-no-capture-grab.sh` all green. `tst_menubar`
gained state coverage for all 15 states and a battery-level continuity case.
`make check` still aborts at `check-desktop-names`, which is pre-existing red on

**Capture.** `scripts/capture-t19-menubar-phosphor.sh` →

**Next task must know.** `PhosphorIcon` uses `Shape.GeometryRenderer`; it does
render holes (battery outline is hollow), but ancestor `clip` does not clip a
child `Shape` under software. Do not detect marks by pixel alpha — the offscreen
grab is opaque (compare RGB against `pixel(0,0)`). Create and grab temporary
glyphs one at a time; overlapping siblings share a window grab.
