## Goal

Swap every menu-bar status mark from the original-geometry Canvas in
`shell/menubar/StatusGlyph.qml` to Phosphor glyphs, rendered as plain monochrome
marks sized for the bar (no container). Keep the Dragonfruit system-menu logo
(`design-system/components/DragonfruitLogo.qml`) exactly as it is.

## Context (read first)

- `shell/menubar/StatusGlyph.qml` — the current marks and their state variants:
  `wifi` (+ `wifi-secure`, `wifi-off`, `wifi-disabled`, `wifi-connecting`,
  `wifi-error`), `bluetooth`, `volume` / `volume-muted`, `battery` /
  `battery-charging` (with a continuous `level`), `focus`, `accessibility`,
  `control-center`, `mission-control`.
- `shell/menubar/StatusItem.qml` / `MenuBar.qml` — how a status item sizes and
  places its glyph; the migrated glyph must keep the same footprint so the bar
  layout does not shift.
- `shell/tests/tst_menubar.qml` — the existing glyph/state assertions that must
  be updated rather than deleted.
- `design-system/components/PhosphorIcon.qml` (from T-19.1a).

## Scope

- [ ] Rewrite `StatusGlyph.qml` to render a Phosphor glyph per state through
      `PhosphorIcon`, keeping its public API (`name`, `color`, `size`, `level`,
      `backgroundColor`) so `StatusItem`/`MenuBar` need no changes.
- [ ] Map each state to a Phosphor glyph, confirming names against the pinned
      set (indicative): `wifi-high` / `wifi-low` / `wifi-slash` / `wifi-x`;
      `bluetooth`; `speaker-high` / `speaker-x`; `moon` (focus); `person`
      (accessibility); `sliders-horizontal` (control center);
      `squares-four` (mission control).
- [ ] Preserve state legibility where Phosphor has no direct variant:
      `wifi-connecting` may be `wifi-high` at reduced opacity (static under
      reduced motion) and `wifi-error` `wifi-x`; document the choices.
- [ ] Battery keeps a **continuous** level: compose a Phosphor battery outline
      with the token level fill overlay and a charging bolt (or, if quantizing
      to Phosphor's fixed levels, state that explicitly in the Hand-off).
- [ ] Keep the marks monochrome in `color`; do not introduce the Settings
      gradient container here.
- [ ] Update `tst_menubar.qml` for the new rendering and add a state-coverage
      case (every `name` produces a non-empty mark).

## Out of scope

- The system-menu **logo** — `DragonfruitLogo.qml` is unchanged.
- Control Center / OSD glyphs that are not in the menu bar (`Icon.qml` path) →
  not this unit; migration there is a follow-up.
- Dock artwork / app icons → T-19.1d.

## Design notes

- A menu-bar glyph is a plain mark: no tile, no gradient. It should read at the
  same optical weight as today; if Phosphor's `fill` weight is too heavy at
  `Theme.controls.menuBar.iconSize`, use the `regular`/`bold` weight and record
  it.
- A state with no Phosphor equivalent must still be visually distinct.
- The existing test asserts real pixels under the headless scene graph; keep
  that property.
