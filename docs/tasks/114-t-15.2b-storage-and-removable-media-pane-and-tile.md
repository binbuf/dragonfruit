## Hand-off

**State: done.** The Storage pane and Control Center tile ship as one unit over
a fourth interface on the existing `dragonfruit-system-status` bridge host
(ADR 0120). The pane applies live (mount/unmount/eject through the adapter),
the tile reflects state and writes it, and both absence cases are documented
and tested.

Decisions / deviations:

- **Top-level `Storage` pane, not under `General`.** The reference puts Storage
  in `General > Storage`, but `General` has not shipped (T-15.10); a top-level
  row keeps the no-half-panes rule without gating Storage behind a later task.
  ADR 0120 records it; the row can move into General when it lands.
- **Fourth interface on the bridge host, not a second service.** Matches the
  Bluetooth pane/tile decision (ADR 0118).
- **Settings link is a T-16 entry point** (logs).
- **A compact tile.** The Control Center surface is a fixed 360x780 and the
  content must fit (`tst_controlcenter` asserts it); the Storage tile shows one
  compact row per volume plus the Settings link.
- **The Eject fixture case runs last** (`test_zz_eject…`): the mock cannot
  restore an ejected drive, so it must not precede the cases that need it.

Live visual check: `bash scripts/capture-t15-storage-pane.sh` on the host
