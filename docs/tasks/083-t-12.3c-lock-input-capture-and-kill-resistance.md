## Goal

Capture all input while locked and keep the session locked if the lock UI dies.

## Scope

- Input capture while locked.
- Kill-resistance: killing the lock UI does not unlock.

## Explicitly deferred

- None.

## Acceptance (agent-completable)

- [ ] No input reaches clients while locked; killing the UI leaves the session locked.

## Test plan

- Headless: synthetic input is swallowed; kill test stays locked.

## Hand-off

What landed (T-12.3c):

- **Compositor** — `compositor/src/lock.rs`: `LockModel::input_surface`
  (first live lock surface) and `is_lock_surface`; `compositor/src/input.rs`:
  `route_locked_keyboard` focuses the lock surface and forwards keys with no
  shortcut filter, while pointer/touch/gesture stay dropped. `state.rs`
  `new_surface` focuses the lock surface; `unlock` clears focus. The
  `ext_session_lock_manager_v1` request is gated on the T-07 launch-token
  trust model, so only the trusted shell can lock (an untrusted request is
  refused with `finished`).
- **Synthetic harness** — `query lock` reports
  `lock locked=<0|1> surfaces=<n> lock-focus=<0|1>`.
- **Shell** — `ShellProtocol::lockKeyEvent(key, pressed, shift)` (lock-surface
  keys never reach the chrome), `ShellController::onLockKeyEvent` filling a
  private password buffer (Escape clears, Backspace chops, Return submits via
  the existing `submitLockPassword`, characters mask), and a bullet mask in
  `shell/lock/LockScreen.qml` (`passwordLength`). `shell/src/lockinput.{h,cpp}`
  is the pure US/ASCII evdev mapping.
- **Tests** — `compositor/tests/session_lock_conformance.rs` 3/3 (covers every
  output; untrusted client cannot lock; locked input reaches the lock surface
  and the session stays locked after the lock client's socket is closed);
  `lock::tests` 4/4; `shell/tests/tst_lockinput.cpp` 4/4; `tst_lock.qml` mask.
- **Docs** — ADR 0069; `11-session-and-dev-workflow.md` lock section.

Deviations / gotchas for later tasks:

- **US/ASCII password layout only.** The shell is not an xkb client (it closes
  the compositor keymap fd), so `lockinput.cpp` is a fixed table. Layout-
  accurate typing needs an xkb state in the shell (T-15/T-16).
- **No dead-lock-UI recovery.** Killing the shell keeps the session locked and
  inputless, but Smithay's `SessionLockManagerState.locked_outputs` is not
  cleared, so a restarted shell cannot relock the same outputs in-session. The
  restart/kill matrix (T-12.5b) and the session manager own this.
- **`query lock`** is the external kill-resistance check; it never mutates the
  lock.

- T-12.4 adds idle.
