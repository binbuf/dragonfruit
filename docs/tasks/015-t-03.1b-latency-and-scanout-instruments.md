## Goal

An input-to-photon latency instrument for nested runs and a direct-scanout counter template the DRM rail can reuse.

## Scope

- Input-to-photon latency instrument (nested).
- Direct-scanout counter template and documentation for the DRM rail.
- Record raw numbers and an honest pass/fail in PROGRESS.md.

## Explicitly deferred

- On-hardware measurement (T-03.4).

## Acceptance (agent-completable)

- [ ] Latency numbers recorded for nested; template documented and unit-tested against the counters.

## Test plan

- Headless: latency instrument emits a sample; counter template reads `DfState.stats`.

## Hand-off

**Landed.** The input-to-photon latency instrument and the direct-scanout
counter template are in place, and raw nested numbers are recorded.

- **Nested latency** (`docs/captures/t03-latency-nested.txt`, from
  `bash scripts/latency-trace.sh` / `make latency-trace`, host Wayland
  session, nested backend 60 Hz): n=50 samples, min=3501 us, median=13878 us,
  p95=15223 us, max=15853 us; frame budget = 16666 us; verdict **pass** (max
  under one 60 Hz frame). All 50 injections produced a credited sample;
  skipped(no-damage)=0, dropped(stale)=0.
- **Headless** (`compositor/tests/latency_trace.rs`, part of `make e2e`):
  one sample of 102 us emitted by Ctrl+Up through the real input router,
  within one frame; `direct_scanouts` flat at 0 and the scanout template's
  `considered` = rendered + skipped; flat again while idle.

What landed:

- **`compositor/src/instrument.rs`** (new) — `LatencyInstrument` (earliest
  input per presented frame, 250 ms stale guard, bounded recent ring,
  `within_one_frame`, `summary`) and `ScanoutCounter` (the DRM-rail template:
  `read(&RenderStats)`, `advanced_since`, `engaged_since`, `report`) with 5
  unit tests.
- **`compositor/src/state.rs`** — `RenderStats.latency`; `dump_stats`
  appends `latency_us_last`/`latency_us_max`/`latency_samples`/
  `latency_dropped` to the render-stats line (after `client_wakeups`,
  append-only) and emits `latency stats` + `scanout stats` lines.
- **`compositor/src/input.rs`** — `process_input_event` stamps every input
  (except device hotplug) before routing.
- **`compositor/src/render.rs`** — `post_repaint` and
  `post_repaint_headless` sample the instrument on a presented frame.
- **`compositor/src/backend/drm.rs`** — `render_surface` samples on a
  presented DRM frame (same call site as the scanout counter).
- **`compositor/src/input/synthetic.rs`** — `query latency` and
  `query scanout` introspection replies; parse tests.
- **`compositor/tests/latency_trace.rs`** (new) + `Makefile` `e2e` list.
- **`scripts/latency-trace.sh`** + **`scripts/latency-probe.py`** (new) and
  `Makefile` `latency-trace` target.
- **Docs** — ADR `0010-latency-and-scanout-instruments.md`;
  `docs/design/02-compositor.md` "Input-to-photon latency and direct scanout
  (T-03.1b)"; `docs/captures/README.md`.

Commands that work (repo root; `make` sets the toolchain env):

- `cargo test -p dragonfruit-compositor` — 182 bin unit + all suites green
  (latency_trace 1/1, idle_trace 1/1, window_conformance 22/22).
- `make e2e`; `make fmt-check`; `make clippy` — green.
- `LATENCY_SAMPLES=50 bash scripts/latency-trace.sh` — needs a host Wayland
  session and the built Qt/CMake tree (not CI).

Deviations / for T-03.2/T-03.4:

- The instrument measures **input router → presented frame** (nested: winit
  submit; headless: the synthetic present), not display scanout/vblank. That
  is the compositor-controlled portion; T-03.4 should say so when it fills the
  DRM half of the template.
- The DRM call site is wired (`backend/drm.rs`) but unexercised (no hardware);
  T-03.2/T-03.4 confirm the number and the `direct_scanouts` engagement under
  a fullscreen client. The `ScanoutCounter::advanced_since`/`engaged_since`
  helpers are `#[allow(dead_code)]` until then.
- The render-stats line is append-only ([ADR 0009]); T-03.4 and T-16.11 must
  append, never reorder or rename.
- A stale input (>250 ms before a frame) is counted in `latency_dropped`, not
  sampled; a high drop count means inputs are not producing damage.
