## Hand-off

**State: done.** The text/image/uri-list round-trip matrix is proven on the
headless compositor through the existing data-device bridge. No behaviour
changed: the compositor already delegates `wl_data_device` (Smithay) and
`wlr-data-control`; T-13.5a is the conformance proof and the frozen ownership
contract. Contract in ADR
[0082](../design/adr/0082-clipboard-data-device-bridge-ownership.md).

What landed:

- **`compositor/tests/shell_protocol_conformance.rs`** — new
  `clipboard_round_trips_text_image_and_uri_list`. Two independent Wayland
  clients: the source maps a window, takes keyboard focus (via
  `xdg-activation`), offers `text/plain;charset=utf-8`, `image/png`, and
  `text/uri-list` from one `wl_data_source`, and calls `set_selection`; the
  target maps its own window, takes focus, receives the selection offer, and
  reads every payload back byte-for-byte over the offer pipe. The `TestClient`
  harness gained `source_payloads: HashMap<String, Vec<u8>>`,
  `clipboard_offer`, `clipboard_mimes`, the `wl_data_device.selection` child
  registration, and `read_pipe_to_bytes` (the drag test is unchanged).
- **No compositor code change.** Smithay's `delegate_data_device` already
  carries every MIME type; adding a second owner was explicitly avoided.
- **`docs/design/07-system-integration.md`** — a "Clipboard (T-13.5a)" section:
  one owner (`wl_data_device`), `wlr-data-control` as the manager half, MIME
  opaque, and the test name.
- **ADR 0082** — clipboard ownership and the history-manager forwarding rule.

Commands that work (repo root):

- `cargo test -p dragonfruit-compositor --test shell_protocol_conformance
  clipboard_round_trips_text_image_and_uri_list` — passes (fast, headless).
- `cargo test -p dragonfruit-compositor --test shell_protocol_conformance` —
  35/35.
- `make lint` — exit 0 (fmt, clippy, qmllint, gates; ctest 50/50).
- `make e2e` — exit 0.
- Build note: `export PKG_CONFIG_PATH=$HOME/.local/df-devroot/lib64/pkgconfig:$PKG_CONFIG_PATH`
  and `RUSTFLAGS="-L $HOME/.local/df-devroot/lib64"` (or just `make`).

Live visual check: no surface of its own (clipboard is not visual). Ran
`make demo DEMO_ARGS="--socket-name dragonfruit-t96"`, raised the nested
window with the KWin scripting D-Bus, captured with `spectacle -b -n -a`,
trimmed to the 1920x1200 output: `/tmp/opencode/t96/desktop.png`. Vision:
menu bar (`dragonfruit-settings` + File/Edit/View, clock), the Dock, the dark
wallpaper, Settings "Appearance" (Light/Dark/Auto + accent dots), the X11
demo window; no black regions or clipping.

Gotchas for later tasks:

- **`wl_data_device` selection is focus-gated.** Smithay denies `set_selection`
  from a client without keyboard focus and only pushes the offer to the focused
  client's data device. A test must activate/focus both sides; a background
  copier must use `wlr-data-control` instead.
- **`wlr-data-control` is the manager path.** It is advertised with an open
  filter and needs no focus; T-13.5b's history should observe/forward through
  it, not replace the source (ADR 0082).
- The shell's screenshot copy (T-13.3b) still goes through Qt's clipboard,
  which is the same Wayland data device when the shell runs as a Wayland
  client; T-13.5b can build on that or move to a data-control client.
- T-13.5b adds history if specified.
