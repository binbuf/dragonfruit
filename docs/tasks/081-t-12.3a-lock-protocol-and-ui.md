## Hand-off

**Landed.** `ext-session-lock-v1` is now enforced end to end and the shell is
the first-party lock UI. Contract frozen in
[ADR 0067](../design/adr/0067-session-lock-protocol-and-ui.md).

- **Compositor** — `compositor/src/lock.rs` (new): `LockModel` (one fail-secure
  `locked` flag, lock surfaces keyed by output, `covers`, focus restore) and
  `lock_render_elements`. `SessionLockHandler` (`state.rs`) enters the locked
  state and clears client keyboard focus *before* confirming, configures each
  lock surface to its output's exact size, and composites it above the cursor,
  windows, and chrome (nested + DRM). `process_input_event` drops all user input
  while locked; `activate_window_id` and `xdg-activation` refuse focus.
- **Shell** — `shell/src/shellprotocol.{h,cpp}` binds
  `ext_session_lock_manager_v1` and `wl_output`, requests the lock, and paints
  one lock surface per output. `shell/src/shellcontroller.{h,cpp}` renders the
  new `Dragonfruit.Lock` (`shell/lock/LockScreen.qml`) per configured output and
  handles the `lock-screen` input action. The upstream XML is vendored (MIT) at
  `protocols/wayland-protocols/ext-session-lock-v1.xml` and compiled by CMake.
- **Tests** — `compositor/tests/session_lock_conformance.rs` (added to
  `make e2e ... --test session_lock_conformance`): locks a headless session,
  asserts the `locked` event and a full-output configure per output, then
  unlocks and re-locks. `shell/tests/tst_lock.qml` covers the lock view and its
  a11y contract.

**Commands.** `make lint` exit 0 (40/40 ctest); `make e2e` exit 0;
`cargo test -p dragonfruit-compositor --test session_lock_conformance` 1/1;
`cargo clippy -p dragonfruit-compositor --all-targets -- -D warnings` exit 0.

**Live visual check.** `DF_LOCK_FIXTURE=3000 ./target/debug/dragonfruit dev
--demo --nested --socket-name t81-lock`, captured at
`/tmp/opencode/t81-lock.png`; vision confirms the lock screen covers the nested
output with the clock (`17:11`), date, avatar (initial of `$USER`), user name,
rounded password field ("Press Enter to unlock"), and the drawn lock glyph, no
stray artifacts. The menu bar/Dock are hidden underneath.

**Deviations / for T-12.3b.**
- The lock UI is deliberately inert: **all** input is dropped while locked, so
  the lock surface cannot yet be typed into (T-12.3c owns capture). The password
  field is a view only.
- Unlock is reachable only through `ext_session_lock_v1.unlock_and_destroy`
  (the shell's `ShellProtocol::unlockSession`); T-12.3b calls it from the PAM
  success path. There is no user-facing unlock yet.
- `ext_session_lock_manager_v1` still has an open client filter (any client may
  lock). Restricting it to the trusted shell is part of T-12.3c hardening.
- Capture/demo seam: `DF_LOCK_FIXTURE` (ms to lock) and `DF_LOCK_UNLOCK_MS`
  (ms to auto-unlock) exist only for the visual check; never set in a session.
- Permission error on unlock: the shell only destroys a *non-locked* lock
  object; a locked one is left alive so a shell crash keeps the session locked.
