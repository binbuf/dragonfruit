## Goal

The screenshot portal with Cmd+Shift+3/4 and region/window/fullscreen selection.

## Scope

- Cmd+Shift+3/4 shortcut path; region/window/fullscreen selection.

## Explicitly deferred

- Save/copy and portal-only enforcement (T-13.3b).

## Acceptance (agent-completable)

## Test plan

## Hand-off

Landed:

- **Portal `org.freedesktop.impl.portal.Screenshot` (version 2)** served at
  `/org/freedesktop/portal/desktop`; `BACKEND_INTERFACES` and
  `dragonfruit.portal` now list it. Pure model in `portal/src/screenshot.rs`
  (`CaptureMode`, `ScreenshotOptions`/`ScreenshotRequest`/`ScreenshotResponse`,
  `ScreenshotRegistry`, one-shot completion; the `uri` result normalizes
  through files-core). D-Bus object `ScreenshotPortal` in `interfaces.rs`;
  presenter seam on `org.dragonfruit.Portal1`: `ScreenshotOpened`,
  `CompleteScreenshot(handle, uri)`, `CancelScreenshot(handle)`,
  `PendingScreenshots`.
- **The `mode` option** is a Dragonfruit extension (`fullscreen`/`region`/
  `window`); absent, the mode is `fullscreen` (or `region` when `interactive`).
- **Selection UI**: `shell/screenshot/SelectionOverlay.qml` (full-output scrim,
  mode badge, region drag with live dimensions, window crosshair, Esc/Return)
  and `shell/src/screenshotbridge.{h,cpp}` (the presenter client; `begin`,
  `beginLocal`, `accept`, `complete`, `cancel`). `ShellProtocol` gained the
  full-output `screenshot` overlay surface plus pointer/keyboard routing;
  `ShellController` wires it and `DF_SCREENSHOT_FIXTURE=<mode>`.
- **Shortcut**: the compositor now splits Cmd+Shift+3
  (`InputAction::Screenshot`) from Cmd+Shift+4 (`InputAction::ScreenshotRegion`);
  the shell handles `screenshot` -> fullscreen and `screenshot-region` ->
  region.

Deviations / boundary:

- **The actual framebuffer grab and file write are T-13.3b.** The shell emits
  `captureRequested(mode, x, y, w, h)`; T-13.3b turns it into a saved image and
  calls `ScreenshotBridge::complete(uri)`. Until then a portal request stays
  with the presenter seam and the desktop shortcut just closes the overlay.
  `portal/tests/screenshot.rs` proves each mode's round trip with a presenter
  that supplies the URI (the task's "each selection mode produces a capture
  through the portal"). ADR 0078 records the decision.
- Window mode has no window geometry (the shell is not given window rects), so
  a click emits the pointer position for the capture seam to resolve; region
  and fullscreen are exact.
