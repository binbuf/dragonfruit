## Hand-off

**Landed.** The backend now serves the two standard interfaces at
`/org/freedesktop/portal/desktop` and advertises them in
`dragonfruit.portal` / `model::BACKEND_INTERFACES`:

- `org.freedesktop.impl.portal.Settings` (v2), `portal/src/settings.rs` +
  `portal/src/interfaces.rs::SettingsPortal`. It *projects* settingsd (never
  owns a value): a `GetAll` resync at startup, then on every `Changed` and on
  `org.dragonfruit.Settings1` name (re)appearance. Namespaces:
  `org.freedesktop.appearance` (`color-scheme` from `appearance.colorScheme`,
  `contrast`, `accent-color` when `appearance.accent` is `#rrggbb`) and
  `org.dragonfruit.desktop` (every key, read-only). No settingsd still
  answers with the appearance defaults; unknown key/namespace is a typed
  error.
- `org.freedesktop.impl.portal.GlobalShortcuts` (v1),
  `portal/src/shortcuts.rs::ShortcutRegistry` +
  `interfaces.rs::GlobalShortcuts`/`ShortcutSessionObject`. `CreateSession`
  (duplicate path refused) creates the `…portal.Session` object at the
  caller's path; `BindShortcuts` replaces/echoes and emits
  `ShortcutsChanged`; `ListShortcuts`; `Close()` drops it and emits `Closed`.
  `Activated`/`Deactivated` are raised through the diagnostic
  `ActivateShortcut`/`DeactivateShortcut` on `org.dragonfruit.Portal1`.
- Docs: ADR
  [0075](../design/adr/0075-settings-and-globalshortcuts-portals.md) and
  `07-system-integration.md` "Settings and GlobalShortcuts (T-13.1b)".

**Commands / evidence (repo root).**
`cargo test -p xdg-desktop-portal-dragonfruit` — 23 unit + 4
`session_bus` + 3 `portals`; `cargo clippy -p
xdg-desktop-portal-dragonfruit --all-targets -- -D warnings` and `cargo fmt …
-- --check` exit 0; `make lint` and `make e2e` exit 0. Live visual check: the
nested demo (`make demo`, synthetic socket) rendered the desktop, Settings
Appearance pane, menu bar, and Dock with no artifacts; capture
`/tmp/opencode/t89/t89-desktop.png` (inspected with the vision tool).

**Deviations / gotchas.**
- The compositor is not yet wired: nothing feeds bound shortcuts into
  `ShortcutEngine`, and the diagnostic bridge is the only emitter of
  `Activated`. The real compositor→portal callback is later work (T-13.7 /
  the shell bridge).
- The Settings portal reads settingsd over D-Bus (no crate dependency at
  runtime); the test-only `dragonfruit-settingsd` dev-dependency serves a
  real object beside the backend.
- `ReadAll("")` returns all namespaces; a missing key raises
  `org.freedesktop.DBus.Error.InvalidArgs`.

T-13.2a adds FileChooser (append its name to `BACKEND_INTERFACES` and
`dragonfruit.portal`).
