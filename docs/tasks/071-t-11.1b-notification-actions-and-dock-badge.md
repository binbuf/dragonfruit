## Hand-off

**State: done.** Notification actions round-trip to the originating app, the
banner is interactive with an inline action row, and the Dock's transient
launch-failure badge is replaced by a real notification. See ADR
[0057](../design/adr/0057-notification-actions-and-dock-failure-notice.md).

Gotchas for later tasks:

- **`Invoke` dismisses the banner before the app replies.** The service emits
  `ActionInvoked` and then closes with reason 2; an app that wants to keep a
  notification open must re-`Notify` with `replaces_id`.
- **A missing `Exec` is not an immediate launch failure.** `QProcess::startDetached`
  forks before `exec`, so a nonexistent program still returns true; the shell's
  Dock failure surfaces through the 8 s launch-timeout path, not synchronously.
- **`DF_DOCK_FAIL_FIXTURE` is a capture seam** (raises `org.dragonfruit.Files.desktop`
  once, 1.5 s after startup). It must not be set in a normal session.
- **The banner surface is 380x132 always**; the card is 96 or 132. Only the
  card region is clickable, so the transparent strip passes through. The
  compositor's pre-layout configure is still ignored.
- **The launch-failure banner uses the service default 5 s deadline**; a live
  capture must screenshot within that window (the seam script polls `Banners`).
- **`DF_NOTIFY_FIXTURE` still seeds one action-less banner** with a 60 s
  deadline for the demo/capture; the real D-Bus client is the default.
- **The banner is one at a time** (`NotificationModel::banner()` = newest).
  Stacking and the notification-center entry point remain T-11.2b/T-11.3a.
- **T-11.2a** owns DND/Focus policy; it consumes the existing service bit and
  suppression rule.
