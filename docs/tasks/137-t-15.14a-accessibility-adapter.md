Decisions / gotchas for T-15.14b and later:

- **The host stack is AT-SPI, not a desktop settings schema.** The adapter is
  the projection of `org.a11y.Status` only: `IsEnabled` (toolkit bridge) and
  `ScreenReaderEnabled`. Do not read a named desktop's GSettings; the desktop
  name gate forbids it and the bus is the portable contract.
- **Read-only.** `org.a11y.Status` has no setter. Durable accessibility
  preferences and compositor magnification are T-15.14b's to declare; do not
  add a write to this adapter.
- **Absence is single-layered.** `read() = Ok(None)` = no session bus or no
  `org.a11y.Bus` owner → hidden (`Unavailable`, normal). An all-off bus is
  `Available` with `present() == false` (the second hide rule). A bus that
  owns its name but cannot be read is `Error`, visible and inert.
- **`GetAll` answers `a{sv}`.** Deserialize into `HashMap<String, OwnedValue>`
  and unwrap each bool at the boundary; deserializing `a{sv}` straight into
  `HashMap<String, bool>` fails the signature check. A missing/unexpected
  property is honestly `false`.
- **`AdapterId::ACCESSIBILITY` is `"accessibility"`**, matching
  `menu.control.accessibility` and the shell status-item id. The
  `dragonfruit-system-status` bridge host will need an `Accessibility`
  interface + `DF_ACCESSIBILITY_FIXTURE` seam when T-15.14b lands (through the
  host, not by linking this crate).
- **Reference mapping (for T-15.14b).** Vision/VoiceOver maps to the screen
  reader flag here; Zoom/Display/Motion map to compositor + `settingsd`
  (`accessibility.reduceMotion` already exists); Hearing Devices/Captions/Live
  Captions/Name Recognition are Apple-only or lack a host owner and may be
  omitted per ADR 0122. The macOS rows are a reference, not a spec for this
  adapter.
- Live visual check: `bash scripts/capture-t15-accessibility-adapter.sh`
  produced `docs/captures/t15-14a-accessibility-adapter.png` (2115x1437).
  Vision found the menu bar, Dock, wallpaper, Settings window, and the demo
  client window composited with no blank areas, tearing, or ghosting; the only
  note is the usual nested-session X11 demo-window edge, not a regression.
