## Goal

A user of any distro (Fedora 44 MVP) can browse or search installed
applications from the Dock and add or remove them in two clicks, with the real
name and themed icon. The Dock stops requiring a running app or a dragged
`.desktop` file before an app can be pinned.

## Context (read first)

- `shell/dock/Dock.qml` — divider menu (`dividerMenuModel`, `~1139-1183`), app
  menu Keep/Remove items (`~1055-1095`), popover placement
  (`~1504-1637`), `stackPopover` as the overlay-popover pattern.
- `shell/dock/DockStackPopover.qml` — the closest existing popover (header,
  rows, states, Escape) to mirror.
- `shell/src/appindexclient.{h,cpp}` — `Enumerate` already parses
  `desktopId`/`name`/`iconPath`/`noDisplay`/`exec`; `m_index` is loaded once at
  startup (`shellcontroller.cpp ~291-299`).
- `shell/src/desktopentry.{h,cpp}` — `DesktopEntryIndex::entries()`,
  `isLaunchable`, and the app-index loader (the interim scan is deleted by
  T-14.7).
- `services/app-index/src/view.rs` — the record JSON shape; `index.rs`
  `desktop_dirs()` already covers `/usr/share`, `~/.local/share`, and Flatpak
  export dirs.
- `shell/src/shellcontroller.cpp` — `writeDockSetting()` (`~3582`), Keep/Remove
  handlers (`~4633-4648`), `rebuildDockEntries()` (`~3743`).
- Design-system components: `SearchField`, `ScrollView`, `FocusRing`,
  `Popover`/`Popup` (`design-system/components/`).
- T-14.1c (`102-...`) adds the app-index subscription API — use it so installs/
  uninstalls while the picker is open stay fresh.

## Current behavior (investigated, T101 era)

- The only pin paths are the entry context menu ("Keep in Dock" on a running
  app) and an external `.desktop` drop; removal is context menu or drag-out.
- There is no surface that lists installed apps; a user with an empty Dock has
  no in-product way to add anything.
- `m_index` already holds the full corpus in memory, so a picker needs no
  directory scanning and no D-Bus call while it is open (beyond a refresh).

## Scope

- [ ] Pure helper in `shell/src/` (dockcore, unit-tested): build the picker
      list from `DesktopEntryIndex::entries()` + `dock.pinned` — drop
      `noDisplay` and non-launchable records, dedupe by desktop id, sort by
      localized name (stable tiebreak by id), tag `pinned`; filter by a query
      over name + id (case-insensitive).
- [ ] `shell/dock/DockAppPicker.qml` on the Dock's overlay surface (pattern:
      `DockStackPopover`): title, `SearchField` auto-focused on open, scrollable
      rows (themed `iconPath` at ~24-32 px, name, pinned state), a disabled
      "No applications found" row for an empty filter, and an "Application
      index unavailable" state when the corpus is empty (app-index absent and
      the interim resolver deleted by T-14.7).
- [ ] Selecting a row toggles the pin through the existing `dock.pinned` write
      path; the row state and the Dock update live; pinned rows also allow
      removal from the same list. Escape and click-away close.
- [ ] Keyboard/a11y: SearchField focused on open; Up/Down move rows, Return
      toggles, Escape closes; `FocusRing`; accessible names carry name and
      "In Dock" state; roles list/listitem.
- [ ] Entry point: the divider context menu gains **Add Application…** (opens
      the picker anchored to the divider). The existing entry-menu Keep/Remove
      actions stay.
- [ ] Freshness: keep an `AppIndexClient` on the controller and reload
      `m_index` from the T-14.1c coalesced change signal; fall back to a
      one-shot re-enumerate when the picker opens if no subscription is
      available.
- [ ] Shell plumbing: a Dock `appPickerRequested` signal → controller fills the
      list and opens the picker; `appPinToggled(desktopId, pinned)` →
      `writeDockSetting` + `rebuildDockEntries`.
- [ ] Tests: `tst_dockcore` for the pure list/filter/toggle helpers;
      `tst_dock.qml` for open/close, filtering, toggle emission, empty and
      absence states, keyboard traversal; shell action wiring for the divider
      item.
- [ ] Capture `docs/captures/t14-dock-app-picker.png` (open, filtered, with a
      pinned row) and the `PROGRESS.md` note.

## Explicitly deferred

- Launchpad/app grid and the Spotlight-equivalent search pane (post-gate
  backlog).
- App uninstall, Flatpak management UI, install/update flows.
- `OnlyShowIn`/`NotShowIn`/`TryExec` filtering: app-index does not parse these
  today; record as a follow-up if Fedora's corpus makes it visible.
- Icon pickers / custom tiles.

## Design notes

- The Dock never scans `.desktop` directories itself (T-14.7 deleted the
  fallback); the picker is a consumer of app-index through `m_index`.
- Keep the picker a Dock overlay surface like the chooser/stack so it inherits
  per-output placement and popover dismissal rules.
- The pure list/filter helper has no QML or Wayland types so it is headless
  testable.
- `noDisplay` entries must never appear; `Hidden` is already folded into
  `noDisplay` by app-index.
- Toggling pins must use the single writer path (`dock.pinned` via
  settingsd/settings client) — no local parallel list.
