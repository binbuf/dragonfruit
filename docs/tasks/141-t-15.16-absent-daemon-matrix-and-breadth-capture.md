## Reference UI/UX (macOS screenshots)

Local macOS **Tahoe 26** captures only (`docs/reference/macos/` never ships; see
[14-risks.md](../design/14-risks.md)). The per-image inventories are the
`SystemSettings_*.md` notes under `docs/reference/macos/`; the shared interface
language and Linux adaptations are in
[ADR 0122](../design/adr/0122-tahoe-interface-language-across-chrome.md).
Distilled in [System_Preferences.md](../reference/System_Preferences.md).

This task ships no pane of its own. The committed breadth capture set is
compared against the Tahoe capture set pane by pane — the reference for both
the absent-daemon matrix and the breadth stills — using ADR 0122 as the
shared-language comparison target.

**Apple-only (adapt or omit):** none new; each pane applies the Apple-only
adaptations already fixed in ADR 0122 and the pane's own reference section.

## Live visual check (required)

Before reporting done, run the app and **look at it**:

- Launch the nested session (`make demo`), open the surface this task changed,
  and capture it (e.g. `spectacle -b -n -f -o /tmp/<task>.png`).
- Inspect the image: all UI/UX must be present and read as intended in the
  compositor window — layout, materials, text, and no stray artifacts.
- A green `make e2e` is necessary but **not sufficient**: the headless suites
  render no pixels, so they miss exactly this class of bug. If the task has no
  surface of its own, still launch the demo and confirm the desktop renders.
- Note the capture path and your verdict in the Hand-off.
