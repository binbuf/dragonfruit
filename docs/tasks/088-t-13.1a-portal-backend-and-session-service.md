## Goal

A real session-bus portal backend and session service that degrades when the frontend is absent.

## Scope

- Real session-bus service; session service registration.
- Graceful behavior when the portal frontend is absent.

## Explicitly deferred

- Settings and GlobalShortcuts portals (T-13.1b).

## Acceptance (agent-completable)

- [x] Backend registers; absence of the frontend is graceful.

## Test plan

- Headless: backend registers on a private bus; absent-frontend path.

## Hand-off

**State: done.** `portal/` is a real session-bus portal backend and its
registration, with the frontend-absent path proven on a private bus.
Contract frozen in ADR
[0074](../design/adr/0074-portal-backend-registration-and-frontend-degradation.md).

What landed:

- **`portal/src/`** (new lib + bin) — `model` (pure identity, advertised
  interfaces, `FrontendPresence`/`FrontendTracker`), `data` (the three
  discoverability files + parsers + `install_into`), `dbus` (the
  `org.dragonfruit.Portal1` service, `probe_frontend`, the live
  `NameOwnerChanged` watch, `serve(address)`/`run()`).
- **Identity** — owns `org.freedesktop.impl.portal.desktop.dragonfruit`,
  serves `/org/freedesktop/portal/desktop`. Backend name `dragonfruit`.
- **`portal/data/`** (new) — `dragonfruit.portal`,
  `dragonfruit-portals.conf` (`default=dragonfruit;gtk`),
  `org.freedesktop.impl.portal.desktop.dragonfruit.service`; installed by
  `portal::data::install_into(prefix)` (packaging T-16) and by
  `xdg-desktop-portal-dragonfruit --install-data PREFIX`.
- **Degradation** — the frontend is only observed (startup probe + live
  `NameOwnerChanged`), never required; `org.dragonfruit.Portal1` reports
  `present`/`absent`/`unknown`. A missing frontend never blocks startup.
- **Binary flags** — `--print-interfaces`, `--print-identity`,
  `--check-frontend` (always exits 0), `--install-data PREFIX`.
- **Tests** — `portal/src` 11 unit; `portal/tests/session_bus.rs` 4
  integration on a private `dbus-daemon` (register, absent, present-at-start,
  live appear/disappear). Added to `make e2e`.
- **Docs** — ADR 0074; `07-system-integration.md` "The backend service and
  its registration (T-13.1a)".

Commands that work (repo root):

- `cargo test -p xdg-desktop-portal-dragonfruit` — 11 unit + 4 `session_bus`.
- `cargo clippy -p xdg-desktop-portal-dragonfruit --all-targets -- -D warnings`,
  `cargo fmt -p xdg-desktop-portal-dragonfruit -- --check` — exit 0.
- `make e2e`, `make lint` — exit 0.

Live check: nested demo (`make demo`) still renders the desktop with no
artifacts; the T-13.1a change adds no surface of its own, so this is a
regression check. Capture: `/tmp/opencode/t88-demo.png`.

Gotchas for later tasks:

- **`BACKEND_INTERFACES` is empty and `dragonfruit.portal` has an empty
  `Interfaces=`.** Every later T-13 task adds its interface there; the unit
  test `the_portal_descriptor_names_the_backend_and_agrees_with_the_model`
  keeps the descriptor and the served set in lockstep, so update both.
- **Standard interface names are `org.freedesktop.impl.portal.*`**, not
  `org.dragonfruit.*`; `df_ipc::is_valid_dbus_name` applies only to the
  diagnostic `org.dragonfruit.Portal1`.
- **The diagnostic object is served at the standard path**
  `/org/freedesktop/portal/desktop`; later interfaces are added to the same
  path with `object_server().at(...)`/`serve_at`.
- **No production session wiring of the data files yet** — packaging (T-16)
  calls `install_into`; `portals.conf` uses `gtk` as the generic fallback.
- T-13.1b adds the first portals (Settings, GlobalShortcuts).
