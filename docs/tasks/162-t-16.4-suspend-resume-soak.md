### Changes

- `compositor/tests/suspend_resume_conformance.rs` — new
  `one_hundred_suspend_resume_cycles_leak_no_state`: one headless compositor
  session, one live Wayland client, 100 `suspend`/`resume` round trips. Each
  cycle asserts `suspended=1/0`, `outputs=1`, `windows=1`, and a counter that
  advances by exactly one; after cycle 100 the client connection round-trips
  and input routes; a clean `SIGTERM` then asserts the socket, lock, both
  launch tokens, and the Xwayland `DISPLAY` file are gone. Already in
  `make e2e`.
- `compositor/tests/common/mod.rs` — new `compositor_artifacts(socket)` (the
  one leak list); `cleanup_compositor_artifacts` now loops over it.
- `services/session/tests/suspend.rs` — new
  `one_hundred_cycles_keep_the_supervised_session_alive`: 100 cycles through
  the real `Supervisor` + `MockSuspend`, one platform request per cycle, same
  child pid, zero restarts.
- `scripts/t16-suspend-resume-soak.sh` + `make t16-suspend-resume-soak` (new) —
  runs both suites under an isolated `XDG_RUNTIME_DIR` (asserted empty),
  probes logind, and writes `docs/captures/t16-suspend-resume-soak.txt`.
- `docs/design/adr/0181-t16-suspend-resume-soak.md` (new);
  `docs/design/11-session-and-dev-workflow.md` new "The suspend/resume soak
  (T-16.4)" section; `docs/captures/README.md`.
- `docs/captures/t16-suspend-resume-soak.{txt,md,png}` (new).

### Deviations / remaining work

- The real 100-sleep soak (logind actually suspending the machine 100 times,
  then checking output/input/client recovery on each wake) is **OPEN**: it
  would sleep the developer's own session, and the production logind
  `SuspendBackend` is not yet wired. The hardware rail (T-159…T-161, T-16 VM
  matrix) owns it; `make t16-suspend-resume-soak` on a disposable machine is
  the replacement path. Hibernate stays deferred per the task.
- T-16.5 covers drivers.
