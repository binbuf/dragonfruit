## Goal

Radius-token clipping for chrome, SSD titlebars, and floating windows, matching the shadow pass.

## Scope

- Rounded corners clipped from radius tokens; no square-corner artefacts at edges.
- Applies to the same surfaces as the shadow pass.

## Explicitly deferred

- Blur (T-04.2), degrade tiers (T-04.4a).

## Acceptance (agent-completable)

- [x] Corners clip from tokens; gallery golden matches the reference.

## Test plan

- Headless: corner mask geometry asserted against tokens.

## Hand-off

**Landed.** Token-derived rounded-corner clipping for the surfaces the
compositor draws:

- `compositor/src/window/corner.rs` (new) — `CornerMask`
  (`window()`/`titlebar()`), `RoundedCorners` (`All`/`Top`/`Bottom`),
  `rounded_rect_spans` (non-overlapping horizontal spans; the flat-renderer
  round), `corner_squares` (the four radius squares), and the token consts
  `WINDOW_RADIUS`/`TITLEBAR_RADIUS`. 7 unit tests assert the span tiling, the
  subset-area, the cutout squares, and the token values headless.
- `compositor/src/window/decoration.rs` — the SSD titlebar fill is now
  `CornerMask::titlebar()` spans: top corners rounded to
  `component.titlebar.cornerRadius`, bottom edge square (matches the QML
  `TitleBar` exactly).
- `compositor/src/window/shadow.rs` — `ShadowSpec.radius` (window token) and
  `ShadowLayer.radius = window.radius + blur * spread`; `shadow_elements`
  emits rounded spans per layer, matching `Shadow.qml`'s per-layer `radius`.
- `compositor/src/window/mod.rs` — exports.
- Docs: `docs/design/02-compositor.md` "Rounded-corner clipping (T-04.1b)",
  `docs/design/05-window-decorations.md`, and
  **ADR 0012-rounded-corner-mask.md**.

**Deviations.** A third-party client surface's own pixels are *not* split per
window. Smithay owns those render elements and keys them by `Id` for
presentation feedback; cropping a surface into many `CropRenderElement`s
duplicates that id and risks the frame-callback/direct-scanout paths. The
reusable scene-transform pass (T-04.3, whose scope is exactly scale/translate/
**clip**) owns live-surface clipping and consumes `CornerMask`. First-party QML
windows already round themselves. Third-party windows therefore keep square
*client* bottom corners for now; their compositor chrome and shadow are
rounded. Recorded in ADR 0012.

**Verified.** `cargo test -p dragonfruit-compositor --bin dragonfruit-compositor`
(197 unit tests) and `make e2e` (all suites: window_conformance 22/22,
latency_trace, idle_trace, etc.) green; `make qml-test` 15/15;
`./scripts/check-gallery-snapshots.py --strict` 66/66 (QML untouched);
`make clippy`, `make fmt-check`, `make check-tokens`, `make check-design-tokens`
green.
