## Goal

Sample `source`/`fit`, render per Space, and slide the wallpaper with the Space during a switch.

## Scope

- Image wallpaper with fit; no image configured → current color behavior.
- Large images cached and scaled without per-frame decode.

## Explicitly deferred

- Per-output wallpaper animation polish (T-16).

## Acceptance (agent-completable)

- [x] The wallpaper image moves with its Space; the color fallback still works.

## Test plan

- Headless wallpaper sampling unit tests; nested capture.

## Hand-off

**State: done.** Image wallpapers decode once into a cached memory buffer and
render per Space; a workspace switch slides the outgoing and incoming Spaces'
wallpapers with the live windows. No image configured (or an undecodable source)
keeps the solid color behavior.

What landed:

- **`compositor/src/wallpaper.rs`** (new) — `sample_wallpaper` (pure
  source/fit mapping for fill/fit/stretch/center), `WallpaperCache` (decodes a
  `source` once with the `image` crate into a Smithay `MemoryRenderBuffer`,
  caches misses too), `slide_offset`/`slide_slots` (the per-Space slide, shared
  with `apply_overview_scene`), and `WallpaperSlot`. 8 unit tests.
- **`compositor/src/render.rs`** — `WallpaperRenderElement` (`Image`/`Solid`)
  and `wallpaper_render_elements`: builds the image sampled to its fitted dest
  plus a solid fallback, appended at the **bottom** of each backend's element
  list. One effect seam; no second transform.
- **`compositor/src/state.rs`** — `wallpaper_cache` field, `wallpaper_slide`,
  `wallpaper_slots`; `apply_overview_scene` now uses the shared `slide_offset`.
- **`compositor/src/backend/{nested,drm}.rs`** — added
  `Wallpaper=WallpaperRenderElement<R>` and appended the wallpaper last.
- **`compositor/src/input/synthetic.rs`** — `query wallpaper` (slide
  direction/progress + one `wallpaper slot` line per drawn Space) and its
  parser test.
- **`compositor/tests/window_conformance.rs`** — new
  `wallpaper_follows_the_active_space_and_slides_with_it`: at rest one slot
  (color fallback), mid 3-finger swipe two slots with opposite offsets, cancel
  returns to rest.
- **Dependency** — `image = 0.25.10` (`png` + `jpeg` only) added to the
  workspace deps.
- **Docs** — `02-compositor.md` "Image wallpaper and the per-Space slide
  (T-05.4)", `03-workspaces.md` wallpaper bullet, new ADR
  `0019-image-wallpaper-decode-and-slide.md`.

Deviations / deferred:

- **No nested capture committed.** The capture/review of the live slide is
  T-05.6's package (as the T-05.3 session also noted); this session verifies the
  slide headlessly through `query wallpaper` + the conformance test. The nested
  path renders the same elements (compiles; not run this session).
- **`set_wallpaper` from the shell does not invalidate the cache.** A changed
  file at the same path needs `WallpaperCache::clear()` (T-08/T-16 picks this
  up). The cache is per source path.
- Per-output wallpaper animation polish and multi-monitor edges remain T-16.

Gotchas for later tasks:

- **One element seam**: `render::wallpaper_render_elements` +
  `WallpaperRenderElement`. Do not add a second wallpaper transform; the slide
  reuses `wallpaper::slide_offset`.
- The wallpaper list is front-to-back and the wallpaper must stay **last**
  (bottom-most). Appending it before the shadows/chrome would cover windows.
- The base clear color is still `DfState::wallpaper_color_for` (the active
  Space's fallback); the solid element duplicates it and covers the neighbor's
  letterbox during a slide.
- An image is drawn with `Fourcc::Abgr8888` from `to_rgba8()` bytes; keep that
  pairing if you touch `decode`.

- T-05.5 reuses the pipeline for Desktop Reveal.
