## Hand-off

**State: done.** A new workspace crate `dragonfruit-overview` (`services/overview`)
is the Mission Control and hot corners adapter. Mission Control and hot corners
are compositor-native (no external daemon): the compositor detects corners and
owns the one overview machine, the shell mirrors both over the private
`df_toplevel_manager` bridge. The adapter is the **projection** of that path —
it never re-detects a corner or re-runs a transition. It implements the T-07
contract behind a `MissionControlSource` seam with a `MockMissionControl`
(CI path), reports state and two event streams, and treats a missing bridge as
a normal hidden state. Backend only — the pane and tile are T-15.5b.

Decisions / gotchas for T-15.5b:

- **No live source ships here.** The production source is the shell's
  `df_toplevel_manager` client, which is C++. T-15.5b wires it through the
  status bridge host (the `*Host`/`*Client` precedent) and adds the hot-corner
  assignment settings keys the pane writes. Until then the mock is the tested
  path; the seam is the one the bridge fills.
- **The adapter has no write method.** Runtime state is the compositor's one
  machine; configuration is settingsd-owned and compositor-applied. Applying an
  assignment needs an append-only compositor-policy request, not an adapter
  write (ADR 0126).
- **`HotCornerAction::id()` is the cross-layer spelling** (`mission-control`,
  `notification-center`, `desktop-reveal`, `lock-screen`, `none`) — use it for
  the settings key values and the wire so the pane's popup maps straight on.
- **Absence is one rule** (no second `present()` hide): a missing bridge is
  `Unavailable` (hidden); a present-but-unreadable bridge is `Error` (visible
  inert). No hardware/daemon blocks startup.
