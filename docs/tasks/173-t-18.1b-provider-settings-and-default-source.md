## Goal

Add the additive wallpaper-provider keys, wire the provider's wallpaper API into
System Settings and the shell, and make the shell's effective wallpaper source
prefer the user's choice, then the shipped default, with full restart/resync and
absence behavior.

## Context (read first)

- `services/settingsd/src/schema.rs` — the authoritative key declaration and
  `SCHEMA_VERSION`; every new key is additive within the `1` series.
- `docs/settings-keys.md` — the mirrored table kept in lockstep by
  `services/settingsd/tests/schema_doc.rs`.
- `shell/src/wallpaperpolicy.*` — the pure key → `df_workspace.set_wallpaper`
  mapping (T-09.3).
- `shell/src/shellcontroller.cpp` — the forwarder that consumes the policy.
- `apps/settings/SettingsBridge.*` — the Settings app's one settings client
  (ADR 0036); the provider data reaches QML through it, next to the existing
  `wallpaperPresets` / `wallpaperChooserAvailable` properties.
- ADRs [0055](../design/adr/0055-online-wallpaper-content-provider.md) /
  [0094](../design/adr/0094-bundled-default-wallpaper-and-lazy-cache.md) — keys,
  precedence, and ownership.

## Scope

**Settings keys (additive; bump `SCHEMA_VERSION`, set `since`)**

- [ ] `wallpaper.provider` (s, `wikimedia`), `wallpaper.providerAutoFetch`
      (b, true), `wallpaper.providerLastFetch` (x, 0), `wallpaper.providerSource`
      (s, empty; owner `wallpaperd`).
- [ ] `wallpaper.builtinDefault` (s, empty; owner `wallpaperd`) — the resolved
      path of the shipped original `Default.jpg`.
- [ ] Keep `wallpaper.source` as the user override, owner `apps/settings`
      (unchanged). The provider never writes it.

**Effective source (shipped default wins over the fetched default)**

- [ ] Extend `wallpaperpolicy` with the precedence: `wallpaper.source` when
      non-empty, otherwise `wallpaper.builtinDefault` (the shipped default),
      otherwise `wallpaper.providerSource` (fetched fallback), otherwise the
      Space's solid color. Keep fit/show-on-all-Spaces behavior identical.
- [ ] The provider publishes `builtinDefault` (resolved shipped asset) and
      `providerSource` (the deterministic Nature entry) separately; nothing
      overwrites a user choice.
- [ ] Shell subscribes to both `settingsd` and the provider's D-Bus properties;
      if `settingsd` is absent, fall back to the provider properties directly so
      the shipped default still renders; if the provider is absent, the shipped
      default and the built-in/custom rows still work.

**Wallpaper API wiring (System Settings and other consumers)**

- [ ] `SettingsBridge` gains provider properties (e.g. `providerItems`,
      `providerStatus`, `providerDefault`, `wallpaperBuiltinDefault`) subscribed
      to `org.dragonfruit.Wallpaper1` properties/signals, mirroring the existing
      `wallpaperPresets` pattern. Panes never touch D-Bus (ADR 0036).
- [ ] Expose the provider `Preload` request through the bridge so the Wallpaper
      pane can ask for an eager load on open (the call site itself is T-18.2).
- [ ] Absent provider: `providerItems` is empty, the shipped default still
      resolves, and the failure is not surfaced as an error.
- [ ] Compositor, portal, and `df_workspace.set_wallpaper` are unchanged: the
      provider still resolves to a local file path.

**Restart/resync**

- [ ] Restart/resync: provider or settingsd restart leaves the other working; no
      visible reset; the shipped default holds across restarts.

## Design notes

- Never overwrite a non-empty `wallpaper.source`; a user choice is sticky.
- Precedence is deliberately shipped-default-first: the out-of-box background
  must not depend on the network (ADR 0094).
- New keys are additive only: no rename/removal; existing keys and their
  defaults are frozen.
- Keep the pure mapping in `wallpaperpolicy` so it stays unit-testable without
  a bus.

## Acceptance (agent-completable)

- [ ] `wallpaperpolicy` tests cover user-choice-wins,

- [ ] `SettingsBridge` exposes the provider catalogue and survives the provider

      and no key is lost; with settingsd absent, the provider default still
      reaches the compositor.
