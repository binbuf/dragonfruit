## Goal

Add the additive wallpaper-provider keys and make the shell's effective
wallpaper source prefer a user choice over the fetched default, with full
restart/resync and absence behavior.

## Context (read first)

- `services/settingsd/src/schema.rs` — the authoritative key declaration and
  `SCHEMA_VERSION`; every new key is additive within the `1` series.
- `docs/settings-keys.md` — the mirrored table kept in lockstep by
  `services/settingsd/tests/schema_doc.rs`.
- `shell/src/wallpaperpolicy.*` — the pure key → `df_workspace.set_wallpaper`
  mapping (T-09.3).
- `shell/src/shellcontroller.cpp` — the forwarder that consumes the policy.
- ADR [0055](../design/adr/0055-online-wallpaper-content-provider.md) — keys
  and ownership.

## Scope

- [ ] Additive settingsd keys (bump `SCHEMA_VERSION`, set `since`):
      `wallpaper.provider` (s, `wikimedia`), `wallpaper.providerAutoFetch`
      (b, true), `wallpaper.providerLastFetch` (x, 0), and
      `wallpaper.providerSource` (s, empty; owner `wallpaperd`).
- [ ] Keep `wallpaper.source` as the user override, owner `apps/settings`
      (unchanged). The provider never writes it.
- [ ] Extend `wallpaperpolicy` with an effective-source rule: use
      `wallpaper.source` when non-empty, otherwise `wallpaper.providerSource`;
      keep fit/show-on-all-Spaces behavior identical.
- [ ] Publish the resolved default: when the user has no `wallpaper.source` and
      the provider reports `DefaultSource`, the provider persists it to
      `wallpaper.providerSource` and persists `LastFetch`.
- [ ] Shell subscribes to both `settingsd` and the provider's D-Bus properties;
      if `settingsd` is absent, fall back to the provider property directly so
      the default still renders.
- [ ] Restart/resync: provider or settingsd restart leaves the other working;
      no visible reset.

## Design notes

- Never overwrite a non-empty `wallpaper.source`; a user choice is sticky.
- New keys are additive only: no rename/removal; existing keys and their
  defaults are frozen.
- Keep the pure mapping in `wallpaperpolicy` so it stays unit-testable without
  a bus.

## Acceptance (agent-completable)

- [ ] Schema doc test and settingsd key-set test pass; `--print-keys` shows the
      new owner/consumer pairs.
- [ ] `wallpaperpolicy` tests cover user-choice-wins, provider-default, and
      missing-both cases.
- [ ] With the provider absent, the desktop still renders and no key is lost;
      with settingsd absent, the provider default still reaches the compositor.
