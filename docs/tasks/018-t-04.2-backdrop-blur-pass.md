## Goal

Blur the live scene beneath translucent chrome surfaces.

## Scope

- Sample the scene under the surface's translucent regions and blur it.
- Honor client translucent regions rather than fighting them.
- Applies to menu bar, Dock, popovers (OSD later).

## Explicitly deferred

- Per-surface dmabuf feedback tranches (T-13).

## Acceptance (agent-completable)

- [x] Chrome shows backdrop blur; one effect pass per frame (no double-blur).

## Test plan

- Headless damage-rect assertion for the chrome band; nested visual capture.

## Hand-off

**State: done.** The chrome material pass exists, is token-driven, and is
guarded to one effect per frame on both real backends. The blur itself is a
**flat-tone approximation** (a token-derived stack of translucent rounded
feather layers, below the chrome Wayland surface), not a texture-sampling
gaussian: the flat solid-color renderer has no sampler/offscreen path yet.
This is the same approximation T-04.1a shipped for shadows and is documented
in [ADR 0013](../design/adr/0013-backdrop-blur-pass.md); the real sampler is
swappable behind the tokens the pass already reads.

What landed:

- **`compositor/src/window/backdrop.rs`** (new) — `MaterialRole`
  (`Chrome`/`Popup`, from `df_shell.layer`), `BackdropSpec`
  (`material.{chrome,popup}Blur`/`Opacity` + `component.{menu_bar,popup}.radius`),
  `backdrop_layers`/`backdrop_bounds`/`backdrop_elements` (rounded via
  `CornerMask`), and `BackdropPass` (the once-per-`(frame, output)` guard).
  8 unit tests: tokens per role/scheme, role-from-layer, feather containment,
  rounded union = the chrome band, scale, degenerate clamps, pass skip.
- **`compositor/src/render.rs`** — `chrome_backdrop_render_elements(state,
  output, scale)`: builds the chrome band (union of top/overlay surfaces) in
  output-local logical coords, applies the pass, emits the backdrop elements.
- **`compositor/src/state.rs`** — `DfState.material_pass: BackdropPass`,
  `render_serial: u64`, `begin_render_frame()`, and a `material stats` dump
  line (`backdrop_passes` / `backdrop_skipped`; the latter must stay 0).
- **`compositor/src/shell/mod.rs`** — `ChromeSurface.geometry` (output-local
  logical rect) so the material pass reads the band; `location` is unchanged.
- **`compositor/src/backend/nested.rs`** — `begin_render_frame()` after the
  needs-redraw check; backdrop elements appended **after** `chrome_render_elements`
  (below chrome, above the windows). **`backend/drm.rs`** — same call, wired but
  untested (no hardware); that rail's pre-existing window-before-chrome element
  order is noted inline.
- **Docs** — ADR `0013-backdrop-blur-pass.md`; `02-compositor.md` "Backdrop
  blur pass (T-04.2)"; `10-design-system.md` material-group note.

Gotchas for later tasks:

- **Tokens only.** Blur radii/opacities and the component radius come from
  `design_tokens.rs`; do not hardcode. ADR 0013 is the contract.
- The backdrop is a **flat-tone approximation**, not a live-scene sample. T-13
  (video under the bar) will fail the legacy FR-1 "live content" bar until a
  real sampler replaces `backdrop_layers`; replace the geometry, keep the
  `BackdropPass` contract.
- `BackdropPass` keys on `(render_serial, output)`; a correct backend calls
  `DfState::begin_render_frame()` once per rendered frame. Any new backend or
  render path must do the same or the guard misbehaves.
- Element order matters: backdrop elements go **after** the chrome surfaces and
  **before** the windows in the front-to-back list. Moving them before the
  chrome draws them over it.
- **`ChromeSurface.geometry`** is output-local; `chrome_surfaces` computes both
  it and `location`. The backdrop never forces a redraw, so idle stays at zero
  damage (the `shell_idle_trace` suite is green).
- The matte/feather layers never extend past the chrome band (asserted), so the
  pass does not tint window content outside the chrome.

- T-04.3 folds this pass into the reusable transform.
- T-11 consumes it for Control Center/OSD.
