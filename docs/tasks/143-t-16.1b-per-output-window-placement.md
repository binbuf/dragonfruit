## Hand-off

**Landed.** New windows open on the focused output and inside that output's
reserved zones. `DfState::focused_output()` (pointer-under-output → active
window's output → primary) is the one resolver; ordinary windows cascade over
`reserved_zones_for(name).usable(output)`; workspace assignment follows the
placement output. Both the Wayland (`map_pending_windows`) and Xwayland paths
use it. ADR 0150; `docs/design/02-compositor.md` Placement bullet updated.

**Evidence.**
- `cargo test -p dragonfruit-compositor` — all suites green; the new
  `new_windows_land_on_the_focused_output` in
  `compositor/tests/shell_protocol_conformance.rs` covers two outputs + a
  primary-pinned 28 px bar + three windows (`shell_protocol_conformance` 36 → 37).
- `cargo clippy -p dragonfruit-compositor --all-targets -- -D warnings` and
  `cargo fmt --all -- --check` — clean.
- `make e2e` — EXIT 0 (`/tmp/opencode/t143-e2e.log`).
- Live check: `/tmp/opencode/t143.png` (2115x1437), script
  `/tmp/opencode/capture-t143.sh`. Vision: menu bar, Dock, wallpaper, centered
  Settings window, and the X11 demo window composite cleanly, no artifacts.
  Single host output, so the two-output behavior is covered by the headless
  suite, not the still.

**Deviations.** Pointer-first precedence (not active-window-first) is a
deliberate choice: it matches the existing per-output-chrome pointer signal and
is the only rule that can put a first window on an empty display. Recorded in
ADR 0150. No protocol changes.

**For T-16.2 (hotplug under load).** `focused_output()` walks the live
`space.outputs()`, so a removed output is never selected and focus falls back
automatically. Assignment now matches placement, so a window placed on a
secondary display lands in that display's active Space. Reuse
`focused_output()` / `usable_geometry_for` rather than re-deriving outputs.
