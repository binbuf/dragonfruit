## Hand-off

**State: done.** The live AT-SPI audit and the keyboard-only walkthrough both
pass. What landed:

- `scripts/t16-a11y-audit.sh` + `scripts/t16-a11y-audit.py` (new;
  `make t16-a11y-audit`): launch the nested demo twice (Settings, Files) with
  `QT_LINUX_ACCESSIBILITY_ALWAYS_ON=1` and a synthetic-input socket, dump the
  live AT-SPI tree, assert every interactive node has an accessible name, and
  drive a keyboard-only walkthrough (Tab focus traversal; select a Settings
  pane from the sidebar with Down + Return) reading each move back from
  AT-SPI. Writes `docs/captures/t16-a11y-atspi.txt`; both passes report
  `RESULT: PASS`. Also captures `docs/captures/t16-a11y-desktop.png`.
- `compositor/tests/shell_protocol_conformance.rs` — new
  `keyboard_only_walkthrough_dispatches_every_system_binding` (41 tests total):
  sends every default system chord over the synthetic (libinput-equivalent)
  path and asserts the shared outbox records the matching action with a
  `keyboard` trigger. Covers workspace prev/next/activate, Mission Control,
  Desktop Reveal, app switcher (+ reverse), within-app window cycle
  (+ reverse), notification center, Dock focus/auto-hide, Control Center,
  screenshot full/region, and lock.
- `docs/design/adr/0154-atspi-and-keyboard-audit-boundary.md` (new): the
  boundary. First-party apps are live on the accessibility bus; the shell
  chrome is **not** — it renders through the offscreen QPA, which exposes no
  accessibility backend, so no `QWindow` of the shell ever registers. Shell
  chrome keeps its per-component `Accessible.*` contract (`make qml-test`) and
  its global flows are the headless binding test above.
- `docs/design/04-shell.md` (T-16.6a status), `docs/design/10-design-system.md`
  (quality-gate layering), `docs/captures/README.md` (the new capture).
