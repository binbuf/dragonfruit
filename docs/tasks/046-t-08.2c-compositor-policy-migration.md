## Hand-off

**State: done.** The compositor now consumes the settingsd motion/input policy
over the private protocol; no local settings file remains on either side. The
shell is the only forwarder from the one `SettingsClient` (ADR
[0034](../design/adr/0034-compositor-policy-via-shell-bridge.md)); the
compositor is the only applier.

What landed:

- **`protocols/dragonfruit-toplevel.xml`** — `df_toplevel_manager` is v5 with
  two additive requests: `set_motion_policy(color_scheme,
  titlebar_double_click, minimized_animation)` (strings, `allow-null`) and
  `set_input_policy(repeat_delay_ms, repeat_rate_hz, gestures_enabled,
  gesture_space_switch, gesture_mission_control)`. `set_reduced_motion` (v3)
  is unchanged.
- **`compositor/src/shell/mod.rs`** — `MANAGER_INTERFACE_VERSION = 5`; the two
  requests dispatch to the new `DfState` setters.
- **`compositor/src/state.rs`** — `set_motion_policy` (color scheme, titlebar
  double-click, `minimized_animation`) and `set_input_policy` (clamped repeat
  + gesture flags via the existing `apply_input_settings`), a
  `minimized_animation` field, and the minimize/restore collapse in
  `begin_window_motion_from`.
- **`compositor/src/window/motion.rs`** — `MinimizedAnimation`
  (`genie`/`scale`/`none`); `none` collapses, `genie` currently renders as
  `scale`.
- **`compositor/src/input/gestures.rs`** — `GestureConfig` gained `enabled`,
  `space_switch`, `mission_control` and an `admits()` gate applied in
  `update_swipe`/`update_pinch`.
- **`compositor/src/input/synthetic.rs`** — `query policy` reports the live
  scheme, titlebar double-click, minimized animation, repeat delay/rate, and
  gesture flags (the end-to-end headless observation).
- **`shell/src/compositorpolicy.{h,cpp}`** (new) — the pure `CompositorPolicy`
  view + `compositorPolicyFromValues`/`resolveCompositorColorScheme`
  (`auto` follows the host).
- **`shell/src/shellprotocol.{h,cpp}`** — `setMotionPolicy`/`setInputPolicy`
  guarded on `m_managerVersion >= 5`.
- **`shell/src/shellcontroller.{h,cpp}`** — `applyCompositorPolicy()` on
  `SettingsClient::changed`/`refreshed`, on host `colorSchemeChanged`, and once
  after authenticate; the old `setReducedMotion` call in
  `applyDockSettings` was removed (single forwarder).
- **Tests** — `compositor/tests/shell_protocol_conformance.rs::motion_and_input_policy_requests_apply_live`
  (drives v5, reads `query policy`, proves a disabled gesture family stops
  firing and re-enabling restores it); `compositor/src/input/gestures.rs::gesture_policy_gates_each_family`;
  `shell/tests/tst_compositorpolicy.cpp` (new).
- **Docs** — ADR 0034; `docs/private-protocols.md` v5 list; track doc
  `08-settingsd-live-settings.md` T-08.2c section; `02-compositor.md` scheme
  wording.

Deviations / notes for T-08.3:

- **`workspaces.count` is not in the bridge.** It is a workspace-model key, not
  motion/input, so it is out of this task's scope; nothing owns it yet.
- **`dock.minimizedAnimation=genie` renders as `scale`** (accepted; the genie
  warp is a material-pass follow-up). `none` collapses like reduced motion.
- **`dock.minimizeIntoTileIcon` is not a compositor key** (it is Dock entry
  visibility, handled by the shell), so it was not forwarded.
- T-08.3 owns restart/resync: it should re-drive `applyCompositorPolicy()` on
  the daemon reappearing (already on `refreshed`) and assert no setting is lost
  across a `kill -9`.
