## Goal

When `dock.chooserOnHover` is on, dwelling on a grouped app entry opens its
window chooser without a click, and moving the pointer along the Dock retargets
the open chooser to the newly hovered entry instead of closing and reopening.
A snapshot anchor lets the popover survive a delegate rebuild. Default off, so
the shipping macOS click contract is unchanged.

## Context (read first)

- `shell/dock/Dock.qml` — `entryHoverBegan`/`entryHoverEnded` and the Tooltip
  dwell (`showTooltip`/`hideTooltip`, tokens in `controls.tooltip`), the
  `popoverOpen` gate, `openChooser`/`closePopovers`, and the popover-rect
  headroom path. `springLoadDelay` (500 ms) is the drag spring-load dwell — a
  different interaction; use a distinct chooser dwell token.
- `shell/dock/DockWindowChooser.qml` — `entry`, `anchorItem`, `open`, and the
  `opened`/`closed` signals; T-14.7m/n added the actions and viewport.
- `docs/PROGRESS.md` T-14.7c follow-up (a): a successful pin reorder still
  resets the Repeater through the shell, so live delegates are destroyed — the
  exact failure a stable anchor must survive.
- `services/settingsd/src/schema.rs` — the `KeyGroup::Dock` keys;
  `docs/settings-keys.md`; `apps/settings/DesktopDockPane.qml`; the shell
  settings client seeds new keys.
- Reference behavior only (GPL, never copied): `PopupCoordinator.qml` in
  `~/repos/punchi-dock-remastered` opens on a 280 ms dwell, closes on a 260 ms
  delay, retargets an already-open popup to a new anchor, and uses a snapshot
  anchor (`TaskPopupAnchorProxy.qml`) that survives the delegate being rebuilt.

## Current behavior (investigated, T110 era)

- The chooser only opens on a click with more than one window; there is no
  hover path, and the open popover is anchored to the live delegate, so a
  model rebuild can orphan it (the shell rebuilds `entries` on pin changes).

## Scope

- [ ] Settings key `dock.chooserOnHover` (bool, default `false`): settingsd
      schema + persistence + `Changed` signal, `docs/settings-keys.md`, the
      shell config read, and a Desktop & Dock pane toggle. settingsd remains
      the only writer.
- [ ] Hover behavior (only when the key is on and the entry has `> 1` window):
      a dwell opens the chooser; leaving starts a close delay; the open chooser
      is suppressed by drag, resize, keyboard navigation, or another popover.
      Click still opens/activates as today.
- [ ] Retarget: while the chooser is open, dwelling on a different grouped
      entry anchors the same popover to it without a close/reopen flash;
      releasing onto an entry with `<= 1` window closes it cleanly.
- [ ] Stable anchor: a small snapshot `Item` captures the target entry's rect
      (in the popover parent's coordinates), survives the delegate's
      destruction, and re-parents to force a reposition; the chooser keeps
      using it until it closes. No new surface; it stays inside the existing
      popover buffer (ADR 0100).
- [ ] Motion: open/close/retarget use `motion.popupOpen`/`popupClose`;
      reduced motion makes them instant.
- [ ] Tests: `tst_dock.qml` for dwell-open, close delay, retarget, suppression,
      and anchor survival across a simulated entry-list rebuild/destroy;
      settingsd schema/persistence; settings-pane toggle round-trip.
- [ ] Capture `docs/captures/t14-dock-hover-chooser.png` (two entries, pointer
      between them) and the `PROGRESS.md` note.

## Explicitly deferred

- Live thumbnails / a preview protocol (ADR 0103; separate project).
- Hover-open for single-window entries (activate-on-hover is a different,
  riskier interaction).
- A user-tunable dwell duration (token owns it).
- Media/MPRIS in the popover (belongs to Control Center/menu bar first).

## Design notes

- Default **off** on purpose: macOS opens the chooser on click; hover-open is a
  deliberate opt-in that a user who wants a Plasma-style peek can enable.
- One popover at a time and one Tooltip at a time; a hover-open chooser
  suppresses the hover name label (do not stack both).
- The anchor snapshot must not allocate or resize the Dock's surface; it is a
  geometry proxy only.
- Known risk: hover-open plus retarget is the largest new interaction in this
  addendum. If it proves to need more than one session, split along the two
  behaviours — (a) dwell/retarget, (b) the stable anchor — and record the split
  in the Hand-off rather than shipping a flaky single unit.

## Hand-off

Implemented in one session; the unit was **not** split.

**Key.** `dock.chooserOnHover` (bool, default `false`) is declared in
`services/settingsd/src/schema.rs` at `SCHEMA_VERSION = 8` (`since: 8`), seeded
by `libs/settings-client/settingsclient.cpp`, read into `DockConfig.chooserOnHover`
(`shell/src/dockmodel.{h,cpp}`), pushed to the Dock QML in
`ShellController::applyDockSettings`, and toggled by `DesktopDockPane.qml`
("Open a window chooser by hovering"). Absent settingsd degrades to off.

**Dwell/delay.** Distinct tokens in `component.dock.chooser`: `hoverDwell`
280 ms (open/retarget) and `hoverCloseDelay` 260 ms (pointer leave). Neither is
user-tunable (per the task's deferred list).

**Anchor shape.** A non-visual `Item` `chooserAnchorProxy` in `Dock.qml` with
`capture(item)` (maps the live delegate's rect into Dock coordinates) and
`reposition()` (re-parents to null and back to force the chooser's anchored x/y
bindings and the arrow's `mapToItem` to re-evaluate). `chooserAnchor` is always
the proxy, never the delegate; `openChooser`/`retargetChooser`/`refreshChooserAfterProjection`
re-capture it, so a pin-reorder Repeater rebuild cannot orphan the popover.
Click-opened choosers set `chooserHoverOpened = false` and behave as before.

**Hover/retarget/suppression.** `entryHoverBegan` diverts a grouped running
entry (`> 1` window, not minimized) to the chooser dwell, suppressing the name
label; `entryHoverEnded`/Dock-leave restart the close delay; a second dwell
retargets the same popover. `closePopovers` (drag, resize, another popover) and
`beginKeyboardNavigation` stop it. `handleEntryTap` cancels a pending dwell.

**Tests.** `shell/tests/tst_dock.qml` T-14.7p block: off-by-default, dwell-open,
close delay, retarget, release-onto-single-window, another-popover suppression,
keyboard suppression, anchor survival across a simulated entry rebuild.
`shell/tests/tst_dockcore.cpp`: config default + override.
Settingsd `every_key_round_trips_get_set_and_change_over_the_bus` and
`schema_doc` cover persistence/docs automatically; the two Settings-pane suites
updated for the eleventh row.
