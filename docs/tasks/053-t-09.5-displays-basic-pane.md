## Reference UI/UX (macOS screenshots)

Local art direction only: the pane mirrors macOS System Settings nearly
verbatim in style, order, labels, controls, and wording. Images in
`docs/reference/macos/` (never shipped; see
[14-risks.md](../design/14-risks.md)), distilled in
[System_Preferences.md](../reference/System_Preferences.md).

Sections and rows (observed order):

- **Display preview card**: display artwork labelled `Built-in Display`, with
  an `Arrange…` button for multi-display layouts (T-16).
- **Resolution/scale list**: `Larger Text`…`Default`…`More Space` icon tiles,
  accent border on the selected tile; footer "Using a scaled resolution may
  affect performance."
- **`Brightness`**: slider with sun glyphs at both ends, plus
  `Automatically adjust brightness` toggle.
- **`True Tone`**: toggle with description (Apple-only; see below).
- **`Preset`**: color profile popup (`Apple XDR Display (P3-1600 nits)` in the
  capture).
- **`Refresh rate`**: popup (`ProMotion` in the capture).
- **Night Shift / advanced buttons**: `Night Shift…` and `Advanced…` (cropped
  from the capture).

Wave 1 maps resolution, scale, and rotation to our compositor output API
([08-settings.md](../design/08-settings.md)); rotation is not visible in the
capture. All other rows are the pane's target UI, not deferred: providers —
brightness = compositor/kernel; color = TBD; Night Shift = our night light
(decide the label at implementation); `Advanced…` opens T-15/T-16 output
controls.

Adapt or omit (Apple-only): `True Tone`; Apple display names
(`Apple XDR Display (P3-1600 nits)` → a generic profile); the
`When connected to TV` (`Ask What to Show`) row is Apple TV/AirPlay.

## Hand-off

The Displays-basic pane landed. `apps/settings/DisplaysPane.qml` ships the
`Built-in Display` preview, the five scaled-resolution tiles (`Larger Text` …
`Most Space`) over `display.scale`, and a `Rotation` `Select`
(Standard/90°/180°/270°) over `display.rotation`, all bound through the
`Settings` singleton (the T-09.1b pattern). The keys are persisted by
settingsd (schema 3: `display.scale`, `display.rotation`) and forwarded by the
shell as `df_output.set_scale` / `df_output.set_transform` (ADR 0040). The
reference pane's `Resolution/scale` list is the compositor's scaled-resolution
model, so `display.scale` reaches every announced output.

- Tests: `ctest -R "tst_settings_displays|tst_displayspolicy"` (4 + 5 cases);
  `cargo test -p dragonfruit-compositor --test shell_protocol_conformance
  handshake_chrome_and_control_conformance` asserts the `set_transform`
  round-trip (the `set_scale` round-trip was already asserted).
- Live capture (`/tmp/opencode/t53-final.sh`; real `settingsd` on the session
  bus, nested demo with `DF_SETTINGS_START_PANE=displays`, window zoomed):
  `/tmp/opencode/t53f-before.png`. Raw vision observation on a tight crop: the
  pane shows the preview, five tiles (`Larger Text`, `Large`, `Default`,
  `More Space`, `Most Space`) with `Default` selected, and `Rotation` =
  `Standard`, with no clipping or overlap.
- Deviation: the nested backend renders its host window at a fixed
  size/scale, so a live output scale/transform change is *not* faithfully
  re-rendered by the nested demo (the desktop misrenders because the damage
  tracker is fixed). The shell→compositor path is exercised live (the shell
  logs `display applied (scale=… rotation=…)`) and asserted at the protocol
  level by the conformance test; a real DRM output applies it. Nested scaling
  is a T-16 item.
- Omitted under the no-half-panes rule (no provider yet): `Brightness`,
  `Automatically adjust brightness`, `True Tone`, `Preset`, `Refresh rate`,
  `Night Shift…`, `Advanced…`, and `Arrange…` (multi-display, T-16).
  `df_output.set_mode` is available but unused: exact mode enumeration and
  per-display targeting are T-16.
