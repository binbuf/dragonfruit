## Goal

Render the reference's region structure: a hairline divider between the pinned
prefix and the temporary/recent tail of the app region, plus the divider that
separates the app region from the minimized / stack / Trash region (and the
missing divider before the stacks/Trash tail). Dividers get the reference's
oversized breathing room and near-full-height hairline, so the resting Dock
reads like `Dock.png` rather than as one undivided run of icons.

## Context (read first)

- Legacy [10-dock.md](../tasks/legacy/10-dock.md) §4 already specifies regions
  separated by divider rules:
  `[ pinned | temporary | recent ] │ [ minimized ] │ [ stacks ] [ Trash ]`.
  The current Dock emits only **one** divider entry.
- `shell/dock/Dock.qml` — `items` is
  `appEntries + dividerEntry + minimizedEntries + stackEntry + trashEntry`
  (one synthetic `dividerEntry`, `dividerWidth: 1`). `_baseline` adds a flat
  `gap` on **both** sides of every item, so a divider gets no more room than
  two icons.
- `shell/src/dockmodel.{h,cpp}` — `buildDockEntries` emits pinned, temporary,
  and `recent` entries into one `appEntries` list (recents appended last);
  `applyDockOverflow` and the droppable/non-droppable counts treat the divider
  as a single fixed item. A second boundary is a model concern, not QML-only.
- `shell/dock/DockEntry.qml` — the divider delegate: `divider.width`,
  `height: root.height * divider.heightRatio`, `divider.opacity`; the drag
  handle (`dividerHit`, T-10 §5 divider resize) rides on it.
- Reference measurements from `docs/reference/macos/Dock.png` (pt):
  - three regions, two dividers: `[10 pinned] │ [3 temporary/recent] │
    [folder + Trash]`;
  - normal icon pitch 64 pt (≈15 pt tile-edge gap); pitch across a divider
    93 pt (≈44 pt total gap, ≈22 pt each side);
  - divider 1 pt wide, ~0.78–0.93 of the plate height (shipped
    `divider.heightRatio` is 0.6).

## Current behavior (shipped after T-14.7j)

- One divider only, between the app region and the minimized/stack/Trash
  region; pinned and temporary/recent entries are visually contiguous, and the
  stacks/Trash tail has no leading divider. All spacing around the divider
  equals the icon `gap`.

## Scope

- [ ] Pure model (`dockmodel`): expose the region boundaries explicitly (e.g.
      a `divider` marker between the pinned prefix and the temporary/recent
      tail, and one before the stacks/Trash tail) so `Dock.qml` places
      dividers from the model and the droppable/non-droppable and overflow
      counts account for every divider. Keep the divider a non-entry
      separator, never draggable/reorderable.
- [ ] Tokens: add a `component.dock.divider.gap` (or `spacing`) for the
      over-sized room around a divider (start ~22 pt per side against the icon
      gap) and raise `divider.heightRatio` toward the reference (~0.8);
      regenerate `Theme.qml`.
- [ ] Layout (`Dock.qml`): use the divider-specific spacing at divider
      boundaries in both the resting `_baseline` and the magnified layout, and
      keep it consistent on bottom/left/right positions. The divider before
      the stacks/Trash tail renders whenever the tail is present.
- [ ] Hide a boundary divider when either side is empty (no pinned prefix, no
      temporary/recent tail, or no stacks/Trash), so the resting Dock never
      shows a doubled or orphaned rule.
- [ ] Keep the T-10 §5 divider resize handle working (it lives on the app ↔
      right-region divider); a new boundary must not add a second resize
      handle.
- [ ] Tests: `tst_dockcore` for the region/divider list and drop indices;
      `tst_dock.qml` for divider count, the enlarged spacing, height ratio,
      orphan suppression, and magnification/position variants.
- [ ] Capture `docs/captures/t14-dock-dividers-{light,dark}.png` (three
      regions; empty-tail and single-region cases) and the `PROGRESS.md` note.

## Explicitly deferred

- Region headers/labels; Space grouping in the Dock.
- A user-configurable divider spacing.
- Divider styling as a menu/action affordance (the app-region divider keeps
  its existing resize behavior).
- Pinned/temporary merge semantics (T-10 §4.1) — unchanged.

## Design notes

- The divider is a projection of region structure, not user state; the shell
  supplies the boundaries, the Dock draws them.
- One extra divider must not change `dock.pinned` ordering or the drag-reorder
  path: the pinned prefix boundary follows the pinned count, not a stored slot.
- Do not let the wider divider spacing break the existing gap-drag insertion
  math; update the pure layout and its tests together.
- The reference has no minimized region visible; verify the empty-region
  suppression rather than assuming it.
