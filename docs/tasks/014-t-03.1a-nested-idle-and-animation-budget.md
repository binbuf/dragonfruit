## Goal

Prove zero idle damage/wakeups and one compositor frame per animation frame in a 60 s nested trace.

## Scope

- 60 s nested idle trace: zero damage, zero client wakeups.
- One frame of compositor work per animation frame.
- Record raw numbers and an honest pass/fail in PROGRESS.md.

## Explicitly deferred

- Latency instrument and direct-scanout template (T-03.1b).

## Acceptance (agent-completable)

- [ ] 60 s trace flat; animation frame count matches; numbers recorded.

## Test plan

- Headless: `idle_trace` extended to assert the flat window.

## Hand-off

**Landed.** The idle/animation trace is instrumented directly and the 60 s
headless acceptance run is flat (raw log `docs/captures/t03-idle-trace.txt`):
60.0 s idle window with `frames_rendered=1` (flat, +0),
`animation_frames_stepped=0` (flat, +0), `direct_scanouts=0` (flat, +0),
`client_wakeups=0` (flat, +0); a 320 ms `animate-dummy` advances
`frames_rendered +20` and `animation_frames_stepped +20` (one compositor frame
per animation frame); both flat again after settle. Verdict: pass. Repro:
`bash scripts/idle-trace.sh` (or `make idle-trace`).

**What changed.** `RenderStats::client_wakeups` counts frame-callback batches
handed to mapped windows; `dump_stats` appends it to the render-stats line.
`idle_trace.rs` gained the synthetic-input socket, a `DF_IDLE_TRACE_SECS`
window (default 10 s in-suite), the four-counter flat assertion and the
animation frame-match assertion. `Makefile` adds `idle-trace`;
`scripts/idle-trace.sh` records the acceptance log. ADR
`0009-idle-trace-instrumentation.md`; `docs/design/02-compositor.md` "Idle and
animation frame trace (T-03.1a)".

**Deviations.** (1) The trace runs on the **headless** backend, per the task's
test plan ("Headless: `idle_trace` extended"); the nested/live run and the DRM
run are T-03.2/T-03.4. (2) The in-suite window is 10 s for speed; the 60 s
window is the `make idle-trace` acceptance. (3) `client_wakeups` is a batch
count (one per live window per presented frame), an upper bound, not delivered
`wl_callback.done` events; it is exact enough for the idle assertion and is
counted on DRM via `count_output_windows` until the `DrmCompositor` path is
hooked.

**For T-03.1b.** The render-stats line is a positional, **append-only**
contract: append the latency and scanout fields after `client_wakeups`, never
reorder. The direct-scanout template reads `DfState.stats`; on DRM
`direct_scanouts` already increments in `backend/drm.rs`.
