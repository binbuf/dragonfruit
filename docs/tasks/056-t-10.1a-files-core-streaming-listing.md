## Hand-off

Landed T-10.1a as a new workspace library crate
**`services/files-core/`** (`dragonfruit-files-core`): the streaming
directory model and the platform seam. See
`docs/design/adr/0042-files-core-streaming-listing-and-fallback.md`.

- **Model** — `Location` (URI-addressed, raw-byte-safe percent-encoding),
  `Node` (original name bytes, stable per-session `NodeId`, kind, size,
  modified, symlink target), and `DirectoryModel` (`begin`/`apply`/`drain`,
  generation-keyed so a stale listing is ignored). `check_consistent()`
  asserts the id→index invariant.
- **Streaming** — `DirectorySource`/`DirectoryReader` is the seam; `begin`
  spawns a named worker that forwards `ListingEvent`s over a channel, so no
  I/O runs on the consumer thread. Dropping the `ListingHandle` cancels it.
- **Fallback** — `StdFsSource` (std `read_dir`) is the sanctioned fallback,
  marked by `SANCTIONED_FALLBACK_MARKER` for replacement by GIO/GVfs in
  T-10.1b. It resolves only `file://`; other schemes return
  `UnsupportedScheme`. GIO is absent on this host.
- **Tests** — `cargo test -p dragonfruit-files-core`: 22 pass (15 unit + 6
  integration + 1 doctest). Integration covers a 4000-file directory
  streaming a first batch `<` total then completing with a consistent index,
  `MockSource` arrival order, error reporting, and non-UTF-8 names.
- **Gate** — `make lint` 31/31; `make e2e` exit 0; the Makefile `e2e` target
  now includes `dragonfruit-files-core`.
- **Live visual check** — no surface of its own. Nested demo capture
  `/tmp/opencode/t56-desktop.png` (1920x1200): menu bar and dock render, no
  artifacts; vision read the same (supporting check only).

Deviations: T-10.1a does not sort (nodes are in arrival order) and does not
provide a GIO backend; both are T-10.1b's scope, per the task. The Qt/cxx-qt
bridge is not present in the repo, so the model is not yet embedded in
`apps/files` (T-10.4).

Next (T-10.1b): sort over `DirectoryModel` and finalize the GIO-vs-fallback
decision behind the unchanged `DirectorySource` seam.
